# hedgehug(タスク管理ツール)

## 背景
・ソフトウェア開発チームのタスクを、外部のサービスやサーバーに置かず、git リポジトリに保存して管理したい
・git のリポジトリはチームで共有できるので、remote を通じて複数の人・複数のマシンで同じタスクを扱える
・開発の作業は GitHub の PR や Issue と結びついているため、タスクと PR・Issue をつないで状況を把握したい
・git を使ったことがない人や、git の設定をしていない人でも使えるようにしたい

## アクター
・チームメンバー：Store に書き込める人。タスクを作成・変更・削除し、計画を立てる
・閲覧者：GitHub で読み取りの権限しかなく、Store の中身を見るだけの人
・プロジェクトオーナー：プロジェクトの責任者
・担当者：アイテムを担当して作業する人

## 外部システム
・git リモートリポジトリ：Store を共有するための remote(GitHub など)
・GitHub：アカウントの認証、リポジトリの権限の確認、PR・Issue の情報、コラボレーター、リポジトリの検索

## 要求
・タスクを階層(プロジェクト → Epic → Story・Task・Bug → Step)で管理できる
・バックログ・スプリント・リリースで計画を立て、進み具合をレポートで確認できる
・複数の人が同じタスクを別々のマシンで同時に編集しても、同期で正しくまとめられる
・誰が・いつ・何を変えたかを、すべて記録として残し、あとから確認できる
・自分が担当するタスクと、自分宛ての通知を、すべての Store を通して確認できる
・タスクと GitHub の PR・Issue を結びつけ、その状態をタスクの側で確認できる

## 制約
・タスクの保存先は git リポジトリ(Store)だけで、専用のサーバーやデータベースを持たない
・remote のない Store は、そのマシンの中だけで使える
・GitHub のアカウントは任意で、GitHub を使わなくてもタスク管理はできる
・Store のファイルは、GitHub の画面で人が読める形にする
・個人のメールアドレスは Store にも保存の記録にも残さない
・ブラウザの画面から操作する。CLI は後の段階で用意する
・旧版の hedgehug の Store は引き継がない

## ビジネスポリシー
・Store の中身(ワークスペースの設定、プロジェクト、アイテム、メンバー、履歴)は、remote を通して全員で共有する
・GitHub のアカウント、Store の一覧、通知と既読、保存したビュー、画面の状態は、マシンごとに持つ
・役割による権限の区別はなく、Store に書き込める人は、他の人が作ったものも変更・削除できる
・アクセスの管理は GitHub のリポジトリの権限で行う。読み取りの権限しかない Store は閲覧のみにする
・利用者の 1 回の操作を 1 回の保存(git の 1 コミット)として記録し、操作した人・時刻・内容を残す
・1 回の操作の途中で失敗したら、その操作で変えたものはすべて元のままにする(一括変更だけは、変えられたものを保存し、変えられなかったものと理由を示す)
・元に戻す・やり直しの仕組みは持たない
・削除したものは保持日数のあいだ復元でき、過ぎたら自動で完全に削除する。完全な削除は取り消せない
・同時に編集したときは、項目ごとに新しい変更を生かす。複数の値は両方を生かし、削除と変更が重なったら変更を残す
・「あなた」(操作している人)は Store ごとに、GitHub アカウントのログイン名か、このマシンで入力したログイン名で決め、Store のメンバーに自動で加える。一度加えたメンバーは外さない
・通知は Store に保存せず、各マシンが、自分の操作と同期で受け取った変更から自分宛てのものだけを作る
・アイテム・プロジェクト・ワークスペースは、別のワークスペースや別の Store へ移せる。移したあとも旧 ID からたどれる

## ビジネスパラメータ
・アイテムの種類：Epic・Story・Task・Bug・Step
・ワークスペースごとに、プロパティ(担当者・開始日・終了日・ポイント・見積もり時間・関連システム・優先度・ステータスなど)と、その値を定義できる
・ステータスは分類(未着手・進行中・完了・中止)に属し、ワークフローで移れるステータスを制約できる
・プロジェクトごとに、表示するステータス・制約・使うテンプレート・自動化を上書きできる
・プロジェクトのステータスは Todo・InProgress・Done・Pending・Cancel に固定する
・アイテムどうしの関連：blocks・causes・duplicates・relates to・clones
・ワークスペースの接頭辞(例：HH)の有無で、ID の表示(HH-12、#12)が変わる
・Store ごとの同期の有無と間隔、削除済みの保持日数

## 業務概要
・Store の管理
  - git リポジトリを Store として追加する(新しく作る、remote から clone する、GitHub から検索する)
  - Store の名前・色・非表示・remote・使う GitHub アカウントを設定する
  - Store をこのマシンから削除する
  - Store のメンバーを管理する(GitHub のコラボレーターをメンバーに加える)
  - 初回起動のときに、このマシンのログイン名を入力し、最初の Store を追加する

・ワークスペースの管理
  - ワークスペースを作成し、接頭辞を決める
  - プロパティ・値・ワークフロー・テンプレート・自動化を設定する
  - ワークスペースを別の Store へ移す

・プロジェクトとアイテムの管理
  - プロジェクトを作成し、オーナー・期間・ステータスを決める
  - アイテムを作成・複製・移動・種類の変更・削除する(テンプレートから構成ごと作成できる)
  - アイテムに担当者・期間・ポイント・見積もり時間・優先度・ステータスなどを入力する
  - アイテムにコメント・メンション・作業時間・関連を記録する
  - 自動化で、ステータスの変化や GitHub の出来事をきっかけに値を自動で変える

・検索と一覧
  - マイタスクで、自分が担当する未完了のアイテムを確認する
  - クエリでアイテムを絞り込み、ツリー・カンバン・テーブル・ガントで表示する
  - 検索の条件と表示の設定をビューとして保存する
  - 複数のアイテムをまとめて変更・削除する

・計画とレポート
  - バックログで作業項目の優先順位を決める
  - スプリントを作成・開始・完了し、作業項目を割り当てる
  - リリースを作成し、アイテムを割り当てる
  - バーンダウン・ベロシティ・累積フロー図・サイクルタイム / リードタイム・見積もりと実績のレポートで進み具合を確認する

・同期
  - remote と送信・受信を行い、自動同期の間隔を設定する
  - 同時に編集した変更をまとめる
  - 番号の重なりや、強制 push などで壊れた状態を修復する
  - 他のタブや CLI での変更を、開いている画面に反映する

・通知と記録
  - 受信箱で、自分宛ての通知(担当、メンション、変更など)を確認し、既読にする
  - アクティビティで、Store の変更の記録を確認する
  - アイテムとプロジェクトの履歴を確認する

・GitHub 連携
  - GitHub アカウントを登録する
  - アイテムに PR・Issue をリンクし、タイトルと状態(PR のレビュー・チェックを含む)を表示する
  - ブランチ名や PR のタイトル・本文・コメントに書いたアイテムの ID から、PR を自動でリンクする

・保守
  - 削除済みのアイテムなどを復元する、または完全に削除する
  - 診断で壊れたデータを見つけて修復する
