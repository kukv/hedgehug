# フェーズ 5d-1: Go の API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 5d の画面が使う API・SSE・OpenAPI と、取得とレート制限の状態、ルールの回数の集計を作る。全エンドポイントを Go のテストで確かめ、生成物に差分がない状態にする（spec の 5d-1 の完了条件）。

**Architecture:** server は usecase だけを通す（depguard）。`storage/ghstate`・`storage/config` を読む処理は `usecase`（土台）と `usecase/accounts` に足す。取得の状態は `StoreStatus` に要約を載せて既存の `sync.state` で届け、repo ごとの詳細は `GET /api/github` で返す。`automations.yaml` の変更は watcher が `automations.changed` で知らせる。

**Tech Stack:** Go、huma、fakegh、openapi-typescript。

**Spec:** `docs/superpowers/specs/2026-11-05-phase5-github-design.md` の「データの形」「5d の画面」。

**PR:** この plan・spec の変更・5c の引き継ぎの修正は実装の PR に入れる。

## Global Constraints

- コミットの署名は 1Password。失敗したら index に積んで利用者に知らせる
- `make` は `MAKEFLAGS=-j10`
- cli と server は usecase だけを通す。usecase の領域どうしは import しない
- OS に触る呼び出しは `lib/osfs` を通す
- 生成物は `go generate ./internal/app/server` と `pnpm gen`（`web/` で）で作る
- 既存のテストの期待値は、この plan が明示したものの他は変えない
- web は `SYNC_OPS` と活動の分類だけを変える。画面は 5d-2・5d-3
- 各 Task の終わりに `go vet ./...` と、変えたパッケージの `go test` を通してコミットする

## この回で決めたこと

| # | 項目 | 決定 | 理由 |
|---|---|---|---|
| 1 | PR・Issue のタイトルとブランチ | `gh.prs[].title`・`branch`、`gh.issues[].title` を足す。取り込みが書く | キャンバスのタスク詳細と「リポジトリと PR」の表が出す。2026-11-05 利用者が決定 |
| 2 | リンク元 | `links[].via` を足す（`branch`・`mark`・`id`・`comment`）。手のリンクと既存のリンクには書かない。`off` から `hh link` し直したら消す | 同上。1 つの PR が複数の理由で当たるときは `mentioned` の順の最初 |
| 3 | 一覧のリンク | `TaskView.Links` に移し、`ls --json`・API の一覧にも出す。`ShowView.Links` は消す。`index.Entry.GitHub`（`synced` を除く）を足し、`cacheFormat` を 10 にする | チップは一覧で要る。一覧でタスクファイルを読み直さない |
| 4 | リンクの表示 | `LinkView` に `title`・`branch`・`via`・`fields` を足す | タスク詳細が出す |
| 5 | `hh issue` の repo | `IssueInput.Dir` が空で repo が決まらないときは `issue.repo_required`（400）。CLI は今のまま Dir を渡す | GUI はカレントのリポジトリを持たない |
| 6 | 回数の集計 | `GET /api/automations/stats`。直近 7 日のコミットを history の索引で選び、`Entries` で trailer を読む。索引の形式は変えない。`hh automation list --json` は変えない | 索引は trailer を持たない。7 日分だけなら読む量が小さい |
| 7 | 活動の分類 | `?automation=only\|exclude` を足す。`syncOps` は `merge`・`repair` に戻す。`gh-*` の op と、`Hedgehug-Automation`・`Hedgehug-Automation-Rejected` の trailer を持つコミットが「自動化」 | `?sync=` の URL を壊さない。「人」は両方 `exclude` |
| 8 | ライブ表示 | `tasks.changed` に `automated` を足し、`cache.ts` は「自動化で更新 · 今」と出す | 5b の引き継ぎの宿題。author の文字列を web に持たない |
| 9 | 取得の状態 | `StoreStatus.GitHub`（要約、`omitempty`）を足す。`hh sync --status --json` にも出る。詳細は `GET /api/github` | `ghstate` は履歴の外なので、新しい監視を作らず `sync.state` に乗せる |
| 10 | 次の取得時刻 | `ghstate.Repo.NextAt(now)` を足し、`Due` はそれで判定する | 判定と表示を別に書かない |
| 11 | App の未インストール | `github.ErrNotAccessible` を足す。REST の 403 と GraphQL の `FORBIDDEN` のどちらも `Resource not accessible by integration` で判定する。`ghstate.Repo.AppMissing` に残し、読めたら消す。fakegh は `RestrictApp(owner)`、`fakegh repo restrict <owner>` | spec の決まりどおり |
| 12 | `repo_accounts` | `GET`・`PUT /api/repo-accounts`。PUT は全体の置き換え（ドラッグの結果を送る）。`config.SetRepoAccounts` が `loadRepoAccounts` と同じ検査をする | 順番が意味を持つので 1 件ずつの API にしない |
| 13 | `gh のトークンで代わりに使う` | `PUT /api/accounts/{name}/token-source`、`token` は `gh` か `env:<VAR>` | `add-account` と同じ値。keychain と device は既存の API |
| 14 | `管理者にインストールを依頼` | API を足さない。`GET /api/github` の `account`・`app_missing` と host から、5d-3 が GitHub の URL を作る | サーバーが持つ情報がない |
| 15 | `repo を追加` | 既存の `PATCH /api/tasks/{id}` の `repos` を使う | API が既にある |
| 16 | リンクの解除 | `DELETE /api/tasks/{id}/links?pr=&issue=` | CLI の `--pr`・`--issue` と同じ書き方 |
| 17 | SSE | `automations.changed {store}` を足す | `schema.changed`・`views.changed` と同じ |
| 18 | キャンバスの修正 | spec の 3 点をこの回で直す。`via`・タイトルはキャンバスにもう描かれている | 「5d の前に」 |

## Tasks

各 Task は失敗するテストを書く → 失敗を確かめる → 実装 → 通す → コミットの順で進める。

### Task 1: `gh` のタイトル・ブランチと `via`

- [ ] `github_apply_test.go`: 取り込みで `title`・`branch` が入り、タイトルが変わると `Changed` になる。自動リンクの `via` が `branch`・`mark`・`id`・`comment` になる（表形式）
- [ ] `model`: 3 つのフィールドを足す。`PRState` の順は `ref, title, branch, state, ...`、`IssueState` は `ref, title, state, ...`（すべて `omitempty`）。`Link.Via` は `yaml:"via,omitempty"`
- [ ] `mentioned` を `[]mention{name, via}` を返す形にし、`autoLinks` を `map[ULID][]autoLink{ref, via}` にする。`apply` は `via` を入れて足す
- [ ] `withPull`・`withIssue` がタイトルとブランチを写す
- [ ] `hh issue` の `linkPushed` と `hh gh import` の `gh` にタイトルを書く。`link` の `off` からの再リンクで `Via` を消す
- [ ] `TestApplyGhFormat` などタイトルが増えて変わるゴールデンだけ直す。別のメンバーとの `gh` のマージは既存のキー単位で通ることをテストで固定する

### Task 2: 一覧のリンク

- [ ] `read` のテスト: `ls --json` の行に `links`（`state`・`title`・`via`）が出る。`off` は出ない。`hh show --json` の出力は `links` の項目が増えるだけ
- [ ] `index.Entry.GitHub` を足す。`Synced` は nil にして持つ。`cacheFormat` を 10 にする
- [ ] `LinkViews(links, g)` を作り、`LinkViewsOf` はそれを呼ぶ。`TaskView.Links` を足し、`ShowView.Links` を消す
- [ ] `issue.repo_required`: `in.Dir == ""` で repo が決まらないとき

### Task 3: App の未インストールと `ghstate`

- [ ] `lib/github`: REST の 403 と GraphQL の `FORBIDDEN` で `ErrNotAccessible` になるテスト。`errors.Is(err, ErrForbidden)` は保つ
- [ ] `fakegh`: `RestrictApp(owner)`。その owner の GraphQL が `FORBIDDEN` を返す。`cmd/fakegh` に `repo restrict <owner>`
- [ ] `ghstate`: `NextAt`（`TestDue` の表に揃えたテスト）、`Slowed(now)`、`AppMissing`
- [ ] `fail` の経路で `AppMissing` を立て、成功で消すテスト（`github_fetch_test.go`）

### Task 4: 取得の状態

- [ ] `usecase.GitHubStatus(ss) ([]GitHubRepoView, error)`: `targets` と `ghstate` の和で、`repo`・`store`・`account`・`last_fetch`・`next_fetch`・`warnings`・`limit`・`remaining`・`reset_at`・`slowed`・`app_missing`。`?store=` なしは全 Store
- [ ] `GitHubSummary`: `last_fetch`（最新）、`next_fetch`（最早）、`limit`・`remaining`（残りの割合が最小の repo）、`slowed_until`、`warnings`（件数）、`app_missing`（件数）
- [ ] `StoreStatus.GitHub`。取得対象がなければ省く

### Task 5: 回数の集計

- [ ] `automations.Stats(ss) ([]RuleStat, error)`: `RuleStat{Rule, Applied, Rejected, RejectedTasks []Ref, LastReason}`。直近 7 日（`ss.Now`）。ルールと `mirror` の両方。テストは実際に `FetchGitHub` を回して拒否と適用を作る

### Task 6: `repo_accounts` と取得元

- [ ] `config.SetRepoAccounts`: 順番を保って書き、知らないアカウント・壊れた `match` を拒否する。空なら `repo_accounts` のキーを消す
- [ ] `accounts.RepoAccounts`・`SetRepoAccounts`・`AuthSource`

### Task 7: API

- [ ] `server/github.go`: `POST`・`DELETE /api/tasks/{id}/links`、`POST /api/tasks/{id}/issue`、`GET /api/github`、`POST /api/github/import`、`GET`・`PUT /api/repo-accounts`
- [ ] `server/automations.go`: `GET`・`POST /api/automations`、`DELETE /api/automations/{id}`、`PUT /api/automations/{id}/enabled`、`GET /api/automations/stats`、`GET`・`PATCH /api/automations/fields`
- [ ] `server/accounts.go`: `PUT /api/accounts/{name}/token-source`
- [ ] エンドポイントごとに成功と主な失敗（`problem` のコード）を `server/github_test.go`・`automations_test.go` で確かめる

### Task 8: 活動と SSE

- [ ] `?automation=` のテスト。`syncOps` を戻す。`usecase.AutomatedCommit(op, trailers)` を足す
- [ ] `watch.Change.Automated`、`Sink.AutomationsChanged`、`automations.changed`
- [ ] `cache.ts`: `SYNC_OPS` から `gh-*` を外し、`automated` で「自動化で更新 · 今」。vitest を足す

### Task 9: 生成物と仕上げ

- [ ] `go generate ./internal/app/server`、`pnpm gen`、`git status` で生成物だけが動くことを確かめる
- [ ] `make fmt-check`、`make lint`、`go vet -tags e2e ./internal/app/cli`、`go vet -tags live ./internal/lib/github`、`go test -race ./...`、`pnpm check`・`pnpm lint`・`pnpm test`
- [ ] キャンバス 3 点を直す。親設計の「GitHub から取り込む値」に `title`・`branch`・`via` を足す
- [ ] `2026-11-05-phase5d1-handoff.md` を書く
- [ ] PR を出す
