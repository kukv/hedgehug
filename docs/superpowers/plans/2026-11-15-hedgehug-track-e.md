# hedgehug トラック E(検索とレイアウト)の分け方

**Goal:** 仕様 04(検索とレイアウト)を 7 本の小計画に分け、ほかのトラックから E に回された項目の行き先を決める。各小計画の中身は、それぞれの計画に書く。

**Spec:** `docs/superpowers/specs/2026-11-11-hedgehug-functional-spec/04-search-layouts.md`(全文)。設計書の段階 1 の表「E 検索とレイアウト」。

## 決めたこと

| # | 決めたこと | 根拠 |
|---|---|---|
| E-1 | E は 7 本に分け、それぞれ 1 計画・1 PR にする(下の表) | ユーザーの決定(2026-11-15) |
| E-2 | 検索の照合は、state.db に索引を作らず、表示中の Store をその都度読む(パレット・レポート・履歴と同じ)。設計書(architecture の `port.Index`、storage-design の「このマシンに持つもの」の索引の段・「クエリのキー」の行)とトラック C の決定 11 は E1 の PR で書き換える | ユーザーの決定(2026-11-15)。取り込みの仕組みがまだなく、ほかの画面が Store をその都度読んでいるため |
| E-3 | 順番は E1 → E2 → E3a → (E3b・E4・E5・E6・E7 を並行。同時に動かすのは 4 本まで。E3b は E4〜E7 をブロックしない) | E2〜E7 は E1 のクエリと画面の状態の保存を使う。E4〜E7 は E3a のレイアウトの切り替えとツリーの部品を使う |
| E-4 | 検索の `is:invalid` の判定(08「検出する項目」のアイテムを指す 12 項目)は、E1 で `domain/repair` の 1 つの関数として作る。G の診断は同じ関数を使う | ユーザーの決定(2026-11-15) |
| E-5 | E2 は 3 本に分ける(E2a・E2b・E2c) | ユーザーの決定(2026-11-15) |
| E-6 | ワークスペースの画面の「ツリー」タブ(プロジェクトの行・プロジェクトのメニュー)は E7 | ユーザーの決定(2026-11-15) |
| E-7 | E3 は 2 本に分ける(E3a・E3b)。切り替えには作ってあるレイアウトだけを出し、カンバン・ガントのボタンは E5・E6 が足す | ユーザーの決定(2026-11-15) |
