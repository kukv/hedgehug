# フェーズ 6e の引き継ぎ（2026-11-06 時点）

6e（ガントとグラフ）は plan の Task 1〜8 を実装した。`layout: gantt`、ガントとロードマップ、レポートの画面、スプリントボードのバーンダウンがブラウザで動く。`web/e2e/gantt.spec.ts` と `web/e2e/reports.spec.ts` が通しを確かめる。これでフェーズ6の小フェーズはすべて実装した。

## plan から変えた点

- `tokens.css` にダークテーマはない。色は描くときに1回読むだけで、テーマの変更には追従しない
- `core/messages.ts` に `report.*` の文言がなかったので足した。6c の時点では画面がなく、見つからなかった
- `usePlans` の引数は `null` を返せる。全 Store のスコープでワークスペースが1つに決まらないとき、スプリントもリリースも読まない
- `settings-github.spec.ts` の競合を直した。`hasText: "*"` が別の行にも一致し、描画が速いと落ちる（6e の CI で初めて出た）
- `FilterBar` と `ListBar` を直した。スイッチの多い画面で入力欄が幅 0 になり、見えなくなっていた（6d のカンバンでも起きていた）。入力欄を優先し、CLI の行を縮める。幅が足りなければスイッチを次の行に送る

## 実装で分かったこと

- コミットの時刻は秒単位である。開始と同じ秒に入ったタスクは初期の範囲に数える。E2E で「途中で追加」を見るには秒をまたぐ必要がある
- 開始の日付より後に開始したスプリントは、バーンダウンの前の方の日が範囲 0 で返る。理想線はこれを起点にせず、範囲が入った最初の日から引く
- `<title>` の中で `{a} {b}` と書くと Svelte が空白を詰める。テンプレート文字列にする
- ガントはタスクより後にスプリントを読むので、左へ広がる。今日へのスクロールは1回で済ませず、広がった分だけ足す

## CLI と GUI の突き合わせ

完了条件の「フェーズ6の CLI の操作が GUI でもできる」を、コマンドごとに確かめた。

| CLI | GUI |
|---|---|
| `hh sprint add` / `ls` / `set` / `rm` | スプリントのタブ、計画の節、パレット |
| `hh sprint start` / `close --to` | 開始と終了のダイアログ（次、バックログ、名前） |
| `hh release add` / `ls` / `set` / `notes` / `rm` | リリースのタブ |
| `hh worklog` / `ls` / `rm`（`--date` を含む） | タスク詳細の作業時間の欄 |
| `hh template ls` / `show` / `edit` / `rm` | 設定のテンプレート |
| `hh add --template` / `--no-template` | 作成ダイアログのテンプレートの欄 |
| `hh add --sprint` / `--release` | 作成の後、タスク詳細の欄かバックログで入れる（2 手で同じ結果になる。spec の 6d が作成ダイアログに求めるのはテンプレートの欄だけ） |
| `hh schema scope set --templates` / `--template-default` | プロジェクトの設定 |
| `hh set sprint=` / `releases=` | タスク詳細、バックログのドラッグとメニュー |
| `hh set --query` | テーブルの一括編集、パレット |
| `hh report burndown` / `velocity` / `cfd` / `cycle` / `estimate` | レポートのタブ。条件のフラグはどれも画面の操作にある |
| `hh view save --layout gantt` / `--gantt-start` / `--gantt-end` / `--roadmap` | ガントの操作と「ビューを保存」 |
| `sprint:` / `release:` のクエリ | フィルタの欄 |
