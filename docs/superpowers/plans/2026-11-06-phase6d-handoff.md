# フェーズ 6d の引き継ぎ（2026-11-06 時点）

6d（計画の画面）は plan の Task 1〜12 を実装した。バックログ、スプリント、リリース、タスク詳細の計画の欄、一括更新、WIP 上限、テンプレートがブラウザで動く。`web/e2e/planning.spec.ts` が通しを確かめる。

## plan から変えた点

- `watch.go` の `childTask` に作業時間のパスを足した。`tasks.changed` が作業時間のコミットでタスクの ULID を持たず、詳細の合計が更新されなかった。E2E で見つかった
- `web/app/list/ListBar.svelte` の折り返しを直した。テーブルのタブで `hh view save` の行が長いと、絞り込みの欄が幅 0 になって隠れていた。6d の前からの不具合である

## 実装で分かったこと

- 一覧の `TaskView.props` の値は、ファイルに書かれたとおりの文字列である。`points` は `"5"` で来る。`pointsOf` は数値と文字列の両方を読む
- 親ごとに rank を振るので、親をまたぐ一覧には同じ rank が並ぶ。隣の2件の間には置けないことがあり、`Rerank` は後ろの同じ rank のタスクも振り直す
- `GET /api/sprints` の `workspace` はワークスペースの名前で渡す
- タスクも schema も変えないコミット（スプリントやリリース）は、ULID のない `tasks.changed` になる。`usePlans` と `stores.ts` はこれで読み直す
