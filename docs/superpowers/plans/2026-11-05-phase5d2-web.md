# フェーズ 5d-2: 表示 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PR のチップ、タスク詳細の GitHub セクション、プロジェクトの「リポジトリと PR」、通知、アクティビティ、状態の表示をブラウザで動かす（spec の 5d-2 の完了条件。E2E で確かめる）。

**Architecture:** 判定と文言は `web/core/github.ts` に集め、画面はそれを呼ぶ。ルールと取得の状態は `web/core/github-status.ts` の読み取りで Store ごとに持ち、`automations.changed`・`sync.state` で読み直す。Go の変更は表の PR 列と、E2E のための fakegh のコマンドだけ。

**Tech Stack:** Svelte 5、vitest、Playwright、fakegh。

**Spec:** `docs/superpowers/specs/2026-11-05-phase5-github-design.md` の「5d の画面」。**キャンバス:** Hedgehug GUI デザインの TaskDetail・Inbox・Activity・Project・Kanban・Main・Table・MyTasks・States・Foundations。

**PR:** この plan と引き継ぎは実装の PR に入れる。

## Global Constraints

- コミットの署名は 1Password。失敗したら index に積んで利用者に知らせる
- `make` は `MAKEFLAGS=-j10`。E2E は `make e2e`（`e2e-bin: web` で順番を守る）。`make web e2e-bin` を並べない
- 既存のテストの期待値は、この plan が明示したものの他は変えない（通知のタブの並びと、プロジェクトのタブの数は変わる）
- Go を変えたら `go generate ./internal/app/server` と `pnpm gen` を走らせる
- `$ hh start <ID>`・`PR を作る` は実行せず、コマンドをコピーする

## この回で決めたこと

| # | 項目 | 決定 | 理由 |
|---|---|---|---|
| 1 | 「リポジトリと PR」の場所 | プロジェクトに「概要」タブを足す。中身は当面この表だけ。`/projects/<ULID>` の既定はツリーのまま | キャンバスは概要に描く。2026-11-05 利用者が決定 |
| 2 | `Issue から取り込む` | 5d-2 で `IssueImportDialog` を作る。repo、ラベル、`dry_run` の件数、親はそのプロジェクト。5d-3 の設定はフォームを使い回す | ボタンの行き先を空にしない。2026-11-05 利用者が決定 |
| 3 | パレットの `hh start` | 5d-2 で足す。「<ID> に対して」の組に出す | 同上 |
| 4 | Issue の作成 | `POST /api/tasks/{id}/issue` は 5d-3 の GUI の操作に回す | spec の 5d-2 のタスク詳細の行に入っていない |
| 5 | 表の PR 列 | `view.Builtins` に `pr` を足す。保存できる列にする。`DefaultColumns` は変えない | キャンバスは列として描く。`@store` と違い、利用者が選んで保存する |
| 6 | チップの向き | `merged → draft → CI 失敗 → 修正依頼 → approved → open` の順で 1 つ。`closed` は `closed`、未取得は状態なし | spec。`closed` と未取得は spec にないので足す |
| 7 | 複数の PR | 表の順は「開いている・draft・未取得 → closed → merged」、同じ段はリンクの順。先頭を見せて残りを `+n` | spec の「マージされていない PR を先に」。`closed` は作業が残らないので後ろ |
| 8 | チップのリンク名 | `label` の owner を落とす（`org-a/web#88` → `web#88`）。詳細と表の「PR」はキャンバスどおりで詳細は owner 付き、プロジェクトの表は owner なし | キャンバス |
| 9 | PR の URL | `ref` に `https://` を付ける（`github.com/org-a/web/pull/88`） | ref が host を持つ。web に host の設定は渡さない |
| 10 | カンバンの説明 | `GET /api/automations?project=` の有効なルールから作る。`pr.opened` →「PR を開くと自動でここへ」、`pr.merged` は `when` ありで「全 PR のマージで自動でここへ」、なしで「PR のマージで自動でここへ」。ほかのイベントは出さない。Store が 1 つのボードだけ | 文言を決め打ちしない。spec が出すのは 2 つ |
| 11 | `automations.changed` | `connection.ts` に足す。5d-1 は server だけ足した | ルールの変更で説明を読み直す |
| 12 | 拒否の通知の行動 | `reason` を解釈しない。`rule` → ルール → 行き先のステータス → `requiredFields`（`show.scope`）→ `requiredGap` で埋める項目を出し、`RequiredDialog` を使い回す。文言は `<項目> を入力して<ステータス>にする`。埋める項目がない、ルールが消えた、`mirror` なら `このままにする` だけ | `reason` は英語の `field: msg`。`RequiredDialog` が同じ操作を持つ |
| 13 | `issue_overwritten` | 「自動化」タブに入れる。文言は `side` で分ける。`lost` を打ち消し線で出す | キャンバスは「上書き」でなく自動化の種類で描く |
| 14 | タブの並び | すべて・メンション・割り当て・ウォッチ・上書き・自動化・同期の修復 | キャンバス |
| 15 | アクティビティ | 4 つ目の種類「自動化」は `?sync=automation`。API へは `automation=only` で問い合わせる | 5d-1 の決定 7 |
| 16 | 拒否の行 | `Hedgehug-Automation-Rejected` を web で読み、拒否ごとにタスクへのリンクと理由を出す。ID は `createLookup` で引き、引けなければ ULID | `gh-fetch` のコミットは `task` を持たない。spec の「取り込みのコミットを指す」 |
| 17 | 取得を延ばす文言 | 「取得を 15 分おきに延ばしています · HH:MM に回復」の 15 は定数（5 分の 3 倍）。API は間隔を返さない | spec の決まりどおりの固定値 |
| 18 | タスク詳細の取得時刻 | リンク先の repo の `last_fetch` の新しいほう | 要約は Store 全体を指す |
| 19 | fakegh のレート制限 | `fakegh rate set <remaining> <limit> --reset <sec>` を足す。E2E で表示を確かめる | `SetRateLimit` はあるがコマンドがない |
| 20 | 取得の間隔 | E2E の harness に `expireFetch(store)` を足す。`github.json` の `last_fetch` を 1 時間前にする | scenario テストと同じ方法 |
