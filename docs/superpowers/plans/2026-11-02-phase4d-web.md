# フェーズ 4d: フロントエンドの土台と中心の画面（概要）

> 4d は4回に分ける（2026-11-02 に利用者が決定）。この文書は4回に共通の決定事項・細部・ファイル構成・共通の型。Task の本文は次の4つの plan にある: `2026-11-02-phase4d1-go.md`（Task 1）、`2026-11-02-phase4d2-toolchain-core.md`（Task 2〜6）、`2026-11-02-phase4d3-tree.md`（Task 7〜10、15、16a）、`2026-11-02-phase4d4-detail-create.md`（Task 11〜14、16b、17）。各回は前の回のマージのあとに main から切る。

**Goal:** `hh ui` で開いたブラウザで、ツリーとタスク詳細からタスクを作成・編集でき、CLI の変更が即時に反映される GUI の土台と中心の画面を作る。

**Architecture:** `web/` に pnpm の1パッケージを置く。`web/core/` はフレームワークに依存しない TypeScript（API クライアント、SSE、正規化キャッシュ、保存の制御、CLI の文字列、エラーの文言）、`web/app/` は core を購読して描画するだけの Svelte 5（runes）のコンポーネント。Vite でビルドした `web/dist` を 4c の `web/embed.go` が埋め込む。Go 側は作成で本文とリポジトリを受け付ける変更だけを入れる。

**Tech Stack:** Svelte 5、Vite 8、TypeScript 6.0、pnpm 12、Biome 2.6（`.svelte` のテンプレートも）、svelte-check、Vitest 5 + @testing-library/svelte、Playwright、openapi-typescript + openapi-fetch、CodeMirror 6、Pragmatic drag and drop、TanStack Virtual、@fontsource。Go 側は既存の huma v2。

**Spec:** `docs/superpowers/specs/2026-11-01-phase4-gui-design.md`（「4d・4e フロントエンド」「画面と範囲」「4c サーバー」）。画面は Hedgehug GUI デザインのキャンバス（https://claude.ai/artifact/K14rwULxyyS2nYNbMKSr5L）の Foundations と各アートボードを正とする。

## Global Constraints

- 画面の文言はすべて日本語。コードの識別子・コメントは英語（既存のコードと同じ）
- コンポーネントは色・寸法の 16 進数や px を直接書かず、`web/app/styles/tokens.css` の CSS 変数を使う（Foundations: 「色はトークン名で実装し、画面に 16 進数を直書きしない」）
- ステータスは色だけでなく形で区別する（Foundations のステータスの形）
- 行とカードは ID だけを出し、ULID は ID にカーソルを合わせたときに出してコピーできるようにする。タスク詳細では ULID を常に出す。「キー未確定」・短縮 ID・「次の同期で確定」は作らない
- フォントは `@fontsource` で同梱し、外部（Google Fonts など）に通信しない
- ダークモードは作らない
- キーボード: ⌘K コマンドパレット、C タスクを作成、⇧⌘S 今すぐ同期、Enter 下に追加（ツリー）、Tab / ⇧Tab 字下げ・戻す、⌥↑↓ 並べ替え、Space 完了、S ステータス、K 種類、⌘↵ 詳細を開く・作成。Windows と Linux では ⌘ を Ctrl にする
- 保存は入力が 2 秒止まったとき、またはフォーカスが外れたときに `PATCH`。1操作1コミット
- トーストは左下に 6 秒、取り消し付きは 10 秒。取り消しにくい操作だけ確認ダイアログ。undo は確認しない
- ダイアログとフィルタ欄の足元には同じ操作の `hh` コマンドを出し、コピーできるようにする
- `svelte-check` は警告ゼロ、`biome ci` は指摘ゼロ
- spec・設計と違う挙動にしたくなったら、実装を止めて報告する（自分で決めない）
- Go のテストは `-race` を含めて通す。Go のジョブは `web/dist` なし（`.gitkeep` だけ）で通る

## 利用者の決定（2026-11-02、spec に反映する）

1. Biome は 2.6 の `html.experimentalFullSupportEnabled` で `.svelte` のテンプレートも整形・lint する。バージョンは exact で固定し、Svelte 固有の検査は svelte-check
2. サイドバーの 4e の画面への入口（保存済みビュー、マイタスク、通知、アクティビティ、ワークスペースの「…」メニュー、ワークスペースの概要）は 4e まで出さない。4d のワークスペースの行は `workspace:<名前>` のツリーを開き、4e で概要を開くように変える
3. Onboarding と CreateStore は 4d で作る（spec の表の 4d・4e を直す）
4. Store の色は `GET /stores` の順（設定の登録順）に 7 色を順に割り当て、灰色は閲覧のみ用に残す。色を選ぶ画面と保存場所は 4f（SettingsStores）で足す
5. 作成で本文とリポジトリを渡せるようにする: `ops.AddInput` と `POST /tasks` に `body`・`repos` を足し、`hh add` に `--body` を足す（リポジトリは既存の `-p repos=…`）。作成は1コミットのまま
6. ツリーのフィルタ欄の既定は `-status:canceled`（キャンバスどおり「n 件 · 中止 m 件を除外」）。足元の `hh ls` にもその条件が出る。欄を消せば中止も出る
7. `SyncStatus` に `push_at`（同期ループが次に push する時刻。`max(pending_since, 最後の同期) + sync.push_interval` と次の定期の同期 `next_fetch` の早いほう。push 待ちがないときは省く。2026-11-02 に利用者の決定で、`pending_since + sync.push_interval` から実際の時刻に直した）を足し、同期のカードに「n 秒後に push」を出す
8. コメントと本文の `@`（人）と `#`（タスク）の補完を 4d で作る。`#` はタスクの検索。`@` の候補は `GET /api/people?store=`（その Store のタスクの担当者・ウォッチャー・コメントの作者と、git のコミットの `Hedgehug-Author`。名前順・重複なし）を足して出す。キャンバスの「shared を読めません」の印（コラボレーターの判定）は GitHub の情報が要るので出さない
9. 履歴の「この時点に戻す」は、`GET /api/tasks/{id}/history/{commit}`（そのコミットの時点の `ShowView`）を足し、今との差分（変わるフィールドだけ）を確認ダイアログに並べてから戻す（キャンバスの Dialogs どおり）

### web/core

8. トークン: 起動時に `location.hash` の `#token=<t>` を `sessionStorage` の `hedgehug.token` に移し、`history.replaceState` で hash を消す。トークンがない・401 `auth.token` のときは「この画面は hh ui が開いた URL からだけ使えます。端末で hh ui を実行してください」の画面を出す
9. API クライアントは openapi-fetch の `createClient<paths>({ baseUrl: "" })` にトークンのミドルウェアを付ける。エラー（problem+json）は `ApiError { status, type, detail, args }` を投げる
10. エラーの文言: `type` ごとの日本語の文言を `core/messages.ts` に持つ（ops と server の Code すべて。args を埋め込む）。知らない `type` は「操作に失敗しました（<type>）: <detail>」
11. SSE: `fetch("/api/events")` の本文を読み、`event:`・`data:`・コメント行を解釈する。切れたら 1 秒・2 秒・4 秒、以降は 5 秒ごとに再接続する（States の「5 秒ごとに再接続しています」）。最初の再接続に失敗した時点で「サーバーに接続できない」の画面にし、最後に接続していた時刻を出して編集を止める。つながったら表示中のデータを取り直す
12. `hello` で各 Store の HEAD を覚え、再接続の `hello` で HEAD が前と違う Store があれば、表示中のデータを取り直す。`hello` の直後と Page Visibility の変化で `PUT /api/presence {client, visible}` を送る
13. キャッシュ: タスクは ULID をキーにした `Map<ulid, TaskView>`。一覧・ツリーの問い合わせ（`q`・`tree`・`store`）ごとに結果の ULID の並び（ツリーは入れ子）を持つ。`tasks.changed` では、(a) 表示中の詳細のうち `ulids`・`removed` に入るものを `GET /tasks/{ulid}` で取り直し、(b) 表示中の一覧・ツリーの問い合わせを取り直す（作成・移動・削除で並びが変わるため。spec の「該当の ULID だけを取り直す」から広げる点）。取り直した結果は既存のオブジェクトと比べ、変わったタスクだけを置き換える（変わらない行は再描画しない）
14. 自分の書き込みの見分け: 書き込みの応答の `commit` を覚え、`tasks.changed` の `commit` が自分のものなら印を付けない。それ以外は変わった ULID に 10 秒間の印を付ける。印の文言は op が `merge`・`repair` なら「同期で更新 · 今」、それ以外は「CLI で更新 · 今」（Foundations は「CLI で更新 · 今」だけで、同期の変更を区別するため足す）。HEAD が複数進んだときは最新のコミットだけで判断する
15. 保存の制御: タスクごとに変更中のフィールドを溜め、入力が 2 秒止まるかフォーカスが外れたら1回の `PATCH` で送る。状態は「保存中…」「保存済み」「保存済み · push 待ち」（その Store の `sync.state` の `unpushed` が 1 以上）と、失敗（エラーの文言とやり直し）。編集中のフィールドは、外からの変更で入力を上書きしない（フォーカスが外れたら送る。同じフィールドは後勝ち）
16. CLI の文字列: `hh` で始め、引数は空白・記号を含むときだけダブルクォートで囲む（`"`・`\`・`$`・`` ` `` はバックスラッシュでエスケープ）。表示は先頭に `$ ` を付け、コピーは `$ ` なし

### web/app

17. ルーティング（History API）: `/`（最初のワークスペースのツリー。Store がなければ Onboarding）、`/workspaces/<store>/<ワークスペースの ULID>`（`workspace:<名前>` のツリー）、`/projects/<ULID>`（プロジェクトのツリー。`project:<ULID>`）、`/tasks/<ULID>`（タスク詳細）。ID は振り直しで変わるので URL には ULID を使う。知らないパスは `/` へ
18. サイドバーのワークスペースは、`GET /stores` の各 Store に `GET /workspaces?store=<名前>` を呼んで集める（`GET /workspaces` は Store ごとのため）。プロジェクトは `GET /tasks?q=kind:project`（全 Store）で集め、ワークスペースの ULID で入れ子にする。並びはワークスペースは Store の順・名前順、プロジェクトは rank 順
19. Store の色: `GET /stores` の順に teal・orange・purple・sky・pink・olive・brown（Foundations の8色のうち灰色を除く）を順に割り当て、8 つ目以降は先頭に戻る
20. 人のアバター: 名前の先頭2文字（英字は大文字）。色は名前のハッシュで、デザインの4組（`#DDE3FA/#26399A`、`#FCE7D6/#8A3A06`、`#DCEFE2/#14532D`、`#EEE8FB/#5B33B8`）から選ぶ（トークンにする）
21. 日付の表示: 今年の日付は `11/07`、ほかの年は `2027/01/29`、時刻つきは `11/04 10:12`、相対は「今」「n 分前」「n 時間前」（同期のカード）。すべて Mono
22. ツリーの行の並び: Foundations の順（ID → 種類 → タイトル → 進捗・チェックリスト → 印（CLI で更新・制約違反・ブロック）→ 優先度 → 期限 → 担当者）。PR の欄はフェーズ5で足す
23. ツリーのキー操作は、行にフォーカスがあるときだけ効く（入力欄の中では効かない）。Enter は下に兄弟を作る入力行を開き、タイトルを入れて Enter で `POST /tasks`（`parent` は同じ親、`after` は直前の行）。作成の `after` で直前の行の直下に置くので、いつも1コミット（利用者の決定。作成と並べ替えの2コミットにはしない）。作ったあとは続けて次の入力行を出す（アウトライナーの動き。Esc で止める）。Tab は直前の兄弟の子の末尾へ、⇧Tab は親の後ろへ（`move` の `parent`・`after`）。⌥↑↓ は兄弟の中で1つ前・後ろへ（`before`・`after`）。Space は done カテゴリの既定のステータスと todo カテゴリの既定のステータスを切り替える。S・K は選択肢のメニュー
24. ドラッグ: hitbox の `attachInstruction`（tree-item の既定: 上 1/4 で前、中央 1/2 で子、下 1/4 で後ろ）。子が開いている行の下側 1/4 は「後ろ」でなく「子にする」（利用者の決定。閉じている行・子のない行は従来どおり下 1/4 で後ろ）。置けない場所（スキーマの `kinds[].parents` に合わない、別の Store、別のワークスペース（スプリント・リリースが外れるため。ワークスペースの移動は 4e のダイアログで明示的に行う）、自分の子孫）はドラッグ中に赤枠と「ここには置けません」を出し、離したらトーストで理由を出してデータは変えない
25. タスク詳細のプロパティ欄はスキーマの型で編集部品を選ぶ: `status`・`kind`・`enum` はメニュー、`date` は `<input type="date">`、`datetime` は `<input type="datetime-local">`、`number` は数値入力、`bool` はチェックボックス、`duration` は文字列（`1h30m` の形をサーバーが検証）、`url` は文字列とリンク、`taskref` は ID の検索、`user` と担当者・ウォッチャーは名前の入力（複数はチップ）、それ以外は文字列。スキーマにないプロパティは「（未定義）」の斜体で読み取りだけ
26. 関連の欄は `taskref` 型のプロパティ（`blocked_by` を含む）、`reverse`（逆方向。ラベルは `inverse`）、`referenced_by`（バックリンク）を出す。「関連を追加」は種類（taskref のプロパティ）を選んで ID を検索し、`PATCH` の `props`（`blocked_by` は `blocked_by`）で足す。1つしか持てない種類（単一値の `taskref`）に値があるときは、メニューでその項目を無効にして「すでに設定されています（外してから追加）」を出す（利用者の決定。黙って置き換えない）
27. コメントは全員のコメントに編集・削除を出し、自分のでないときはサーバーの `comment.not_author` の文言を出す（自分のアカウントを返す API がないため）。削除は確認ダイアログを出す（取り消しは付けない。利用者の決定）
28. 削除済みのタスクの詳細は、見出しの下に「削除済み（<日時>）」の帯と「復元」を出し、編集はできない。完全削除は GUI と API から外した（2026-11-02 に利用者が決定。4e の「設定 → 同期と保守」に期間を指定した purge を置く）
29. 作成ダイアログ: 親は今いる画面から決める（ツリーで選んでいる行があればその行、なければ今のプロジェクト、ワークスペースの画面ならルート）。種類は親の種類でスキーマの `parents` に合うものだけを選べ、合わないものは取り消し線と理由のツールチップ。作成後のトーストは「<ID> を作成しました · <ワークスペース>」で、詳細を開くリンク付き。「続けて作成」はタイトル・本文だけを空にしてダイアログを残す
30. コマンドパレットのコマンドは 4d にある画面と操作だけ（今すぐ同期、タスクを作成、プロジェクトを作成、ワークスペース・プロジェクトを開く、選んだタスクのステータス変更・子タスクを作る・詳細を開く）。4e の画面へのコマンド（設定、doctor、ビューの保存など）は 4e で足す。⌘↵ の「新しいタブで」は URL を新しいタブで開く
31. 壊れたファイル（`broken`・`problems` のあるタスク）は行に黄色の警告と、詳細に「`hh doctor` で確かめてください」と CLI の文字列を出す（doctor の画面は 4e の SettingsGeneral）
32. E2E（Playwright、chromium だけ）: テストごとに一時ディレクトリを `HEDGEHUG_HOME` にして `hh store init` で Store を作り、`hh ui --no-open`（ポートは空いているもの）の標準出力の1行目 `Hedgehug UI: <URL>` の URL を開く。4d の流れ: 作成（ダイアログと Enter）、編集と自動保存（タイトル・プロパティ・本文）、ツリーのドラッグ（並べ替え・親の付け替え・拒否）、CLI の変更が SSE で反映されること（印が出る）、削除と復元、完全削除、Onboarding からの Store 作成。カンバン・通知・保存済みビュー・undo の流れは 4e で足す

### 揃えたときに決めた細部（各 Task の要相談から）
