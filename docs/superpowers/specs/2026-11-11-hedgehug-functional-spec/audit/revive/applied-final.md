## 確かめて変えなかったもの

- `#12`・`#P1`・「接頭辞なし」「接頭辞のない」「WS」: 残っているのは、変更点の表の「モック」「覆す決定」の列だけ(01:259、02:745、03:643、04:1070、06:635、08:546)と、Markdown の `#` の説明(02:379)、GitHub の PR・Issue 番号の例(`example-org/web#12`、`WEB-core#418`)。
- 「メイン」: 変更点の表の「モック」の列(01:260、03:656、07:423、08:504・574)だけ。
- 「元に戻す」: 機能としては 01・02・03・04・05・06・08 の変更点の表で「持たない」としているものだけ。「元に戻せません」の確認文、「remote を元に戻す」(設定を前の値にする言い方)、「ワークスペースの設定に戻す…」(03)は別の意味。
- Issue の取り込み・同期・作成・閉じた理由、repoRules・リポジトリごとのルール: 「作らない」「区別しない」と書く行だけで、機能の記述はない。github.com 以外の remote も、「持たない」「出さない」と書く行だけ。
- きっかけの名前と個数: 03(6 つ)と 07(PR・Issue の 4 つ)の名前・個数は一致。
- 見積もり: 「見積り」は 0 件。ポイントと時間の総称が「見積もり」、時間が「見積もり時間」で、05 の表の列も同じ。
- 「使わないステータス」: 02・03・04・05・06 で同じ言い方。03 の見出しは「使うステータス」(区画名)で、本文は「使わないステータス」と使い分けている。
- 表の列数: 8 ファイルのすべての表で、行ごとの `|` の数が見出し行と一致。
- 見出し参照: 「NN の「…」」の形の参照をすべて確かめた。残る 「Store を追加」「マウント」「すべて同期」「親がない」「トークンのない URL」などはボタン・ダイアログ・表の行の名前で、参照先に実在する。

## ユーザーに聞く

なし。次の 3 つは、利用者から見える振る舞いに関わるが、既存の規則で決まるので聞かなかった。

- 「GitHub から検索」のマウントが空のリポジトリのとき(07 と 08 の食い違い): 新しい決定 3 の「空のリポジトリを clone する Store」に当たる。clone のあとに欄を出す形は 08 の「Store を追加」と同じ。
- 旧い接頭辞のアドレスが、別のワークスペースの現在の接頭辞と重なるとき: 検索の「現在の ID を先に出す」規則と同じ向きにした。
- 閲覧のみの Store で親の輪が残るときのツリーの見え方: 閲覧のみでは修復後の形を描かない(N288)ので、見せ方の規則は足さない。
