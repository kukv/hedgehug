## この案で先に決めたこと(全項目に効くもの)

1. **ツリーの「フォーカスのある行」を仕様に足す。** 04 のツリーには、キーで動かす行の概念がない。足す形は R10-1 に書く。行の選択(テーブルとバックログのチェックボックス。04「選択」)とは別のものとして扱う。
2. **画面にアドレスを持たせる。詳細パネルは、アドレスを持たない。** 01 の「開いていたアイテムは覚えない」(再読み込みのとき。記録済み。audit/mid-low-decisions.md の Q-134)は変えない。アイテムを新しいタブで開くための「アイテムの入口」だけを、開くとすぐ画面のアドレスに替わる一度きりのアドレスとして足す(R10-8)。02 の「旧い画面のアドレスは、新しいアイテムを開く」が成り立つために要る。
3. **アドレスは内部 ID で指す。** 画面に出る ID(HH-5)では指さない。「ID が Store をまたいで重なる」問題は、これで起きない(R10-8)。
4. **「URL を人へ渡して共有する」は成り立たない。** 08 が、`hh ui` が開いた URL からしか使えないと決めているため。6 に出す(R10-7、R10-8)。
5. **キーは、すでにある操作の経路に載せる。** ツリーの Alt+↑↓ は「上へ移動」「下へ移動」、S は「ステータスのメニュー」、K は「種類を変更…」と同じ。そうすれば、閲覧のみの Store・遷移の制約・通知・アクティビティなどは、既存の規則で決まる。唯一、新しい経路になるのはツリーの Space で、これは 02 の「Step のチェック」と同じ規則を使う(R10-1)。
6. **閲覧のみの Store のキー操作は、何も起こさない。** 01 の「操作してから断るのではなく、操作できない見た目にする。」に合わせて、現行のトースト(`readOnlyToast`)は戻さない。同じ理由で、その行のボタンやメニューの項目が無効なときのキーも何も起こさない。

# R10-1 ツリーのキー操作

## 1. 何ができるようになるか

ツリーのレイアウトがあるすべての画面(ワークスペース、プロジェクト、検索、保存したビュー)で、行をキーだけで動かし、開き、変える。ツリーは Tab で入る 1 つのフォーカス先で、中の行は矢印で動かす。Tab・Shift+Tab は、ツリーに入る・出るために使う(ツリーの中ではどの行でも、次の部品へ出る)。

| キー | アイテムの行 | プロジェクトの行(検索・ワークスペースのツリー) |
|---|---|---|
| ↑ ↓ | 見えている前・次の行へフォーカスを動かす。端で止まる(回り込まない)。 | 同じ |
| → | 閉じていて子があれば開く。開いていれば最初の子へ。子がなければ何もしない。 | 同じ |
| ← | 開いていれば閉じる。閉じていれば親の行へ。その画面の一番上の階層(プロジェクトの画面の Epic、検索・ワークスペースのプロジェクトの行)では何もしない。 | 開いていれば閉じる。閉じていれば何もしない |
| Enter、Ctrl+Enter(Cmd+Enter) | 詳細パネルを開く(タイトルを押したのと同じ)。 | プロジェクトの概要を開く(タイトルを押したのと同じ) |
| Space | 完了と未着手を切り替える(下の規則) | 何もしない |
| S | ステータスのメニューを開く(ステータスのボタンを押したのと同じ) | 何もしない |
| K | 「種類を変更…」を開く(アイテムのメニューと同じ。Epic は何もしない) | 何もしない |
| Alt+↑、Alt+↓ | アイテムのメニューの「上へ移動」「下へ移動」と同じ | プロジェクトのメニューの「上へ移動」「下へ移動」と同じ |
| Alt+Shift+↑、Alt+Shift+↓ | 前の親の下へ、次の親の下へ移す(下の規則) | 何もしない(プロジェクトには親がない) |
| C | その行の兄弟として、作成ダイアログを開く(02) | その行の下に Epic を作成する作成ダイアログを開く(「Epic を追加」の「+」と同じ) |
| メニューキー、Shift+F10 | 行のメニュー(「…」のボタンと同じ)を開く | 同じ |
| Tab、Shift+Tab | ツリーを出て、前後の部品へフォーカスを移す(ブラウザの通常の動き) | 同じ |

**Space の規則。** 02「子と Step」の「Step のチェック」と同じにする。行の分類が「完了」なら、未着手の既定のステータス(03)にする。完了でない(未着手・進行中・中止、またはワークスペースの一覧にない値)なら、完了の既定のステータスにする。遷移の制約に反するときは、何も変えずに 02「ステータスの変更」の文言「ワークフローの制約: {いま} から {移行先} には変更できません({移れる先}のみ)」をエラーのトーストで出す。

**Alt+Shift+↑↓ の規則(Tab の字下げの代わり)。** 親を変える操作を、キーで 1 回で行う。移す先は、02「同じワークスペースの中での移動」の「移動…」の候補(Story・Task・Bug は Epic、Step は Story・Task・Bug、Epic はほかのプロジェクト。自分と自分の子孫、いまの親は除く)のうち、いま画面に見えている行にあるものである。フォーカスのある行から、上(Alt+Shift+↑)または下(Alt+Shift+↓)へ行を順に見て、最初に見つかった候補を新しい親にする。自分の子孫の行は飛ばす。見つからなければ何もしない。移すと、「移動…」で選んだのと同じ結果になる(新しい親の子の末尾に入り、アクティビティ・履歴・トーストも「移動…」と同じ。02)。新しい親が閉じていれば開き、動かした行にフォーカスを置く。

**連続して押したとき。** Alt+↑↓ と Alt+Shift+↑↓ は、押した回数だけ 1 回ずつ順に実行する。途中で断られたとき、ほかのキーを押したとき、画面を移ったときは、待っている分を捨てる(現行の振る舞いのとおり。`web/app/tree/TreeView.svelte:455-503`)。

**使えない場面。** 入力欄の中(絞り込み欄など)、ダイアログを開いているあいだは使えない。C キーと同じ(01)。メニューを開いているあいだは、キーはメニューが受ける。

**フォーカスの扱い。**
- フォーカスのある行は、行全体を囲む枠で示す。選択の色とは別である。
- ツリーに Tab で入ったときは、その画面で最後にフォーカスした行が見えていればその行、なければ先頭の行にフォーカスが付く。
- フォーカスは保存しない。画面の状態の一覧にも、保存したビューの「未保存の変更」の比べる対象にも入れない(04 の「折りたたみと、選択、詳細パネルは、比べる対象に入れない」と同じ扱い)。
- フォーカスのある行が、絞り込み・同期・削除・移動で見えなくなったときは、次の見えている行に、なければ前の見えている行に、フォーカスを移す。行がなくなれば、フォーカスはない。
- フォーカスの対象は、プロジェクトの行とアイテムの行(一致せず薄く出した祖先の行を含む)である。ワークスペースの見出しは対象にしない。

**具体例。** プロジェクト「v2 画面リニューアル」のツリーで、Epic HH-2 の下に Task HH-3・HH-5 があるとする。
1. Tab でツリーに入る。HH-2 に枠が付く。↓ を 2 回押すと HH-5 に枠が付く(HH-2 が開いているとき)。
2. Space を押す。HH-5 のステータスが Done(完了の既定)になる。もう一度 Space で Todo(未着手の既定)に戻る。
3. Alt+↑ を押す。見えている直前の兄弟 HH-3 のすぐ前に HH-5 が動く。アクティビティに「HH-5 の順位を変更」と残る。
4. 次の Epic HH-8 が同じプロジェクトにあるとき、Alt+Shift+↓ を押す。HH-5 が HH-8 の子の末尾に入り、HH-8 が閉じていれば開く。トーストは「HH-5 を HH-8 の下に移動しました」。
5. C を押す。作成ダイアログが、親 HH-2・種類 Task・ワークスペースとプロジェクトは HH-5 と同じで開く。「続けて作成」をオンにすれば、タイトルだけを入れ直して続けて作れる。
6. Enter を押す。HH-5 の詳細パネルが開く。

ツリーは、キーボードだけでも使える。ツリーは Tab で入る 1 つのフォーカス先で、中の行は矢印で動かす。Tab・Shift+Tab はツリーの中でも、ツリーを出て前後の部品へ移すために使う(ブラウザの通常のフォーカス移動)。このキー操作は、ツリーのレイアウトがあるすべての画面(ワークスペース、プロジェクト、検索、保存したビュー)で同じである。

フォーカスのある行は、行全体を囲む枠で示す(行の選択ではない)。フォーカスの対象は、プロジェクトの行とアイテムの行(一致せず薄く出した祖先の行を含む)で、ワークスペースの見出しは対象にしない。ツリーに入ったときは、その画面で最後にフォーカスした行が見えていればその行、なければ先頭の行にフォーカスが付く。フォーカスは保存しない。保存したビューの「未保存の変更」の比べる対象にも入れない。フォーカスのある行が、絞り込み・同期・削除・移動で見えなくなったときは、次の見えている行に、なければ前の見えている行に移す。

| キー | アイテムの行 | プロジェクトの行 |
|---|---|---|
| ↑ ↓ | 見えている前・次の行へ動かす。端で止まる | 同じ |
| → | 閉じていて子があれば開く。開いていれば最初の子へ | 同じ |
| ← | 開いていれば閉じる。閉じていれば親の行へ。その画面の一番上の階層の行では何もしない | 開いていれば閉じる。閉じていれば何もしない |
| Enter、Ctrl+Enter(Cmd+Enter) | 詳細パネルを開く | プロジェクトの概要を開く |
| Space | 完了と未着手を切り替える。分類が完了でなければ完了の既定のステータスに、完了なら未着手の既定のステータスにする(03)。遷移の制約に反するときは、何も変えず、02「ステータスの変更」の文言をエラーとして表示する | 何もしない |
| S | ステータスのメニューを開く(02) | 何もしない |
| K | 「種類を変更…」を開く(02)。Epic は何もしない | 何もしない |
| Alt+↑、Alt+↓ | メニューの「上へ移動」「下へ移動」と同じ(絞り込み中は見えている兄弟の間) | プロジェクトのメニューの「上へ移動」「下へ移動」と同じ |
| Alt+Shift+↑、Alt+Shift+↓ | 前の親の下へ、次の親の下へ移す(下) | 何もしない |
| C | その行の兄弟として、同じワークスペース・プロジェクト・親・種類で作成ダイアログを開く(02) | その行の下に Epic を作る作成ダイアログを開く |
| メニューキー、Shift+F10 | 行のメニューを開く | 同じ |

キーで行う書き込み(Space、S、K、Alt+↑↓、Alt+Shift+↑↓、C)は、同じ働きをするボタン・メニューの項目が無効なときは、何も起こさない。トーストも出さない(01 の「閲覧のみの Store」)。Enter、矢印、メニューキーは、閲覧のみの Store の行でも使える。入力欄の中とダイアログを開いているあいだは、これらのキーは使えない。

Alt+Shift+↑↓ は、親を変える。移す先は、02「同じワークスペースの中での移動」の「移動…」の候補のうち、いま見えている行にあるものである。フォーカスのある行から上(Alt+Shift+↑)または下(Alt+Shift+↓)へ見える行を順にたどり、最初に見つかった候補を新しい親にする。自分の子孫の行は飛ばす。見つからなければ何もしない。移した結果は「移動…」と同じで、新しい親の子の末尾に入り、アクティビティ・履歴・トーストも同じである。新しい親が閉じていれば開き、動かした行にフォーカスを置く。例: Epic HH-2 の下の HH-5(Task)で Alt+Shift+↓ を押すと、HH-2 の次に見える Epic HH-8 の子の末尾に HH-5 が入る。

Alt+↑↓ と Alt+Shift+↑↓ を続けて押したときは、押した回数だけ 1 回ずつ順に実行する。途中で断られたとき、ほかのキーを押したとき、画面を移ったときは、待っている分を捨てる。

**Tab・Shift+Tab の「字下げ・戻す」。**
- 画面とキー: ツリーの行にフォーカスがあるとき。

- 案 A: Tab・Shift+Tab を、ツリーの中でも通常のフォーカス移動にして、親を変える手段は行のメニューの「移動…」だけにする(復活を縮める)。結果: キーだけで親を変えられない。
- 案 B(勧める): Tab・Shift+Tab は通常のフォーカス移動にし、親を変える働きを Alt+Shift+↑↓ に移す。結果: 例の HH-5 で Alt+Shift+↓ を押すと、次の Epic HH-8 の子の末尾に入る。字下げ(直前の行の子にする)が、仕様で意味を持つ形(いまの親と違う、置ける親の下へ移す)になる。
- 案 C: Tab・Shift+Tab を残し、押すたびに 02 の断り文言のトーストを出す。結果: 動く場面がなく、ツリーから Tab で出られなくなる。
- 勧める案 B の理由: 字下げの目的は、親を素早く変えることである。この目的は仕様の決まりの中で達せられる。Tab をツリーが取らないので、キーボードだけの利用者がツリーから出られる。覆す記録済みの決定はない。親子の決まり(01 の表。Epic の親はプロジェクトの直下、Story・Task・Bug の親は Epic、Step の親は Story・Task・Bug)は、そのまま変えない。

# R10-2 「今すぐ同期」のショートカット

## 1. 何ができるようになるか

Shift+Ctrl+S(Mac は Shift+Cmd+S)で、「すべて同期」を実行する。サイドバーがあるすべての画面(設定、初回起動の案内を含む)で使える。名前は仕様の「すべて同期」にそろえる(現行の「今すぐ同期」は、Store 単位のメニュー項目の名前になった)。

- 入力欄で文字を入れている最中でも、ダイアログを開いているあいだでも使える。同期は、編集中の入力欄の内容を書き換えない(06「手動の同期でも、編集中の入力欄の内容は書き換えない」)ので、入力は消えない。
- 結果は、サイドバーの「すべて同期」ボタンと同じ 1 つのトーストで出す。
- ヒントは、サイドバーの同期カードの「すべて同期」ボタンにポインターを置いたときの案内と、コマンドパレットの「すべての Store を同期」の右端に出す。

具体例 1。Store team-a(remote あり)と personal(remote なし)を表示中。コメント入力欄に文字を入れたまま Shift+Ctrl+S を押す。team-a だけが同期され、トースト「1 件の Store を同期しました」が出る。コメント欄の文字は残る。remote のない personal は件数に数えない(06「remote がない Store は、「すべて同期」の件数に数えない」)。

具体例 2。remote のある Store が 1 つもないときに押す。何も同期せず、トースト「同期する Store がありません(remote のある、表示中の Store が要ります)」が出る(02 のパレットの文言と同じ)。

## 2. 今の仕様への合わせ方

# R10-3 パレットの選択中アイテムのコマンド

## 1. 何ができるようになるか

Ctrl+K で開いたパレットに、いま扱っているアイテムに対する群「{ID} に対して」を出す。マウスでメニューを探さなくても、ステータスの変更・子の追加・詳細を開く・別のワークスペースへの移動を、入力だけで行える。

**「選んでいるアイテム」の決め方。** パレットを開いた時点で、次の順に探して、最初に見つかった 1 件にする。
1. 詳細パネルを開いているアイテム。
2. ツリーでフォーカスのある行のアイテム(R10-1)。プロジェクトの行は対象にしない。
3. テーブルとバックログで、選択(チェックボックス)がちょうど 1 件のとき、そのアイテム。複数選択のときは「選んでいるアイテムなし」とする。

どれもないときは、群を出さない。

**群の中身(最大 4 件)。**

| 項目 | 動作 | 出す条件 |
|---|---|---|
| ステータスを変更… | パレットの中で、ステータスの一覧に切り替える。各項目に分類を添え、いまのステータスにチェックを付ける。遷移の制約で移れない項目は無効にし、理由をヒントで出す(02「ステータスの変更」のメニューと同じ)。選ぶと変更して、パレットを閉じる | 書き込める Store のアイテム |
| {種類} を追加 | パレットを閉じてから、そのアイテムを親にした作成ダイアログを開く。種類は、そのアイテムの下に置ける最初の種類(Epic なら Story、Story・Task・Bug なら Step。04 の「+」と同じ) | 書き込める Store の、Step 以外のアイテム |
| 詳細を開く | 詳細パネルを開く。Ctrl+Enter(Cmd+Enter)なら新しいタブで開く(R10-7) | いつでも。ただし、そのアイテムの詳細パネルがすでに開いているときは出さない |
| 別のワークスペースへ移動… | パレットを閉じてから、02 の「別のワークスペースへ移動…」のダイアログを開く。同じ Store の別のワークスペースも、別の Store のワークスペースも選べる(現行の「別の Store へ移動…」は、このダイアログに含まれる) | 書き込める Store の、Epic・Story・Task・Bug |

入力があるときは、名前に入力を含む項目だけを出す(コマンドと同じ。大文字小文字を区別しない)。たとえば「ス」と入れると、「ステータスを変更…」だけが残る。ID(「HH-12」など)を入れたときは、どの項目の名前にも含まれないので、群は出ず、アイテムの候補が出る。

具体例 1。HH-12(Task)の詳細パネルを開いたまま Ctrl+K を押す。パレットに「コマンド」の下に「HH-12 に対して」が出る。「ステータスを変更…」を選び、一覧から「InProgress」を選ぶ。パレットが閉じ、HH-12 のステータスが InProgress に変わる。

具体例 2。ツリーで HH-5 にフォーカスを置いて Ctrl+K を押し、「Step」と入れる。コマンドに「Step」を含むものがなければ、「Step を追加」(HH-5 は Task)だけが残る。Enter で、パレットが閉じ、親 HH-5・種類 Step の作成ダイアログが開く。

# R10-4 パレットの「このクエリで」の群

## 1. 何ができるようになるか

パレットに、検索のクエリ(04)を打つと、「このクエリで」の群を出す。パレットを抜けずに、そのクエリで検索を開く、ビューとして保存する、一致するアイテムをまとめて変更する、ができる。

**クエリとして読む条件。** 入力が、04「クエリ言語」の規則で、キーを 1 つ以上含み(「語の先頭が、英字で始まる英字・数字・`_` の並びで、そのあとに `:`、`<`、`<=`、`>`、`>=` が続くとき」)、エラー(「キーのあとに値がない」「どのワークスペースにもないキー」)にならないときである。キーを含まない語だけの入力は、クエリとして読まない。

群の中身(3 件)。

| 項目 | 動作 |
|---|---|
| 検索で開く | ヒントに一致する件数「{N} 件」を添える。パレットを閉じて、検索の画面をテーブルで開き、絞り込みを入力したクエリにする。Ctrl+Enter(Cmd+Enter)なら新しいタブで開く |
| ビューとして保存… | パレットを閉じて、検索の画面をテーブルで開き、絞り込みを入力したクエリにしたうえで、04 の「ビューとして保存」ダイアログを開く(確認の表示は「レイアウト: テーブル ・ 条件: `…`」) |
| {N} 件をまとめて変更… | パレットを閉じて、検索の画面をテーブルで開き、絞り込みを入力したクエリにし、すべての行を選び(04 の「すべて選択」と同じ)、「選択したアイテムを一括変更」ダイアログを開く。一致が 0 件、または一致がすべて閲覧のみの Store のものなら、無効にして理由を添える(「一致するアイテムがありません」「閲覧のみの Store です」) |

件数は、検索の画面と同じ範囲(表示中のすべての Store。削除済みと非表示の Store は含めない)で数える。

アイテムの候補は、これまでどおり、入力した文字列全体を ID・タイトルに含むものを探す。たとえば `fix: ログイン` と入れると、「fix」というキーはないので、クエリとして読まず(群は出ない)、タイトルに「fix: ログイン」を含むアイテムが、アイテムの候補に出る。`status:done` と入れると、群が出る(アイテムの候補には、タイトルに「status:done」を含むものがなければ何も出ない)。

具体例。パレットに `status:inprogress assignee:@me` と入れる。「このクエリで」に「検索で開く(7 件)」「ビューとして保存…」「7 件をまとめて変更…」が出る。「7 件をまとめて変更…」を選ぶと、パレットが閉じ、検索のテーブルに 7 件が出て、全部が選ばれ、一括変更のダイアログが開く。ダイアログを閉じても、7 件の選択は残り、「7 件を選択中」のバーが出る。

## 2. 今の仕様への合わせ方

| 現行 | この案 | 理由 |
|---|---|---|
| `:` を含む語か比較演算子の語があると、パレット全体が「クエリ」のモードになる。結果を最大 20 件、パレットに並べる | 04 のクエリの読み方の規則で、キーがあり、エラーにならないときだけ、群を足す。アイテムの候補は変えず、結果の一覧はパレットに並べない | タイトルに `:` を含むアイテム(「fix: ログイン」など)を、これまでどおり探せるようにするため。結果の一覧は、検索の画面で見られる |

# R10-5 パレットの拡張コマンド(作成・設定への移動)

## 1. 何ができるようになるか

パレットに入力すると、画面を移るコマンドと作成のコマンドが出る。入力が空のときの「コマンド」は、仕様の 8 件のままにする。

**「作成」の群(最大 3 件。入力があるとき、名前に入力を含むものだけ)**

| 項目 | 動作 | 出す条件 |
|---|---|---|
| プロジェクトを作成 | パレットを閉じて、プロジェクトの作成ダイアログを開く。ワークスペースの初めの値は、作成ダイアログと同じ順(いま開いているワークスペース、いま開いているプロジェクトのワークスペース、書き込める Store の先頭のワークスペース)で決める(02) | 書き込める Store のワークスペースがあるとき。なければ、押すと 02 のトースト(「先にワークスペースを作ってください」「アイテムを作成できる Store がありません(閲覧のみの Store だけです)」)を出す |
| スプリントを作成 | パレットを閉じて、そのワークスペースの「スプリント」タブを開き、スプリントの作成ダイアログを開く | ワークスペースの画面か、プロジェクトの画面を開いているとき(そのワークスペース)で、書き込める Store のとき |
| リリースを作成 | パレットを閉じて、そのワークスペースの「リリース」タブを開き、リリースの作成ダイアログを開く | 同上 |

**「設定」の群(最大 6 件。入力があるとき、名前に入力を含むものだけ)**

| 項目 | 動作 |
|---|---|
| 設定: アカウントとメンバー | 設定の「アカウントとメンバー」タブを開く |
| 設定: Store | 設定の「Store」タブを開く |
| 設定: 削除済み | 設定の「削除済み」タブを開く |
| 設定: 診断と修復 | 設定の「診断と修復」タブを開く。診断は実行しない(「診断を実行」のボタンを押したときだけ実行する。08) |
| 設定: ワークスペース({名前}) | 開いているワークスペースの「設定」タブを開く。ワークスペースの画面か、プロジェクトの画面を開いているときだけ出す |
| 設定: プロジェクト({名前}) | 開いているプロジェクトの「設定」タブを開く。プロジェクトの画面を開いているときだけ出す |

(「設定を開く」は、仕様の「コマンド」にあり、設定の「一般」タブを開く。)

具体例 1。ワークスペース Web のスプリントの画面で Ctrl+K を押し、「スプリ」と入れる。「作成」に「スプリントを作成」が出る。Enter で、パレットが閉じ、「スプリントを作成」のダイアログが開く。

具体例 2。マイタスクで Ctrl+K を押し、「診断」と入れる。「設定」に「設定: 診断と修復」が出る。Enter で設定の「診断と修復」タブが開く。診断はまだ実行されない。

# R10-6 パレットの最近開いたもの

## 1. 何ができるようになるか

# R10-7 新しいタブで開く

## 1. 何ができるようになるか

画面やアイテムを、いまのタブを残したまま、新しいタブで開く。2 つのアイテムを見比べたり、ツリーを開いたまま別のワークスペースを見たりできる。

- 画面を移る、または詳細パネルを開く部品(サイドバーの項目、パンくずとタブ、行のタイトルと ID のリンク、アクティビティ・受信箱のリンク)を、Ctrl+クリック(Cmd+クリック)、Shift+クリック、中クリックすると、押したのと同じ行き先を新しいタブで開く。ステータスのボタンやメニューの項目のような、操作を行う部品は対象にしない。
- コマンドパレットで、行き先のある候補(アイテム・プロジェクト・ワークスペース・ビュー・最近開いたもの・画面を開くコマンド)を Ctrl+Enter(Cmd+Enter)で選ぶと、新しいタブで開き、パレットを閉じる。ダイアログを開く候補と操作を行う候補では、Enter と同じ動きになる。
- アイテムは、そのアイテムの「入口」で開く(R10-8)。新しいタブでは、そのアイテムのプロジェクトのツリーが開き、詳細パネルが開いた状態になる。
- アプリの中の操作で開いた新しいタブは、元のタブと同じように使える。
- ブラウザの右クリックメニューの「新しいタブで開く」や、アドレスをコピーして貼り付けたタブは、`hh ui` が開いた URL ではないので、08 の「トークンのない URL」の画面になる(6 に出す)。

具体例 1。ツリーの HH-5 のタイトルを Ctrl+クリックする。新しいタブが開き、HH-5 のプロジェクトのツリーが、HH-5 の詳細パネルを開いた状態で出る。元のタブはそのまま。

具体例 2。パレットに「Web」と入れて、ワークスペース「Web」の候補を Ctrl+Enter で選ぶ。パレットが閉じ、新しいタブで Web の概要が開く。

具体例 3。パレットで「新規作成」を Ctrl+Enter で選ぶ。ダイアログを開く候補なので、Enter と同じに、パレットを閉じて作成ダイアログを開く(新しいタブは開かない)。

## 6. 記録済みの決定とぶつかって、復活の意味が変わるもの

**右クリックの「新しいタブで開く」と、アドレスの貼り付け。**
- 画面: ワークスペース Web のカンバンのタブ「テーブル」を、ブラウザの右クリックメニューの「新しいタブで開く」で開く。または、アドレス欄の URL をコピーして、新しいタブに貼る。
- 具体例: 新しいタブに、「Hedgehug の画面を開けません。この画面は `hh ui` が開いた URL からのみ利用できます。端末で `hh ui` を実行してください。」と出る(08)。
- 案 A(勧める): このとおりにする。仕様に「右クリックのメニューと貼り付けのタブは 08 の画面になる」と書く(上の 4-3)。結果: 利用者は、アプリの中のクリック(Ctrl+クリック・中クリック)で新しいタブを開けば、問題なく使える。
- 案 B: 右クリックと貼り付けのタブも使えるようにする(08 の「`hh ui` が開いた URL からだけ使える」を、「同じブラウザの、`hh ui` で開いたことのあるタブからなら使える」などに変える)。結果: 貼り付けも右クリックも動くが、記録済みの決定(08「トークンのない URL」の「URL にトークンが付いていない…場合」)を覆し、トークンが残る場所が増える。
- 勧める案 A の理由: アプリの中の操作で、新しいタブを開く用途は満たされる。08 の決定を覆さずに済む。右クリックで開く人には、08 の画面の文言が `hh ui` を実行するよう案内する。

# R10-8 URL での画面の共有とブラウザの戻る・進む

## 1. 何ができるようになるか

画面がアドレスを持ち、ブラウザの戻る・進む・再読み込み・新しいタブで画面を扱える。詳細パネルは、アドレスを持たない(再読み込みで開いていたアイテムを覚えない。01、Q-134)。URL を人へ渡して共有することはできない(6)。

- 戻る・進む: マイタスクからワークスペース Web を開き、「カンバン」タブから「テーブル」タブへ移ったあと、ブラウザの戻るを押すと、「カンバン」に戻る。もう一度押すと、マイタスクに戻る。進むで逆に進む。詳細パネルを開く・閉じる、絞り込みの入力、レイアウトの切り替えは、履歴に積まない。
- 再読み込み: Web の「テーブル」タブで再読み込みすると、同じ画面が開く。HH-12 の詳細パネルを開いたまま再読み込みすると、同じ画面が詳細パネルなしで開く(01)。
- `hh ui` で開く: 画面を指さない URL で開くので、最後に開いていた画面を開く(01)。
- 戻る・進むで移るとき、詳細パネルの説明やコメントの入力欄に保存していない内容があれば、「入力を破棄」の確認を出す。「キャンセル」を押すと、移らずにその画面に留まる。

具体例。HH-12 の詳細パネルでコメントを書きかけたまま、ブラウザの戻るを押す。「入力を破棄」(本文「保存していないコメントを破棄します。」)が出る。「キャンセル」を押すと、画面は動かず、コメント欄に戻る。「破棄」を押すと、前の画面に戻り、パネルは閉じる。

## 5. ユーザーに聞くこと

なし。理由: 詳細パネルがアドレスを持つかは、Q-134 の記録済みの決定(再読み込みで覚えない)を変えずに、アイテムの入口を足して決めた。検索の絞り込みの持ち主は、04 の「このマシンに残す」で決まる。保存したビューのアドレスは、04 の「名前を変えられる」「Store に属さない」で識別子に決まる。ID が重なる問題は、内部 ID で指すことで起きない。

## 6. 記録済みの決定とぶつかって、復活の意味が変わるもの

**URL を人へ渡して共有する。**
- 画面: ワークスペース Web のカンバンを開いたタブのアドレス欄。
- 具体例: 太郎さんが、Web のカンバンのアドレスをコピーして、チャットで花子さんに送る。花子さんが自分のブラウザで開くと、「Hedgehug の画面を開けません。この画面は `hh ui` が開いた URL からのみ利用できます。端末で `hh ui` を実行してください。」が出る(08)。太郎さんが自分の別のタブに貼っても、同じ画面になる。
- 案 A(勧める): 「URL の共有」は仕様にしない。使えるのは、同じタブの戻る・進む・再読み込み、アプリの中の操作で開いた新しいタブ、`hh ui` で開く画面である。結果: 現行にあった「アドレスのコピーで同じ検索を共有できる」は、現行でも別のタブ・別のブラウザではトークンがなく 08 の画面になるので、使えなくなるものはない。
- 案 B: アドレスにトークンを含めて、コピーして貼れるようにする。結果: 太郎さんの別のタブでは使えるようになるが、花子さんは、花子さんの端末の `hh ui` が出すトークンでしか使えず、人へ渡す共有にはならない。URL にトークンが残るので、記録済みの決定(08「画面は…`hh ui` を実行すると開く URL からだけ使える」)を覆す。
- 案 C: アドレスからトークンを除いた形をコピーする「リンクをコピー」を足し、受け取った人が自分の端末の `hh ui` に渡して開く。結果: 人へ渡す共有になるが、`hh ui` の引数は CLI の仕様の範囲(01「画面を開く `hh ui` コマンドの引数と動作は、CLI の仕様で定める」)で、この仕様では決められない。相手が同じ Store を追加していないと、画面が開かない(02 の「見つからないとき」の扱いになる)。
- 勧める案 A の理由: 08 の決定を覆さず、現行から失われるものがない。共有が要ると分かったときは、案 C を CLI の仕様とあわせて決められる。
