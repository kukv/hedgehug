## 2. 判断

### N184 自動リンクした PR の「×」を押したあと、その PR をまた自動で付けるか
- 画面: アイテムの詳細パネル > GitHub の欄 > PR の行の「×」。
- 例: WEB-1 にブランチ名から自動リンクされた PR #15 を、関係ないので「×」で外す。#15 にコメントが付いて GitHub で更新される。
- 案 A: 解除の記録を Store に持つ。#15 は二度と自動で付かない。記録は画面に出さない。複製・完全な削除・同期の扱いの規則が増える(N185〜N187)。
- 案 B: 記録を持たない。外しても、次の読み取りで #15 が更新されていればまた付く。外す意味が薄い。
- 案 C: 自動リンクをやめ、手でリンクするだけにする。外した PR は戻らない。復活の範囲が縮む。
- 勧め: A の最小形。記録は持つが、検出元の保存と表示(N183)・解除を時刻によらず勝たせる特別な合わせ方(N186)は持たず、06 の「複数の値の項目は 1 つずつの追加を両方生かす」に合わせる。外した PR が戻らないことが自動リンクを使える条件のため。
- 関係する Q: Q6(PR の印。自動リンクの別の経路)。方針「新しい仕組みを足さない」とも重なる(3 節)。

### N195 GitHub から取り直した PR の変更(状態・タイトル・レビュー・自動リンク)で、ウォッチ・割り当ての通知を出すか
- 画面: 受信箱。アイテムの詳細パネルのウォッチ。
- 例: WEB-1 をウォッチしている。リンクした PR #12 のレビューが「承認済み」に変わる、またはタイトルが変わる。
- 案 A: 通知を出さない(02・06 の表のとおり)。自動化のルールが動いたときだけ「自動化」の通知が届く。受信箱は静か。
- 案 B: 他の人の変更として通知する(記録済みの決定 Q-030・B-12、07 の現行の文)。PR の状態が変わるたびにウォッチ中の人へ届く。GitHub の読み取りは 5〜60 分ごとなので、件数が増える。
- 勧め: A。02・06 が 3 か所で「通知しない」と書き、B-12 の前提だった Issue の同期は廃止済みで、通知が増えすぎないため。ただし記録済みの決定を覆すので、ユーザーの承認が要る。
- 関係する Q: なし。

## 3. 方針と食い違う N
Issue のきっかけ(方針「GitHub Issue はリンクだけ」。07 には現に「Draft、Closed、Issue では何も起きない」とある。Q8 もこの前提で動いている)

- N203: きっかけを 6 つにし、Issue の動き(再び開いて閉じたとき、閉じた理由は Q8)を含む。直し方: きっかけを 5 つにし、Issue の行と閉じた理由を消す。
- N208: Issue が閉じたときにルールが動く。直し方: 項目ごと消す。
- N211: ルール一覧の説明に「リンクした Issue が閉じたとき」を含む。直し方: その文だけ消す。
- N212: Issue のきっかけのルールの「すること」の値。直し方: 項目ごと消す。
- N213: 削除中に Issue が閉じたときの扱い。直し方: 項目ごと消す。
- N215: 「Issue はアイテムの値を変えない」を、ルールが動くときは変えると書き換える。直し方: 書き換えず、元の文のままにする。
- N216: 07 の表に Issue が閉じたときを含む括弧がある。直し方: 括弧から Issue を外す。
- 上の 8 件を直すと Q8 は不要になる。まとめて 1 回で決められる。
