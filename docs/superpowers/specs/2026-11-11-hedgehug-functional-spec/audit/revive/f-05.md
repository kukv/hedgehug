# R2-a 見積もりと実績のレポート(A #59)

## 1. 現行の振る舞い

**画面**: レポートのタブの最下段「見積もりと実績」(`ReportsPage.svelte:275-328`)。

- 見出しの横に「合計 見積もり {合計} / 実績 {合計}」(`:279-281`)。例: 「合計 見積もり 2h / 実績 3h」。行が 0 件でも「合計 見積もり 0m / 実績 0m」と出る(`reports.go:543` は 0 のときも `Duration.String()` を返し、`0m` になる)。
- 1 行 = 1 件のアイテム。左に ID とタイトル(押すとそのアイテムの画面へ。`:301-306`)、中央に横軸のトラック、右に「{見積もり} → {実績}」(`:315-318`)。例: DM-1 の見積もり 2h、作業時間の合計 3h なら右に「2h → 3h（超過）」と出る(`web/e2e/reports.spec.ts:82`、`ReportsPage.test.ts:76`)。
- トラックには、見積もりの位置に白抜きの丸、実績の位置に塗りの丸が付く(`:307-314`)。位置は、表示中のすべての行の見積もりと実績のうち最大の値を 100% とした割合(`web/core/reports.ts:134-138`)。実績が見積もりを超える行(`a > e`)は、実績の丸と右の数字が赤になり、「（超過）」が付く(`reports.ts:150`)。
- 片方しかない行は、ない側を「—」で出し、その側の丸は描かない(`reports.ts:146-147`)。見積もりが 0m のとき、最大値が 0 なら丸は両方出ない(`reports.ts:138`)。
- 空のとき「見積もりも作業時間もありません」(読み込み中は「読み込み中…」)(`:323`)。
- 区画の下に `hh report estimate [--sprint "…"]` の案内行(`:325-327`)。

**計算**(`internal/app/usecase/reports/reports.go:492-545`):

- 対象は、Store のインデックスのアイテムのうち、削除済みでなく(`DeletedAt != nil` を除く)、指定のワークスペースにあり、スプリント指定があるときはそのスプリントに入っているもの(`:514`)。**種類の絞り込みはない**ので、Epic・Story・Task・Bug・Step のすべてが対象になる。分類(中止かどうか)の絞り込みもないので、中止のアイテムも入る。
- 見積もり: `estimate` プロパティが 1 件の値で、`ParseDuration` に通るときだけ数える(`:518-523`)。通らない値は黙って見積もりなしになる。
- 実績: アイテムの作業時間の記録のうち、削除していないものの合計(`:524-534`)。記録の日付は見ない(過去の日付で入れた記録も、期間を問わず入る)。
- 行に入れる条件は「見積もりがある、または作業時間の記録が 1 件以上ある」(`:539`)。どちらもないアイテムは出ない。
- 行の順は ULID の昇順(作成の順)(`:510`)。
- 時間の書式は `Duration.String()`: 「45m」「6h」「1h30m」(時間と分だけ。`duration.go:48-58`)。
- 単位(ポイント/件数)の選択は、この区画に効かない。ポイントは見ない。

**操作が断られる場面**: 見積もりと実績のレポート自体は読むだけなので、閲覧のみの Store でもふつうに見える。オフラインでは、読み込みに失敗して赤字のエラーが出る(`:295-296`、`failed` スニペット)。

**複数 Store**: 開いているワークスペースの Store だけを読む(`where = { store, workspace }`、`:38`)。別の Store から移したアイテムは、移動のときに作業時間が一緒に移る(仕様 03:132)ので、移動先で数える。現行の Store の仕組みでも作業時間はアイテムのディレクトリに属し、`o.s.Worklogs(e.ULID)` で読む(`reports.go:526`)。

## 1. 現行の振る舞い
