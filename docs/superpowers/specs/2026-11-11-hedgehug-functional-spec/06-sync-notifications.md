# hedgehug 機能仕様 06: 同期・通知・アクティビティ

複数の人が同じ Store を使うと、同じ項目への変更が重なる。この文書は、同期がいつ動くか、重なった変更で何が残るか、残らなかった人にどう知らせるかを定める。通知は Store に保存せず、各マシンが自分宛てのものだけを作る。

用語、「あなた」、保存の単位、元に戻す、閲覧のみの Store は 01 を参照する。アイテムは 02、自動化の定義は 03、GitHub の PR と Issue の状態の取得は 07、完全な削除と診断は 08 が定める。

## 同期とは

**同期**は、その Store の remote とこのマシンのあいだで、保存を送り、受け取ることである。同期が行われても、保存の内容は利用者が気づかないうちに書き換わらない。重なった変更の扱いは「同時に編集したとき」で定める。

remote がない Store は、このマシンの中だけで使うので、同期の対象にならない。

### 手動で同期する

| 操作 | 対象 |
|---|---|
| サイドバーの同期カードにある「すべて同期」ボタン | 表示中で remote がある Store すべて |
| コマンドパレットの「すべての Store を同期」、設定の「一般」にある「すべて同期」ボタン | 同上 |
| サイドバーの同期カードの要約をクリックして出る「Store ごとの同期状態」から Store を選ぶ | その Store |
| サイドバーの Store メニューの「今すぐ同期」、設定の「Store」にある「今すぐ同期」 | その Store |

Store メニューの「今すぐ同期」は、remote がない Store では無効にし、「remote なし」と添える。設定の「一般」の「すべて同期」ボタンは、表示中で remote がある Store が 1 つもなければ出さない。

手動の同期は、条件を待たずにすぐ始まる。閲覧のみの Store も同期できる。非表示の Store は「すべて同期」の対象にならず、設定の「Store」にある「今すぐ同期」でだけ同期できる。

同じ Store の同期がすでに動いているときは、新しく始めずに、動いている同期の結果を使う。

### 自動で同期する

設定の「一般」にある「裏で自動的に同期する」(初期値はオン)と「間隔」(1・5・15・30・60 分ごと、初期値は 5 分ごと)で決める。どちらもこのマシンだけの設定である。「裏で自動的に同期する」をオフにすると、次の契機のすべてが止まり、「間隔」は選べなくなる。

自動で同期する契機は次の 4 つである。

| 契機 | 動き |
|---|---|
| 間隔 | その Store を最後に同期してから、設定した間隔が過ぎたとき |
| アプリを開いたとき | 開いた直後に、対象のすべての Store |
| オンライン復帰 | オフラインからつながったときに、対象のすべての Store |
| 書き込み後 | Store に保存したあと、10 秒のあいだ次の保存がなければ、その Store。10 秒のあいだに保存が続くあいだは、最後の保存から数え直す |

自動で同期する対象は、remote があり、非表示ではなく、同期に使うアカウントが設定されている Store である。閲覧のみの Store も対象で、受け取りだけを行う(01)。閲覧のみの Store には書き込みがないので、「書き込み後」の契機は起きない。

自動の同期は、次のあいだは始めずに待つ。条件が解けたら、そのあと続けて同期する。待つのは、入力の途中で画面が書き換わって、入力が失われるのを防ぐためである。

- ダイアログ、メニュー、コマンドパレットが開いているとき
- ドラッグしているとき
- 説明やコメントを編集しているとき
- 入力欄にカーソルがあるとき

自動の同期は、成功してもトーストを出さず、失敗してもエラーのトーストを出さない。結果は、同期カードの状態と、アクティビティの同期の行で確かめる。

### オフライン

このマシンがネットワークにつながっていないとき、ページの上部に「オフラインです。変更はこのマシンにコミットし、つながったら push します。」と表示する。保存はこれまでどおり行え、未送信の保存として溜まる。つながったら、自動の同期の「オンライン復帰」で送る。

オフラインのときに手動で同期すると、エラーのトーストで「オフラインのため同期できません。つながったら同期します」と表示する。「すべて同期」では、Store ごとに数えず、このメッセージを 1 つだけ出す。オフラインは Store の同期の状態をエラーにしない。

### 同期のエラー

同期できなかったときは、その Store の状態を「同期エラー」にする。次に同期が成功するまで、この状態が続く。

| 場合 | 手動で同期したときの表示 | Store の状態 |
|---|---|---|
| remote がない | 「{Store 名} には remote がないため、同期するものはありません」 | 変わらない |
| アカウントが設定されていない | 「{Store 名} にアカウントが設定されていないため同期できません」(エラー) | 同期エラー |
| 認証に失敗した | 「{Store 名} の同期に失敗しました: 認証に失敗しました」(エラー) | 同期エラー |
| remote につながらない | 「{Store 名} の同期に失敗しました: remote に接続できません」(エラー) | 同期エラー |
| push が拒否された(書き込みの権限がない) | 「{Store 名} の同期に失敗しました: remote への書き込みが許可されていません」(エラー) | 同期エラー |
| remote の中身が hedgehug の Store でない | 「{Store 名} の同期に失敗しました: remote が hedgehug の Store ではありません」(エラー) | 同期エラー |

アカウントを設定すると、アカウントが設定されていないことによるエラーの表示は消える。アカウントの削除で同期に使っていた Store が同期できなくなる扱いは 07 を参照する。

### 同期の結果

1 つの Store を同期したときは、トーストで「{Store 名} を同期しました(送信 N 件・受信 M 件)」と表示する。N は送った保存の数、M は受け取った保存の数である。

「すべて同期」では、対象の Store をすべて同期したあとに、結果を 1 つのトーストにまとめる。

| 結果 | 表示 |
|---|---|
| すべて成功 | 「N 件の Store を同期しました」 |
| 失敗がある | 「成功 N 件・失敗 M 件」と、失敗した Store ごとに 1 行、「{Store 名}: {理由}」。理由は上の表の文言 |

remote がない Store は、「すべて同期」の件数に数えない。

### 同期の状態の表示

サイドバーの下部に、同期カードを置く。表示中で remote がある Store が 1 つもなければ、カードごと出さない。

カードの 1 行目は要約である。

- 同期エラーの Store が 1 つでもあれば、「N 件の Store で同期エラー」とエラーの色で表示する
- そうでなければ、すべての Store の「未送信 X」と「受信待ち Y」を「 · 」でつなぐ。0 のものは省く。どちらも 0 なら「すべて最新」と表示する

未送信は、このマシンで保存して、まだ送っていない保存の数である。受信待ちは、remote にあって、まだ受け取っていない保存の数で、同期が終わると 0 になる。

2 行目は「最終同期 {相対時間} · Store N 件」である。相対時間は、対象の Store の中で最も新しい同期の時刻を、01 の書式で表したものである。1 度も同期していない Store は数えず、すべてがそうなら「なし」と表示する。最後の同期からの経過時間が 24 時間以上の Store があるときは(表示の書式とは関係なく、経過時間で判定する)、3 行目に「N 件の Store が 24 時間以上同期されていません」と警告の色で表示する。

要約をクリックすると、メニュー「Store ごとの同期状態」が開く。remote がある表示中の Store を 1 行ずつ並べ、Store 名のあとに「{要約} · {相対時間 または 未同期}」を添える。要約は、同期エラーなら「同期エラー」、そうでなければ「未送信 X · 受信待ち Y」または「最新」である。最後の同期からの経過時間が 24 時間以上の Store は、相対時間を警告の色にする。項目を選ぶと、その Store を同期する。

同期カードの右端のボタン「すべて同期」で、手動の同期を行う。設定の「Store」にも、Store ごとの同期の状況(未送信件数、最終同期、エラー)を出す(08)。

## 同時に編集したとき

複数の人が、同期の前に同じ値を変えることがある。このとき、**項目ごとに、保存した時刻があとの変更が勝つ**。これを後勝ちと呼ぶ。保存時刻は各マシンの時計である。保存時刻が同じときは、ログイン名(大文字と小文字を区別しない)が辞書順であとの人の変更が勝つ。どのマシンで同期しても、同じ結果になる。

項目は、1 つの値ごとに分ける。タイトル、説明、各プロパティ、スプリント、リリース、親、種類、プロジェクトのタイトル・ステータス・オーナー・開始日・終了日・説明がそれぞれ 1 つの項目である。同じアイテムでも、別の項目の変更はどちらも残る。

| 重なり方 | 残るもの |
|---|---|
| 別の項目を変えた | どちらも残る |
| 同じ項目を、同じ値に変えた | その値。通知は作らない |
| 同じ項目を、別の値に変えた | 保存時刻があとの値。負けた人に「上書き」の通知を作る |
| コメント、リンク、関連、作業時間を追加した | どちらも残る |
| アイテムを作成した | どちらも残る(番号の重なりは次節) |
| 一方が削除し、他方が変更した | 削除が残り、アイテムは削除済みになる。他方の変更は、復元したときの値に含まれる |

あなたの値が負けたときは、あなたのマシンが、同期で受け取った変更を見て、あなた宛てに「上書き」の通知を作る。勝った人のマシンには、何も作らない。

### 上書きの通知

通知は、本文「{項目名}が上書きされました」、差出人は上書きした人である。受信箱では、項目の種類によって表示が分かれる。

| 項目 | 表示 | 「自分の値に戻す」 |
|---|---|---|
| タイトル、プロパティ、スプリント、リリース、プロジェクトのタイトル・ステータス・オーナー・開始日・終了日 | 「あなたの値 X → 残った値 Y」 | 出す |
| 説明、親、種類 | 本文だけ | 出さない |

説明は履歴に差分を残さず、親と種類は戻すとアイテムの親子の決まり(01)に合わなくなることがあるので、戻すボタンは出さない。

「自分の値に戻す」を押すと、あなたの値を、新しい 1 回の保存として書く。ワークフローの制約は無視する。アクティビティには「{ID} の{プロパティ名}を上書き前の値に戻す」(プロジェクトでは「{タイトル} の{項目名}を上書き前の値に戻す」)と残る。「上書き前の値に戻しました」と表示し、トーストの「元に戻す」で取り消せる。通知は既読になり、ボタンの代わりに「自分の値に戻しました」を表示する。この保存はあとの時刻になるので、次の同期で、上書きした人の値に勝つ。

アイテムが削除済み、または存在しないときは、ボタンを出さない。閲覧のみの Store では、ボタンを無効にして「閲覧のみの Store です」と添える。

### 番号の重なりの修復

2 人が同期の前に、それぞれ同じワークスペースにアイテムを作ると、同じ番号(01 の ID)を取ることがある。同期で重なりが分かったとき、あとから同期した方のアイテムに、そのワークスペースの次の空き番号を振り直す。先に同期した方の番号は変わらない。コメントや説明に書いた ID は、文字のまま変わらない。

振り直しは保存として記録する。アクティビティでは、実行者を「同期」として「{旧 ID} を {新 ID} に振り直し」と表示する。どのマシンが同期しても、同じ番号に振り直す。

振り直されたアイテムを作った人の受信箱に、「同期の修復」の通知を作る。本文は「2 台で同時に {旧 ID} が作られたため、あとから届いた方を {新 ID} に振り直しました」である。

### スプリントの実行中が 2 つになったとき

ワークスペースの実行中のスプリントは 1 つだけである(05)。2 人が同期の前に、別のスプリントを開始すると、同期で実行中が 2 つになる。このときは、開始日が早い方を実行中のままにし、もう一方を計画中に戻す。開始日が同じなら、開始の保存時刻が早い方を残す。

計画中に戻した保存は、番号の振り直しと同じく、実行者を「同期」として記録する。戻されたスプリントを開始した人の受信箱に、「同期の修復」の通知を作る。本文は「実行中のスプリントが 2 つになったため、「{スプリント名}」を計画中に戻しました」である。

### 親が削除されたとき

ある人がアイテムを削除しているあいだに、別の人がその子を追加すると、同期で、削除済みの親の下に、削除されていない子が残る。このときは、子も同じ削除操作で削除済みにする。親を復元すれば、子も戻る。

子を追加した人の受信箱に、「同期の修復」の通知を作る。本文は「{親の ID} が削除されたため、{子の ID} も削除済みにしました」である。

### 修復の決まり

- 修復を保存するのは、Store に書き込めるマシンだけである。閲覧のみの Store の利用者には、同期の修復の通知を作らない(自分が書いたものがないため)
- 上の 3 つ以外のずれは、同期では直さず、診断と修復(08)で見つける
- 同期のあとに、ほかのマシンが同じ修復を行っても、結果は変わらず、通知も増えない

## 通知

通知は、あなたに関わる変更を知らせる。各マシンが、このマシンでの自分の操作と、同期で受け取った他の人の変更から、あなた宛てのものだけを作る。他の人宛ての通知は作らない。通知と既読の状態は、このマシンだけで持つ(01)。

通知は 7 種類である。

| 種類 | 受信箱のタブ | 作る条件 | 本文 |
|---|---|---|---|
| 割り当て | 割り当て | 受け取った変更で、アイテムの担当者、またはプロジェクトのオーナーが、あなたになった | 「あなたに割り当てました」、プロジェクトでは「プロジェクト「{タイトル}」のオーナーになりました」 |
| メンション | メンション | 受け取ったコメントと説明(アイテム、プロジェクトとも)に、新しく増えた @ログイン名 が、あなたのログイン名だった | 書かれた本文全体 |
| ウォッチ | ウォッチ | あなたがウォッチしているアイテムを、他の人が変えた | 変更の内容 |
| 上書き | 上書き | あなたの値が、同時に編集した他の人の変更に負けた | 「{項目名}が上書きされました」 |
| 自動化 | 自動化 | あなたの操作や、あなたのマシンが取得した GitHub の状態で、自動化が動いた。ステータスやメンバーの削除で自動化が無効になった(03)場合も含む | 「「{ルール名}」で{変更の内容}しました」。無効になったときは 03 の文言 |
| 自動化が制約で止まった | 自動化 | 自動化が動こうとしたが、ワークフローの制約で止まった | 「「{ルール名}」が制約で止まりました」 |
| 同期の修復 | 同期の修復 | 同期での修復が、あなたの作ったものを変えた。診断での修復(08)も含む | 前節の各文言、診断では「診断で修復しました: {検出した内容}」 |

通知を作らない場合を、まとめて定める。

- 自分の変更では、割り当て、メンション、ウォッチの通知を作らない
- 閲覧のみの Store でも、受け取った変更から、割り当てとメンションの通知を作る
- Store を追加したときに取得した、それ以前の変更からは、通知を作らない
- 同じ変更で、上書きとウォッチの条件がどちらも合うときは、上書きだけを作る
- 同じ保存で、同じ人が複数回メンションされたときは、1 通にまとめる

### 割り当て

担当者の設定、アイテムの作成と複製で担当者があなたになった場合を含む。自動化が担当者をあなたに変えた場合も作る。差出人は、自動化のときは「hedgehug」、そうでなければ変えた人である。

### メンション

メンション先は、Store のメンバーのログイン名と一致する @ログイン名 で、大文字と小文字を区別しない。メールアドレスの一部(@ の直前が英数字)は、メンションとして扱わない。

保存したとき、その本文で新しく増えた @ログイン名 だけを対象にする。すでに本文にあった @ログイン名 は、保存し直しても通知しない。コメントの編集でも、編集で増えた分は通知する。

### ウォッチ

ウォッチは、アイテムの詳細パネルのボタンで入り切りする。アイテムを作成または複製した人は、自動でウォッチになる。担当者になった人やメンションされた人は、自動ではウォッチにならない。

ウォッチ中のアイテムで、次の変更を受け取ったときに通知する。

- プロパティの変更。本文は「{プロパティ名}を {値} に変更」
- タイトルの変更。本文は「タイトルを「{新しいタイトル}」に変更」
- コメントの投稿。本文は「コメント: {先頭 40 字}」

説明の変更、リンク、関連、作業時間、削除、移動、種類の変更では通知しない。自動化による変更でも通知する。

### 自動化

自動化が動いたマシンの利用者宛てに作る。他のマシンは、受け取った自動化の変更から、自動化の通知を作らない(割り当てやウォッチの条件に合えば、その通知は作る)。自動化の動く条件と連鎖の決まりは 03 を参照する。差出人は「hedgehug」である。

### 同期の修復

差出人は「hedgehug」である。診断での修復の通知も、この種類に含める。

## 受信箱

受信箱は、すべての Store のあなた宛ての通知を 1 つの一覧にする(01)。非表示の Store の通知は出さず、未読数にも数えない。表示に戻せば、また出る。見出しは「受信箱」、補足は「同期で届いた変更、メンション、割り当て、上書きされた値」である。

### タブと未読数

| タブ | 出る通知 |
|---|---|
| すべて | すべての種類 |
| メンション | メンション |
| 割り当て | 割り当て |
| ウォッチ | ウォッチ |
| 上書き | 上書き |
| 自動化 | 自動化、自動化が制約で止まった |
| 同期の修復 | 同期の修復 |

各タブに、未読の通知の数を出す。0 件なら数字を出さない。サイドバーの「受信箱」には、「すべて」の未読数を出す。

### 並びと行の表示

通知を作った時刻の新しい順に並べる。

1 行は、次のものからなる。

- 左端の点。未読のときは目立つ色にする。クリックで既読と未読を切り替える
- 種類を示すピル(メンション・割り当て・ウォッチ・上書き・自動化・同期の修復)
- アイテムの種類のアイコン、ID、タイトル。クリックすると、通知を既読にして、詳細パネルを開く
- 通知を作った時刻の相対時間(01 の書式)
- 差出人のアバターと名前。差出人がなければ「hedgehug」。続けて本文を Markdown で表示する
- 種類によって、本文の下に操作を出す(後述)

通知がアイテムではなくプロジェクトを指すとき(プロジェクトのオーナーの割り当て、プロジェクトの説明へのメンション、プロジェクトの項目の上書き)は、アイテムの代わりにプロジェクト名を出し、クリックでプロジェクトの概要を開く。アイテムが削除済みのときは「削除されたアイテム」と表示し、リンクにしない。完全に削除したアイテム(08)の通知は、一覧から消える。

### 操作

- **すべて既読にする**: 見出しの右のボタン。いま表示しているタブの通知だけを既読にする。そのタブに未読がなければ無効にする
- **既読と未読の切り替え**: 左端の点をクリックする
- **上書きの通知**: 「あなたの値 X → 残った値 Y」を表示し、「自分の値に戻す」を出す(「上書きの通知」の節)。戻したあとは「自分の値に戻しました」を表示する
- **自動化が制約で止まった通知**: 本文の下に、止まった理由を表示し、次の 2 つのボタンを出す。どちらかを押すと、通知は既読になり、ボタンの代わりに結果のピルを表示する

| ボタン | 動き | ピル |
|---|---|---|
| 制約を無視して {ステータス名} にする | アイテムのステータスを、制約を無視して変える。1 回の保存で、アクティビティには「「{ルール名}」の変更を制約を無視して適用」と残る。「適用しました」と表示する | 適用しました |
| 変更しない | 何も保存しない | このままにしました |

アイテムが削除済みのときは、2 つのボタンを出さない。閲覧のみの Store では、2 つのボタンと「自分の値に戻す」を無効にして「閲覧のみの Store です」と添える。

既読と未読の切り替え、すべて既読、「変更しない」は、Store を変えないので、保存にもアクティビティにも元に戻すにも入らない(01)。

### 空のとき

| タブ | 表示 |
|---|---|
| 上書き | 「お知らせはありません」、補足は「このマシンで変えた値が、同期であとから届いた変更に負けると、ここに出ます。試すには、値を変えてからサイドバーの同期ボタンを押してください。」 |
| 同期の修復 | 「お知らせはありません」、補足は「同期のときに直したもの(番号の重なり、消えた親など)がここに出ます。」 |
| そのほか | 「お知らせはありません」 |

## アクティビティ

アクティビティは、Store の変更の記録を新しい順に並べる画面である。見出しは「アクティビティ」、補足は「Store の git 履歴。1 つの変更が 1 つのコミットです」である。

### 対象

表示中の Store の記録だけを出す。非表示の Store の記録は出さない。記録になるのは、Store を変える保存だけである。一覧に入るのは次のものである。

- このマシンでの自分の保存
- 同期で受け取った他の人の保存。保存した人の行として、その人が保存した時刻に並ぶ
- 自動化の変更(「「{ルール名}」で{変更の内容}」)と、自動化が制約で止まった記録
- 操作した人のいない自動の変更。GitHub からのリンクの取り直しと、Issue の mirror による保存(07)
- 同期の行と、同期での修復

元に戻した保存は、「元に戻す: 〜」として残る(01)。

同期の行は、送った保存か受け取った保存が 1 件以上あった同期だけに作る。実行者は「同期」、本文は「origin と同期 (送信 N 件・受信 M 件)」である。両方が 0 件の同期は残さない。

### 絞り込み

| 絞り込み | 選び方 | 出る記録 |
|---|---|---|
| ワークスペース | セレクト。「すべて」と、「{Store 名} / {ワークスペース名}」(表示中の全ワークスペース) | そのワークスペースの記録と、そのワークスペースがある Store の同期の行 |
| 種類 | 「すべて」「人の変更だけ」「同期だけ」「自動化だけ」 | 下の表のとおり |

| 種類 | 出る記録 |
|---|---|
| すべて | すべて |
| 人の変更だけ | 人が行った保存。自動化、GitHub、同期の記録は除く。同期で受け取った他の人の保存は含む |
| 同期だけ | 同期の行と、同期での修復 |
| 自動化だけ | 自動化の記録と、GitHub からの自動の変更 |

ワークスペースと種類は、組み合わせて使える。この絞り込みは画面の状態で、Store には保存しない(01)。

### 表示

日付ごとにまとめ、見出しは「今日」「昨日」、それより前は「YYYY/MM/DD」にする(01 の日付の書式とは違い、年を省かない)。日付と時刻は、このマシンの時刻帯で表す(01)。同じ日の中は、時刻の新しい順に並べる。

1 行は、次のものからなる。

- 時刻(HH:MM)
- 実行者のアイコン。同期は同期のアイコン、自動化は「A」、GitHub は GitHub のアイコン、人はアバター
- 実行者の名前(同期は「同期」、自動化は「自動化」、GitHub からの自動の変更は「GitHub」)に続けて、記録の本文
- Store のバッジ、ワークスペース名、対象のアイテムの ID(削除済みでなければリンク)、対象のプロジェクト名(削除済みでなければリンク)
- コミットの短縮した SHA。実際のコミットの SHA の先頭 7 桁を出す

### 件数

一度に出すのは 300 件で、日付の区切りをまたいで数える。さらに記録があるときは、末尾に「さらに読み込む」を出し、押すと次の 300 件を足す。0 件のときは「この条件のコミットはありません」と表示する。

## 元に戻すと同期

元に戻す規則は 01 に定めた。同期の側から見ると、次のようになる。

- 同期は、元に戻せる保存の一覧を消さない。同期の前の保存も、同期のあとに、新しいものから順に戻せる
- 送信済みの保存も戻せる。戻す保存は、元の操作と逆の変更を新しい保存として記録するので、次の同期で送られる
- 戻そうとする項目に、その保存のあとで同期で受け取った他の人の変更があるときは、何も変えず、その保存を元に戻す対象から外す。表示は 01 のとおり
- 自分の値が負けたときの「自分の値に戻す」は、通知の操作であり、元に戻すとは別である。その保存も、元に戻す対象に入る
- 同期の行と、同期での修復(番号の振り直しなど)は、あなたの保存ではないので、元に戻す対象に入らない

## 同期のあとの完全な削除

削除済みのものを、保持日数を過ぎたら自動で完全に削除する(08)。この削除は、Store に書き込めるマシンが、同期に成功した直後に行う。remote のない Store では、アプリを開いたときに行う。閲覧のみの Store は、このマシンでは行わない。複数のマシンが同じものを削除しても、結果は同じである。同期が失敗したとき、オフラインのときは、行わない。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| 同期で元に戻す履歴が消える(R1-48、F2) | 同期すると、元に戻せる履歴がすべて消える | 消えない。他の人があとから変えた項目だけ戻さない | 自動同期が定期的に動くため(01 にも記載) |
| 通知の作り方(F1、B20) | ウォッチや割り当ての通知を、操作したマシンが他人宛てに作って積む | 各マシンが、あなた宛てだけを、自分の操作と同期で受け取った変更から作る | 通知はマシンごとに持ち、Store に保存しないため |
| 同期カードの最終同期(R1-46) | 最も古い同期の時刻を、「最終同期」として出す | 最も新しい同期の時刻を出す。24 時間以上同期していない Store があれば、その数を警告する | ラベルと中身を一致させ、古い Store を見落とさないため |
| 「すべて同期」の結果(R1-47、B23) | 成否に関わらず「N 件の Store を同期しました」。エラーは握りつぶす | 失敗があるときは「成功 N 件・失敗 M 件」と、失敗した Store ごとの理由を出す。オフラインは 1 つのメッセージ | 失敗に気づけるようにするため |
| 同期の失敗の種類 | アカウント未設定だけがエラーになる | 認証に失敗した、remote につながらない、push が拒否された、hedgehug の Store でない、を同じ扱いで加える | 実際の同期では起こりうるため |
| 自動同期(R1-49) | 30 秒ごとのタイマーで、間隔が過ぎた Store を同期する | 間隔ごと、アプリを開いたとき、オンライン復帰、書き込みの 10 秒後。入力中や選択中などは待つ | 文言「バックグラウンドで同期します」「つながったら push します」に合わせるため |
| 書き込み後の同期 | なし | 最後の保存から 10 秒後に、その Store を同期する(送信と受信の両方) | 送るだけの同期を別に作ると、状態の種類が増えるため |
| 閲覧のみの Store の自動同期(B22) | 自動同期の対象外。手動なら同期できる | 自動同期の対象にする(受け取りのみ) | 閲覧のみの Store は更新を受け取る必要があるため |
| 同じ Store の同期が重なる | 決まっていない | 動いているあいだは新しく始めず、その結果を使う | 自動と手動が同時に動いても、二重に送らないため |
| すべて既読にする(R1-50) | 表示中のタブに関わらず、全タブの通知を既読にする | 表示中のタブの通知だけを既読にする。無効の条件もタブの未読数で決める | ボタンがタブの中にあるので、全タブの通知が既読になるとは読み手が思わないため |
| 受信箱の並び(R1-51) | 並べ替えず、作った順の逆に依存する | 通知を作った時刻の新しい順を明示する | 受け取った順で並びが変わらないようにするため |
| アクティビティの SHA(R1-53) | モックの ID の末尾 7 文字 | 実際のコミットの SHA の先頭 7 桁 | 実物のコミットに対応させるため |
| ワークスペースの絞り込み(R1-54) | 暗黙に、同期の行を Store 単位で拾う | 同じ動きを仕様に明記する | 同期の行にはワークスペースがないため |
| アクティビティの件数(R1-55) | 先頭 300 件だけで、続きはない | 300 件ずつ「さらに読み込む」 | 古い記録も見られるようにするため |
| 種類の絞り込み(R1-56) | `by` の有無と、同期と自動化のフラグが混在 | 人の変更だけ(自動化と同期以外)、同期だけ、自動化だけ。同期で受け取った他の人の保存は、人の変更に入れる | 絞り込みの意味を、実行者で一貫させるため |
| 非表示の Store(R1-57、B22) | 一覧、同期、検索から外れる(暗黙) | アクティビティと自動同期から外す。「すべて同期」からも外す。設定の「今すぐ同期」では同期できる | 非表示でも設定から同期できるようにするため |
| 元に戻す対象(R1-58) | commit を通らない操作は戻せない(暗黙) | 既読、「変更しない」などを、保存にもアクティビティにも元に戻すにも入れないと明記する(01) | 対象を迷わないようにするため |
| スプリントの実行中が 2 つ(R1-8) | 対処なし。最初に見つかった方が実行中になる | 開始日が早い方を残し、他を計画中に戻す。同じなら開始の保存時刻が早い方。「同期の修復」の通知 | どちらの利用者にも同じ結果にするため |
| 番号の重なりの修復(Q6) | 受信する側の画面で、通知だけを作る | あとから同期した方の番号を振り直し、保存として記録する。作った人に通知する | 全マシンで同じ番号になるため |
| 項目ごとの後勝ち(Q6) | 未同期の値が、あとから届く値で必ず負ける | 保存時刻があとの値が勝つ。同じ時刻ならログイン名が辞書順であとの人 | 先に同期した方が不利にならず、どのマシンでも同じ結果になるため |
| 上書きの通知の範囲 | プロパティだけ | タイトル、説明、スプリント、リリース、親、種類、プロジェクトの項目にも出す。値の表示と戻すボタンは、タイトル、プロパティ、スプリント、リリース、プロジェクトの項目だけ | 負けた値を、どの項目でも知らせるため。説明・親・種類は戻せない |
| 重なりのほかの扱い | 決まっていない | コメント、リンク、関連、作業時間、作成は両方残す。削除は他の変更に負けない | 追加は競合しないため。削除を取り消すと、利用者の意図に反するため |
| 親が削除されたとき(修復) | 決まっていない | 子も同じ削除操作で削除済みにし、「同期の修復」を通知する。親が完全に削除されて存在しないときは診断(08) | 親を復元すれば子も戻り、データを失わないため |
| 修復の通知先 | 受信した側が自分宛てに作る | 修復で変わったものを作った人宛て。保存は書き込めるマシンだけが行う | 通知を、関係する人にだけ出すため |
| メンション(B6) | 保存のたびに本文のすべてのメンションを通知。コメント編集とプロジェクトの説明では通知しない。`foo@bar` も一致する | 新しく増えた分だけ通知する。コメントの編集とプロジェクトの説明でも通知する。メールアドレスの一部は除く | 同じ人に何度も通知しないため |
| 自動化が制約で止まった(通知の種類) | 「自動化」の中の 1 種類 | 7 種類のひとつとして数える。タブは「自動化」に出す | 操作ボタンと文言が他と違うため |
| プロジェクトを指す通知 | アイテムがないので「削除されたアイテム」と表示する | プロジェクト名を表示し、プロジェクトの概要へのリンクにする。削除済みのアイテムの通知だけ「削除されたアイテム」 | オーナーの割り当ては、アイテムがない通知だから |
| 非表示の Store の通知 | 非表示にしても通知は出る | 出さず、未読数にも数えない(08) | 非表示の Store は一覧から外すため |
| 通知の寿命 | 完全に削除するときだけ、通知を消す(個別の削除のみ) | 完全に削除したアイテムの通知を消す。Store を追加したときの過去の変更では通知を作らない | 古い履歴で受信箱が埋まるのを防ぐため |
| 閲覧のみの Store の通知の操作 | 操作できる | 戻す操作と制約を無視する操作を無効にする(01) | 閲覧のみの Store は書き込めないため |
| 同期の行(アクティビティ) | 受信した内容を、同期の行の本文に並べる。受け取った保存は個別の行にならない | 受け取った保存を、保存した人の行として並べ、同期の行には件数だけ。両方 0 件の同期は記録しない | アクティビティは Store の保存の記録だから。5 分ごとの同期で行があふれないため |
| GitHub からの自動の変更 | なし | 実行者を「GitHub」とし、絞り込みでは「自動化だけ」に含める(07) | 操作した人がいない変更を区別するため |
| 同期の修復の実行者 | なし | アクティビティの実行者を「同期」とする | 利用者が行った保存と区別するため |
| 自動の完全削除(D3) | なし(手動のみ) | 書き込めるマシンが、同期に成功した直後に行う。複数のマシンが同じものを消しても結果は同じ | 保持日数後に自動で消すため(08) |
