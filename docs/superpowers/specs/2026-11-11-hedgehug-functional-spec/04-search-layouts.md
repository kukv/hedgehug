# hedgehug 機能仕様 04: 検索とレイアウト

アイテムを探して一覧する画面を定める。サイドバー、マイタスク、検索、保存したビューは、同じクエリ言語と、ツリー・カンバン・テーブル・ガントの 4 つのレイアウトでアイテムを見せる。この文書は、そのクエリの書き方、各レイアウトの表示と操作、一括変更までを扱う。用語・階層・「あなた」・書き込み・閲覧のみの Store は 01 に従い、ここでは繰り返さない。

## この文書の範囲

| 扱う | 扱わない(参照先) |
|---|---|
| サイドバー、マイタスク、検索、保存したビュー | 同期カード(06)、受信箱とアクティビティ(06) |
| クエリ言語と検索ヘルプ | コマンドパレット(02) |
| ツリー・カンバン・テーブル・ガントの表示と操作 | アイテムの作成・移動・削除・種類の変更・詳細パネル、ステータスメニュー、アイテムのメニューの中身(02) |
| 一括選択、一括変更、一括削除 | バックログの選択(05。選択と一括変更のバーはこの文書と同じ) |
| ワークスペース概要の統計とプロジェクト一覧 | スプリントの進捗・バーンダウンなどの集計(05)、アクティビティの表示(06) |
| 進捗・未完了・期限切れの定義 | ワークスペースの設定(03) |

ステータスの変更は、どの画面から行っても 02 の規則に従う。遷移が禁じられているときは断る。この文書では、その規則を「02 の規則」と呼ぶ。

## 集計の定義

進捗・未完了・期限切れは、サイドバー、マイタスク、概要、各レイアウトで同じ意味を使う。

| 用語 | 定義 |
|---|---|
| 未完了 | ステータスの分類が「未着手」か「進行中」のアイテム |
| 終了済み | 分類が「完了」か「中止」のアイテム |
| 期限切れ | 未完了で、終了日が今日より前のアイテム。終了日が今日のものは「今日」と呼び、期限切れとは数えない |
| 進捗 | 対象のうち完了の割合。パーセントは四捨五入し、対象が 0 件なら 0% |
| 進捗の対象 | 中止を除く。進捗の分母にも分子にも入れない |

進捗を出す場所と、数えるアイテムは次のとおり。

| 場所 | 数えるアイテム |
|---|---|
| プロジェクトの進捗 | プロジェクトの下の、Epic と Step を除くすべてのアイテム(Story・Task・Bug) |
| Epic の進捗 | Epic の下の、Step を除くすべてのアイテム |
| ツリーの Story・Task・Bug の行の「完了/対象」 | その行の下の Step。対象が 0 件なら出さない |

進捗の表示は、棒と「N%」である。棒の上にポインターを置くと「{完了} / {対象}」が出る。

期限の表示は、終了日がないアイテムでは何も出さない。あるときは日付を出す。書式は 01 の日付の表示に従う(同じ年なら「5/12」、別の年なら「2027/01/05」)。未完了のアイテムでは、期限切れなら「期限切れ 5/12」、今日なら「今日 5/12」と強調する。終了済みのアイテムは強調しない。

日付が変わったとき(このマシンの日付が前回と変わったとき。1 分ごとの確認と、画面に戻ったとき・スリープから戻ったときの確認)は、日付で決まる表示を自動で更新する。マイタスクのグループとバッジ、期限の強調と「期限切れ」「今日」の表示、概要の「期限切れ」カードの件数、`today`・`-7d` のような日付を書いたクエリの結果が対象である。入力中の欄と開いているダイアログは動かさない(01)。

## サイドバー

左側にあり、上から次の順に並ぶ。

1. アプリの名前と、設定を開く歯車(設定は 06〜08)。
2. 「ID・検索・コマンド」のボタン(Ctrl+K)と、「新規作成」のボタン(C。どちらも 02)。
3. ナビ 4 つ。
4. Store ごとのブロック。
5. 保存したビュー。
6. 同期カード(06)。

### ナビ

| 項目 | バッジ | 開く画面 |
|---|---|---|
| マイタスク | あなたが担当する未完了のアイテムの件数(後述)。0 件なら出さない | マイタスク |
| 受信箱 | 未読の件数(06) | 受信箱 |
| アクティビティ | なし | アクティビティ |
| 検索 | なし | 検索(テーブル) |

いま開いている画面の項目を強調する。

### Store ごとのブロック

表示中の Store ごとに、次のブロックを出す。非表示にした Store は出さない。Store の並びは、設定の「Store」の並びと同じである(08)。

- 見出し: Store の名前を、Store の色のバッジで出す。右にメニューのボタンがある。
- ワークスペースの行: 開閉の矢印、ワークスペース名、接頭辞、メニューのボタン。名前を押すとワークスペースの概要を開く。
- プロジェクトの行: 各ワークスペースの下に、プロジェクトの名前を並べる。名前の前の点は、プロジェクトのステータスに応じた色にする。Todo と Pending は未着手、InProgress は進行中、Done は完了、Cancel は中止の色である。押すとプロジェクトの概要を開く。
- ブロックの末尾に「ワークスペースを追加」を置く。ワークスペースが 1 つもないときは、その上に「ワークスペースはまだありません」と出す。

ワークスペースの行の矢印は、その下のプロジェクトの行を隠したり出したりする。初めはすべて開いている。開閉はワークスペースごとに覚え、このマシンに残す(01 の画面の状態)。保存にもアクティビティにも残らない。

### 並び順と並べ替え

ワークスペースは Store の中で、プロジェクトはワークスペースの中で、それぞれ並び順を持つ。新しく作ったものは末尾に入る。並べ替えるときに位置が変わるのは動かした 1 件だけで、ほかの並びは保たれる。このため、別々の人が別々のものを並べ替えても、同期のあとで並びが崩れない。同じ 1 件を 2 人が別の位置に動かしたときは、保存時刻があとの位置が勝つ(06)。順位が同じ別のものは、作成の保存が早い方を先にし、同じなら内部 ID の辞書順で並べる。たとえば田中さんの「Web」と鈴木さんの「Docs」が同じ順位でも、全員の画面で Web、Docs の順に並ぶ。

| 操作 | 方法 |
|---|---|
| ワークスペースを並べ替える | サイドバーで行をドラッグして、同じ Store の別のワークスペースの上か下にドロップする。または、ワークスペースのメニューの「上へ移動」「下へ移動」 |
| プロジェクトを並べ替える | サイドバーで行をドラッグして、同じワークスペースの別のプロジェクトの上か下にドロップする。または、プロジェクトのメニュー(ツリーの行、概要の一覧の行)の「上へ移動」「下へ移動」 |

「上へ移動」は先頭の行で、「下へ移動」は末尾の行で無効にする。別の Store やワークスペースへは、ドラッグでは移せない。別の Store の欄や別のワークスペースの下に落としたときは、何も変えずに、ワークスペースなら「別の Store へは、設定の「別の Store へ移動」から移せます」、プロジェクトなら「別のワークスペースへは、設定の「別のワークスペースへ移動」から移せます」と表示する(移動は 02・03)。並べ替えは 1 回の保存になり、アクティビティに「{名前} の並びを変更」と残る。閲覧のみの Store では、ドラッグとメニューの項目を無効にする。

### Store のメニュー

| 項目 | 動作 |
|---|---|
| 今すぐ同期 | その Store を同期する(06)。remote がない Store では無効にし、「remote なし」と添える |
| ワークスペースを追加 | ワークスペースの作成ダイアログを開く(03)。閲覧のみの Store では無効 |
| Store の設定 | 設定の「Store」を開く(08) |
| サイドバーで非表示 | その Store をサイドバーから隠す |

「サイドバーで非表示」を選ぶと、その Store はサイドバー、マイタスク、検索、保存したビュー、受信箱、アクティビティの対象から外れる(06・08)。保存にもアクティビティにも残らない(01)。いま開いている画面がその Store のワークスペース、プロジェクトなら、マイタスクに移る。保存したビューはこのマシンのものなので開いたままにし、その Store のアイテムが結果から消える。開いていた詳細パネルがその Store のアイテムなら閉じる。トーストは「{Store 名} を非表示にしました。設定の「Store」から再表示できます」と出す。再表示は設定の「Store」から行う(08)。

### ワークスペースのメニュー

| 項目 | 動作 |
|---|---|
| プロジェクトを作成 | プロジェクトの作成ダイアログを開く(02)。閲覧のみの Store では無効 |
| 設定を開く | ワークスペースの設定タブを開く(03) |
| 上へ移動・下へ移動 | 前節のとおり |
| 削除… | ワークスペースを削除する(03)。閲覧のみの Store では無効 |

### 保存したビュー

このマシンに保存したビューを、名前順に並べる。各行は、ビューのアイコンと名前を出す。1 件もないときは「検索の画面から保存できます」と出す。ビューの内容は「保存したビュー」の節で定める。

## マイタスク

あなたが担当する未完了のアイテムを、期限・プロジェクト・ワークスペースのどれかでまとめて見せる画面である。見出しは「マイタスク」、補足は「あなたが担当しているタスク」とする。

### 対象

表示中の Store のアイテムのうち、次のすべてに当たるもの。クエリで書けば `assignee:@me -category:done,canceled -kind:epic` である。

- 担当者が「あなた」(Store ごとに決まる。01)
- 終了済みでない
- Epic でない(Story・Task・Bug・Step)

閲覧のみの Store のアイテムも対象に入る。サイドバーのバッジは、この条件に当たるアイテムの件数で、画面の絞り込みには影響されない。

### 絞り込みとまとめ方

- 絞り込み欄(「絞り込み 例: priority:high」)に、クエリ言語で書ける。条件は対象の条件に加わる。書き方に誤りがあるときは、エラーを赤字で出し、一覧は空にする。
- 「期限」「プロジェクト」「ワークスペース」のどれかを選んで、まとめ方を切り替える。初めは「期限」である。絞り込みとまとめ方は、このマシンに残す(01 の画面の状態)。

| まとめ方 | グループ | グループの並び | グループの中の並び |
|---|---|---|---|
| 期限 | 期限切れ、今日、今週、来週以降、期限なし | 左の順に固定 | 終了日の早い順。同じ日は並び順 |
| プロジェクト | プロジェクトごと | プロジェクト名の順 | 終了日の早い順。終了日がないものは末尾。同じ日は並び順 |
| ワークスペース | ワークスペースごと。見出しに Store のバッジを添える | ワークスペース名の順。同名は Store の順 | プロジェクトと同じ |

「期限」の区分は次のとおり。週は月曜に始まり日曜に終わる(01)。

| グループ | 終了日 |
|---|---|
| 期限切れ | 今日より前 |
| 今日 | 今日 |
| 今週 | 明日から、今週の日曜まで |
| 来週以降 | 今週の日曜より後 |
| 期限なし | なし |

「期限切れ」と「今日」の見出しは警告の色にする。今日が日曜のときは、「今週」は空になり、明日以降が「来週以降」に入る。件数のないグループは出さない。各見出しに件数を添える。

### 行

種類のアイコン、ID、タイトル、Store の点とプロジェクト名、期限、優先度、ステータスのボタンを並べる。タイトルを押すと詳細パネルを開く(02)。ステータスのボタンはステータスのメニューを開く(02 の規則)。閲覧のみの Store のアイテムの行は、ステータスのボタンを無効にし、「閲覧のみの Store です」と添える。

### 空のとき

| 状況 | 表示 |
|---|---|
| 対象が 1 件もない | 「担当しているタスクはありません」と、「新しく割り当てられると、ここと受信箱に出ます。」 |
| 絞り込みで 0 件 | 「一致するものはありません」と、「絞り込みを変えてみてください。」 |

## クエリ言語

絞り込み欄とビューは、同じ書き方を使う。この書き方(キーの名前、値の形、候補の出し方)は暫定であり、使いながら見直す前提で設計する。キーを足す・名前を変えるときに、保存したビューの条件を読み替えられるようにしておく。

```
key:value        key:value1,value2        -key:value        key>n        key<=date
語               "空白を含む語"            sort:key         sort:-key
```

### 組み立て方

- 語をスペースで区切ると、すべてに一致するものだけが残る。
- 1 つの語の中で `,` で区切ると、どれか 1 つに一致すればよい。
- 語の前に `-` を付けると否定になり、その語に一致しないものが残る。値のないアイテムは、否定では一致する側に入る。たとえば `-assignee:@me` は、担当者のいないアイテムも残す。
- 名前、ログイン名、ID の比較は、大文字と小文字を区別しない。キーの名前も区別しない(`Status:done` も使える)。
- `-` だけの語は、否定ではなく自由な語として扱う。
- 空白を含む値は、`"` で囲む。たとえば `release:"v2.0 beta"`。`"` で囲んでも `,` は区切りのままである。閉じていない `"` があるときは、そこから末尾までを 1 つの語とする。
- キーの前に `-` を付けた `-sort:` の `-` は無視する。降順にするには値に `-` を付ける。
- 空のクエリは、すべてのアイテムに一致する。
- 対象になるのは、削除済みでないアイテムである。ただし、否定でない `is:deleted` の語があるときは、対象が削除済みのアイテムだけになる(後述)。画面ごとに、元になるアイテムの範囲が決まっている(検索とビューは表示中のすべての Store、ワークスペースの画面はそのワークスペース、プロジェクトの画面はそのプロジェクト、マイタスクは前節の対象)。

### 自由な語

キーのない語は、ID、タイトル、説明のどれかに含まれるアイテムに一致する(部分一致)。ID は `HH-12` の形で書き、`HH-1` は `HH-12` にも一致する。別の Store に同じ ID のアイテムがあれば、どちらにも一致する。別のワークスペースへ移動したアイテムと、接頭辞を変える前のアイテムは、移動前の旧 ID、変更前の旧い接頭辞の ID でも見つかる(02、03)。移動を重ねたときは、いまある場所のアイテムが見つかる。旧 ID で見つかったものには「旧 ID」と添える(02)。旧い接頭辞をあとから別のワークスペースが使っているときは、現在の ID が一致するものと旧 ID で一致するものの両方を出す。`"…"` で囲むと、空白を含む語を 1 つの語として探す。

語の先頭が、英字で始まる英字・数字・`_` の並びで、そのあとに `:`、`<`、`<=`、`>`、`>=` が続くときは、キーとして読む。それ以外は自由な語として探す。たとえば `http://` と `v2<v3` はキーとして読まれ、「「http」というキーはありません」「「v2」というキーはありません」のエラーになる。`C++>11` は、`C++` が形に合わない(`+` を含む)ので、自由な語として探す。そのまま探したいときは `"` で囲む。

### キー

| キー | 値 | 一致する条件 |
|---|---|---|
| `status` | ステータスの名前 | アイテムのステータスの名前が一致する。複数のワークスペースに同じ名前があれば、どれも一致する |
| `category` | `todo`(未着手)、`doing`(進行中)、`done`(完了)、`canceled`(中止) | ステータスの分類が一致する |
| `kind` | `epic`、`story`、`task`、`bug`、`step` | 種類が一致する |
| `system` | 関連システムの名前、`none` | 関連システムのどれかが一致する。`none` は関連システムがない |
| `assignee` | ログイン名(`@` を付けてもよい)、`@me`、`none`。表示名では書けない(候補から選ぶ。後述) | 担当者が一致する。`@me` は、そのアイテムの Store での「あなた」。`none` は担当者がない |
| `watching` | ログイン名、`@me`、`none` | その人がウォッチしている。`none` は、ウォッチしている人がいない |
| `mentions` | ログイン名(`@` を付けてもよい)、`@me`、`none` | 説明と、削除されていないコメントの中に、その人の `@ログイン名` がある(コードの中も含む。`@` の前の文字は問わない)。`@me` は、そのアイテムの Store での「あなた」。`none` は、説明にもコメントにもメンションがない。通知の行と違い、いまの本文で判定する |
| `priority` | 優先度の名前 | 優先度が一致する。優先度には「なし」がないので、`none` は書けない(書くと「priority に none は使えません」のエラー) |
| `sprint` | スプリントの名前、`current`、`next`、`none` | スプリントが一致する。`current` はそのワークスペースの実行中のスプリント、`next` は計画中のスプリントのうち開始日が最も早いもの(開始日のないものは最後)。`none` はスプリントに入っていない |
| `release` | リリースの名前、`none` | リリースが一致する。`none` はリリースに入っていない |
| `project` | プロジェクトの ID(`HH-P1`) | プロジェクトが一致する。移動前の旧 ID や、接頭辞を変える前の旧 ID でも、いまのプロジェクトが一致する |
| `parent`、`epic` | 祖先の ID、`none` | 親、親の親、…のどれかの ID が一致する。2 つのキーは同じ意味である。移動前の旧 ID や、接頭辞を変える前の旧 ID でも、いまのアイテムが一致する(02、03)。`none` は親がない |
| `blocks`、`blocked_by`、`causes`、`caused_by`、`duplicates`、`duplicated_by`、`relates_to`、`clones`、`cloned_by` | アイテムの ID、`none` | 02 の関連の 9 つの表記と同じ名前のキー(空白を `_` にした綴り)。そのアイテムの関連の一覧に、その表記で相手の ID が出るアイテムに一致する。たとえば `blocked_by:HH-3` は、HH-3 にブロックされているアイテム。`relates_to` は向きがなく、どちら側からでも一致する。`none` は、その表記の見出しが一覧に出ない。削除済みの相手は一覧に出ないので、数えない。移動前の旧 ID や、接頭辞を変える前の旧 ID でも、いまのアイテムが一致する(02、03) |
| `workspace` | ワークスペースの名前、接頭辞 | ワークスペースが一致する |
| `store` | Store の名前 | Store が一致する。Store の名前を変えたときは、保存したビューと、いまの検索のクエリにある `store:旧名` を `store:新名` に書き換える(08) |
| `is` | `blocked`、`overdue`、`invalid`、`deleted`、`overwritten` | `blocked` は終わっていないブロッカーがある(「ブロック中」)、`overdue` は期限切れ(集計の定義)。`invalid` は、08 の診断の「検出する項目」のうち、アイテムを指す行に当たる(ワークスペースとメンバーの設定の問題、設定が指す存在しない値、持ち主のないプロジェクト別のルールは含めない)。診断を実行しなくても、保存された状態で判定する。`deleted` は後述。`overwritten` は、このマシンの受信箱に、そのアイテムを指す未読の「上書き」の通知がある(06)。既読にするか、自分の値に戻すと外れる。結果はマシンごとにちがう。未完了・終了済みは `category:` で書く |
| `has` | プロパティのキー、`sprint`、`release`、`pr` | その値がある。`pr` は PR のリンクがある。チェックのプロパティでは、オンのときだけ「ある」とみなす |
| `points` | 数、`none` | ポイントを比べる。`none` はポイントがない |
| `estimate` | 数(時間)、`none` | 見積もり時間を比べる。`none` は見積もり時間がない |
| `start`、`end` | 日付、`none` | 開始日、終了日を比べる。`none` は日付がない |
| `created`、`updated` | 日付。`none` は書けない | `created` は、アイテムを作った(作成の保存の)日。別のワークスペース・別の Store へ移しても変わらず、複製したアイテムは複製した日になる。`updated` は、最後に変わった日。詳細パネルの履歴の行のうち、実行者が人か自動化のものの、いちばん新しい行の日で、実行者が「GitHub」「同期」の行は使わない。日付は、このマシンの時刻帯の日付。比較演算子が使える。`none` を書くと「created に none は使えません」のエラー |
| ワークスペースで追加したプロパティのキー | 型による(次節) | そのプロパティの値で比べる |
| `sort` | 並べ替えのキー | 一致の判定には使わず、並べ替えにだけ使う(後述) |
| `group` | テーブルの「グループ」の項目 | 一致の判定には使わず、グループ分けにだけ使う(後述) |

`is`・`has` に上の表にない値を書いても、エラーにはならず、何にも一致しない。`-is:foo` のように否定すれば、すべてが残る。

追加したプロパティのキーは、型ごとに次のように比べる。そのキーを持たないワークスペースのアイテムは、一致しない(否定では一致する)。

| 型 | 値の書き方 |
|---|---|
| 単一選択・複数選択 | 選択肢の名前、`none` |
| 数値 | 数。比較演算子が使える。`none` は値がない |
| 日付 | 日付。比較演算子が使える。`none` は値がない |
| ユーザー | ログイン名、`@me`、`none` |
| チェック | `true`、`false`。`false` は、オフのものと未設定のものの両方に一致する |
| テキスト・URL | 語(部分一致)、`none` |

`created` のように組み込みのキーと同じ綴りの追加プロパティが、すでにあるワークスペースでは、検索のキーとしては組み込みの意味を使う。そのプロパティは、テーブルの列とセルでは使え、検索と並べ替えには使えない。新しく作るときは、03 の予約語として断る。

### 比較と日付

`points`、`estimate`、`start`、`end`、`created`、`updated`、数値と日付のプロパティでは、`:`(等しい)のほかに `<`、`<=`、`>`、`>=` が使える。他のキーに比較演算子を書いたときは、`:` と同じに読む。値がないアイテムは、比較には一致しない。たとえば `end<today` は、終了日のないアイテムを含まない。

日付は、次の形で書く。

| 書き方 | 意味 |
|---|---|
| `2026-12-01` | その日 |
| `today` | 今日 |
| `+3d`、`3d` | 今日の 3 日後 |
| `-7d` | 今日の 7 日前 |

日付として読めない値と、数として読めない値は、何にも一致しない。日付の「今日」は、01 のとおりこのマシンの日付である。

### 並べ替え

`sort:priority` で昇順、`sort:-priority` で降順に並べる。`sort:` が効くのは、テーブルの行の並びと、カンバンの列(レーン)の中のカードの並びだけである。ツリーとガントは、階層と並び順のまま動かさない。`sort:` が複数あるときは、最初のものだけを使う。キーは次のとおり。

| キー | 並び |
|---|---|
| `id` | 番号の順 |
| `title` | タイトルの五十音順 |
| `kind` | Epic、Story、Task、Bug、Step の順 |
| `status` | ワークスペースで定めたステータスの順 |
| `priority` | ワークスペースで定めた優先度の順 |
| `assignee` | 担当者の表示名の順 |
| `project` | プロジェクトのタイトルの順 |
| `parent` | 親の ID の順 |
| `sprint`、`release` | 名前の順 |
| `system` | 関連システムの値の順(下記) |
| 追加プロパティ・`start`・`end`・`points`・`estimate` | 値の順(選択は選択肢の定義順、ユーザーは表示名の順) |
| `created` | 作成の時刻の順(古いものが先) |
| `updated` | 最後に変わった時刻の順(古いものが先。`updated` の定義はキーの表のとおり) |

値を複数持つもの(関連システム、複数選択のプロパティ)は、そのアイテムの値を、ワークスペースの定義順に並べ直し、先頭から順に比べる。先頭が同じなら 2 番目を比べ、値の数が少ない方を先にする。降順は、その逆の並びである。選択肢の定義順を使うもの(関連システム、単一選択、複数選択)が複数のワークスペースにまたがるときは、同じ名前の値を 1 つにし、ワークスペースの並び(Store、ワークスペース)の順に、各ワークスペースの定義順で最初に現れた位置の順にする。

値がないアイテムは、昇順でも降順でも最後に置く。値が同じアイテムは、並び順(アイテムが持つ順位。作成したものは末尾に入り、バックログやツリーで並べ替えると変わる)で並べる。`sort:` がないときも、この並び順に従う。並び順も同じ値のアイテムは、作成の保存が早い方を先にし、同じなら内部 ID の辞書順で並べる。複数のワークスペースにまたがるときも、`sort:` や列の見出しで並べ替えたときは、全体を 1 本にしてそのキーの順に並べ、値が同じものだけをサイドバーと同じ順(Store、ワークスペース)、次に並び順で並べる。`sort:` も列の見出しもないときは、サイドバーと同じ順(Store、ワークスペース)にまとめ、ワークスペースの中を並び順で並べる。上の表にないキーを書いても、エラーにはならず、並び順のままになる。

### まとめ方

`group:kind` で、テーブルの行を種類ごとのグループに分ける。書ける項目は、テーブルの「グループ」の設定と同じで、`status`、`assignee`、`project`、`parent`、`kind`、`priority`、`sprint`、`system`、`created`、`updated` である。グループの並びと見出しは、テーブルのグループの節に従う。

「グループ」の設定が「なし」以外のときは、設定が `group:` より優先する。`group:` が複数あるときは、最初のものだけを使う。1 つの `group:` に `,` で複数の値を書いたときも、最初の値だけを使う。キーの前の `-`(`-group:`)と、値の前の `-`(`group:-kind`)は無視する。グループに降順はない。上の項目にない値を書いても、エラーにはならず、グループには分けない。

カンバンでは、スイムレーンの設定が「なし」のときだけ、`group:assignee`・`group:project`・`group:priority` を、それぞれ「担当者」「プロジェクト」「優先度」のスイムレーンとして使う。ほかの値は使わない。ツリーとガントでは、`group:` を使わず、階層と並び順のまま動かさない。

### 候補

絞り込み欄で、次のキーのあとに文字を打つと、欄の下に候補を出す。候補は名前やタイトルで探し、選ぶと、キーのあとに ID などの書き方を入れる。日本語で打っても候補が出る。

| キー | 探す対象 | 候補の表示 | 選ぶと入るもの |
|---|---|---|---|
| `project:` | プロジェクトのタイトルと ID | 「HH-P1 モバイルアプリ刷新」 | `project:HH-P1` |
| `assignee:` | メンバーの表示名とログイン名 | 「田中 美咲 @tanaka」 | `assignee:tanaka` |
| `parent:`・`epic:`、関連の 9 つのキー | アイテムのタイトルと ID | 「HH-12 ログイン画面の改修」 | `parent:HH-12`、`blocks:HH-12` など、書いたキーのまま |
| `workspace:` | ワークスペースの名前と接頭辞 | 「Web HH」 | `workspace:HH` |

- `project:`・`workspace:`・`assignee:` の候補は、その画面の範囲の入れ物(プロジェクト・ワークスペース・メンバー)から出し、アイテムの有無は問わない。範囲は、検索とビューでは表示中のすべての Store、ワークスペースの画面ではそのワークスペース、プロジェクトの画面ではそのプロジェクトのワークスペースである。`parent:`・`epic:`・関連のキーの候補は、範囲のアイテムから出す。どれも削除済みと非表示の Store のものを除いて、10 件まで出す。閲覧のみの Store のものも出す。マイタスクでは、`project:` の候補だけは、マイタスクに出るアイテムがあるプロジェクトに限る。
- ↑↓ で選び、Enter かクリックで入れる。Esc で候補を閉じる(詳細パネルなども開いているときは、候補だけを閉じ、2 回目の Esc で次に閉じるものを閉じる。順は 01)。候補は、欄にフォーカスがあるあいだだけ出る。日本語入力の変換を確定する Enter では入れない(01)。
- 一致するものがないときは、候補を出さない。
- 別の Store に同じ ID のアイテムやプロジェクトがあるときは、候補の頭に Store の点を出して見分けられるようにする。

### エラー

次のときは、絞り込み欄の下にエラーを赤字で出し、一覧は 0 件にする。複数あるときは、1 行ずつ並べる。

| 状況 | 文言 |
|---|---|
| キーのあとに値がない(`status:` や `status:,`) | 「{書いた語}に値がありません」。語は `-` を含めて書いたとおりに出す。たとえば「「-status:」に値がありません」 |
| どのワークスペースにもないキー | 「「{キー}」というキーはありません」 |
| `none` が使えないキーに `none` を書いた(`priority:none`、`created:none`、`updated:none`) | 「{キー} に none は使えません」(たとえば「priority に none は使えません」) |

「どのワークスペースにもない」は、このマシンにあるすべてのワークスペース(非表示の Store を含む)のプロパティを見て決める。キーは小文字にそろえて出す。

### 削除済みを探す

`is:deleted` を書くと、検索の対象が、削除済みのアイテムだけになる。`is:deleted` の語が `,` で複数の値を持っていても、否定でなければ同じである。ほかの語は、その中を絞る。`-is:deleted` は、書かないのと同じである。

対象は、設定の「削除済み」(08)の一覧に行として出るアイテムである。表示中の Store だけで、非表示の Store は含めない。

削除済みの行は、テーブルでだけ出す。薄く出し、「削除済み」のピルと、「あと N 日で完全に削除」(保持日数を過ぎているときは「保持日数を過ぎています」。08)を添える。ステータスのボタン、セル、選択のチェックボックス、アイテムのメニューは無効にし、「すべて選択」にも含めない。タイトルを押すと、設定の「削除済み」を開き、そのアイテムの行を選んだ状態にして、見える位置までスクロールする。復元と完全に削除は、設定の「削除済み」で行う。

ツリー、カンバン、ガントでは、削除済みの行を描かず、本体の代わりに「削除済みのアイテムはテーブルで表示します。」と「テーブルで開く」を出す。「テーブルで開く」は、絞り込みを残してテーブルに切り替える。

### 検索ヘルプ

絞り込み欄の横の「検索ヘルプ」で開く。見出しは「検索ヘルプ」、閉じるボタンは「閉じる」である。最初の説明文は次のとおり。

> 語をスペースで区切ると、すべてに一致するものだけが残ります。`-` を前に付けると否定、`,` で区切るとどれか 1 つに一致します。

そのあとに、次の表を出す。

| 書き方 | 説明 |
|---|---|
| `status:InProgress` | ステータスの名前 |
| `category:done` | ステータスの分類(todo / doing / done / canceled) |
| `kind:story,bug` | 種類(epic / story / task / bug / step) |
| `assignee:@me` / `assignee:none` | 担当者(ログイン名、@me、none) |
| `watching:@me` | ウォッチしている人(ログイン名、@me、none) |
| `mentions:@me` | 説明やコメントで呼ばれている人(ログイン名、@me、none)。いまの本文から探す |
| `system:API` | 関連システムの名前 |
| `priority:high` | 優先度の名前 |
| `sprint:current` / `sprint:none` | スプリント(current / next / none / 名前) |
| `release:v2.0.0` | リリースの名前 |
| `project:HH-P1` | プロジェクトの ID(日本語で打つと候補が出る) |
| `parent:HH-1` | 祖先の ID(親、親の親も含む) |
| `blocked_by:HH-1` / `relates_to:HH-1` | 関連(blocks・blocked_by・causes・caused_by・duplicates・duplicated_by・relates_to・clones・cloned_by)。ブロック中かどうかは `is:blocked`(終わっていないブロッカーがあるもの)で書く |
| `workspace:HH` / `store:team-b` | ワークスペースの名前か接頭辞、Store の名前 |
| `is:blocked` / `is:overdue` | 状態(ブロック中・期限切れ) |
| `is:invalid` | 診断で直せるデータの問題があるもの(理由と直し方は設定の「診断と修復」) |
| `is:deleted` | 削除済みのアイテム(テーブルで表示。復元は設定の「削除済み」) |
| `is:overwritten` | このマシンの受信箱に、未読の「上書き」の通知があるもの |
| `points>=3` / `end<today` / `start>-7d` | 数値と日付の比較(today、+3d、-7d も使用できます) |
| `estimate<=2` | 見積もり時間(時間)の比較 |
| `updated>-7d` / `created:today` | 変更した日、作成した日の比較 |
| `sort:-updated` | 最近変わった順(`created` も使える) |
| `has:end` / `has:pr` | 値があるもの |
| `customer:サンプル` | ワークスペースで追加したプロパティのキー |
| `sort:-priority` | 並び順(- で降順。テーブルとカンバンで使われる) |
| `group:kind` | まとめ方(テーブルとカンバン。項目はテーブルの「グループ」と同じ) |
| `ガント` / `"ガント 表"` | 語だけを書くと、ID・タイトル・説明に含む語。空白を含むときは引用符で囲む |

## 検索

すべての Store のアイテムを、クエリで絞り込んで見る画面である。見出しは「検索」、補足は「すべての Store のアイテムを、条件で絞り込んで見ます」とする。非表示にした Store のアイテムは含めない。

- 画面は、絞り込み欄、レイアウトの切り替え(ツリー・カンバン・テーブル・ガント)、そのレイアウトの設定、件数、「ビューとして保存」のボタンで成り立つ(共通の構成は後述)。
- サイドバーの「検索」から開くと、テーブルで開く。コマンドパレットの「このクエリで」(02)と、設定の「診断と修復」の「検索で開く」(08)から開いたときも、テーブルで開き、絞り込みだけを置き換える(レイアウトの設定と列は変えない)。レイアウトを切り替えても、絞り込みと各レイアウトの設定は残る。
- 絞り込みとレイアウトの設定は、このマシンに残す(01 の画面の状態)。

## 保存したビュー

検索の条件とレイアウトの設定に名前を付けて、このマシンに保存したもの。自分だけのもので、Store には書かず、ほかの人とも、自分の別のマシンとも共有しない(01)。当面この形で使い、共有が要るとわかったら見直す。

### ビューが持つもの

| 持つもの | 内容 |
|---|---|
| 名前 | このマシンのビューの中で重複できない(大文字と小文字を区別しない) |
| レイアウト | ツリー・カンバン・テーブル・ガントのどれか |
| クエリ | 絞り込みの条件 |
| カンバンの設定 | 列の分け方、スイムレーン、列ごとの WIP 制限 |
| テーブルの設定 | 表示する列、グループ、列見出しの並べ替え |
| ガントの設定 | 目盛り、ロードマップの有無 |

クエリには、`group:`、`is:deleted` など、すべてのキーを書ける。ツリーとガントのビューに `sort:` や `group:` があっても、保存はそのままである(画面の構成)。

ツリーには専用の設定がない。ビューが見せるアイテムの範囲は、検索の画面と同じく、表示中のすべての Store である。

ワークスペースやプロジェクトの画面の設定はビューにできない。ビューにできるのは、検索の画面だけである。

ビューは Store を変えないので、保存・名前の変更・複製・削除のどれも、アクティビティに残らない(01)。

### 保存する

検索の画面の「ビューとして保存」で、ダイアログ「ビューとして保存」を開く。

| 項目 | 内容 |
|---|---|
| 名前 | 1 行の入力欄。Enter で保存する |
| 確認の表示 | 「レイアウト: テーブル ・ 条件: `…`」。条件がないときは「(なし)」 |

次のときは保存せず、ダイアログに理由を出す。

| 条件 | 文言 |
|---|---|
| 名前が空(前後の空白を除く) | 「名前を入力してください」 |
| 同じ名前のビューがある(大文字と小文字を区別せず、前後の空白を除いた名前で比べる) | 「同じ名前のビューがあります」 |

保存するとき、表示する列のうち、どのワークスペースにもなくなったプロパティのキーは外す(判定は、ビューの画面の「保存」と同じ)。

保存できたら、トースト「ビュー「{名前}」を保存しました」を出し、そのビューの画面に移る。

### ビューの画面

見出しの上に「保存したビュー」を出す。見出しはビューの名前で、右にメニューのボタンがある。中身は、検索の画面と同じ構成(絞り込み欄、レイアウトの切り替え、設定、件数)である。

ビューを開くと、保存されている内容が画面に載る。そこで、前節の表にあるもの(絞り込み、レイアウト、カンバンの列の分け方・スイムレーン・WIP 制限、テーブルの列・グループ・列見出しの並べ替え、ガントの目盛り・ロードマップ)のどれかを変えると、「未保存の変更」の印が付く。レイアウトを切り替えたときも同じである。この状態では保存されたビューは変わらない。

「未保存の変更」の印がついたときは、見出しの横に、印と「変更を破棄」「保存」を出す。

| 操作 | 動作 |
|---|---|
| 変更を破棄 | 画面の内容を、保存されている内容に戻す。レイアウトも戻る |
| 保存 | 画面の内容を、レイアウトも含めてビューに保存する。トースト「ビューを保存しました」を出す。表示する列のうち、どのワークスペースにもなくなったプロパティのキーは、保存するときに外す(このマシンにあるすべてのワークスペースを、非表示の Store を含めて見る。エラーの節と同じ範囲) |

「未保存の変更」かどうかは、保存されている内容と画面の内容を、中身で比べて決める。設定を変えて元に戻したときは、印は消える。折りたたみと、選択、詳細パネルは、比べる対象に入れない。

未保存の変更は、別の画面に移って戻っても、アプリを閉じて開き直しても残る(このマシンの画面の状態。01)。未保存の変更はビューごとに持ち、名前の変更では引き継ぎ、複製では引き継がず、削除では捨てる。

### ビューのメニュー

| 項目 | 動作 |
|---|---|
| 名前を変更… | 「ビューの名前を変更」のダイアログを開く。空なら「名前を入力してください」、別のビューと同じなら「同じ名前のビューがあります」と断る。自分自身の大文字・小文字だけを変えることはできる |
| 複製 | 保存されている内容(未保存の変更は含めない)を、新しいビューとして作る。名前は「{元の名前} のコピー」で、重複する(比べ方は上と同じ)ときは「{元の名前} のコピー 2」、「… 3」と番号を付ける。作ったビューの画面に移る |
| 削除… | 確認ダイアログ(見出し「ビューを削除」、本文「ビュー「{名前}」を削除します。アイテムは消えません。元に戻せません。」、ボタン「削除」)のあとに削除する |

削除したあと、トースト「ビューを削除しました」を出し、マイタスクに移る。ビューは「削除済み」(08)に入らず、復元もできない。そのビューの未保存の変更(画面の状態)も一緒に捨てる。同じ名前で作り直したビューは別のビューで、未保存の変更は付かない。

ワークスペースを削除しても、そのワークスペースだけを参照するビューは残る。一致するアイテムがなくなるだけである。

## 4 つのレイアウトに共通すること

ツリー・カンバン・テーブル・ガントは、1 つの絞り込み結果を 4 通りに描く。次の画面で使う。

| 画面 | 元になるアイテム | レイアウトの選び方 |
|---|---|---|
| ワークスペースのタブ(ツリー・カンバン・テーブル・ガント) | そのワークスペースのアイテム | タブで選ぶ |
| プロジェクトのタブ(同上) | そのプロジェクトのアイテム | タブで選ぶ |
| 検索 | 表示中のすべての Store のアイテム | 画面内の切り替え |
| 保存したビュー | 表示中のすべての Store のアイテム | 画面内の切り替え(未保存の変更になる) |

### 画面の構成

上から、絞り込み欄、ツールバー、本体の順に並ぶ。

- 絞り込み欄: 入力に合わせて絞り込む。薄い文字で「絞り込み 例: assignee:@me status:InProgress system:Web」と案内する。右に「検索ヘルプ」がある。`/` を押すと、この欄に移る(01)。
- ツールバー: 左から、レイアウトの切り替え(検索とビューだけ)、そのレイアウトの設定、件数「{N} 件」、画面ごとの操作(検索の「ビューとして保存」など)。
- エラー: 書き方に誤りがあるときは、ツールバーの下に赤字で出し、本体は 0 件の表示にする。
- 注記: ツリーかガントを開いていて、絞り込み欄に `sort:` か `group:` があるときは、エラーとは別に、欄の下に灰色で、書いたキーに合わせて「ツリー・ガントでは sort: は使われず、並び順のままです」「ツリー・ガントでは group: は使われず、並び順のままです」「ツリー・ガントでは sort: と group: は使われず、並び順のままです」のどれかを出す。カンバンを開いていて、`group:` の値が担当者・プロジェクト・優先度のどれでもなく、スイムレーンの設定が「なし」のときは、同じ位置に灰色で「カンバンでは group: は担当者・プロジェクト・優先度だけ使われます」と出す。ビューのクエリに `sort:` や `group:` があって、ツリーに切り替えても、保存はそのまま。
- 人の表示: 担当者やオーナーなど人を出す箇所で、その人が Store のメンバーにいないときは「不明なユーザー」と出す(01)。

件数は、そのレイアウトで行やカードとして出るアイテムのうち、絞り込みに一致したものの数である。ツリーとガントで祖先として薄く出る行は数えない。カンバンは、Step を出していないときは Step を数えない。ガントは Step を出さないので、数えない。

### Store をまたぐ画面の同じ ID

検索と保存したビューは複数の Store をまたぐ。接頭辞は Store の中でしか一意でないため、同じ ID のアイテムが別の Store に並ぶことがある。そこで、ツリー・カンバン・テーブル・ガントのアイテムとプロジェクトの行・カードには、Store の点(Store の色)を添える(マイタスクの行と同じ)。クエリで ID を書いたとき(`project:`・`parent:`・`epic:`、自由な語)は、同じ ID があるすべてのアイテムに一致する。

### 画面の状態

画面ごとの状態として、絞り込みと、レイアウトの設定を持つ。このマシンに残す(01 の画面の状態)。保存にもアクティビティにも残らない。

| レイアウト | 設定 |
|---|---|
| ツリー | なし |
| カンバン | 列の分け方(ステータス / ステータスの分類)、スイムレーン、列ごとの WIP 制限 |
| テーブル | 表示する列、グループ、列見出しの並べ替え |
| ガント | 目盛り(日・週・月)、ロードマップの有無 |

スプリントのタブの実行中のカードにあるボード(05)は、絞り込みと、列の分け方・スイムレーン・列ごとの WIP 制限を持つ。ワークスペースごとに別の状態で、カンバンのタブとは独立している。

ワークスペースの画面とプロジェクトの画面は、ワークスペースごと、プロジェクトごと、タブごとに別の状態を持つ。たとえば、あるワークスペースのカンバンで絞り込んでも、同じワークスペースのテーブルや別のワークスペースのカンバンには影響しない。保存したビューでは、画面の状態が保存された内容と比べられる(前節)。

折りたたみ(ツリーの行、ガントの行、カンバンのスイムレーン)も、画面ごとに覚える。同じワークスペースのツリーとガントで、同じ Epic を別々に開閉できる。

### 閲覧のみの Store のアイテム

01 の規則のとおり、閲覧のみの Store のアイテムは表示するが、編集の手段をすべて無効にする。このレイアウトでは、次のものが無効になる。

- ステータスのボタン、カンバンのドラッグ、テーブルのセル、ツリーのドラッグ、ガントのドラッグ、「日付を入力」、行の「+」、アイテムのメニューの変更系の項目(「詳細を開く」と「ID をコピー」は使える)
- 無効にしたものには、「閲覧のみの Store です」と添える

Store に書かないものは、無効にしない。折りたたみ、テーブルの列見出しの並べ替え、カンバンの WIP 制限(「列の設定」)、絞り込みとレイアウトの設定、選択は、閲覧のみの Store のアイテムでも使える。ガントのバーは、ドラッグだけを無効にし、3 ピクセル未満のクリックは、詳細パネル(プロジェクトならプロジェクトの概要)を開く。

画面に閲覧のみの Store のアイテムが含まれるときは、01 の帯「{Store 名} は閲覧のみの Store です。閲覧はできますが、作成・変更・削除はできません。」を、画面の上部に出す。ワークスペースとプロジェクトの画面は、01 のとおりアイテムがなくても出す。マイタスク、検索、保存したビューでは、一覧に閲覧のみの Store のアイテムが 1 件でも含まれるときに、その Store ごとに 1 本出す。

### ドラッグの代わりの経路

ドラッグでできる操作は、マウスとタッチの両方で動く(01)。この文書のドラッグには、それぞれメニューかセレクトで同じことができる経路がある。

| ドラッグ | 同じことができる経路 |
|---|---|
| ツリーで子にする、プロジェクトの直下に置く | アイテムのメニューの「移動…」(02) |
| ツリーで兄弟の順を変える | アイテムのメニューの「上へ移動」「下へ移動」 |
| カンバンで列を変える | ステータスのボタン(ステータスのメニュー) |
| カンバンでレーンを変える(担当者・優先度) | 詳細パネルとテーブルのセル |
| ガントで日付を動かす | テーブルのセルと詳細パネルの日付 |
| サイドバーの並べ替え | メニューの「上へ移動」「下へ移動」 |

## ツリー

プロジェクト、Epic、Story・Task・Bug、Step を、親子の入れ子で見せる。

### 行

- 並び: 検索とビューでは、ワークスペースとプロジェクトをサイドバーと同じ順に並べる。ワークスペースの見出し(ワークスペースを限定しない画面だけ。Store のバッジとワークスペース名)、プロジェクト、Epic、Story・Task・Bug、Step の順に入れ子にする。兄弟の並びは、アイテムの並び順に従う。バックログやスプリントの順位(05)と同じ並びで、順位が同じものは、作成の保存が早い方を先にし、同じなら内部 ID の辞書順で並べる。
- プロジェクトの行: 開閉の矢印、プロジェクトのアイコン、タイトル(押すとプロジェクトの概要を開く)、ステータス、オーナー、進捗、「Epic を追加」の「+」、メニューのボタン。プロジェクトの画面では、プロジェクトの行は出さず、Epic を一番上の階層に並べる。
- アイテムの行: 開閉の矢印(子があるとき)、種類のアイコン、ID、タイトル(押すと詳細パネルを開く)、「ブロック中」(終わっていないブロッカーがあるとき)、Step の進捗「完了/対象」(Epic 以外で子があるとき。集計の定義)、期限、ポイント、ステータスのボタン、担当者、子を追加する「+」、メニューのボタン。
- 「+」は、その行の下に置ける最初の種類を作る。プロジェクトの行は Epic、Epic の行は Story、Story・Task・Bug の行は Step である。作成のダイアログは 02。Step の行には「+」がない。
- メニュー: アイテムのメニュー(02)に、「上へ移動」「下へ移動」を加えたもの。この 2 つは、同じ親の下の兄弟の間で動かす。絞り込み中は、画面に見えている兄弟の間で動かす。「上へ移動」は見えている直前の兄弟のすぐ前に、「下へ移動」は見えている直後の兄弟のすぐ後ろに置き、見えていない兄弟は動かさない(たとえば並びが HH-3・HH-4・HH-5・HH-7・HH-9 で HH-4 と HH-7 が見えていないとき、HH-5 の「上へ移動」で並びは HH-5・HH-3・HH-4・HH-7・HH-9 になる)。見えている兄弟の先頭の行は「上へ移動」を、末尾の行は「下へ移動」を無効にする(見えていない兄弟が先にあっても無効)。テーブルの行のメニューも、その画面に見えている兄弟の間で動かす。プロジェクトの行のメニューは、「開く」「Epic を追加」「名前を変更…」「削除…」に、同じ「上へ移動」「下へ移動」を加えたもの(並びは、サイドバーと共通)。

### 絞り込んだとき

一致したアイテムと、その祖先を出す。一致しない祖先の行は薄く出す。クエリがあるときは、一致するアイテムを含まないプロジェクトを隠す。

### 空のとき

| 状況 | 表示 |
|---|---|
| プロジェクトが 1 件もない | 「プロジェクトはまだありません」と、「ワークスペースにプロジェクトを作ると、ここに Epic・Story・Task・Bug・Step の木が並びます。」。ワークスペースの画面では「プロジェクトを作成」を添える |
| 行が 0 件 | 絞り込み中は「一致するものはありません」と「絞り込みを変えてみてください。」、そうでなければ「まだ何もありません」。プロジェクトの画面では「Epic を作成」を添える |

プロジェクトの画面では、末尾に「Epic を追加」のボタンを置く。

### ドラッグ

行をドラッグして、別の行にドロップする。ドロップした位置で、動作が変わる。

| ドロップする位置 | 動作 |
|---|---|
| 行の中央 | ドロップした行の子にする。プロジェクトの行に Epic をドロップすると、そのプロジェクトの直下に置く |
| 行の上端 | ドロップした行の直前に、兄弟として入れる |
| 行の下端 | ドロップした行の直後に、兄弟として入れる |

行を高さで上・中・下の 3 つに等しく分ける。兄弟として入れるときは、ドロップした行と同じ親の下に入る。親が変わるときは、子にするときと同じ規則を使う。ドロップして位置を決めて移したときは、その位置に入る。位置を決めない移動(メニューの「移動…」)と作成は、親の子の末尾に入る(02)。

次のときは、何も変えずに理由を表示する。

| 条件 | 文言 |
|---|---|
| ドロップ先の親に、その種類を置けない | 「{種類} は {種類} の下に置けません」(たとえば「Story は Task の下に置けません」) |
| 別のワークスペースの行にドロップした | 「別のワークスペースには移せません。移動はメニューの「移動…」から」 |
| プロジェクトの行に、Epic 以外をドロップした | 「プロジェクトの直下には Epic だけを置けます」 |
| 自分自身の上にドロップした | 何も起こさない |
| ドロップしても親も位置も変わらない | 何も起こさない |

親が変わった移動は 1 回の保存になる。トーストは子にしたとき「{ID} を {ID} の下に移動しました」、プロジェクトに置いたとき「{ID} を {プロジェクト名} に移動しました」である。アクティビティには「{ID} を {ID} の下に移動」「{ID} を {プロジェクト名} に移動」と残る。同じ親の下で順だけを変えたときは、トーストを出さず、アクティビティに「{ID} の順位を変更」と残る。

プロジェクトが変わる移動(別のプロジェクトのアイテムの子にする、別のプロジェクトの行に置く)で、移動先のプロジェクトが使わないステータスのアイテムがあるときは、ドロップのあとに、メニューの「移動…」と同じ確認ダイアログ(見出し「ステータスの置き換え」。02「同じワークスペースの中での移動」)を出す。「移動」を押すまで移さず、「キャンセル」では何も変えない。

### ツリーのキー操作

ツリーは、キーボードだけでも使える。ツリーは Tab で入る 1 つのフォーカス先で、中の行は矢印で動かす。Tab・Shift+Tab は、ツリーの中でも、ツリーを出て前後の部品へ移すために使う(ブラウザの通常のフォーカス移動)。このキー操作は、ツリーのレイアウトがあるすべての画面(ワークスペース、プロジェクト、検索、保存したビュー)で同じである。

フォーカスのある行は、行全体を囲む枠で示す(行の選択ではない)。対象は、プロジェクトの行とアイテムの行(一致せず薄く出した祖先の行を含む)で、ワークスペースの見出しは対象にしない。ツリーに入ったときは、先頭の行にフォーカスが付く。フォーカスは保存しない。保存したビューの「未保存の変更」の比べる対象にも入れない。フォーカスのある行が、絞り込みや、削除・移動(同期や、別のブラウザのタブ・別のプログラムの保存によるものを含む)で見えなくなったときは、次の見えている行に、なければ前の見えている行に移す。行がなくなれば、フォーカスはない。

| キー | アイテムの行 | プロジェクトの行 |
|---|---|---|
| ↑ ↓ | 見えている前・次の行へ動かす。端で止まる(回り込まない) | 同じ |
| → | 閉じていて子があれば開く。開いていれば最初の子へ。子がなければ何もしない | 同じ |
| ← | 開いていれば閉じる。閉じていれば親の行へ。その画面の一番上の階層の行では何もしない | 開いていれば閉じる。閉じていれば何もしない |
| Enter | 詳細パネルを開く(タイトルを押したのと同じ) | プロジェクトの概要を開く(タイトルを押したのと同じ) |
| Ctrl+Enter(Cmd+Enter) | その行の詳細パネルを、新しいブラウザのタブで開く(タイトルを Ctrl+クリックしたのと同じ。01) | プロジェクトの概要を、新しいブラウザのタブで開く |
| Space | 完了と未着手を切り替える。分類が完了でなければ完了の既定のステータスに、完了なら未着手の既定のステータスにする(03)。遷移の制約に反するときは、何も変えず、02「ステータスの変更」の文言をエラーとして表示する | 何もしない |
| S | ステータスのメニューを開く(02) | 何もしない |
| K | 「種類を変更…」を開く(02)。Epic は何もしない | 何もしない |
| Alt+↑、Alt+↓ | メニューの「上へ移動」「下へ移動」と同じ(絞り込み中は見えている兄弟の間) | プロジェクトのメニューの「上へ移動」「下へ移動」と同じ |
| Alt+Shift+↑、Alt+Shift+↓ | 前の親の下へ、次の親の下へ移す(下) | 何もしない |
| C | その行の兄弟として、同じワークスペース・プロジェクト・親・種類で作成ダイアログを開く(02) | その行の下に Epic を作る作成ダイアログを開く |
| メニューキー、Shift+F10 | 行のメニューを開く | 同じ |

キーで行う書き込み(Space、S、K、Alt+↑↓、Alt+Shift+↑↓、C)は、同じ働きをするボタン・メニューの項目が無効なときは、何も起こさない。トーストも出さない(01 の「閲覧のみの Store」)。Enter、Ctrl+Enter、矢印、メニューキーは、閲覧のみの Store の行でも使える。入力欄の中とダイアログを開いているあいだは、これらのキーは使えない。メニューを開いているあいだは、キーをメニューが受ける。

Alt+Shift+↑↓ は、親を変える。移す先は、02「同じワークスペースの中での移動」の「移動…」の候補のうち、いま見えている行にあるものである。フォーカスのある行から上(Alt+Shift+↑)または下(Alt+Shift+↓)へ見える行を順にたどり、最初に見つかった候補を新しい親にする。自分の子孫の行は飛ばす。見つからなければ何もしない。移した結果は「移動…」と同じで、新しい親の子の末尾に入り、アクティビティ・履歴・トーストも同じである。プロジェクトが変わり、移動先のプロジェクトが使わないステータスのアイテムがあるときは、「移動…」と同じ確認ダイアログ(「ステータスの置き換え」)を出し、「移動」を押すまで移さない。新しい親が閉じていれば開き、動かした行にフォーカスを置く。たとえば、Epic HH-2 の下の HH-5(Task)で Alt+Shift+↓ を押すと、HH-2 の次に見える Epic HH-8 の子の末尾に HH-5 が入る。

Alt+↑↓ と Alt+Shift+↑↓ を続けて押したときは、押した回数だけ 1 回ずつ順に実行する。途中で断られたとき、ほかのキーを押したとき、画面を移ったときは、待っている分を捨てる。

## カンバン

アイテムをカードにして、ステータスごとの列に並べる。

### カード

- 表示するのは、Epic・Story・Task・Bug である。Step は、クエリに、否定でない `kind:` の条件があり、その値に `step` が含まれるときだけ出す(たとえば `kind:step` や `kind:story,step`)。`-kind:step` では出さない。
- ステータスや優先度の値がワークスペースの一覧にないとき(復元などで残った削除された値)は、カードの現在値に「(削除された値)」と薄い字で出す(01)。
- カードには、種類のアイコン、ID、優先度、ステータスの変更ボタン(「ステータスを変更」。ステータスのメニュー)、タイトル(押すと詳細パネルを開く)、親(ID とタイトル)、関連システム、期限、「ブロック中」、ポイント、担当者を出す。

### 列

「列」の設定で、列の分け方を選ぶ。初めは「ステータス」である。

| 分け方 | 列 |
|---|---|
| ステータス | 対象のワークスペースにあるステータスの名前ごとに 1 列。複数のワークスペースに同じ名前があれば 1 列にまとめ、最初に見つかったものの色と分類を使う |
| ステータスの分類 | 「未着手」「進行中」「完了」「中止」の 4 列 |

ステータスが対象のワークスペースの一覧にないカードは、「ステータス」の分け方では、列の右端に「(削除された値)」の列を作って入れる(カードがあるときだけ。件数と WIP 制限は他の列と同じ)。「ステータスの分類」の分け方と集計では、未着手として扱う(05)。

対象のワークスペースは、ワークスペースの画面ではそのワークスペース、プロジェクトの画面ではそのプロジェクトのワークスペース、検索とビューでは、表示中の Store のすべてのワークスペースである。検索とビューの列は、絞り込みの結果に関わらず、これらのワークスペースのステータス名を合わせたものにする。列の並びは、ワークスペースの並び(Store、ワークスペース)の順に、各ワークスペースのステータスの定義順に並べる。ワークスペースが 1 つもないときは、ステータスの分類の 4 列を出す。

プロジェクトの画面では、そのプロジェクトで使わないステータス(03 の「プロジェクト別のルール」)の列を出さない。使わないステータスのアイテムがあるときだけ、そのステータスの列を元の位置に出し、見出しに「使わない」の印を付ける。件数と WIP 制限は他の列と同じである。ワークスペースの画面、検索、ビューの列は変えない。「ステータスの分類」の分け方も変えない。

### スイムレーン

「スイムレーン」の設定で、カードを横に分ける。初めは「なし」である。

| スイムレーン | レーン | レーンの名前 |
|---|---|---|
| なし | 分けない | なし |
| 担当者 | 担当者ごと | 表示名。担当者のないカードは「未割り当て」。Store のメンバーにいない人は「不明なユーザー」(01) |
| プロジェクト | プロジェクトごと | プロジェクトのタイトル |
| Epic | Epic ごと | 「{ID} {タイトル}」。Epic の下にないカードと、Epic 自身のカードは「Epic なし」 |
| 優先度 | 優先度の名前ごと(複数のワークスペースで同じ名前なら 1 つ) | 優先度の名前 |

レーンは名前の五十音順に並べ、「なし」に当たるレーンは最後に置く。レーンの見出しには、開閉の矢印、名前、レーンのカードの数を出す。レーンを閉じると、そのレーンの各列を隠す。見出しの件数と、列の見出しの件数は、閉じていても変わらない。

絞り込み欄の `group:assignee`・`group:project`・`group:priority` は、スイムレーンの設定が「なし」のときだけ、それぞれのスイムレーンとして働く。設定が「なし」以外のときは、設定を使う。

### WIP 制限

列の見出しの右のボタン(「列の設定」)で、その列に置けるカードの上限を決める。

| 項目 | 内容 |
|---|---|
| ダイアログ | 見出し「WIP 制限」、ラベル「この列に置けるカードの上限(空にすると制限なし)」、ボタン「設定」 |
| 入力 | 空か数字。それ以外は「数字で入力してください」と断る |
| 空か `0` | 制限をなくす |

列の見出しには「{件数} / {上限}」を出す。件数は列全体のカードの数で、スイムレーンで分けても、閉じても、列の合計である。件数が上限を超えると警告の色にする。上限を超えても、カードを置けなくはしない。

上限は、列の分け方ごとに、列の名前で持つ。「ステータス」の列の上限と、「ステータスの分類」の列の上限は別である。ステータスの名前を変えたときは、03 の「値の編集」の規則で、上限を新しい名前に付け替える。新しい名前にすでに上限があるときは、新しい名前の上限を残し、旧い名前の上限は捨てる。旧い名前のステータスがほかに残っているかは、このマシンに追加してあるすべての Store(非表示を含む)のワークスペースで見て、残っていれば付け替えない。保存したビューの上限にも同じ規則を使う。上限はカンバンの設定の一部なので、保存したビューでは保存した内容に含まれ、ワークスペースやプロジェクトの画面ではこのマシンだけに残る(前節の画面の状態)。WIP 制限の変更は、保存にもアクティビティにも残らない。

### ドラッグ

カードをドラッグして、列(とレーン)にドロップする。

- ステータスの決め方は、列の分け方による。「ステータス」では、ドロップした列と同じ名前のステータス(そのカードのワークスペースにあるもの)にする。「ステータスの分類」では、カードがいまそのステータスの分類にいるならいまのステータスのままにし、違うなら、そのカードのワークスペースで、ドロップした分類の既定のステータス(03)にする。
- そのカードのワークスペースに同じ名前のステータスがないときは、何も変えずに「{ワークスペース名} にはこのステータスがありません」と表示する。
- スイムレーンが「担当者」か「優先度」のとき、別のレーンのセルにドロップすると、ステータスに加えて、担当者か優先度も、そのレーンの値に変える。「未割り当て」のレーンなら、担当者を空にする。そのカードのワークスペースに同じ名前の優先度がないときは、何も変えずに「{ワークスペース名} には優先度「{名前}」がありません」と表示する。担当者のレーンの人が、そのカードの Store のメンバーにいないときは、何も変えずに「{名前} は {Store 名} のメンバーにいません」と表示する。
- スイムレーンが「プロジェクト」か「Epic」のときは、レーンを変えられない。ドラッグ中は、同じレーンの列だけをドロップできる場所として強調し、別のレーンのセルにドロップしたときは、何も変えずに「プロジェクト(Epic)を変えるときは、メニューの「移動…」から」と表示する。
- 遷移が禁じられているときは、02 の規則で断る。
- カードのプロジェクトが使わないステータスの列へドロップしたときは、何も変えずに「このプロジェクトでは「{ステータス}」を使いません」と表示する。
- 何も変わらないドロップのしかた(同じ列・同じレーンなど)は、何も保存しない。
- 変えられるときは 1 回の保存になる。アクティビティには「{ID} をボードで移動」と残る。トーストは出さない。担当者を「あなた」以外の人に変えたときは、新しい担当者に「割り当て」の通知が出る(06)。

### 空のとき

カードが 0 件でクエリも空なら、「カードはまだありません」と「Story・Task・Bug を作ると、ステータスごとの列に並びます。」を出し、「作成」を添える。クエリがあって 0 件のときは、メッセージを出さず、空の列だけを並べる。空の列には「ここにドラッグ」と出す。

## テーブル

アイテムを 1 行にして、列で見せる。

### 列

固定の列は次の 17 個である。ID、種類、タイトル、ステータス、担当者、優先度、開始日、終了日、ポイント、見積もり時間、関連システム、スプリント、リリース、プロジェクト、親、作成日、更新日。

これに、対象のワークスペースで追加したプロパティを足す。対象のワークスペースは、ワークスペースの画面ではそのワークスペース、プロジェクトの画面ではそのプロジェクトのワークスペース、検索とビューでは表示中の Store のすべてのワークスペースである。

- 列の名前は、ワークスペースで付けた名前を使う。複数のワークスペースで名前が違うときは、固定の列は標準の名前(上の表)、追加した列はプロパティのキーを出す。
- 同じキーのプロパティは、型が違っても 1 つの列にまとめる。型は最初に見つかったものを使う。
- 初めに出す列は、ID、タイトル、ステータス、担当者、優先度、終了日、ポイントである。
- 「表示する列」のメニューで、列を出したり隠したりする。タイトルは隠せない。メニューは、1 つ選んでも開いたままである。新しく出した列は右端に付く。列の並びを入れ替える操作はない。
- 存在しないプロパティの列は、表示しない。

### 並べ替え

列の見出しを押すと、「昇順(↑)」「降順(↓)」「並べ替えなし」の順に切り替わる。値のないアイテムは、昇順でも降順でも最後に置く。値が同じアイテムは、並び順で並べる。関連システムの列は、前述の並べ替えの規則(複数の値は、定義順に並べ直して先頭から比べる)で並べる。作成日・更新日の列は時刻の順である。

列見出しの並べ替えは、クエリの `sort:` より優先する。クエリに `sort:` があるときも、列見出しで並べ替えていれば、そちらで並べる。どちらもないときは、並び順で並べる。列見出しの並べ替えは、テーブルの設定として、このマシンの画面の状態に残る。保存したビューでは、保存した内容に含まれ、「未保存の変更」の比較の対象になる。

### グループ

「グループ」の設定で、行をグループに分ける。初めは「なし」である。設定が「なし」のときは、絞り込み欄の `group:` を使う(前述)。

| グループ | まとめる単位 | 値がないときの見出し |
|---|---|---|
| ステータス | ステータスの名前(複数のワークスペースで同じ名前なら 1 つ) | なし |
| 担当者 | 担当者(Store のメンバーにいない人は「不明なユーザー」。01) | 未割り当て |
| プロジェクト | プロジェクト | なし |
| 親 | 親のアイテム。見出しは「{ID} {タイトル}」 | 親なし |
| 種類 | 種類 | なし |
| 優先度 | 優先度の名前 | (優先度は必ずあるので、空のグループはない) |
| スプリント | スプリント | スプリントなし |
| 関連システム | 関連システムの値ごと。1 件のアイテムが複数の値を持つときは、それぞれのグループに入る(複数のワークスペースで同じ名前なら 1 つ) | 関連システムなし |
| 作成日 | 作成した日(このマシンの時刻帯の日付)。見出しは日付 | (必ず値があるので、空のグループはない) |
| 更新日 | 最後に変わった日(`updated` の定義はキーの表のとおり)。見出しは日付 | (同上) |

グループの並びは、並べ替えたあとの行に最初に現れた順である。ステータスの定義順や優先度の順位では並べない。1 件のアイテムが複数のグループに入るとき(関連システム)は、そのアイテムの値を定義順に並べ、その順に、まだないグループを作る。グループ分けをしたときは、見出しの行に名前と件数を出す。複数のグループに入るアイテムは、それぞれの見出しの件数に数える(件数の合計がアイテムの数を超えることがある)。ツールバーの件数、「{N} 件を選択中」、「すべて選択」は、アイテムを 1 回ずつ数える。同じアイテムの行は、どの見出しの下でも同じ選択の状態になる。

### セル

| 列 | 動作 |
|---|---|
| ID、種類、プロジェクト、親 | 表示だけ。親は、押すと親の詳細パネルを開く |
| 作成日、更新日 | 表示だけ。01 の相対時間で出す(たった今、N 分前、N 時間前、N 日前。7 日以上は日付)。「更新日」の見出しにポインターを置くと「GitHub と同期による変更は含みません」と出す |
| タイトル | 押すと詳細パネルを開く |
| ステータス | ボタン。ステータスのメニューを開く(02 の規則) |
| 優先度 | ボタン。メニューに「なし」は置かない。選択肢が 7 件以上のときは、検索欄を出す |
| 単一選択 | ボタン。メニューの先頭は「なし」。選択肢が 7 件以上のときは、検索欄を出す |
| 担当者、ユーザー | セレクト。「未割り当て」と、Store のメンバー(あなたには「(あなた)」を添える)。いまの値の人がメンバーにいないときは「不明なユーザー」と出す(01) |
| 日付 | 日付の入力欄 |
| 数値(ポイント・見積もり時間を含む) | 数値の入力欄。空にすると値を消す |
| チェック | チェックボックス |
| 複数選択、関連システム | ボタン。メニューで複数を選ぶ(1 つ選んでも開いたまま。選択肢が 7 件以上のときは検索欄を出す) |
| URL | リンクの表示だけ。編集は詳細パネルで行う |
| テキスト | 入力欄。前後の空白を除いて保存し、空にすると値を消す |
| スプリント | Story・Task・Bug だけにセレクトを出す(それ以外の種類は空)。選択肢は「バックログ」と、完了していないスプリント、そのアイテムが現在入っている完了済みのスプリント |
| リリース | Step 以外にセレクトを出す。選択肢は「なし」と、アーカイブしていないリリース、そのアイテムが現在入っているアーカイブ済みのリリース |

その種類で使わないプロパティのセルは「—」と出し、編集できない。値がワークスペースの一覧にないとき(削除された値)は、セルの現在値に「(削除された値)」と薄い字で出す(01)。押すと選択肢が開き、選び直せる。メニューに「(削除された値)」の項目は足さない。値を変えたときは、1 回の保存になる。アクティビティには「{ID} の{プロパティ名}を {値} に変更」と残る(スプリントとリリースは「{ID} の スプリント を {名前} に変更」のように書く。値のないときは、スプリントは「バックログ」、リリースは「なし」と書く)。トーストは出さない。値が変わらなければ、何も保存しない。開始日と終了日の順が逆になる入力は、01 の「終了日は開始日以降にしてください」で断る。ポイントなどの値の検査は 02 に従う。担当者を「あなた」以外の人に変えたときは、新しい担当者に「割り当て」の通知が出る(06)。

### 選択

行の末尾に「…」のメニューを置く(中身は 02 のアイテムのメニュー)。行の先頭のチェックボックスで、行を選ぶ。見出しの行のチェックボックス(「すべて選択」)は、並べ替えたあとの全アイテム(グループの見出しは除く。同じアイテムが複数のグループに出るときは 1 回)を選ぶ。選ぶと「一括選択と一括変更」のバーが出る(後述)。

### 空のとき

絞り込み中は「一致するものはありません」と「絞り込みを変えてみてください。」、そうでなければ「まだ何もありません」と「作成」のボタンを出す。

## ガント

アイテムの期間を、時間の軸に帯(バー)で描く。

### 行

プロジェクト、Epic、Story・Task・Bug の入れ子で並べる。Step は常に出さない。一致したアイテムと、その祖先を出し、一致しない祖先の行は薄く出す。クエリがあるときは、一致するアイテムを含まないプロジェクトを隠す。プロジェクトの画面では、プロジェクトの行は出さず、Epic を一番上の階層に並べる。

検索とビューでも、ワークスペースとプロジェクトはサイドバーと同じ順に並べ、ワークスペースの見出しは出さない。左の列(「名前」)に、各行の名前を出す。プロジェクトの行は、開閉の矢印、アイコン、タイトル(押すとプロジェクトの概要を開く)である。アイテムの行は、Step 以外の子があるときの開閉の矢印、種類のアイコン、ID、タイトル(押すと詳細パネルを開く)である。行の開閉は画面ごとに覚える。

「ロードマップ(プロジェクトと Epic のみ)」を入れると、Epic より下のアイテムの行を出さない。開閉の矢印も出ない。

### バーの期間

行ごとに、次の順で、最初に決まったものを使う。

| 順 | 対象 | 条件 | 期間 | バーの種類 |
|---|---|---|---|---|
| 1 | プロジェクト | 開始日と終了日の両方がある | その期間 | 実線。ドラッグできる |
| 2 | プロジェクト | 片方でも欠ける | 下のすべてのアイテム(Step を含む)の開始日と終了日の最小から最大まで。日付が 1 つもなければバーなし | 点線 |
| 3 | アイテム | 開始日と終了日の両方がある | その期間 | 実線。ドラッグできる |
| 4 | アイテム | 片方だけがある | その 1 日分 | 実線。ドラッグできる |
| 5 | アイテム | 日付がなく、スプリントに入っていて、そのスプリントに期間がある | スプリントの期間 | 破線 |
| 6 | アイテム | 日付がなく、下のアイテム(Step を含む)に日付がある | 下のアイテムの開始日と終了日の最小から最大まで | 点線 |
| 7 | アイテム | どれにも当たらない | バーなし | |

バーは終了日の日を含む。幅は 1 日分より短くならない。バーの色は、アイテムのステータスの色、プロジェクトのステータスの色である。完了のアイテムは、完了の見た目にする。中止のアイテムは、特別な見た目にしない。バーにポインターを置くと、「{タイトル}: {開始日} 〜 {終了日}」を出す。点線のバーは末尾に「(子の日付から)」、破線のバーは「(スプリントの期間)」を添える。

### 「日付を入力」

アイテムの行で、開始日と終了日のどちらかが空のときに出す。バーがない行では今日の位置に、バーがある行ではバーの右隣に置く。プロジェクトの行には出さない(プロジェクトの期間は 02 の概要で入力する)。押すと、空の日付だけを次のように埋める。

| いまの日付 | 押したあとの日付 |
|---|---|
| どちらも空 | 開始日が今日、終了日が今日の 2 日後 |
| 開始日だけ | 終了日が開始日の 2 日後 |
| 終了日だけ | 開始日が終了日の 2 日前 |

1 回の保存になり、アクティビティに「{ID} の日付を設定」と残る。トーストは出さない。

### 表示範囲と目盛り

横軸の範囲は、描くバーのうち一番早い開始日と今日のうち早いほうの 7 日前から、一番遅い終了日と今日のうち遅いほうの 14 日後までとする。バーが 1 本もないときは、今日の 14 日前から 30 日後までとする。その画面を最初に開いたとき(アプリを起動して最初、別のワークスペース・プロジェクト・ビュー・検索を開いたとき)は、今日の線が中央に見える位置に動く。同じワークスペース・プロジェクトの別のタブへ移って戻ったときは、移る前の位置を保つ。アプリを閉じると忘れる(画面の状態には保存しない)。「日」「週」「月」を切り替えたときと、絞り込みで描く範囲が変わったときは、いま中央にある日付を中央のままにする。日付が変わったら今日の線を引き直す(位置は動かさない)。

「日」「週」「月」の目盛りを選ぶ。初めは「週」である。

| 目盛り | 見え方 |
|---|---|
| 日 | 1 日ごとに目盛りと日付(「5/12」)を出す。土日は背景を変え、月曜を強調する。1 日の幅が最も広い |
| 週 | 月曜ごとに目盛りと日付を出す。範囲の左端は、その週の月曜に合わせる |
| 月 | 1 日ごとに目盛りと「2026/5」の形の年月を出す。範囲の左端は、その月の 1 日に合わせる。1 日の幅が最も狭い |

今日の日付には縦の線を引き、ポインターを置くと「今日」と出す。日付はすべてこのマシンの日付である(01)。

### ドラッグ

実線のバー(期間が自分の日付で決まるもの)だけ、ドラッグできる。点線と破線のバーは動かせない。

| 掴む場所 | 変わるもの |
|---|---|
| バーの本体 | 開始日と終了日を、同じ日数だけ動かす |
| 左端 | 開始日だけ |
| 右端 | 終了日だけ |

動く日数は、動かした幅を 1 日の幅で割って四捨五入したものである。月の目盛りでは 1 日の幅が狭いので、細かくは動かせない。動かしている間は、1 日の位置にそろえて表示する。0 日なら何も変えない。動かした幅が 3 ピクセル未満のときは、ドラッグではなくクリックとして扱い、アイテムなら詳細パネルを、プロジェクトならプロジェクトの概要を開く。

ガントのドラッグで日付が逆転するときの文言は、入力欄の文言(01 の「終了日は開始日以降にしてください」)とは別にする。ドラッグは入力ではなく、動かせないことを伝えるためである。

- アイテム: 日付が片方しかないときは、その日を 1 日のバーとみなして動かし、動かしたあと両方の日付を入れる。終了日が開始日より前になるときは、何も変えずに「終了日が開始日より前になるため、動かせません」と表示する。1 回の保存になり、アクティビティには「{ID} の日付を {開始日}〜{終了日} に変更」と残る。
- プロジェクト: 開始日と終了日の両方があるときだけドラッグできる。終了日が開始日より前になるときは、アイテムと同じ文言で断る。1 回の保存になり、アクティビティには「{プロジェクト名} の期間を変更」と残る。変更前後の日付は、プロジェクトの履歴にも残る(02)。
- どちらもトーストは出さない。

### 警告

バーの上に、警告を一覧で出す。押すと、そのアイテムの詳細パネルを開く。ガントに行として出ているアイテムだけが対象で、折りたたんだ行や、ロードマップで出していない行は対象にならない。

| 条件 | 文言 |
|---|---|
| 終了日が開始日より前 | 「⚠ {ID} は終了日が開始日より前です」 |
| 終わっていないブロッカーの終了日が、自分の開始日以降 | 「⚠ {ID} は {ブロッカーの ID} が終わる前に始まります({ブロッカーの ID} がブロック中)」 |

ブロッカーが完了か中止のときは、2 つ目の警告を出さない。

### 依存の矢印

あるアイテムが別のアイテムをブロックするとき、両方の行が出ていて、両方にバーがあれば、ブロッカーの終了から、ブロックされるアイテムの開始まで矢印を引く。ブロックされるアイテムの開始が、ブロッカーの終了以前なら、矢印を赤くして遅れを示す。ブロッカーが完了か中止なら、赤くしない。ロードマップのときは、Epic どうしの矢印だけを引く。

### 説明と空のとき

ガントの下に「バーをドラッグすると日付が動きます。両端をドラッグすると開始日・終了日だけが変わります。点線は子の日付から、破線はスプリントの期間から引いたバーです。」と案内する。

行が 0 件(プロジェクトの行も数える)のときは、絞り込み中は「一致するものはありません」、そうでなければ「線を引けるものがありません」と「開始日と終了日を入れると、ここにバーが引かれます。」を出す。行は出ているがバーが 1 本もないとき(日付のない行に「日付を入力」が出ている状態)は、行をそのまま出し、バーの領域の上に 1 行の案内「線を引けるものがありません。開始日と終了日を入れると、ここにバーが引かれます。」を出す。日付が入れば案内は消える。

## 一括選択と一括変更・一括削除

テーブルとバックログ(05)では、行を選んで、まとめて変更したり削除したりできる。

### 選択

- 選択は、いま開いている画面ごとに持つ。別の画面に移ると解除する。コマンドパレットの「{N} 件をまとめて変更…」(02)は、検索のテーブルを開いてすべての行を選び、一括変更のダイアログを開く。
- 絞り込みなどで一覧から消えたアイテムは、選択から外す。削除済みになったアイテムも外す。同期で受け取った変更や、別のブラウザのタブ・別のプログラムの保存で消えたり、絞り込みから外れたりしたものも同じである。たとえば 3 件を選択中に 1 件が同期で削除されたら「2 件を選択中」になり、0 件になればバーは閉じる。
- 1 件以上選ぶと、一覧の上にバーが出る。「{N} 件を選択中」と、「一括変更…」「一括削除…」「選択を解除」のボタンを並べる。「選択を解除」は、選択をすべて外す。
- 選んだアイテムがすべて閲覧のみの Store のものなら、「一括変更…」と「一括削除…」を無効にし、「閲覧のみの Store です」と添える。

### 一括変更

「一括変更…」で、ダイアログ「選択したアイテムを一括変更」を開く。

| 項目 | 内容 |
|---|---|
| 概要 | 「{N} 件({種類}・{種類}…)」 |
| 項目 | ステータス、担当者、優先度、スプリント、リリース、関連システムを追加、関連システムを削除、ポイント、見積もり時間、開始日、終了日から選ぶ。初めは「ステータス」 |
| 値 | 項目に応じた入力欄(次の表) |
| 説明 | 「値は名前で合わせます。ワークスペースに同じ名前の値がないアイテム、ワークフローの制約に合わないアイテム、プロジェクトで使わないステータスにはできないアイテムは変えずに残し、件数を知らせます。」。ポイント・見積もり時間・開始日・終了日では「空にすると値を削除します。」を添える |
| ボタン | 「{項目}を変更」(たとえば「ステータスを変更」)。項目が「関連システムを追加」「関連システムを削除」のときは、その名前のまま「関連システムを追加」「関連システムを削除」とする |

| 項目 | 値の入力 |
|---|---|
| ステータス | 選んだアイテムのワークスペースにあるステータスの名前を合わせた一覧から選ぶ。選んだアイテムのどのプロジェクトでも使わない名前は、一覧から除く。一覧の末尾に「分類で変更」の項目として「未着手」「進行中」「完了」「中止」を足す。分類を選ぶと、各アイテムを、そのワークスペースのその分類の既定のステータス(03)にする。すでにその分類のステータスのアイテムは変えない(カンバンのドラッグと同じ)。実行のときの既定のステータスを使う |
| 優先度 | 優先度の名前を合わせた一覧から選ぶ。「なし」はない |
| スプリント | 「バックログ」と、完了していないスプリントの名前を合わせた一覧から選ぶ |
| リリース | 「なし」と、アーカイブしていないリリースの名前を合わせた一覧から選ぶ |
| 担当者 | 「未割り当て」と、選んだアイテムの Store のメンバーを、ログイン名でまとめた一覧 |
| 関連システムを追加、関連システムを削除 | 選んだアイテムのワークスペースにある関連システムの名前を合わせた一覧から、複数を選ぶボタン(02 の入力と同じ)。何も選ばないときは、ボタンを押せない |
| ポイント | 数値の入力欄。0 以上の数 |
| 見積もり時間 | 数値の入力欄。0 以上の数で、小数第 2 位まで |
| 開始日・終了日 | 日付の入力欄 |

ポイントが 0 未満の数や数でない値のときは、「ポイントは 0 以上の数で入力してください」と、ダイアログに出して断る。見積もり時間が 0 未満の数や数でない値のときは「見積もり時間は 0 以上の数で入力してください」、小数第 3 位以下のときは「見積もり時間は小数第 2 位までで入力してください」と、同じようにダイアログに出して断る。

「{項目}を変更」を押すと、実行の前に確認ダイアログを開く。件数と変わる内容を本文に出す。変わるアイテムが 0 件のときは、確認を出さず、結果の表示の「1 件も変わらない」を出す。確認ダイアログを開いている間は、ダイアログの対象と件数を、開いた時点の選択で固定する(ダイアログの下の一覧は更新してよい)。

| 項目 | 内容 |
|---|---|
| 見出し | 一括変更 |
| 本文 | 「{N} 件の{項目}を {値} に変更します。」(たとえば「3 件のステータスを Done に変更します。」)。N は、変えずに残すものと、値がすでに同じものを除いた件数。値のないときは、01 のとおり「なし」(スプリントは「バックログ」)と書く。分類を選んだときは「{N} 件のステータスを 分類「完了」(各ワークスペースの既定のステータス)に変更します。」。見積もり時間の値は「N 時間」の形で書く。項目が「関連システムを追加」のときは「{N} 件に関連システム「{値}」を追加します。」、「関連システムを削除」のときは「{N} 件から関連システム「{値}」を削除します。」と書く(値が複数のときは「, 」でつなぐ) |
| ボタン | 「{N} 件を変更」 |

変更は、アイテムごとに判定する。次のものは、変えずに残し、理由を控える。

| 項目 | 変えずに残す条件 | 理由の書き方 |
|---|---|---|
| すべて | 閲覧のみの Store のアイテム | 「{ID}(閲覧のみ)」 |
| すべて | 実行のときに、削除済みか存在しない | 「{ID}(削除済み)」 |
| すべて | その種類で使わないプロパティ(たとえば優先度を使わない種類) | 「{ID}({種類} には{項目}がない)」 |
| ステータス、優先度、スプリント、リリース、関連システムを追加 | ワークスペースに、同じ名前の値がない(ステータスを分類で変更するときは起きない。関連システムは、選んだ値のうち 1 つでもない) | 「{ID}(値がない)」 |
| ステータス | 遷移が禁じられている | 「{ID}({02 の規則のメッセージ})」 |
| ステータス | アイテムのプロジェクトが、そのステータスを使わない | 「{ID}(このプロジェクトでは使わないステータス)」 |
| スプリント | Story・Task・Bug 以外 | 「{ID}({種類} はスプリントに入れない)」 |
| リリース | Step | 「{ID}(Step はリリースに入れない)」 |
| 担当者 | その Store に、ログイン名が一致するメンバーがいない | 「{ID}(担当者がこの Store のメンバーにいません)」 |
| 開始日・終了日 | 変えると終了日が開始日より前になる | 「{ID}(終了日が開始日より前になる)」 |

値がすでに同じアイテムは、変更にも「そのまま」の件数にも入れない。関連システムを追加するときに、アイテムがすでに選んだ値をすべて持っているとき、削除するときに、選んだ値を 1 つも持たないときも、同じである。一部だけ持つときは、持たない値だけを足す。

複数の Store のアイテムを選んでいるときは、Store ごとに 1 回ずつ保存する(01)。アクティビティには「{N} 件の{項目}を一括変更」と、Store ごとに、その Store で選んだ件数で残る。関連システムを追加・削除するときは、{項目} を「関連システム」と書く。担当者を「あなた」以外の人に変えたアイテムごとに、新しい担当者に「割り当て」の通知が出る(06)。

ステータスと担当者の一括変更は、自動化のルールの判定の対象である(03)。ルールは、アイテムごとに、そのアイテムの変更で判定する。たとえば 10 件を Done にすれば、ルールは 10 回動き、変えたアイテムごとに通知を 1 件出す(割り当ての通知と同じ数え方)。ルールによる変更は、一括変更と同じ保存に入る。「Step がすべて完了したとき」は、1 回の操作が終わった時点で、操作の前は全 Step が完了・中止ではなく、操作のあとは全 Step が完了・中止になった親ごとに、1 回だけ動く。同じ親の Step 3 件を一括変更で完了にしても 1 回である。

Store ごとの保存は互いに独立である。保存に失敗した Store のアイテムは「そのまま」として数え、ほかの Store の変更は残す。理由は「{Store 名} の {M} 件(保存できませんでした)」と書き、結果の表示の「一部だけ変わった」に含める。

結果の表示は次のとおり。

| 結果 | 表示 |
|---|---|
| すべて変わった | トースト「{N} 件を変えました」 |
| 一部だけ変わった | エラーの色のトースト「{N} 件を変えました。{M} 件はそのままです: {理由の一覧}」。理由は「、」でつなぐ |
| 1 件も変わらない(残したものがある) | 何も保存せず、エラーのトースト「変更できたものはありません: {理由の一覧}」 |
| 1 件も変わらない(残したものがない) | 何も保存せず、エラーのトースト「変わるものはありません」 |

理由の一覧は、同じ理由ごとにまとめる。「{ID}・{ID}・{ID} ほか {K} 件({理由})」のように ID を 3 件まで並べ、残りは「ほか K 件」とする。

バックログの一括変更(05)では、完了・中止になってバックログの枠に出なくなるアイテムがあるとき、変わったものがあるときのトーストの末尾に「。{K} 件は完了のため、バックログには表示されません」を続ける(K は完了・中止になってバックログに出ない件数。完了と中止が混じるときは「完了・中止のため」)。

一括変更のあとは、選択を解除しない。ダイアログだけ閉じる。変更で絞り込みに合わなくなって一覧から消えたアイテムは、前述の規則で選択から外れる。変えずに残したアイテムは、選択のまま残る。一括削除は、削除済みになるので選択を解除する。

### 一括削除

「一括削除…」で、確認ダイアログを開く。

| 項目 | 内容 |
|---|---|
| 見出し | 一括削除 |
| 本文 | 「{ID}、{ID}… と、その下にあるものを削除します。設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」(N はその Store の保持日数。複数の Store にまたがるときは「保持日数を過ぎると完全に削除されます。」)。ID は先頭の 10 件まで並べ、残りは「ほか {N} 件」とする。閲覧のみの Store のアイテムを選んでいるときは、「閲覧のみの Store の {K} 件は削除しません。」を添える |
| ボタン | 「{N} 件を削除」(危険な操作の見た目) |

実行すると、選んだアイテムと、その下にあるものをすべて削除済みにする。削除済みは、設定の「削除済み」から戻せる(08)。複数の Store にまたがるときは、Store ごとに 1 回ずつ保存し、アクティビティには「{N} 件を一括削除」と残る。N は、その Store で削除済みに入った件数(下にあるものを含み、同じアイテムを重ねて数えない。実行のときにまだ削除されていなかったものだけ)である。閲覧のみの Store のアイテムは、削除せず、数えない。

削除したら、選択を解除する。開いている詳細パネルが削除したアイテムなら、閉じる。トースト「{M} 件を削除しました」(下にあるものを含む件数。複数の Store にまたがるときは Store ごとの N の合計)を出す。閲覧のみの Store のアイテムを残したときは、「{M} 件を削除しました。{K} 件は閲覧のみの Store のためそのままです」とする。

## ワークスペースの概要とプロジェクトの一覧

ワークスペースの画面の見出しと、概要の統計、プロジェクトの一覧、最近の変更をここで定める。

### 見出し

Store のバッジ、ワークスペースの名前、接頭辞を出す。右に「プロジェクト」のボタンを置く。実行中のスプリントがあるときは、補足の表示を 05 に従って出す。見出しの下に、概要・ツリー・カンバン・テーブル・バックログ・スプリント・リリース・ガント・レポート・設定のタブが並ぶ。

### 統計

4 つのカードを並べる。

| カード | 内容 |
|---|---|
| プロジェクト | ワークスペースのプロジェクトの数 |
| 未完了のアイテム | Step を除くアイテムのうち、未完了の件数 |
| 期限切れ | Step を除くアイテムのうち、期限切れの件数。0 件でなければ強調する |
| {スプリント名} の完了ポイント | 実行中のスプリントの「{完了のポイント} / {対象のポイント} pt」。実行中のスプリントがないときは「—」と、「実行中のスプリントなし」 |

「期限切れ」のカードを押すと、テーブルのタブを開き、絞り込みを `is:overdue -kind:step` にする。テーブルの列、グループなど、ほかの設定は変えない。

「完了ポイント」の対象は、スプリントに入っている Story・Task・Bug である。中止のアイテムは対象に含めない(集計の定義)。ポイントのないアイテムは 0 として数える。スプリントの進捗の詳しい定義は 05 に従う。

### プロジェクトの一覧

| 列 | 内容 |
|---|---|
| タイトル | プロジェクトのアイコンとタイトル。押すとプロジェクトの概要を開く |
| ステータス | プロジェクトのステータス |
| オーナー | アイコンと表示名。いなければ「未割り当て」 |
| 期間 | 「開始日 〜 終了日」。片方がないときは、ない側を「?」と書く。どちらもないときは「—」 |
| 進捗 | 集計の定義のとおり |
| (メニュー) | プロジェクトのメニュー(02。「上へ移動」「下へ移動」を含む) |

並びは、サイドバーと同じ並び順である。プロジェクトが 1 件もないときは、「プロジェクトはまだありません」と「プロジェクトの下に Epic、その下に Story・Task・Bug、さらに Step を作れます。」と、「プロジェクトを作成」のボタンを出す。見出しの右の「作成」ボタンと、ワークスペースの画面の上部の「プロジェクト」ボタンも、同じ作成ダイアログを開く(02)。閲覧のみの Store では、これらを無効にする。

### 最近の変更

そのワークスペースのアクティビティを、新しい順に 6 件出す。各行は、相対時間(01)、実行者(人はアイコン。メンバーにいない人は「不明なユーザー」。自動化と GitHub は 06 の実行者の表示)、本文である。同期の行は、ワークスペースを持たないので含めない。見出しの右の「すべて見る」で、そのワークスペースで絞り込んだアクティビティを開く(06)。1 件もないときは「まだ変更はありません」と出す。

プロジェクトは、概要ページで内容を見る。プロジェクトを詳細パネルのように横に開くことはしない(02)。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| ステータスの条件 | `status:` がステータスの名前と分類の両方に一致する | `status:` は名前だけにし、分類は別のキー `category:` で書く | 「Done」という名前のステータスと分類「done」が区別できないため |
| 自由な語 | ID とタイトルだけを探す | ID・タイトル・説明を探す | 説明の中の語でも探せるようにするため |
| `project:` | プロジェクト名の一部で探す | プロジェクトの ID(`HH-P1`)で探す。日本語で打つと候補が出て、選ぶと ID が入る | 名前の一部だと別のプロジェクトまで一致し、名前を変えると保存したビューが壊れるため(ユーザーの指示) |
| プロジェクトの ID | ない | アイテムとは別の連番で `HH-P1` を振る | 検索やリンクでプロジェクトを一意に指すため。アイテムの ID と見分けるため(ユーザーの指示) |
| `is:open`・`is:closed` | `is:open` は使え、`is:closed` は使えるがヘルプにない | どちらもなくし、`category:` で書く | 同じことを書く方法を 2 つ持たないため(ユーザーの指示) |
| `assignee:` の表示名 | 表示名でも探せる | ログイン名だけ。表示名は候補から選ぶ | 同じ表示名の人を区別できないため(ユーザーの指示) |
| 絞り込み欄の候補 | ない | `project:`・`assignee:`・`parent:`・`workspace:` で、日本語の名前やタイトルから候補を出し、選ぶと ID などの形を入れる | 書き方を覚えなくても ID で条件を書けるようにするため(ユーザーの指示) |
| ヘルプにないキー | `watching`、`store`、`workspace`、`epic` は載っていない | `watching`・`store`・`workspace` と `category` を加え、`epic` は `parent` と同じと表に書く | 使えるキーがすべて分かるようにするため |
| 比較の規則 | 名前・ログイン名・ワークスペース名・Store 名が大文字と小文字を区別する比較、それ以外は区別しない | 名前・ログイン名・ID の比較はすべて区別しない | 比較の規則を 1 つにそろえるため。メンションの規則(ログイン名は区別しない)とも合わせる |
| `none` | `points`、数値・日付のプロパティ、`watching` では効かない | 値が空になりうるキーはすべて `none` が使える | キーによって使えたり使えなかったりするのを避けるため |
