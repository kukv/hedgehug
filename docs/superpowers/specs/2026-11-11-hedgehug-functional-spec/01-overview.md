# hedgehug 機能仕様 01: 全体の前提

hedgehug は、タスクを git リポジトリに保存し、ブラウザの画面から操作するタスク管理ツールである。この仕様は、画面モックをもとに、利用者から見た振る舞いを定める。この文書は 8 本ある仕様のうち、すべての画面に共通する前提をまとめたもの。

## この仕様の範囲

扱うのは、利用者から見た振る舞いである。画面に何が出るか、操作で何が変わるか、どんな条件で操作を断るか、そのとき何と表示するかを定める。データの保存形式、同期の実装方法、技術構成、CLI は扱わない。それらは次の段階で決める。

出発点は画面モック(https://claude.ai/artifact/Qw2jqgdbYtbcA4VTMHGCVA)である。仕様はモックの振る舞いに従う。モックと違う振る舞いにした箇所は、各文書の最後にある「モックからの変更点」に、理由とともに挙げる。

仕様は次の 8 本に分かれる。

| 文書 | 扱う範囲 |
|---|---|
| 01 全体の前提(この文書) | 用語、階層、共有する範囲、「あなた」、書き込みと元に戻す、閲覧のみの Store、日付の表示、画面の移り方と共通の表示、画面の一覧、キーボード |
| 02 アイテムとプロジェクト | 種類と親子、プロパティ、作成・複製・移動・種類の変更・削除、詳細パネル |
| 03 ワークスペースの設定 | プロパティ、値、ワークフロー、テンプレート、自動化 |
| 04 検索とレイアウト | クエリ、ツリー・カンバン・テーブル・ガント、保存したビュー、一括変更 |
| 05 計画とレポート | バックログ、スプリント、リリース、レポートの定義 |
| 06 同期・通知・アクティビティ | 同期、競合の扱い、番号の重なりの修復、受信箱、アクティビティ |
| 07 GitHub 連携 | アカウント、リポジトリのルール、PR と Issue のリンク、Issue の取り込みと同期、Store の検索 |
| 08 Store と保守 | Store の追加・削除・非表示、メンバー、削除済み、診断と修復、初回起動 |

モックにだけある次の機能は作らない。

- 「この人として操作」(操作する人の切り替え)
- 設定の「画面の状態」(オフライン・接続できない画面・トークンのない画面・初回起動の画面への切り替え)、「サンプルデータに戻す」、データを空にする操作
- 「マージされたことにする」、デバイスフローの「許可しました」「期限切れにする」、診断の「壊れたデータを作成」
- PR・Issue のリンクでタイトルと状態を手で入力する欄、Issue を作成したときの仮の番号。実物は GitHub から取得する(07)
- Issue の取り込みや Store の検索に出る、固定のサンプルのリポジトリ・Issue・ラベル

## 用語と階層

データは次の階層になる。

```
Store(git リポジトリ 1 つ)
└─ ワークスペース(接頭辞は任意)
   └─ プロジェクト
      └─ Epic
         └─ Story / Task / Bug
            └─ Step
```

- **Store**: タスクを保存する git リポジトリ。remote があれば、remote を通して複数の人で共有できる。remote がなければ、このマシンの中だけで使う。
- **ワークスペース**: プロパティの定義、ステータス、ワークフロー、スプリント、リリースを持つ単位。英大文字で始まる 10 文字以内の接頭辞(英大文字と数字)を持てる。
- **プロジェクト**: Epic をまとめる単位。持つ項目は固定で、タイトル・説明・オーナー・開始日・終了日・ステータスである。ステータスも Todo・InProgress・Done・Pending・Cancel の 5 つに固定し、利用者は変更できない。
- **アイテム**: Epic・Story・Task・Bug・Step の総称。Story・Task・Bug をまとめて**作業項目**と呼ぶ。スプリントに入れられるのは作業項目だけである。
- **ID**: アイテムを指す番号。ワークスペースに接頭辞があれば `HH-12`、なければ `#12` と表示する。番号はワークスペースごとの連番で、Step にも番号を振る。
- **プロジェクトの ID**: プロジェクトを指す番号。アイテムとは別の、ワークスペースごとの連番で、`HH-P1`(接頭辞がなければ `#P1`)と表示する。作ったときに自動で振る。
- **内部の ID**: ワークスペース・プロジェクト・アイテムは、画面に出ない内部の ID も持つ。画面の ID が振り直しや移動で変わっても、同じものだと分かるのはこの ID による。形式(ULID など)は保存形式の段階で決める。
- **メンバー**: 担当者・オーナー・メンションの候補になる人の一覧。Store ごとに持ち、Store の中で共有する。各メンバーは表示名とログイン名を持つ。メールアドレスは持たない。
- **あなた**: この画面を操作している人。Store ごとに、メンバーの誰かに対応づける(後述)。
- **アカウント**: GitHub のアカウント。登録は任意で、マシンごとに持つ(07)。

アイテムの親子には、次の決まりがある。この決まりに合わない場所へは、作成・移動・種類の変更のどの経路でも置けない。

| 子の種類 | 置ける親 |
|---|---|
| Epic | プロジェクトの直下 |
| Story・Task・Bug | Epic |
| Step | Story・Task・Bug |

## Store で共有するものと、マシンごとに持つもの

Store の中身は、remote を通して全員で共有する。Store の外にある設定は、このマシンだけのものである。分け方は次のとおり。

| Store で共有する | マシンごとに持つ |
|---|---|
| ワークスペースとその設定(プロパティ、値、ワークフロー、テンプレート、自動化、スプリント、リリース、GitHub Issue の同期設定) | GitHub のアカウントと、リポジトリごとのアカウントのルール |
| プロジェクト、アイテム、コメント、作業時間、関連、PR・Issue のリンク、履歴 | Store の一覧と、各 Store の remote・同期に使うアカウント・色・非表示 |
| メンバーの一覧 | 自動同期の有無と間隔 |
| 削除済みの保持日数 | このマシンのログイン名、通知と既読の状態 |
| | 保存したビュー(自分だけのもの。04) |
| | 画面の状態(最後に開いていた画面、絞り込み、レイアウトの設定、折りたたみ、詳細パネルの幅、レポートの選択) |

通知は Store に保存しない。各マシンが、自分の操作と、同期で受け取った他の人の変更から、あなた宛ての通知を作る(06)。

## 「あなた」の決まり方

「あなた」は Store ごとに、ログイン名で決まる。使うログイン名は次の順に選ぶ。

1. その Store の同期に使う GitHub アカウントがあれば、そのログイン名
2. なければ、このマシンの設定「ログイン名」(08)

Store のメンバーに、そのログイン名(大文字と小文字を区別しない)の人がいれば、その人として操作する。いなければ、ダイアログを出さずにメンバーへ追加し、「{ログイン名} をメンバーに追加しました」と表示する。追加するのは、その Store をこのマシンに追加したとき(08 の「Store を追加」、07 の Store の検索の「マウント」)である。同期に使うアカウントを変えたなどで、あとから「あなた」がメンバーに見つからなくなったときは、その Store に次に書き込むときに、その書き込みと一緒に追加する。追加したメンバーの表示名は、ログイン名にする。表示名は、あとから自分の行の編集で変えられる(08)。追加を含む保存を元に戻しても、追加したメンバーは残す。閲覧のみの Store では追加しない。

Store をこのマシンから削除しても(08)、メンバーからは外さない。複数のマシンで同じ Store を使う人がいるためと、担当を外すとチームの作業に影響するためである。リポジトリの権限が外れれば、その人は Store を見られなくなる。アクセスは GitHub の権限で管理するので、メンバーから外す操作は持たない。一度載ったメンバーは残り続ける。

このマシンの設定「ログイン名」は、初回起動のときに利用者が入力して決める。入力しないと始められない。初回起動で GitHub アカウントを登録していれば、そのログイン名を初期値として入れておく。そうでなければ空欄にする。git の設定や OS のユーザー名からは決めない。あとから設定の「一般」でも変えられる(08)。

メールアドレスは、Store に書かない。hedgehug が作る保存(コミット)の作者情報にも、本物のメールアドレスは入れない。

マイタスクや受信箱のように複数の Store にまたがる画面では、Store ごとに決まった「あなた」を使う。

## 書き込みの単位

利用者の 1 回の操作が、1 回の保存になる。保存は Store の git の 1 コミットに当たり、操作した人、時刻、何をしたかの説明を記録する。この記録が、アクティビティの画面と、アイテムやプロジェクトの履歴になる(06)。

1 回の操作が複数の Store にまたがるとき(一括変更や Store をまたぐ移動)は、Store ごとに 1 回ずつ保存する。

操作が条件に合わないときは、何も変更せずに理由を表示する。1 回の操作の途中で 1 つでも失敗したら、その操作で変えたものはすべて元のままにする。例外は一括変更で、変えられなかったものを残して変えられたものだけを保存し、件数と理由を表示する(04)。

次の操作は Store を変えないので、保存にもアクティビティにも残らない。

- 通知の既読と未読の切り替え、自動化が止まった通知の「変更しない」(06)
- Store の追加(新しく作るときの「メイン」の作成は保存になる。08)と、このマシンからの削除。どちらも元に戻せない
- Store の色・非表示・remote・アカウントの変更、自動同期の設定、アカウントとルールの編集
- 画面の状態の変更(絞り込みの入力、保存していないビューの変更、折りたたみ、テーブルの並べ替え)
- 保存したビューの保存・名前の変更・複製・削除(ビューはこのマシンに置く。04)。削除は元に戻せない

## 元に戻す

あなたがこのマシンで行った保存は、新しいものから順に元に戻せる。同期のあとでも戻せる。

- **操作**: Ctrl+Z(macOS は Cmd+Z)、保存のあとに出るトーストの「元に戻す」、コマンドパレットの「元に戻す」。入力欄にカーソルがあるときの Ctrl+Z は、入力欄の文字の取り消しになる。
- **対象**: 前節の「Store を変えない操作」と、作成の操作を除く、あなたの保存。アプリを開いているあいだの最大 40 件。アプリを閉じると戻せなくなる。
- **作成の操作**: アイテム・プロジェクト・ワークスペース・スプリント・リリースの作成、アイテムの複製、Issue の取り込み(07)は、元に戻す対象にしない。作ったものを消すときは、削除を使う(02・03)。
- **戻し方**: 元の操作と逆の変更を、新しい保存として記録する。アクティビティには「元に戻す: 〜」と残る。元に戻した保存を、さらに元に戻すことはしない。やり直し(Redo)は持たない。
- **複数の Store にまたがった操作**: Store ごとに分かれた保存(一括変更、Store をまたぐ移動など)は、1 回の「元に戻す」でまとめて戻す。どれか 1 つでも戻せないときは、どれも戻さず、その操作全体を元に戻す対象から外す。
- **戻せないとき**: 戻そうとする項目を、その保存のあとで他の人が変えていた(同期で受け取った)場合は、何も変えずに理由を表示し、その保存を元に戻す対象から外す。表示例は「HH-12 のステータスは 田中 美咲 さんがあとから変更したため、元に戻せません」。
- **元に戻せない操作**: 完全に削除(08)と、Store のこのマシンからの削除(08)は元に戻せない。確認ダイアログで「元に戻せません」と示す。

戻せる操作がないときは「元に戻せる変更はありません」と表示する。戻したときは「元に戻しました」と表示する。

## 閲覧のみの Store

GitHub で読み取りの権限しかないリポジトリを Store として追加すると、その Store は閲覧のみになる(07・08)。閲覧のみの Store の中身は表示できるが、作成・変更・削除はできない。

- 入力欄、メニューの項目、ドラッグ、作成ボタンを無効にし、「閲覧のみの Store です」と添える。操作してから断るのではなく、操作できない見た目にする。
- 作成ダイアログや移動先の候補に、閲覧のみの Store とその中のワークスペースを出さない。
- ワークスペースとプロジェクトの画面、アイテムの詳細パネルの上部に、「{Store 名} は閲覧のみの Store です。閲覧はできますが、作成・変更・削除はできません。」と表示する。マイタスク・検索・保存したビューでも、閲覧のみの Store のアイテムが一覧に含まれるときに表示する(04)。
- 同期では受け取りだけを行う。自動同期の対象にも含める(06)。

## 日付と時刻

日付は、すべてこのマシンの時刻帯での日付として扱う。「今日」「期限切れ」「残り日数」「ガントの今日の線」は、どれも同じ日付を使う。週は月曜に始まり日曜に終わる。

日付の範囲を入力する箇所では、終了日が開始日より前なら「終了日は開始日以降にしてください」と表示して断る。開始日と終了日が同じ日は認める。

日付は、今年なら「M/D」、それ以外の年なら「YYYY/MM/DD」と表示する。時刻は「HH:MM」である。「何分前」のような相対時間は次のように表示する。

| 経過 | 表示 |
|---|---|
| 1 分未満 | たった今 |
| 1 時間未満 | N 分前 |
| 1 日未満 | N 時間前 |
| 7 日未満 | N 日前 |
| 7 日以上 | 日付 |

## 画面の移り方と、共通の表示

- 画面を移ると、開いている詳細パネル・メニュー・サイドバーのドロワーを閉じ、本文の先頭を表示する。
- アプリを開き直すと、最後に開いていた画面を開く。その画面がもうないとき(削除された、Store を非表示にしたなど)と、初めて開いたときは、マイタスクを開く。開いている画面が操作や同期でなくなったときも、マイタスクに移る。
- 幅が 860px 以下の画面では、サイドバーは左から出るドロワーになり、ページの見出しにメニューのボタンを出す。ドロワーは、背景を押すか Esc で閉じる。
- ダイアログは、背景を押すか Esc で閉じる。閉じたときは何も保存しない。詳細パネルの幅は、左の縁のドラッグで、480px から「画面の幅 − サイドバー − 160px」までの範囲で変えられる。
- 色は、OS の設定に合わせて明るい表示と暗い表示を切り替える。
- トーストは画面の下に、同時に 4 件まで出す。5 件目が出ると古いものから消える。通常は 4.5 秒、エラーは 7 秒で消え、「×」でも閉じられる。保存のトーストのうち、元に戻せるものには「元に戻す」ボタンを付ける。
- 値を文で表示するとき(履歴の「{項目}を 旧 → 新」、通知の「{項目}を {値} に変更」など)は、空の値を「なし」、チェックを「オン」「オフ」、複数の値を「, 」でつないで表示する。削除された値は「(削除された値)」と表示する。

## キーボード

| キー | 動作 |
|---|---|
| Ctrl+K(Cmd+K) | コマンドパレットを開く。ダイアログを開いていても開く |
| C | アイテムを作成する。入力中とダイアログを開いているときは使えない |
| / | 絞り込みの入力欄に移る。入力中とダイアログを開いているときは使えない |
| Ctrl+Z(Cmd+Z) | 元に戻す |
| Esc | 開いているものを閉じる。メニュー、パレット、ダイアログ、詳細パネル、サイドバーの順 |
| Enter | 1 行の入力欄で確定する。複数行の入力欄では Ctrl+Enter(Cmd+Enter)で確定する。日本語入力の変換を確定する Enter では確定しない |
| Enter・Space | ボタンとして働く要素(行の見出しなど)を押す |

ドラッグでできる操作には、どれもメニューかセレクトでも同じことができる経路を用意する。ドラッグはマウスとタッチの両方で動くようにする。

## 文言

画面の動詞は、非表示・削除・解除・移動・復元・変更・選択・検索・入力のような、画面でよく使う語にそろえる。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| 元に戻す | 同期すると元に戻せる履歴がすべて消える | 同期のあとも、あなたの保存を逆の変更で戻せる。他の人があとから変えた項目は戻さない | 自動同期が 5 分ごとに動くと、気づかないうちに戻せなくなるため |
| 作成を元に戻す | 作成も元に戻せる | 作成・複製・Issue の取り込みは元に戻す対象にしない。消すときは削除する | 作成の逆は削除と同じ結果になり、元に戻すで扱う利点がないため |
| 閲覧のみの Store | 操作してから保存のときに断る。帯はワークスペースとプロジェクトの画面だけ | 操作できない見た目にし、候補からも外す。詳細パネル・マイタスク・検索・保存したビューにも帯を出す | 操作のあとで断られるより、先に分かるほうが迷わないため |
| メンバー | 全 Store で 1 つの一覧 | Store ごとの一覧を Store の中で共有する | 担当者の候補は、その Store を使う人であるべきため |
| 「あなた」 | 決まっていない(モックでは切り替えられる) | Store のアカウントのログイン名、なければこのマシンの「ログイン名」でメンバーと照合する。見つからなければ、Store をこのマシンに追加したときに自動で追加する(あとで見つからなくなったら、次に書き込むときに追加する)。このマシンから削除してもメンバーからは外さない。メンバーから外す操作は持たない | 実際に操作している人をメンバーに結びつけるため。追加の手間をなくすため。外すと、複数のマシンで使う人や担当に影響するため。アクセスは GitHub の権限で止めればよく、残すほうが影響が少ないため(ユーザーの指示) |
| メールアドレス | なし | メンバーにも保存の作者情報にも持たない | チームで共有する Store に個人のメールアドレスを残さないため |
| 通知 | 他の人宛ての通知も自分のマシンに作る | 各マシンが、あなた宛ての通知だけを作る | 通知はマシンごとに持つため |
| 日付 | ローカルの日付と UTC の日番号が混ざる | すべてローカルの日付 | 日付の境目で 1 日ずれるのを防ぐため |
| 日付の範囲の文言 | 「終了日は開始日より後にしてください」など、画面によって違う | 「終了日は開始日以降にしてください」にそろえる | 同じ日を認めているのに「より後」と書いていたため |
| 書き込みを断る仕組み | 一部の操作が保存を通らず、元に戻せず記録もされない(メンバーの追加など) | Store を変える操作はすべて保存として記録し、元に戻せる | 共有するデータの変更が記録に残らないのを防ぐため |
| 保存したビュー | Store に保存して共有する | このマシンに置く自分だけのもの | ユーザーの指示。共有のビューは見る人が追加している Store によって中身が変わるため |
| 複数の Store にまたがる操作 | 最初の Store か、先頭のアイテムの Store に 1 回だけ記録する | Store ごとに 1 回ずつ保存する | 変更を、変えた Store に記録するため |
