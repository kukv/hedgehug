# hedgehug 機能仕様 01: 全体の前提

hedgehug は、タスクを git リポジトリに保存し、ブラウザの画面から操作するタスク管理ツールである。この仕様は、画面モックをもとに、利用者から見た振る舞いを定める。この文書は 8 本ある仕様のうち、すべての画面に共通する前提をまとめたもの。

## この仕様の範囲

扱うのは、利用者から見た振る舞いである。画面に何が出るか、操作で何が変わるか、どんな条件で操作を断るか、そのとき何と表示するかを定める。データの保存形式、同期の実装方法、技術構成、CLI は扱わない。それらは次の段階で決める。画面を開く `hh ui` コマンドの引数と動作は、CLI の仕様で定める。この仕様が定めるのは、08 の 2 つの画面(サーバーに接続できない、トークンのない URL)だけである。

出発点は画面モック(https://claude.ai/artifact/Qw2jqgdbYtbcA4VTMHGCVA)である。仕様はモックの振る舞いに従う。モックと違う振る舞いにした箇所は、各文書の最後にある「モックからの変更点」に、理由とともに挙げる。

仕様は次の 8 本に分かれる。

| 文書 | 扱う範囲 |
|---|---|
| 01 全体の前提(この文書) | 用語、階層、共有する範囲、「あなた」、書き込み、閲覧のみの Store、日付の表示、画面の移り方と共通の表示、画面の一覧、キーボード |
| 02 アイテムとプロジェクト | 種類と親子、プロパティ、作成・複製・移動・種類の変更・削除、詳細パネル |
| 03 ワークスペースの設定 | プロパティ、値、ワークフロー、テンプレート、自動化 |
| 04 検索とレイアウト | クエリ、ツリー・カンバン・テーブル・ガント、保存したビュー、一括変更 |
| 05 計画とレポート | バックログ、スプリント、リリース、レポートの定義 |
| 06 同期・通知・アクティビティ | 同期、競合の扱い、同期の修復(番号の重なりなど)、受信箱、アクティビティ |
| 07 GitHub 連携 | アカウント、PR と Issue のリンク、Store の検索 |
| 08 Store と保守 | Store の追加・削除・非表示、メンバー、削除済み、診断と修復、初回起動 |

モックにだけある次の機能は作らない。

- 「この人として操作」(操作する人の切り替え)
- 設定の「画面の状態」(オフライン・接続できない画面・トークンのない画面・初回起動の画面への切り替え)、「サンプルデータに戻す」、データを空にする操作
- 「マージされたことにする」、デバイスフローの「許可しました」「期限切れにする」、診断の「壊れたデータを作成」
- PR・Issue のリンクでタイトルと状態を手で入力する欄。実物は GitHub から取得する(07)
- Store の検索に出る、固定のサンプルのリポジトリ

## 用語と階層

データは次の階層になる。

```
Store(git リポジトリ 1 つ)
└─ ワークスペース(接頭辞は任意)
   └─ プロジェクト
      └─ Epic
         └─ Story / Task / Bug
            └─ Step
```

- **Store**: タスクを保存する git リポジトリ。remote があれば、remote を通して複数の人で共有できる。remote がなければ、このマシンの中だけで使う。
- **ワークスペース**: プロパティの定義、ステータス、ワークフロー、スプリント、リリースを持つ単位。英大文字で始まる 10 文字以内の接頭辞(英大文字と数字)を持てる。接頭辞のないワークスペースは、1 つの Store に 1 つだけである。
- **プロジェクト**: Epic をまとめる単位。持つ項目は固定で、タイトル・説明・オーナー・開始日・終了日・ステータスである。ステータスも Todo・InProgress・Done・Pending・Cancel の 5 つに固定し、利用者は変更できない。
- **アイテム**: Epic・Story・Task・Bug・Step の総称。Story・Task・Bug をまとめて**作業項目**と呼ぶ。スプリントに入れられるのは作業項目だけである。
- **ID**: アイテムを指す番号。ワークスペースに接頭辞があれば `HH-12`、なければ `#12` と表示する。番号はワークスペースごとの連番で、Step にも番号を振る。
- **プロジェクトの ID**: プロジェクトを指す番号。アイテムとは別の、ワークスペースごとの連番で、`HH-P1`(接頭辞がなければ `#P1`)と表示する。作ったときに自動で振る。
- **内部の ID**: ワークスペース・プロジェクト・アイテムは、画面に出ない内部の ID も持つ。画面の ID が振り直しや移動で変わっても、同じものだと分かるのはこの ID による。形式(ULID など)は保存形式の段階で決める。
- **メンバー**: 担当者・オーナー・メンションの候補になる人の一覧。Store ごとに持ち、Store の中で共有する。各メンバーは表示名とログイン名を持つ。メールアドレスは持たない。
- **あなた**: この画面を操作している人。Store ごとに、メンバーの誰かに対応づける(後述)。
- **アカウント**: GitHub のアカウント。登録は任意で、マシンごとに持つ(07)。

アイテムの親子には、次の決まりがある。この決まりに合わない場所へは、作成・移動・種類の変更のどの経路でも置けない。

| 子の種類 | 置ける親 |
|---|---|
| Epic | プロジェクトの直下 |
| Story・Task・Bug | Epic |
| Step | Story・Task・Bug |

## Store で共有するものと、マシンごとに持つもの

Store の中身は、remote を通して全員で共有する。Store の外にある設定は、このマシンだけのものである。分け方は次のとおり。

| Store で共有する | マシンごとに持つ |
|---|---|
| ワークスペースとその設定(プロパティ、値、ワークフロー、テンプレート、自動化、スプリント、リリース) | GitHub のアカウント |
| プロジェクト、アイテム、コメント、作業時間、関連、PR・Issue のリンク、履歴 | Store の一覧と、各 Store の名前・remote・GitHub に使うアカウント・色・非表示 |
| メンバーの一覧 | 自動同期の有無・間隔・書き込みのあと同期するまでの時間、GitHub を読む間隔 |
| 削除済みの保持日数 | このマシンのログイン名、通知と既読の状態、通知を作った保存の記録 |
| | 保存したビュー(自分だけのもの。04) |
| | 画面の状態(最後に開いていた画面、絞り込み、レイアウトの設定、折りたたみ、詳細パネルの幅、レポートの選択) |

通知は Store に保存しない。各マシンが、自分の操作と、同期で受け取った他の人の変更から、あなた宛ての通知を作る(06)。通知は、完全に削除したアイテム・プロジェクト・ワークスペースの通知と、Store をこのマシンから削除したときの通知が消える(06・08)。

## 「あなた」の決まり方

「あなた」は Store ごとに、ログイン名で決まる。使うログイン名は次の順に選ぶ。

1. その Store に割り当てた GitHub アカウントがあれば、そのログイン名
2. なければ、このマシンの設定「ログイン名」(08)

Store のメンバーに、そのログイン名(大文字と小文字を区別しない)の人がいれば、その人として操作する。いなければ、ダイアログを出さずにメンバーへ追加し、「{ログイン名} をメンバーに追加しました」と表示する。この書き込みは保存になり、アクティビティに「メンバー {ログイン名} を追加」と残る。追加するのは、その Store をこのマシンに追加したとき(08 の「Store を追加」、07 の Store の検索の「マウント」)である。Store のアカウントを変えたなどで、あとから「あなた」がメンバーに見つからなくなったときは、その Store に次に書き込むときに、その書き込みと一緒に追加する。追加したメンバーの表示名は、ログイン名にする。表示名は、あとから自分の行の編集で変えられる(08)。閲覧のみの Store では追加しない。

Store をこのマシンから削除しても(08)、メンバーからは外さない。複数のマシンで同じ Store を使う人がいるためと、担当を外すとチームの作業に影響するためである。リポジトリの権限が外れれば、その人は Store を見られなくなる。アクセスは GitHub の権限で管理するので、メンバーから外す操作は持たない。一度載ったメンバーは残り続ける。

このマシンの設定「ログイン名」は、初回起動のときに利用者が入力して決める。入力しないと始められない。入力欄の初期値は、このマシンのログイン名が設定済みならそれ、なければ入力欄で選んでいる「GitHub に使うアカウント」のログイン名、なければ空欄にする。入力して追加すると、その値がこのマシンのログイン名になる。初回起動の案内で「GitHub から検索」から「マウント」で最初の Store を追加するときも、マウントの前に入力欄を出して入力させ、初期値は同じ順で決める(07・08)。入力欄の下には、「この名前はメンバーとして Store に残り、あとから消せません。」と添える。git の設定や OS のユーザー名からは決めない。あとから設定の「一般」でも変えられる。変えると「あなた」が変わる Store があるときは、確定の前に確認ダイアログを出す(08)。

メールアドレスは、Store に書かない。hedgehug が作る保存(コミット)の作者情報にも、本物のメールアドレスは入れない。保存の作者の名前は、その保存をした「あなた」のログイン名(例: taro)、メールアドレスは「{ログイン名}@hedgehug.invalid」(例: taro@hedgehug.invalid)にする。コミッターも同じ値である。人でない保存(GitHub・同期・自動化・実行者なし)の作者の名前は「hedgehug[bot]」、メールアドレスは「bot@hedgehug.invalid」にする。角かっこはログイン名に使えない文字(08)なので、人のログイン名とぶつからない。実行者の区別の記録の仕方は、保存形式の段階で決める。画面は、作者の名前をその Store のメンバーのログイン名(大文字と小文字を区別しない)と照合して操作した人を出し、メンバーにいなければ「不明なユーザー」と表示する。表示名は作者に使わない。

マイタスクや受信箱のように複数の Store にまたがる画面では、Store ごとに決まった「あなた」を使う。

## 書き込みの単位

利用者の 1 回の操作が、1 回の保存になる。保存は Store の git の 1 コミットに当たり、操作した人、時刻、何をしたかの説明を記録する。この記録が、アクティビティの画面と、アイテムやプロジェクトの履歴になる(06)。

保存は、利用者の操作のほか、同期の修復(実行者「同期」)、GitHub からのリンクの取り直し(実行者「GitHub」)、保持日数を過ぎたものの自動の完全削除(実行者なし)でも作る。どれも Store を変えるときだけである。自動化による変更は、きっかけになった操作と同じ保存に入る(03)。診断の修復は、「あなたが行った変更」として保存する(08)。同期そのもの(送信と受信)は保存ではない。アクティビティの同期の行は同期の結果の記録で、コミットではないので、SHA は出さず空にする(06)。

役割の区別はなく、Store に書き込める人なら、他の人が作ったものも変更・削除できる。

1 回の操作が複数の Store にまたがるとき(一括変更や Store をまたぐ移動)は、Store ごとに 1 回ずつ保存する。

操作が条件に合わないときは、何も変更せずに理由を表示する。1 回の操作の途中で 1 つでも失敗したら、その操作で変えたものはすべて元のままにする。例外は一括変更で、変えられなかったものを残して変えられたものだけを保存し、件数と理由を表示する(04)。複数の Store にまたがる一括変更では、Store ごとの保存は互いに独立で、保存できなかった Store のアイテムは変えなかったものとして数える。

次の操作は Store を変えないので、保存にもアクティビティにも残らない。

- 通知の既読と未読の切り替え、自動化が止まった通知の「変更しない」(06)
- Store の追加(「あなた」をメンバーに載せる書き込みと、新しく作るときの「メイン」の作成は保存になる。08)と、このマシンからの削除
- Store の名前・色・非表示・remote・アカウントの変更、自動同期の設定、アカウントの編集
- 画面の状態の変更(絞り込みの入力、保存していないビューの変更、折りたたみ、テーブルの並べ替え)
- 保存したビューの保存・名前の変更・複製・削除(ビューはこのマシンに置く。04)

完全に削除(08)と、Store のこのマシンからの削除(08)は、取り消せない。確認ダイアログで「元に戻せません」と示す。元に戻す・やり直しの仕組みは持たない。

## 閲覧のみの Store

GitHub で読み取りの権限しかないリポジトリを Store として追加すると、その Store は閲覧のみになる(07・08)。閲覧のみの Store の中身は表示できるが、作成・変更・削除はできない。

- 入力欄、メニューの項目、ドラッグ、作成ボタンを無効にし、「閲覧のみの Store です」と添える。操作してから断るのではなく、操作できない見た目にする。無効にするのは、Store に書く操作(保存になるもの)の入力欄・ボタン・メニューの項目・ドラッグだけである。次は無効にしない。画面の移動とタブの切り替え。中身を見るために開くもの(「詳細を開く」「ID をコピー」、パンくず、子の行のタイトル、全画面)。画面の状態とこのマシンの設定の変更(下の「Store を変えない操作」の一覧、WIP 制限、レポートの単位とスプリントの選択、Store の色・非表示)。
- 作成ダイアログや移動先の候補に、閲覧のみの Store とその中のワークスペースを出さない。
- ワークスペースとプロジェクトの画面、アイテムの詳細パネルの上部に、「{Store 名} は閲覧のみの Store です。閲覧はできますが、作成・変更・削除はできません。」と表示する。マイタスク・検索・保存したビューでも、閲覧のみの Store のアイテムが一覧に含まれるときに表示する(04)。この 4 か所以外の画面では帯を出さず、Store ごとの枠の見出しと、無効にした入力欄・ボタンへの添え書きで示す。
- 同期では受け取りだけを行う。自動同期の対象にも含める(06)。
- 閲覧のみの印は、Store を追加したときに GitHub から読んだ権限で決まる。そのあと、閲覧のみの Store に限り、remote を空にしたとき、remote を別の github.com のリポジトリに変えたとき、「GitHub に使うアカウント」を選び替えたときだけ、権限を見直す。書き込めるとわかれば印を外す(07・08)。書き込める Store は見直さず、送信が拒否されたときに気づく(06)。「閲覧のみ」に戻す操作はなく、戻すにはこのマシンから削除して追加し直す。

## 日付と時刻

日付は、すべてこのマシンの時刻帯での日付として扱う。「今日」「期限切れ」「残り日数」「ガントの今日の線」は、どれも同じ日付を使う。このマシンの日付が前回と変わったとき(1 分ごとの確認と、画面に戻ったとき・スリープから戻ったときの確認)は、日付で決まる表示を自動で更新する。更新するのは、マイタスクのグループとバッジ、期限の強調と「期限切れ」「今日」の表示、ガントの今日の線(位置は動かさない)、概要の「期限切れ」カードの件数、スプリントの「残り N 日」、削除済みの「あと N 日」、アクティビティの「今日」「昨日」の見出しである。入力中の欄と開いているダイアログは動かさない。日付が変わったときは、同期しない Store の自動の完全削除も行う(06・08)。週は月曜に始まり日曜に終わる。

日付の範囲を入力する箇所では、終了日が開始日より前なら「終了日は開始日以降にしてください」と表示して断る。開始日と終了日が同じ日は認める。

日付は、今年なら「M/D」、それ以外の年なら「YYYY/MM/DD」と表示する。時刻は「HH:MM」である。「何分前」のような相対時間は次のように表示する。

| 経過 | 表示 |
|---|---|
| 1 分未満 | たった今 |
| 1 時間未満 | N 分前 |
| 1 日未満 | N 時間前 |
| 7 日未満 | N 日前 |
| 7 日以上 | 日付 |

## 画面の移り方と、共通の表示

- 画面を移ると、開いている詳細パネル・メニュー・サイドバーのドロワーを閉じ、本文の先頭を表示する。
- アプリを開き直すと、最後に開いていた画面を開く。その画面がもうないとき(削除された、Store を非表示にしたなど)と、初めて開いたときは、マイタスクを開く。開いている画面が操作や同期でなくなったときも、マイタスクに移る。詳細パネルは閉じた状態で開き、開いていたアイテムは覚えない。例: HH-12 の詳細パネルを開いたまま再読み込みすると、同じ画面が詳細パネルなしで開く。HH-12 は、一覧の行を押せばまた開ける。
- 幅が 860px 以下の画面では、サイドバーは左から出るドロワーになり、ページの見出しにメニューのボタンを出す。表示中の Store に同期エラーがあるあいだは、メニューのボタンにエラーの色の点を付ける(06)。ドロワーは、背景を押すか Esc で閉じる。
- ダイアログは、背景を押すか Esc で閉じる。閉じたときは何も保存しない。詳細パネルの幅は、左の縁のドラッグで、480px から「画面の幅 − サイドバー − 160px」までの範囲で変えられる。
- 色は、OS の設定に合わせて明るい表示と暗い表示を切り替える。
- トーストは画面の下に、同時に 4 件まで出す。5 件目が出ると古いものから消える。通常は 4.5 秒、エラーは 7 秒で消え、「×」でも閉じられる。
- 値を文で表示するとき(履歴の「{項目}を 旧 → 新」、通知の「{項目}を {値} に変更」など)は、空の値を「なし」、チェックを「オン」「オフ」、複数の値を「, 」でつないで表示する。削除された値は「(削除された値)」と表示する。値がワークスペースの一覧にないときは、詳細パネルのボタン・テーブルのセル・カンバンのカード・作成と一括変更のダイアログの現在値にも、同じ文言を薄い字で出す。押すと選択肢が開き、選び直せる。
- コメント・作業時間・履歴・アクティビティなどに出す人が、その Store のメンバーにいないときは、名前を「不明なユーザー」と表示し、アバターは中身のない印にする。アイテム・プロジェクト・ワークスペースを別の Store へ移すときは、移すものに現れるすべての人(書いた人を含む)を移動先のメンバーに載せる(02・03)ので、移動では起きない。Store のデータがメンバーの一覧にない人を指していたときの表示である。

## キーボード

| キー | 動作 |
|---|---|
| Ctrl+K(Cmd+K) | コマンドパレットを開く。ダイアログを開いているときは使えない。パレットから選んだ候補がダイアログを開くときは、パレットを閉じてから開く |
| C | アイテムを作成する。入力中とダイアログを開いているときは使えない |
| / | 絞り込みの入力欄に移る。入力中とダイアログを開いているときは使えない |
| Esc | 開いているものを閉じる。メニュー、絞り込み欄の候補、パレット、ダイアログ、詳細パネル、サイドバーの順。候補が出ているとき、1 回目は候補だけを閉じる。候補は欄にフォーカスがあるあいだだけ出る。入力欄の中身が保存してある内容と違うときは、確認ダイアログ「入力を破棄」を出す(02)。日本語入力の変換中の Esc は、変換の取り消しに使い、この確認の対象にしない |
| Enter | 1 行の入力欄で確定する。複数行の入力欄では Ctrl+Enter(Cmd+Enter)で確定する。日本語入力の変換を確定する Enter では確定しない |
| Enter・Space | ボタンとして働く要素(行の見出しなど)を押す |

ドラッグでできる操作には、どれもメニューかセレクトでも同じことができる経路を用意する。ドラッグはマウスとタッチの両方で動くようにする。

## 文言

画面の動詞は、非表示・削除・解除・移動・復元・変更・選択・検索・入力のような、画面でよく使う語にそろえる。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| ダイアログを開いているときの Ctrl+K | ダイアログを開いていても開く | ダイアログを開いているときは使えない。C キー・/ キーと同じ | ユーザーの指示(2026-11-12)。パレットとダイアログが重なって開くのを避けるため |
| 元に戻す | Ctrl+Z・トーストの「元に戻す」・コマンドパレットで戻せる。同期すると戻せる履歴がすべて消える | 元に戻す・やり直しの仕組みを持たない | ユーザーの指示(2026-11-12)。管理が複雑になる。誤操作で押したとき、何を戻したか分からないため |
| 閲覧のみの Store | 操作してから保存のときに断る。帯はワークスペースとプロジェクトの画面だけ | 操作できない見た目にし、候補からも外す。詳細パネル・マイタスク・検索・保存したビューにも帯を出す | 操作のあとで断られるより、先に分かるほうが迷わないため |
| メンバー | 全 Store で 1 つの一覧 | Store ごとの一覧を Store の中で共有する | 担当者の候補は、その Store を使う人であるべきため |
| 「あなた」 | 決まっていない(モックでは切り替えられる) | Store のアカウントのログイン名、なければこのマシンの「ログイン名」でメンバーと照合する。見つからなければ、Store をこのマシンに追加したときに自動で追加し、保存として記録する(あとで見つからなくなったら、次に書き込むときに追加する)。このマシンから削除してもメンバーからは外さない。メンバーから外す操作は持たない | 実際に操作している人をメンバーに結びつけるため。追加の手間をなくすため。外すと、複数のマシンで使う人や担当に影響するため。アクセスは GitHub の権限で止めればよく、残すほうが影響が少ないため(ユーザーの指示) |
| メールアドレス | なし | メンバーにも保存の作者情報にも持たない | チームで共有する Store に個人のメールアドレスを残さないため |
| 通知 | 他の人宛ての通知も自分のマシンに作る | 各マシンが、あなた宛ての通知だけを作る | 通知はマシンごとに持つため |
| メンバーにいない人の表示 | 人の一覧が全 Store で 1 つなので起きない | 「不明なユーザー」と表示する | メンバーを Store ごとに持つため、一覧にない人を指すデータがありうるため(ユーザーの指示) |
| 日付 | ローカルの日付と UTC の日番号が混ざる | すべてローカルの日付 | 日付の境目で 1 日ずれるのを防ぐため |
| 日付の範囲の文言 | 「終了日は開始日より後にしてください」など、画面によって違う | 「終了日は開始日以降にしてください」にそろえる | 同じ日を認めているのに「より後」と書いていたため |
| 書き込みを断る仕組み | 一部の操作が保存を通らず、元に戻せず記録もされない(メンバーの追加など) | Store を変える操作はすべて保存として記録する | 共有するデータの変更が記録に残らないのを防ぐため |
| 保存したビュー | Store に保存して共有する | このマシンに置く自分だけのもの | ユーザーの指示。共有のビューは見る人が追加している Store によって中身が変わるため |
| 複数の Store にまたがる操作 | 最初の Store か、先頭のアイテムの Store に 1 回だけ記録する | Store ごとに 1 回ずつ保存する | 変更を、変えた Store に記録するため |
| GitHub Issue の取り込み・同期・作成 | 設定の「GitHub Issue」で取り込み、Issue の状態・担当者・マイルストーンを同期し、詳細パネルから Issue を作れる | 作らない。Issue はリンクだけを残し、番号でリンクして、タイトルと状態(Open・Closed)を GitHub から読んで表示する。アイテムの値は変えない | ユーザーの指示(2026-11-12)。取り込みと同期は、アイテムの値を GitHub と双方向に合わせるため、競合・制約・通知の細かな規則が増え、管理が複雑になるため |
