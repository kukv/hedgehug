# hedgehug 機能仕様 01: 全体の前提

hedgehug は、タスクを git リポジトリに保存し、ブラウザの画面から操作するタスク管理ツールである。この仕様は、画面モックをもとに、利用者から見た振る舞いを定める。この文書は 8 本ある仕様のうち、すべての画面に共通する前提をまとめたもの。

## この仕様の範囲

扱うのは、利用者から見た振る舞いである。画面に何が出るか、操作で何が変わるか、どんな条件で操作を断るか、そのとき何と表示するかを定める。データの保存形式、同期の実装方法、技術構成、CLI は扱わない。ただし、CLI など別のプログラムが Store に保存した変更が、開いている画面にどう出るかは 06 で定める。それらは次の段階で決める。画面を開く `hh ui` コマンドの引数と動作は、CLI の仕様で定める。この仕様が定めるのは、08 の 2 つの画面(サーバーに接続できない、トークンのない URL)だけである。

出発点は画面モック(https://claude.ai/artifact/Qw2jqgdbYtbcA4VTMHGCVA)である。仕様はモックの振る舞いに従う。モックと違う振る舞いにした箇所は、各文書の最後にある「モックからの変更点」に、理由とともに挙げる。

仕様は次の 8 本に分かれる。

| 文書 | 扱う範囲 |
|---|---|
| 01 全体の前提(この文書) | 用語、階層、共有する範囲、「あなた」、書き込み、閲覧のみの Store、日付の表示、画面の移り方と共通の表示、画面のアドレス、画面の一覧、キーボード |
| 02 アイテムとプロジェクト | 種類と親子、プロパティ、作成・複製・移動・種類の変更・削除、詳細パネル |
| 03 ワークスペースの設定 | プロパティ、値、ワークフロー、テンプレート、自動化 |
| 04 検索とレイアウト | クエリ、ツリー・カンバン・テーブル・ガント、保存したビュー、一括変更 |
| 05 計画とレポート | バックログ、スプリント、リリース、レポートの定義 |
| 06 同期・通知・アクティビティ | 同期、競合の扱い、同期の修復(番号の重なりなど)、受信箱、アクティビティ |
| 07 GitHub 連携 | アカウント、PR と Issue のリンク、Store の検索 |
| 08 Store と保守 | Store の追加・削除・非表示、メンバー、削除済み、診断と修復、初回起動 |

モックにだけある次の機能は作らない。

- 「この人として操作」(操作する人の切り替え)
- 設定の「画面の状態」(オフライン・接続できない画面・トークンのない画面・初回起動の画面への切り替え)、「サンプルデータに戻す」、データを空にする操作
- 「マージされたことにする」、デバイスフローの「許可しました」「期限切れにする」、診断の「壊れたデータを作成」
- PR・Issue のリンクでタイトルと状態を手で入力する欄。実物は GitHub から取得する(07)
- Store の検索に出る、固定のサンプルのリポジトリ

## 用語と階層

データは次の階層になる。

```
Store(git リポジトリ 1 つ)
└─ ワークスペース(接頭辞を持つ)
   └─ プロジェクト
      └─ Epic
         └─ Story / Task / Bug
            └─ Step
```

- **Store**: タスクを保存する git リポジトリ。remote があれば、remote を通して複数の人で共有できる。remote がなければ、このマシンの中だけで使う。
- **ワークスペース**: プロパティの定義、ステータス、ワークフロー、スプリント、リリースを持つ単位。英大文字で始まる 10 文字以内の接頭辞(英大文字と数字)を必ず持つ。
- **プロジェクト**: Epic をまとめる単位。持つ項目は固定で、タイトル・説明・オーナー・開始日・終了日・ステータスである。ステータスも Todo・InProgress・Done・Pending・Cancel の 5 つに固定し、利用者は変更できない。このほか、下のアイテムの決まり(使うステータス・遷移の制約・テンプレート・自動化)の一部を、プロジェクトごとに変えられる。これは項目ではなく、ワークスペースの設定の一部である(03)。
- **アイテム**: Epic・Story・Task・Bug・Step の総称。Story・Task・Bug をまとめて**作業項目**と呼ぶ。スプリントに入れられるのは作業項目だけである。
- **ID**: アイテムを指す番号。ワークスペースの接頭辞と番号をつないで、`HH-12` と表示する。番号はワークスペースごとの連番で、Step にも番号を振る。
- **プロジェクトの ID**: プロジェクトを指す番号。アイテムとは別の、ワークスペースごとの連番で、`HH-P1` と表示する。作ったときに自動で振る。
- **内部の ID**: ワークスペース・プロジェクト・アイテムは、画面に出ない内部の ID も持つ。画面の ID が振り直しや移動で変わっても、同じものだと分かるのはこの ID による。形式(ULID など)は保存形式の段階で決める。内部の ID は画面に出さない。ただし、アイテムの詳細パネルの「PR 用の印をコピー」は、PR の説明に貼る 1 行(`hedgehug:` に内部の ID を続けたもの)として、内部の ID を渡す(02、07)。
- **メンバー**: 担当者・オーナー・メンションの候補になる人の一覧。Store ごとに持ち、Store の中で共有する。各メンバーは表示名とログイン名を持つ。メールアドレスは持たない。
- **あなた**: この画面を操作している人。Store ごとに、メンバーの誰かに対応づける(後述)。
- **アカウント**: GitHub のアカウント。登録は任意で、マシンごとに持つ(07)。

アイテムの親子には、次の決まりがある。この決まりに合わない場所へは、作成・移動・種類の変更のどの経路でも置けない。

| 子の種類 | 置ける親 |
|---|---|
| Epic | プロジェクトの直下 |
| Story・Task・Bug | Epic |
| Step | Story・Task・Bug |

## Store で共有するものと、マシンごとに持つもの

Store の中身は、remote を通して全員で共有する。Store の外にある設定は、このマシンだけのものである。分け方は次のとおり。

| Store で共有する | マシンごとに持つ |
|---|---|
| ワークスペースとその設定(プロパティ、値、ワークフロー、テンプレート、自動化、プロジェクト別のルール、スプリント、リリース) | GitHub のアカウント |
| プロジェクト、アイテム、コメント、作業時間、関連、PR・Issue のリンク、履歴 | Store の一覧と、各 Store の名前・remote・ミラー・GitHub に使うアカウント・色・非表示・既定 |
| メンバーの一覧 | 自動同期の有無・間隔・書き込みのあと同期するまでの時間、GitHub を読む間隔 |
| 削除済みの保持日数 | このマシンのログイン名、通知と既読の状態、通知を作った保存の記録 |
| | 保存したビュー(自分だけのもの。04) |
| | 画面の状態(最後に開いていた画面、絞り込み、レイアウトの設定、折りたたみ、詳細パネルの幅、レポートの選択) |
| | GitHub を最後に読んだ時刻の記録、PR のチェックの結果(最後に読んだ値) |
| | 最近開いたアイテム(コマンドパレットの「最近開いたもの」。02) |

通知は Store に保存しない。各マシンが、自分の操作と、同期で受け取った他の人の変更から、あなた宛ての通知を作る(06)。通知は、完全に削除したアイテム・プロジェクト・ワークスペースの通知と、Store をこのマシンから削除したときの通知が消える(06・08)。

## 「あなた」の決まり方

「あなた」は Store ごとに、ログイン名で決まる。使うログイン名は次の順に選ぶ。

1. その Store に割り当てた GitHub アカウントがあれば、そのログイン名
2. なければ、このマシンの設定「ログイン名」(08)

Store のメンバーに、そのログイン名(大文字と小文字を区別しない)の人がいれば、その人として操作する。いなければ、ダイアログを出さずにメンバーへ追加し、「{ログイン名} をメンバーに追加しました」と表示する。この書き込みは保存になり、アクティビティに「メンバー {ログイン名} を追加」と残る。追加するのは、その Store をこのマシンに追加したとき(08 の「Store を追加」と「フォルダから探す」、07 の Store の検索の「マウント」)である。Store のアカウントを変えたなどで、あとから「あなた」がメンバーに見つからなくなったときは、その Store に次に書き込むときに、その書き込みと一緒に追加する。追加したメンバーの表示名は、ログイン名にする。表示名は、あとから自分の行の編集で変えられる(08)。閲覧のみの Store では追加しない。

Store をこのマシンから削除しても(08)、メンバーからは外さない。複数のマシンで同じ Store を使う人がいるためと、担当を外すとチームの作業に影響するためである。リポジトリの権限が外れれば、その人は Store を見られなくなる。アクセスは GitHub の権限で管理するので、メンバーから外す操作は持たない。一度載ったメンバーは残り続ける。

このマシンの設定「ログイン名」は、初回起動のときに利用者が入力して決める。入力しないと始められない。入力欄の初期値は、このマシンのログイン名が設定済みならそれ、なければ入力欄で選んでいる「GitHub に使うアカウント」のログイン名、なければ空欄にする。入力して追加すると、その値がこのマシンのログイン名になる。初回起動の案内で「GitHub から検索」から「マウント」で、または「フォルダから探す」の「取り込む」で最初の Store を追加するときも、マウントまたは取り込みの前に入力欄を出して入力させ、初期値は同じ順で決める(07・08)。入力欄の下には、「この名前はメンバーとして Store に残り、あとから消せません。」と添える。git の設定や OS のユーザー名からは決めない。あとから設定の「一般」でも変えられる。変えると「あなた」が変わる Store があるときは、確定の前に確認ダイアログを出す(08)。

メールアドレスは、Store に書かない。hedgehug が作る保存(コミット)の作者情報にも、本物のメールアドレスは入れない。保存の作者の名前は、その保存をした「あなた」のログイン名(例: taro)、メールアドレスは「{ログイン名}@hedgehug.invalid」(例: taro@hedgehug.invalid)にする。コミッターも同じ値である。人でない保存(GitHub・同期・自動化・実行者なし)の作者の名前は「hedgehug[bot]」、メールアドレスは「bot@hedgehug.invalid」にする。角かっこはログイン名に使えない文字(08)なので、人のログイン名とぶつからない。実行者の区別の記録の仕方は、保存形式の段階で決める。画面は、作者の名前をその Store のメンバーのログイン名(大文字と小文字を区別しない)と照合して操作した人を出し、メンバーにいなければ「不明なユーザー」と表示する。表示名は作者に使わない。

マイタスクや受信箱のように複数の Store にまたがる画面では、Store ごとに決まった「あなた」を使う。

## 書き込みの単位

利用者の 1 回の操作が、1 回の保存になる。保存は Store の git の 1 コミットに当たり、操作した人、時刻、何をしたかの説明を記録する。この記録が、アクティビティの画面と、アイテムやプロジェクトの履歴になる(06)。

保存は、利用者の操作のほか、同期の修復(実行者「同期」)、GitHub からのリンクの取り直しと PR の自動リンク(実行者「GitHub」)、保持日数を過ぎたものの自動の完全削除(実行者なし)でも作る。どれも Store を変えるときだけである。自動化による変更は、きっかけになった操作と同じ保存に入る(03)。診断の修復と、remote の履歴へののせ直しは、「あなたが行った変更」として保存する(08)。同期そのもの(送信と受信)は保存ではない。アクティビティの同期の行は同期の結果の記録で、コミットではないので、SHA は出さず空にする(06)。

役割の区別はなく、Store に書き込める人なら、他の人が作ったものも変更・削除できる。

1 回の操作が複数の Store にまたがるとき(一括変更や Store をまたぐ移動)は、Store ごとに 1 回ずつ保存する。

操作が条件に合わないときは、何も変更せずに理由を表示する。1 回の操作の途中で 1 つでも失敗したら、その操作で変えたものはすべて元のままにする。例外は一括変更で、変えられなかったものを残して変えられたものだけを保存し、件数と理由を表示する(04)。複数の Store にまたがる一括変更では、Store ごとの保存は互いに独立で、保存できなかった Store のアイテムは変えなかったものとして数える。

次の操作は Store を変えないので、保存にもアクティビティにも残らない。

- 通知の既読と未読の切り替え、自動化が止まった通知の「変更しない」(06)
- Store の追加(「あなた」をメンバーに載せる書き込みと、新しく作るときのワークスペースの作成は保存になる。08)と、このマシンからの削除
- Store の名前・色・非表示・remote・ミラー・アカウント・既定の変更、自動同期の設定、アカウントの編集
- 画面の状態の変更(絞り込みの入力、保存していないビューの変更、折りたたみ、テーブルの並べ替え)
- 保存したビューの保存・名前の変更・複製・削除(ビューはこのマシンに置く。04)

完全に削除(08)と、Store のこのマシンからの削除(08)と、remote の履歴にそろえる操作(08)は、取り消せない。確認ダイアログで「元に戻せません」と示す。元に戻す・やり直しの仕組みは持たない。

## 閲覧のみの Store

GitHub で読み取りの権限しかないリポジトリを Store として追加すると、その Store は閲覧のみになる(07・08)。閲覧のみの Store の中身は表示できるが、作成・変更・削除はできない。

- 入力欄、メニューの項目、ドラッグ、作成ボタンを無効にし、「閲覧のみの Store です」と添える。操作してから断るのではなく、操作できない見た目にする。無効にするのは、Store に書く操作(保存になるもの)の入力欄・ボタン・メニューの項目・ドラッグだけである。次は無効にしない。画面の移動とタブの切り替え。中身を見るために開くもの(「詳細を開く」「ID をコピー」、パンくず、子の行のタイトル、全画面)。画面の状態とこのマシンの設定の変更(下の「Store を変えない操作」の一覧、WIP 制限、レポートの選択(単位、スプリント、累積フロー図の層の分け、見積もりと実績の対象)、Store の色・非表示)。累積フロー図の期間の入力も、保存しない画面の状態なので、無効にしない。
- 作成ダイアログや移動先の候補に、閲覧のみの Store とその中のワークスペースを出さない。
- ワークスペースとプロジェクトの画面、アイテムの詳細パネルの上部に、「{Store 名} は閲覧のみの Store です。閲覧はできますが、作成・変更・削除はできません。」と表示する。マイタスク・検索・保存したビューでも、閲覧のみの Store のアイテムが一覧に含まれるときに表示する(04)。この 4 か所以外の画面では帯を出さず、Store ごとの枠の見出しと、無効にした入力欄・ボタンへの添え書きで示す。
- 同期では受け取りだけを行う。自動同期の対象にも含める(06)。
- 閲覧のみの印は、Store を追加したときに GitHub から読んだ権限で決まる。そのあと、閲覧のみの Store に限り、remote を空にしたとき、remote を別の github.com のリポジトリに変えたとき、「GitHub に使うアカウント」を選び替えたときだけ、権限を見直す。書き込めるとわかれば印を外す(07・08)。書き込める Store は見直さず、送信が拒否されたときに気づく(06)。「閲覧のみ」に戻す操作はなく、戻すにはこのマシンから削除して追加し直す。

## 日付と時刻

日付は、すべてこのマシンの時刻帯での日付として扱う。「今日」「期限切れ」「残り日数」「ガントの今日の線」は、どれも同じ日付を使う。このマシンの日付が前回と変わったとき(1 分ごとの確認と、画面に戻ったとき・スリープから戻ったときの確認)は、日付で決まる表示を自動で更新する。更新するのは、マイタスクのグループとバッジ、期限の強調と「期限切れ」「今日」の表示、ガントの今日の線(位置は動かさない)、概要の「期限切れ」カードの件数、スプリントの「残り N 日」、削除済みの「あと N 日」、アクティビティの「今日」「昨日」の見出し、`today`・`-7d` などを含む検索の結果、期間を指定していない累積フロー図(直近 21 日)である。入力中の欄と開いているダイアログは動かさない。日付が変わったときは、同期しない Store の自動の完全削除も行う(06・08)。週は月曜に始まり日曜に終わる。

日付の範囲を入力する箇所では、終了日が開始日より前なら「終了日は開始日以降にしてください」と表示して断る。開始日と終了日が同じ日は認める。

日付は、今年なら「M/D」、それ以外の年なら「YYYY/MM/DD」と表示する。時刻は「HH:MM」である。「何分前」のような相対時間は次のように表示する。

| 経過 | 表示 |
|---|---|
| 1 分未満 | たった今 |
| 1 時間未満 | N 分前 |
| 1 日未満 | N 時間前 |
| 7 日未満 | N 日前 |
| 7 日以上 | 日付 |

## 画面の移り方と、共通の表示

- 画面を移ると、開いている詳細パネル・メニュー・サイドバーのドロワーを閉じ、本文の先頭を表示する。
- アプリを開き直す(`hh ui` が開く、画面を指さない URL で開く)と、最後に開いていた画面を開く。ブラウザのタブの再読み込みは、そのタブのアドレスの画面を開く(下の「画面のアドレス」)。その画面がもうないとき(削除された、Store を非表示にしたなど)と、初めて開いたときは、マイタスクを開く。開いている画面が操作や同期、別のブラウザのタブや別のプログラムの変更でなくなったときも、マイタスクに移る。詳細パネルは閉じた状態で開き、開いていたアイテムは覚えない。例: HH-12 の詳細パネルを開いたまま再読み込みすると、同じ画面が詳細パネルなしで開く。HH-12 は、一覧の行を押せばまた開ける。
- 幅が 860px 以下の画面では、サイドバーは左から出るドロワーになり、ページの見出しにメニューのボタンを出す。表示中の Store に同期エラーがあるあいだは、メニューのボタンにエラーの色の点を付ける(06)。ドロワーは、背景を押すか Esc で閉じる。
- ダイアログは、背景を押すか Esc で閉じる。閉じたときは何も保存しない。詳細パネルの幅は、左の縁のドラッグで、480px から「画面の幅 − サイドバー − 160px」までの範囲で変えられる。
- 色は、OS の設定に合わせて明るい表示と暗い表示を切り替える。
- トーストは画面の下に、同時に 4 件まで出す。5 件目が出ると古いものから消える。通常は 4.5 秒、エラーは 7 秒で消え、「×」でも閉じられる。
- 値を文で表示するとき(履歴の「{項目}を 旧 → 新」、通知の「{項目}を {値} に変更」など)は、空の値を「なし」、チェックを「オン」「オフ」、複数の値を「, 」でつないで表示する。削除された値は「(削除された値)」と表示する。値がワークスペースの一覧にないときは、詳細パネルのボタン・テーブルのセル・カンバンのカード・作成と一括変更のダイアログの現在値にも、同じ文言を薄い字で出す。押すと選択肢が開き、選び直せる。
- コメント・作業時間・履歴・アクティビティなどに出す人が、その Store のメンバーにいないときは、名前を「不明なユーザー」と表示し、アバターは中身のない印にする。アイテム・プロジェクト・ワークスペースを別の Store へ移すときは、移すものに現れるすべての人(書いた人を含む)を移動先のメンバーに載せる(02・03)ので、移動では起きない。Store のデータがメンバーの一覧にない人を指していたときの表示である。

## 画面のアドレス

画面にはアドレスがあり、ブラウザの戻る・進む・再読み込み・新しいタブで画面を扱える。アドレスが区別するものを次に定める。アドレスの綴りは定めない。

| 画面 | アドレスが区別するもの |
|---|---|
| マイタスク、アクティビティ、検索 | 画面だけ(絞り込みやレイアウトは入れない) |
| 受信箱 | タブ(すべて・メンション・割り当て・ウォッチ・上書き・自動化・同期の修復) |
| 保存したビュー | ビュー(このマシンがビューごとに振る識別子。名前を変えても変わらない) |
| ワークスペース | Store 名、ワークスペースの接頭辞、タブ(概要・ツリー・カンバン・テーブル・バックログ・スプリント・リリース・ガント・レポート・設定) |
| プロジェクト | Store 名、プロジェクトの ID(`HH-P1`)、タブ(概要・ツリー・カンバン・テーブル・ガント・設定) |
| 設定 | タブ(一般・アカウントとメンバー・Store・削除済み・診断と修復) |
| アイテムの入口 | Store 名、アイテムの ID。開くと、そのアイテムのプロジェクトの「ツリー」を、詳細パネルを開いた状態で表示する。開いたあと、アドレスはそのツリーの画面のものに替わる |

- 画面に出る ID(`HH-5`)と接頭辞(`HH`)で指す。旧い ID や旧い接頭辞でもよく、いまの場所へは、02・03 の旧 ID と転送の記録の規則でたどり着く。詳細パネルを開く・閉じる操作は、アドレスを変えない。
- アドレスの Store 名の Store を先に探す。Store 名の Store では、いまの ID(接頭辞)、旧い接頭辞、転送の記録の順に探す。その 3 つのどれでも見つからないとき(Store の名前を変えた、別の Store へ移したなど)は、表示中のほかの Store を探す。ほかの Store では、サイドバーの並びの順に、すべての Store のいまの ID(接頭辞)を見てから、すべての Store の旧い接頭辞、すべての Store の転送の記録の順に見る。例: サイドバーが Store「work」・Store「team」の順で、Store「work」のワークスペース「Web」が接頭辞 `WEB`・旧い接頭辞 `HH`、Store「team」のワークスペースがいまの接頭辞 `HH` のとき、`/s/work/w/HH/overview` は Store「work」のワークスペース「Web」を開き、`/s/nope/w/HH/overview` は Store「team」のワークスペースを開く。
- 履歴に積むのは、画面を移る操作と、上の表のタブの切り替えである。積まないのは、詳細パネルの開閉、絞り込みの入力、レイアウトの切り替え、折りたたみ、選択、メニュー、ダイアログ、設定のサブタブの切り替えである。
- 戻る・進むで画面を移ると、「画面の移り方」に従い、詳細パネル・メニューを閉じ、本文の先頭を表示する。画面の状態は、そのとき保存されている値で復元する。詳細パネルの説明やコメントの入力欄に保存していない内容があるときは、02 の確認「入力を破棄」を出し、「キャンセル」を押したときは、移らずにその画面に留まる。ダイアログやパレットを開いているときは、それらを閉じて移る(何も保存しない)。
- アドレスの画面がないとき(削除された、Store を非表示にした、このマシンから削除したなど)は、マイタスクを開く。見つからない理由は、02・03 の転送の記録の「見つからないとき」のトーストで案内する。移動したものは、旧 ID と同じく、いまある場所を開く(02、03)。
- ブラウザのタブを再読み込みすると、そのタブのアドレスの画面を開く。詳細パネルは閉じた状態で開く。アイテムの入口も、開いたあとはアドレスが替わるので、再読み込みでは開かない。開いているアイテムが削除されたあとの戻るは、画面は開けるが、パネルは閉じている(パネルは履歴に積まない)。
- `hh ui` が開く URL は、画面を指さない。この URL でアプリを開いたときは、最後に開いていた画面を開く(上の「画面の移り方」)。最後に開いていた画面は、いずれかのブラウザのタブで最後に移った画面である。
- 複数のブラウザのタブは、別々の画面を使える。画面の状態(絞り込み、レイアウトの設定、折りたたみ、ビューの未保存の変更)は、ブラウザのタブを開いた時点の値で始まり、あとの変更は別のブラウザのタブへ反映しない。2 つのブラウザのタブが同じ画面の状態を変えたときは、あとに変えた方が残る。Store の変更の反映は 06 に従う。
- アドレスは、`hh ui` が開いた画面の中でだけ使える(08)。アドレスをコピーして、別のブラウザのタブや別の人に渡しても、トークンがないので、08 の「トークンのない URL」の画面になる。URL を人へ渡して共有することは、この仕様では定めない。

### 新しいタブで開く

アプリの中の操作で、画面や詳細パネルの行き先を、新しいタブで開ける。

- 画面を移る、または詳細パネルを開く部品(サイドバーの項目、パンくずとタブ、行のタイトルと ID のリンク、アクティビティ・受信箱のリンク)を、Ctrl+クリック(Cmd+クリック)、Shift+クリック、中クリックすると、押したのと同じ行き先を新しいタブで開く。ステータスのボタンやメニューの項目のように、操作を行う部品は対象にしない。通知の行のリンクを新しいタブで開いても、通知は既読にならない(06)。
- コマンドパレットで、行き先のある候補(アイテム・プロジェクト・ワークスペース・ビュー・最近開いたもの・画面を開くコマンド)を Ctrl+Enter(Cmd+Enter)で選ぶと、新しいタブで開き、パレットを閉じる(02)。ダイアログを開く候補と操作を行う候補では、Enter と同じ動きになる。
- アイテムは、そのアイテムの入口で開く。新しいタブでは、そのアイテムのプロジェクトのツリーが開き、詳細パネルが開いた状態になる。
- アプリの中の操作で開いた新しいタブは、元のタブと同じように使える。ブラウザの右クリックメニューの「新しいタブで開く」や、アドレスをコピーして貼り付けて開いたタブは、`hh ui` が開いた URL ではないので、08 の「トークンのない URL」の画面になる。
- 新しいブラウザのタブは、元のタブとは別に動く。開いた時点の画面の状態で始まり、画面の状態(絞り込み、レイアウト、折りたたみ)の変更は互いに反映しない。Store の変更の反映は 06 に従う。閲覧のみの Store の行き先も開ける。

## キーボード

| キー | 動作 |
|---|---|
| Ctrl+K(Cmd+K) | コマンドパレットを開く。ダイアログを開いているときは使えない。パレットから選んだ候補がダイアログを開くときは、パレットを閉じてから開く |
| C | アイテムを作成する。入力中とダイアログを開いているときは使えない |
| / | 絞り込みの入力欄に移る。入力中とダイアログを開いているときは使えない |
| Esc | 開いているものを閉じる。メニュー、絞り込み欄の候補、パレット、ダイアログ、詳細パネル、サイドバーの順。候補が出ているとき、1 回目は候補だけを閉じる。候補は欄にフォーカスがあるあいだだけ出る。入力欄の中身が保存してある内容と違うときは、確認ダイアログ「入力を破棄」を出す(02)。日本語入力の変換中の Esc は、変換の取り消しに使い、この確認の対象にしない |
| Shift+Ctrl+S(Shift+Cmd+S) | 「すべて同期」を実行する(06)。入力中でも、ダイアログを開いているときでも使える |
| Enter | 1 行の入力欄で確定する。複数行の入力欄では Ctrl+Enter(Cmd+Enter)で確定する。日本語入力の変換を確定する Enter では確定しない |
| Enter・Space | ボタンとして働く要素(行の見出しなど)を押す。ツリーの行そのものにフォーカスがあるときは、04 の「ツリーのキー操作」に従う |

ツリーの行にフォーカスがあるときのキー(矢印、Enter、Space、S、K、C、Alt+↑↓、Alt+Shift+↑↓、メニューキー)は 04 に定める。Tab・Shift+Tab はツリーの中でも通常のフォーカス移動である。

ドラッグでできる操作には、どれもメニューかセレクトでも同じことができる経路を用意する。ドラッグはマウスとタッチの両方で動くようにする。

## 文言

画面の動詞は、非表示・削除・解除・移動・復元・変更・選択・検索・入力のような、画面でよく使う語にそろえる。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| ダイアログを開いているときの Ctrl+K | ダイアログを開いていても開く | ダイアログを開いているときは使えない。C キー・/ キーと同じ | ユーザーの指示(2026-11-12)。パレットとダイアログが重なって開くのを避けるため |
| 元に戻す | Ctrl+Z・トーストの「元に戻す」・コマンドパレットで戻せる。同期すると戻せる履歴がすべて消える | 元に戻す・やり直しの仕組みを持たない | ユーザーの指示(2026-11-12)。管理が複雑になる。誤操作で押したとき、何を戻したか分からないため |
| 閲覧のみの Store | 操作してから保存のときに断る。帯はワークスペースとプロジェクトの画面だけ | 操作できない見た目にし、候補からも外す。詳細パネル・マイタスク・検索・保存したビューにも帯を出す | 操作のあとで断られるより、先に分かるほうが迷わないため |
| メンバー | 全 Store で 1 つの一覧 | Store ごとの一覧を Store の中で共有する | 担当者の候補は、その Store を使う人であるべきため |
| 「あなた」 | 決まっていない(モックでは切り替えられる) | Store のアカウントのログイン名、なければこのマシンの「ログイン名」でメンバーと照合する。見つからなければ、Store をこのマシンに追加したときに自動で追加し、保存として記録する(あとで見つからなくなったら、次に書き込むときに追加する)。このマシンから削除してもメンバーからは外さない。メンバーから外す操作は持たない | 実際に操作している人をメンバーに結びつけるため。追加の手間をなくすため。外すと、複数のマシンで使う人や担当に影響するため。アクセスは GitHub の権限で止めればよく、残すほうが影響が少ないため(ユーザーの指示) |
| メールアドレス | なし | メンバーにも保存の作者情報にも持たない | チームで共有する Store に個人のメールアドレスを残さないため |
| 通知 | 他の人宛ての通知も自分のマシンに作る | 各マシンが、あなた宛ての通知だけを作る | 通知はマシンごとに持つため |
| メンバーにいない人の表示 | 人の一覧が全 Store で 1 つなので起きない | 「不明なユーザー」と表示する | メンバーを Store ごとに持つため、一覧にない人を指すデータがありうるため(ユーザーの指示) |
| 日付 | ローカルの日付と UTC の日番号が混ざる | すべてローカルの日付 | 日付の境目で 1 日ずれるのを防ぐため |
| 日付の範囲の文言 | 「終了日は開始日より後にしてください」など、画面によって違う | 「終了日は開始日以降にしてください」にそろえる | 同じ日を認めているのに「より後」と書いていたため |
| 書き込みを断る仕組み | 一部の操作が保存を通らず、元に戻せず記録もされない(メンバーの追加など) | Store を変える操作はすべて保存として記録する | 共有するデータの変更が記録に残らないのを防ぐため |
| 保存したビュー | Store に保存して共有する | このマシンに置く自分だけのもの | ユーザーの指示。共有のビューは見る人が追加している Store によって中身が変わるため |
| 複数の Store にまたがる操作 | 最初の Store か、先頭のアイテムの Store に 1 回だけ記録する | Store ごとに 1 回ずつ保存する | 変更を、変えた Store に記録するため |
| GitHub Issue の取り込み・同期・作成 | 設定の「GitHub Issue」で取り込み、Issue の状態・担当者・マイルストーンを同期し、詳細パネルから Issue を作れる | 作らない。Issue はリンクだけを残し、番号でリンクして、タイトルと状態(Open・Closed)を GitHub から読んで表示する。Issue の状態をアイテムの値に写すことはしない(自動化のルールが動いたときだけ、03 のとおり変える) | ユーザーの指示(2026-11-12)。取り込みと同期は、アイテムの値を GitHub と双方向に合わせるため、競合・制約・通知の細かな規則が増え、管理が複雑になるため。あとの復活の決定(同日)で自動化のきっかけ「リンクした Issue が閉じたとき」を残したので、「アイテムの値は変えない」を、ルールが動いたときだけ変える形に直した。双方向の同期はしないままで、決定の理由は覆さない |
| プロジェクトごとの決まり | 記載なし | プロジェクトの項目は固定のまま、下のアイテムの決まりの一部を、ワークスペースの設定の一部としてプロジェクトごとに持てる(03)。「Store で共有するもの」の表に加える | ユーザーの指示(2026-11-12)。現行にある機能を、設定はワークスペース単位という構造に合わせて残すため |
| PR の自動リンクとレビュー・チェックの表示 | 記載なし | 07 のとおり戻す。PR を自動でリンクした保存の実行者は「GitHub」。最後に読んだ時刻の記録とチェックの結果は、このマシンだけが持つ | ユーザーの指示(2026-11-12、復活)。チェックの結果は、1 回の CI のたびに保存を作らないため、Store に置かない |
| 内部の ID を渡す「PR 用の印をコピー」 | 記載なし | 内部の ID は画面に出さない。ただし、詳細パネルの「PR 用の印をコピー」は、PR の説明に貼る 1 行として内部の ID を渡す(02、07) | ユーザーの指示(2026-11-12、復活)。接頭辞を変えたり、アイテムを移したりしても、PR を同じアイテムに結びつけ続けるため。「画面に出ない内部の ID」の例外を 1 つ足す |
| 別のブラウザのタブ・別のプログラムの変更の反映 | 記載なし | CLI など別のプログラムや別のブラウザのタブが Store に保存した変更を、開いている画面へ自動で反映する(06)。開いている画面がそれでなくなったときは、マイタスクに移る | ユーザーの指示(2026-11-12、復活)。複数のタブや CLI を使っても、画面が古いままにならないため |
| remote の履歴が書き換えられたときの、のせ直し | 記載なし | 診断の修復と同じく、remote の履歴へののせ直しは「あなたが行った変更」として保存する(08)。「remote の履歴にそろえる」は取り消せず、確認ダイアログで「元に戻せません。」と示す | ユーザーの指示と回答(2026-11-12、復活)。古い履歴を残すと、書き換えの目的(誤って入れた秘密の削除など)に反するため |
| 閲覧のみの Store で変えられるレポートの選択 | 記載なし(01 は「レポートの単位とスプリントの選択」だけを挙げていた) | 累積フロー図の層の分けと、見積もりと実績の対象の選択も、無効にしない。累積フロー図の期間の入力も無効にしない | どれも Store に書かないため。期間は保存しないので、保存する選択の列挙には入れない |
| 日付で自動更新する表示 | マイタスク・期限の表示・ガントの今日の線など(列挙) | `today`・`-7d` などを含む検索の結果と、期間を指定していない累積フロー図(直近 21 日)も、日付が変わったときに更新する | 日付で決まる表示が、画面ごとにずれて残らないため |
| すべて同期のキー | 記載なし | Shift+Ctrl+S(Mac は Shift+Cmd+S)。サイドバーがある画面ならどこでも、入力中・ダイアログを開いているときも使える | ユーザーの指示(2026-11-12、現行のショートカットを残す)。ダイアログを開いているときの Ctrl+K を使えなくした決定とは理由が違う。同期はダイアログやパレットと重ならず、入力欄の内容も書き換えないため |
| ツリーのキー操作 | 記載なし | ツリーの行にフォーカスがあるときのキーは 04 に従う。Enter・Space の行にその旨を足す。Tab・Shift+Tab はフォーカス移動のまま。親を変えるのは Alt+Shift+↑↓ | ユーザーの指示と回答(2026-11-12、現行のキー操作を残す)。親子の決まりでは、現行の字下げ(Tab・Shift+Tab)が必ず断られるため、親を変えるキーを別にした |
