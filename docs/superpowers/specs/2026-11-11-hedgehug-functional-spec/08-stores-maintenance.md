# hedgehug 機能仕様 08: Store と保守

この文書は、設定画面の「一般」「Store」「削除済み」「診断と修復」と、「アカウントとメンバー」のうちメンバー、そして初回起動の案内と、サーバーに接続できないときの画面を定める。Store を用意する、メンバーを管理する、消したものを戻す・完全に消す、壊れたデータを直す、という Store の面倒を見る操作がここにまとまっている。用語と共通の決まり(書き込みの単位、閲覧のみの Store、「あなた」)は 01 を参照する。

## 設定画面の構成

設定は、サイドバー上部の歯車から開く。見出しは「設定」、補足は「このマシンの設定と、Store の管理」で、次の 5 つのタブを持つ。

| タブ | 内容 | 定める文書 |
|---|---|---|
| 一般 | 同期のタイミングの設定、キーボードの一覧 | 08(同期の動作は 06) |
| アカウントとメンバー | GitHub アカウント、メンバー | アカウントは 07、メンバーは 08 |
| Store | Store の一覧と管理 | 08(GitHub からの検索は 07) |
| 削除済み | 論理削除されたものの一覧、復元、完全に削除 | 08 |
| 診断と修復 | 壊れたデータの検出と修復 | 08 |

## 一般

最初に「ログイン名」を置く。このマシンで操作する人の名前で、Store に割り当てた GitHub アカウントがないときに、「あなた」を決めるのに使う(01)。入力欄 1 つで、Enter(日本語変換の Enter は確定しない)か、欄からフォーカスが外れたときに確定し、確定するとすぐに変わる。値が変わっていなければ何もしない。前後の空白は取り除いてから検査して保存する。使える文字はメンバーのログイン名と同じ(英数字・ハイフン・アンダースコア)で、39 文字以内(GitHub の上限)。合わなければ「英数字・ハイフン・アンダースコアのログイン名(39 文字以内)を入力してください」と表示して、元の値に戻す。初回起動で利用者が入力した値が入っている(01)。この設定も Store に保存しない。

「あなた」が変わる Store があるときは、確定の前に、「GitHub に使うアカウント」の選択を変えるとき(後述)と同じ確認ダイアログを出す。本文は Store ごとに 1 行で、「{Store 名} での あなた が @{旧ログイン名} から {新ログイン名} に変わります。」、ボタンは「変更」(警告色)と「キャンセル」。キャンセルすると欄は元の値に戻る。対象は、GitHub に使うアカウントがなく、このマシンのログイン名で「あなた」を決めている Store(閲覧のみ・非表示を含む)である。アカウントがある Store だけのとき、Store が 0 件のときなど、「あなた」が変わらないときは出さない。例: team-a(アカウントなし)で「taro」を「tarou」に直すと、「team-a での あなた が @taro から tarou に変わります。」と出る。「変更」を押したあと、次に team-a へ書き込むときに @tarou が自動でメンバーに加わり、トースト「tarou をメンバーに追加しました」が出る(後述の「GitHub に使うアカウント」と同じ)。

ログイン名の下に、時計のずれの警告を出すことがある。GitHub に問い合わせるたびに、GitHub の応答に付く日時とこのマシンの時計を比べ、5 分以上ずれていたら、警告の色で「このマシンの時計が GitHub の時刻より {N} 分進んでいます。同期で後から届いた変更の勝ち負けと、削除済みを完全に削除する日が、他の人とずれます。OS の日時の設定を確かめてください。」と表示する(遅れているときは「進んで」を「遅れて」にする)。5 分未満に戻ったら消す。閲覧のみの Store だけでも同じで、GitHub に問い合わせたことがないマシン(アカウントも remote もない)には出さない。保存時刻の補正はしない(06)。

次に「同期のタイミング」を置く。このマシンだけの設定として次の 4 つを置く。注意書きは「このマシンだけの設定です。」とする。

| 項目 | 内容 | 既定 |
|---|---|---|
| 裏で自動的に同期する | チェックボックス。オフにすると、下の 3 つの選択を無効にし、GitHub を自動で読むのも止める | オン |
| 間隔 | 「1 分ごと」「5 分ごと」「15 分ごと」「30 分ごと」「60 分ごと」から選ぶ | 5 分ごと |
| 書き込みのあと同期するまで | 「10 秒」「30 秒」「60 秒」から選ぶ | 30 秒 |
| GitHub を読む間隔 | 「5 分ごと」「15 分ごと」「30 分ごと」「60 分ごと」から選ぶ | 5 分ごと |

変更はすぐに有効になる。Store には書かないので、保存にもアクティビティにも残らない(01)。自動同期がいつ動き、いつ待つかは 06、「GitHub を読む間隔」の使われ方は 07 で定める。

remote を持つ Store が 1 つでも表示中なら、「すべて同期」のボタンを出す。押したときの動作と結果の表示は 06 に従う。

その下に「キーボード」の一覧を置く。内容は 01 の表のうち、Ctrl+K(コマンドパレット)、C(新規作成)、/(絞り込みに移る)、Esc(閉じる)、Shift+Ctrl+S(すべて同期)の 5 つを、そのままの順で並べる。続けて、見出し「ツリー」のもとに、04 の「ツリーのキー操作」の表を、そのままの順で並べる。

## Store

### 一覧

画面の上部に「Store は 1 つの git リポジトリです。共有する相手ごとに分けます。」と書き、右に「GitHub から検索」(07)、「フォルダから探す」、「Store を追加」を置く。Store がないときは、一覧を空にして、この 3 つのボタンだけを出す。

Store ごとに 1 つの枠を作り、追加した順に並べる。枠の中身は次のとおり。

| 場所 | 内容 |
|---|---|
| 見出し | Store の名前(色つき)、「N ワークスペース」。既定なら「既定」、非表示なら「非表示」、閲覧のみなら「閲覧のみ」の印 |
| ボタン | 「色」「非表示」(非表示のときは「表示」)「既定にする」(既定でない Store だけ。閲覧のみの Store では無効にして「閲覧のみの Store は作成先にならないため」と添える)「このマシンから削除…」 |
| 入力 | 「名前」の入力欄、「remote」の入力欄(空のとき「なし(このマシンだけ)」と薄く表示)、「GitHub に使うアカウント」の選択(「なし」と、登録済みのアカウントを「表示名 (@ログイン名)」で並べる) |
| 保存先 | この Store のコピーが、このマシンのどこにあるか(絶対パス、等幅。編集はできない)。右に「コピー」ボタン。押すとパスをクリップボードにコピーし、トースト「保存先のパスをコピーしました」を出す。閲覧のみ・非表示の Store でも使える |
| ミラー | 「ミラー」の見出しと「追加」ボタン。ミラーごとに 1 行で、URL、状態(「最終送信 {相対時間}」。まだ送っていなければ「未送信」。送れなかったときは「送れませんでした: {短い理由}」を警告の色で(短い理由は、06「同期のエラー」のミラーの段落の 5 つの文)。閲覧のみの Store では「閲覧のみのため送りません」)、「削除」ボタン。remote がない Store は、「追加」を無効にして「remote を入れると使えます」と添える(後述の「ミラー」) |
| 同期の状況 | remote があれば「未送信 N 件 · 最終同期 …」。最終同期がなければ「なし」。remote があって GitHub に使うアカウントが「なし」なら、同期を試していなくても「同期エラー: アカウントが設定されていません」を添える。アカウントはあるが直前の同期が失敗したときは「同期エラー: {理由}」を添える(理由は 06 の同期のエラーの短い理由)。remote がなければ「remote がないため同期しません」。remote があれば「今すぐ同期」のボタンも出す。理由が「remote の履歴が書き換えられています」のときは、その下に「remote を元に戻すか、このマシンの履歴を remote の新しい履歴にそろえてください。」と、ボタン「remote の履歴にそろえる…」を出す(後述の「remote の履歴が書き換えられたとき」) |
| ワークスペース | 配下のワークスペースを 1 行ずつ。名前を押すとそのワークスペースの設定を開く。接頭辞、「N プロジェクト · M アイテム」を添える |

名前・色・非表示・remote・アカウント・ミラー・このマシンから削除は、このマシンだけの設定なので、閲覧のみの Store でも操作できる。閲覧のみになるかどうかは、GitHub の権限から決まる(07)。マウントで GitHub から読んだ権限が元になり、見直すのは、remote の変更とアカウントの選び替え(後述)のときだけである。

### 追加

「Store を追加」でダイアログ「Store を追加」を開く。remote を入れるかどうかで、新しく作るか、すでにあるものを clone するかが分かれる。

| 項目 | 内容 |
|---|---|
| 名前 | 必須。入力例は「team-b」 |
| remote(任意) | 入力例は「https://github.com/org/tasks.git」。github.com のリポジトリの URL に限る(後述の検査)。入れると clone する。空にすると、このマシンに新しい Store を作る |
| GitHub にリポジトリを作る | チェックボックス。初期はオフ。remote が入力されていて、GitHub に使うアカウントが「なし」でないときだけ選べる(remote が空のときは「remote を入れると選べます」、アカウントが「なし」のときは「アカウントを選ぶと使えます」と添える)。オンにすると、remote のリポジトリがなければ、private で作り、新しい Store として追加する。remote の owner が選んだアカウントのログイン名と同じなら個人のリポジトリ、違えばその owner の組織のリポジトリとして作る。すでに空のリポジトリがあれば、作らずに使う |
| GitHub に使うアカウント | remote がなくても選べる。「なし」と登録済みのアカウントから選ぶ。既定は、登録順の先頭のアカウント。アカウントがなければ「なし」 |
| ログイン名 | Store が 1 つもないとき(初回起動)だけ出す。一般のログイン名の設定と同じもの。必須で、初期値は次の順で決める。(1) このマシンのログイン名が設定済みならそれ、(2) なければ、ダイアログで選んでいる「GitHub に使うアカウント」のログイン名、(3) なければ空欄。(2) から入れた値は、アカウントの選択を変えたとき、利用者がまだ編集していなければ、新しいアカウントのログイン名に入れ替える。(1) の値は入れ替えない。欄の下に、注意書き「この名前はメンバーとして Store に残り、あとから消せません。」を添える。アカウントを選んでいるあいだは、続けて「この Store では GitHub のログイン名 @{アカウントのログイン名} があなたになります。ここに入れた名前は、アカウントを使わない Store で使います。」を出す(「なし」のときは出さない)。空や使えない文字(39 文字を超える場合を含む)なら「英数字・ハイフン・アンダースコアのログイン名(39 文字以内)を入力してください」と表示して、何も作らない。「追加」を押すと、欄の値がこのマシンのログイン名になる(一般の設定と同じ)。Store が 0 件のときなので、「あなた」が変わる Store はなく、確認ダイアログは出ない |
| ワークスペースの名前 | 必須。remote が空のとき、または「GitHub にリポジトリを作る」がオンのときに出す。この Store に最初に作るワークスペースの名前。検査は「ワークスペースの作成」(03)と同じ |
| ワークスペースの接頭辞 | 必須。名前と同じときに出す。入力と同時に大文字にする。入力例は「WEB」。検査は「ワークスペースの作成」(03)と同じ。入れた接頭辞で、アイテムの ID は「WEB-1」、プロジェクトは「WEB-P1」のようになる |
| 色 | 7 色(teal・orange・purple・sky・pink・olive・brown)から選ぶ。既定は、ほかの Store が使っていない最初の色。すべて使われていれば teal |

ダイアログの下に「remote を入れると clone し、空にすると新しい Store を作ります。」と添える。続けて「「GitHub にリポジトリを作る」をオンにすると、remote のリポジトリがなければ作って、新しい Store を作ります。」と添える。

「追加」を押すと、次の順に確かめる。1 つでも合わなければ、ダイアログを閉じずに、その理由を赤字で示す。何も作らない。

| 条件 | 表示 |
|---|---|
| 名前が `^[A-Za-z0-9][A-Za-z0-9_-]*$` に合わない | 名前は英数字、ハイフン、アンダースコアにしてください(先頭は英数字) |
| 同じ名前の Store がある(大文字と小文字を区別しない) | 同じ名前の Store があります |
| remote が github.com のリポジトリの URL でない(受け付ける形は `git@github.com:owner/name(.git)` と `https://github.com/owner/name(.git)` の 2 つで、末尾の `/` は無視する。clone は試みない。remote が空のときは検査しない) | remote は github.com のリポジトリの URL を入力してください |
| remote が、すでに追加した Store の remote と同じ(後述の比べ方) | この remote はすでに Store「{その Store の名前}」として追加されています |
| ワークスペースの名前か接頭辞の欄を出していて、「ワークスペースの作成」(03)の名前・接頭辞の検査に合わない | 03 と同じ文言 |
| 「GitHub にリポジトリを作る」がオンで、remote のリポジトリがすでにあり、空でない | {remote} は空ではありません。「GitHub にリポジトリを作る」をオフにして、clone して追加してください |
| 「GitHub にリポジトリを作る」がオンで、作れない | 07「GitHub との通信に失敗したとき」の表示(書き込む権限がない、通信できない、認証エラー、利用上限) |
| clone できない(URL が違う、アカウントに権限がない、つながらない) | {remote} を clone できません。remote の URL とアカウントを確認してください |
| clone したリポジトリが hedgehug の Store ではない | {remote} は hedgehug の Store ではないため追加できません |
| clone したリポジトリが、この hedgehug より新しい版の形式で保存されている | {remote} は新しい版の hedgehug で作られています。hedgehug を更新してください |

clone している間は、「追加」を押せないようにして「clone しています…」と表示する。作成するときは、「追加」を押せないようにして「リポジトリを作っています…」と表示する。

remote を入れたときは、clone したリポジトリが空(hedgehug のデータが何もない)で、書き込める Store になるときだけ、clone のあと、ダイアログを閉じずに「ワークスペースの名前」「ワークスペースの接頭辞」の欄を出し、「追加」で続ける。合わない入力は、上の表のワークスペースの行と同じに断る。キャンセルすると、何も追加しない。hedgehug のデータがあるリポジトリと、閲覧のみの Store には、この欄を出さない。

remote の同じ・違うは、ホスト名、owner、リポジトリ名を取り出して比べる。大文字と小文字は区別せず、末尾の「.git」は無視する。SSH の形式(`git@github.com:org/tasks.git`)と HTTPS の形式(`https://github.com/org/tasks`)は、同じ remote として扱う。remote を変えるとき(後述)にも同じ比べ方を使う。

hedgehug の Store でないリポジトリとは、中身が空ではなく、hedgehug が保存したデータを持たないリポジトリである。空のリポジトリは、Store でないとは扱わない。

Store のコピーは、このマシンの保存先に置く。保存先は、追加したときの名前から決まり、名前を変えても変わらない。同じ名前の保存先(大文字と小文字を区別しない)がすでにあるときは、名前の末尾に -2、-3 を付けた保存先にする。保存先の場所は、設定の「Store」の枠で確かめられる。

条件に合えば Store を一覧の末尾に追加し、使っているアカウントと色を設定する。追加した直後の扱いは次のとおり。

- 新しく作った Store と、中身が完全に空のリポジトリ(hedgehug のデータが何もない)を clone した Store には、ダイアログで入力された名前と接頭辞のワークスペースを 1 つ作る。clone したリポジトリに hedgehug のデータがあれば、ワークスペースが 0 件でも、すべて削除済みでも、作らない。そのときのサイドバーは「ワークスペースはまだありません」と「ワークスペースを追加」を出す(04)。閲覧のみの Store は書き込めないので、空でも作らず、欄も出さない。
- 書き込める Store では、「あなた」がまだメンバーに見つからないときは、追加した時点で、ダイアログなしで自動的にメンバーに追加する(01)。この書き込みは保存になり、アクティビティに「メンバー {ログイン名} を追加」と残る。ワークスペースを作るときは、同じ保存で作る。追加するメンバーの表示名とログイン名は、どちらも「あなた」のログイン名とする。表示名は、あとから自分の行の編集で変えられる。トースト「{ログイン名} をメンバーに追加しました」を出す。閲覧のみの Store では追加しない。
- ワークスペースを作ったときのトーストは「{名前} を追加しました。ワークスペース「{ワークスペースの名前}」を作りました」。作らなかったときは「{名前} を追加しました」。
- 「GitHub にリポジトリを作る」で作ったときは、リポジトリに topic「hedgehug-store」を付ける(GitHub 上で Store のリポジトリを見分ける印で、Store の検索には使わない。07)。付けられなかったときは、追加は成功のまま、トースト「topic を付けられませんでした。GitHub で付けるとリポジトリを見つけやすくなります」を出す。すでにあった空のリポジトリを使うときは付けない。
- 「GitHub にリポジトリを作る」で作った Store の最初の送信は、追加が終わったあとの通常の同期として行う(06)。送れなかったときも、Store の追加は成功のままで、同期の状況に「同期エラー: {理由}」を出す。

初回起動の案内から追加するときも、設定の「Store」から追加するときも、このダイアログを使う。GitHub からの検索で見つけた Store を追加するときは、07 の手順に従い、上の表のうち remote に関わる検査のうち、clone、Store かどうか、新しい版の形式の 3 つを同じ文言で行う。「同じ remote」の検査は置かない(追加済みのリポジトリの行には「マウント」がなく、同じ remote には到達しないため)。色は、上の表の既定と同じにし、選択は設けない(あとから設定の「Store」で変える)。マウントした Store が空のリポジトリだったときは、上の clone した Store と同じに、ワークスペースの名前と接頭辞を入力させる(07)。そのとき Store が 1 つもなければ、「マウント」の前にログイン名の入力欄を出す(07)。初期値は、このマシンのログイン名が設定済みならそれ、なければそのアカウントの GitHub のログイン名で、欄の下には上の表と同じ注意書きを出す(アカウントのログイン名は、その行のアカウントのもの)。空や使えない文字なら、上の表のログイン名と同じ文言で断る。

Store の名前は、追加したあとに、Store の枠の「名前」の入力欄で変えられる(後述)。

### フォルダから探す

このマシンのフォルダにある Store のコピーを見つけて、このマシンの Store として取り込む。「このマシンから削除」でコピーを残した Store や、別の場所に置いてあるコピーを使い続けるための入口である。入口は、設定の「Store」の「フォルダから探す」と、初回起動の案内の手順 2 である。

ダイアログ「フォルダから探す」に、「フォルダ」の入力欄(入力例は「/home/taro/ghq」)と「探す」ボタンを置く。欄が空のあいだは「探す」を無効にする。「探す」を押すと、そのフォルダの下から、hedgehug の Store のコピー(hedgehug が保存したデータを持つ git リポジトリ)を探す。見つけたコピーの中は、さらに探さない。探している間は「探しています」と表示する。コピーの origin があって github.com のリポジトリの URL でないものは、remote を引き継げないため、一覧に出さない。この hedgehug より新しい版の形式で保存されたコピーは一覧に出し、「取り込む」を押したときに「{パス} は新しい版の hedgehug で作られています。hedgehug を更新してください」と断る。

一覧の各行に次を表示する。

| 表示 | 内容 |
|---|---|
| パス | 見つかったコピーの場所(等幅) |
| remote | コピーの origin の github.com のリポジトリの URL。origin がないときは「なし(このマシンだけ)」 |
| 名前の入力欄と「取り込む」ボタン | まだ取り込んでいないもの。名前の初期値は、フォルダ名から末尾の `.git` と `-tasks` を除き、07 の「GitHub から Store を検索」と同じ規則で整えたもの。このマシンに Store が 1 つもないときは、「ログイン名」の入力欄も出す(07 と同じ。初期値は、このマシンのログイン名が設定済みならそれ、なければ空欄) |
| 「追加済み」(灰) | remote が、すでに追加した Store の remote と同じもの(「追加」の比べ方)。「取り込む」は出さない |
| 「取り込みました」(灰) | このダイアログで取り込んだもの。ダイアログは開いたままにする |

「取り込む」を押すと、名前を「Store を追加」と同じ順で確かめ(形、重複)、合わなければその行の下に赤字で理由を出す。通ったら、コピーの中身をこのマシンの保存先にコピーして、Store を一覧の末尾に追加する。元のフォルダは変えない。remote は上の表のとおり引き継ぎ、「GitHub に使うアカウント」は「Store を追加」と同じ既定にする。色は 07 の「マウント」と同じ既定にする(選択は設けない)。remote があって、アカウントがあるときは、GitHub に書き込みの権限を問い合わせ、読み取りのみなら閲覧のみの Store にする。問い合わせられないときは、書き込める Store にする。取り込んだ Store にワークスペースは作らず、欄も出さない(取り込むのは hedgehug のデータを持つコピーだけである)。書き込める Store では、「あなた」がメンバーにいなければ、追加した時点で自動的にメンバーに追加する(01)。取り込みは Store の追加として扱い、前に受け取った履歴の記録は持たない。最初の同期は、共通の履歴の検査だけを行う(06)。

トーストは「{名前} を取り込みました」と、必要なら「{ログイン名} をメンバーに追加しました」を、別々に出す。

見つからなかったときは「Store は見つかりませんでした」、読めないフォルダがあったときは「読めないフォルダが N 件ありました」を表示する。起点のフォルダが存在しない、または読めないときは「フォルダを開けません」を赤字で表示する。

### 名前の変更

「名前」の入力欄を書き換えて、Enter か、欄からフォーカスが外れたときに確定する(「remote」の入力欄と同じ)。前と同じなら何もしない。検査は追加のときと同じ文言で行い、合わないときは入力欄を元の名前に戻す。自分以外の Store との重複は、大文字と小文字を区別せずに比べる。大文字と小文字だけを変える(tema-a から Tema-A)のは認める。その Store を同期しているあいだは、「{Store 名} を同期しています。終わってから変更してください」と断る。トーストは「Store の名前を変更しました」。

名前はこのマシンだけの呼び名なので、Store には書かず、保存にもアクティビティにも残らない。ほかのマシンの名前は変わらない。閲覧のみの Store、非表示の Store でも変えられる。名前を出すところは、すべて新しい名前で出る。保存したビューと、いまの検索のクエリにある `store:旧名`(大文字と小文字を区別しない)は、`store:新名` に書き換える。保存先(枠の「保存先」の行)は、名前を変えても変わらない。

### 色

「色」を押すと、7 色の名前を並べたメニューが開き、いまの色にチェックが付く。選ぶとすぐに変わる。色は Store の名前の印とサイドバーの点に使う。

### 既定の Store

既定の Store は、コマンドパレットの「ワークスペースを追加」で、ダイアログの「Store」の初期値になる(03)。このマシンだけの設定で、Store には書かず、保存にもアクティビティにも残さない。

「既定にする」を押すと、すぐに変わり、トースト「既定の Store を {名前} にしました」を出す。既定は 1 つだけで、前の既定の印は外れる。「既定を外す」操作はない。

既定がなくて、書き込める Store を追加したときは、その Store が既定になる(閲覧のみの Store は既定にならない)。既定の Store をこのマシンから削除すると、既定はなくなる。非表示にしても既定のままだが、非表示のあいだは初期値に使わない。

### 非表示と再表示

「非表示」を押すと、その Store はないものとして扱う。サイドバー、マイタスク、検索、受信箱、アクティビティには出ず(保存したビューの結果にも、その Store のアイテムは出ない)、作成ダイアログと移動先の候補にも出さない(ワークスペースの作成先と移動先を含む)。自動同期と「すべて同期」の対象からも外し、GitHub の自動の取り直しも、PR の自動リンクの探し方もしない。データは消えず、設定の Store の一覧と、「今すぐ同期」は使える。

非表示にしたとき、すでに始まっている同期は最後まで続け、途中で止めない。結果のトーストは、非表示にしたあとも出す。同期で受け取った変更から作る通知は作るが、非表示のあいだは受信箱に出さず、未読にも数えない。再表示すれば出る。

サイドバーの Store 名の右にあるメニューからも、非表示にできる。このメニューの項目は次の 4 つである。

| 項目 | 動作 |
|---|---|
| 今すぐ同期 | その Store を同期する(06)。remote がなければ無効にして「remote なし」と添える |
| ワークスペースを追加 | 03 のダイアログを開く |
| Store の設定 | 設定の「Store」タブを開く |
| サイドバーで非表示 | その Store を非表示にする |

非表示にしたとき、開いていた画面がその Store のワークスペース・プロジェクトなら、マイタスクへ移る。トーストは「{名前} を非表示にしました。設定の「Store」から再表示できます」。

「表示」を押すと、元の表示に戻る。

### remote の変更

remote の入力欄を書き換えて確定すると、すぐに変わる。空にすると remote をなくし、その Store はこのマシンの中だけで使う。未送信の変更は、そのまま残る。

- 入れた remote が github.com のリポジトリの URL でないときは、追加のときと同じ検査・同じ文言で断り、入力欄を元の値に戻す。検査の順は追加のときと同じで、同じ remote の検査より先に行う。
- 入れた remote が別の Store の remote と同じなら、追加のときと同じ理由で断り、入力欄を元の値に戻す。
- 入れたときのトーストは「remote を設定しました」、空にしたときは「remote を削除しました」。
- 閲覧のみの Store では、remote の変更のときに「閲覧のみ」の印を見直す(書き込める Store は見直さない。push が拒否されたときに 06 で気づく)。remote を空にしたときは印を外し、その Store は書き込めるローカルの Store になる。トーストは「remote を削除しました。{Store 名} は編集できます」。remote を別の github.com のリポジトリに変えたときは、新しい remote の権限を、その Store のアカウントで GitHub に問い合わせる。書き込めるなら印を外し、トーストは「remote を設定しました。{Store 名} は書き込めるようになりました」。読み取りのみ・読めないときは印を残す。通信に失敗したときは、印を残し、変更自体は受け入れ、07 の「GitHub との通信に失敗したとき」の表示をエラーのトーストで出す。
- 印を外したあと、「あなた」がメンバーにいなければ、次の書き込みで自動的にメンバーに追加する(01)。「閲覧のみ」に戻す操作は設けない。戻すには、このマシンから削除して、マウントし直す(07)。
- remote を入れたのに、GitHub に使うアカウントが「なし」のときは、同期の状況に「同期エラー: アカウントが設定されていません」と出す。
- 入れた remote につながらない、または中身が合わないときは、変更はそのまま受け入れ、最初の同期で「同期できません」と表示する(06)。
- 入れた remote の履歴が、この Store と共通の履歴を持たないときは、同期で合わせず、最初の同期で断る(06)。remote が空のリポジトリは、最初の送信として認める(上の「空のリポジトリ」)。同じ Store の fork やコピーなど、共通の履歴があるものも認める。直すには、remote を元に戻すか、Store をこのマシンから削除して clone し直す。このマシンだけで作った Store を既存のチームの Store にまとめたいときは、「別の Store へ移動」(03)を使う。
- remote を変えたとき(上の比べ方で、違うリポジトリになったとき)と、remote を空にしたときは、前に受け取った履歴の記録を捨てる。次の同期は、書き換えの検査ではなく、共通の履歴の検査を行う。同じ remote の別の書き方(SSH と HTTPS など)への書き換えでは、捨てない。Store の追加(clone・フォルダから探して取り込む)のあとの最初の同期も、共通の履歴の検査だけを行う。
- 入れた remote が、その Store のミラーと同じなら、追加のときと同じ理由で断り、入力欄を元の値に戻す。

### remote の履歴が書き換えられたとき

同期が「remote の履歴が書き換えられています」で止まったとき(06)、設定の「Store」の同期の状況に、説明とボタン「remote の履歴にそろえる…」を出す。診断(「診断と修復」)には載せない。閲覧のみの Store でも使える。同期が動いているあいだは無効にし、「同期しています」を添える。オフラインでも使える。

押すと、確認ダイアログ「remote の履歴にそろえる」を出す。本文は次の順に並べる。行は、当てはまるものだけを出す。

| 行 | 出す条件 |
|---|---|
| 「{Store 名} の remote の履歴が書き換えられています。このマシンの履歴を、remote の新しい履歴に置き換えます。」 | いつも |
| 「まだ送っていない保存 {N} 件は、新しい履歴の上に 1 回の保存としてのせ直します。」 | 書き込める Store で、N が 1 以上 |
| 「まだ送っていない保存はありません。」 | 書き込める Store で、N が 0 |
| 「remote の新しい履歴にない {M} 件のアイテム(削除済みを含む)が、このマシンからも消えます。」 | M が 1 以上。プロジェクト・ワークスペースがあれば「{P} 件のプロジェクト」「{W} 件のワークスペース」も並べる |
| 「そのものへの未送信の変更は、のせ直せません。内容は受信箱の「同期の修復」に残します。」 | M が 1 以上で、のせ直せない変更がある |
| 「ミラー {K} 件には、古い履歴が残ります。送られなくなるので、ミラーを削除して、空のリポジトリに付け直してください。」 | その Store のミラーが 1 件以上(K 件) |
| 「remote が誤って書き換えられたときは、先に remote を元に戻してください。戻れば、そろえずに同期が再開します。」 | いつも |
| 「元に戻せません。」 | いつも |

ボタンは「そろえる」(警告色)と「キャンセル」。N は、同期カードの「未送信」と同じ数え方である。キャンセルすると何も変えない。

実行すると、次の順に行う。

1. 同期で受け取った、書き換えられた remote の履歴を、このマシンの履歴にする。
2. 未送信の保存を、06「同時に編集したとき」の合わせ方で、新しい履歴の上にのせ直す。基準は、書き換えの前に受け取っていた履歴で、項目ごとの保存時刻は元のままにする。remote の新しい履歴にないもの(アイテム・プロジェクト・ワークスペース)は、完全に削除されたものと同じに扱う(06「完全な削除と重なったとき」)。そのものへの未送信の変更と、そのものの下に作った未送信のアイテムは、のせ直さない。
3. 受信箱の、消えたものの通知を消す。のせ直せなかった変更を、アイテム(プロジェクト・ワークスペース)ごとに 1 件、受信箱の「同期の修復」に出す。本文は「{ID} は remote の新しい履歴にないため、あなたの変更は反映されませんでした: {変更の内容}」である。{変更の内容} は、プロパティなら「{プロパティ名}を {値} に変更」、コメントなら「コメント: {本文全体}」、説明なら「説明: {本文全体}」、下に作ったアイテムなら「「{タイトル}」を作成」を、1 行ずつ並べる。プロジェクト・ワークスペースのときは、{ID} のかわりに「プロジェクト「{名前}」」「ワークスペース「{名前}」」と書く。
4. このマシンの古い履歴は残さない。
5. 続けて、通常の同期を行う。のせ直した保存が remote へ送られる。

途中で止まったときは、元のままになる。のせ直した保存は、書き込める Store にだけできる。閲覧のみの Store では、保存を作らず、履歴だけを置き換える。

トーストは「remote の履歴にそろえました」。のせ直せなかった変更があるときは、「remote の履歴にそろえました。戻せなかった変更が {K} 件あります。受信箱の「同期の修復」を見てください」(K はアイテム・プロジェクト・ワークスペースの数)。アクティビティには、のせ直した保存があるときだけ、実行者あなたで「remote の履歴にそろえ、未送信の保存 {N} 件をのせ直し」と残る。

次の場合は、ボタンを押せなくし、説明を出す。

| 場合 | 出す説明 |
|---|---|
| 書き換えられた remote の履歴に、前に受け取った履歴のワークスペースが 1 つも残っていない(別の Store になっている) | 「remote は、この Store とは別の Store になっています。remote を元に戻すか、Store をこのマシンから削除して clone し直してください。」 |

hedgehug は remote の履歴を書き換える送信をしない。ミラーへの送信も書き換えない。置き換わるのは、このマシンにあるコピーだけである。

### ミラー

ミラーは、Store の保存を、remote のほかにも送っておくための書き込み先である(例: 個人のアカウントのリポジトリにバックアップを置く)。送るだけで、ミラーからは受け取らない。github.com のリポジトリだけで、その Store の「GitHub に使うアカウント」で送る。このマシンだけの設定で、Store には書かない。

「ミラー」の「追加」を押すと、入力欄が 1 つ出る。URL を入れて Enter か、欄からフォーカスが外れたときに確定し、すぐに追加する。空のまま外れたときは何もしない。確かめる順と表示は、「Store を追加」の remote と同じ(github.com の URL の形)に、次を足す。

| 条件 | 表示 |
|---|---|
| その Store の remote と同じ(比べ方は「追加」と同じ) | この remote はすでに Store「{その Store の名前}」として追加されています |
| 同じ Store の別のミラーと同じ | このミラーはすでに追加されています |
| 別の Store の remote またはミラーと同じ | この remote はすでに Store「{その Store の名前}」として追加されています |

合わないときは、入力欄を空に戻す。通ったときのトーストは「ミラーを追加しました」。追加のときは通信しない。つながらない、または権限がないときは、最初の同期でミラーの行に出す(06)。

「削除」を押すと、確認なしでミラーを外す。トーストは「ミラーを削除しました」。ミラーのリポジトリの中身は GitHub に残る。

remote を空にすると、ミラーも外す(トースト「remote を削除しました。ミラー {K} 件も外しました」)。閲覧のみの Store では、ミラーの欄を操作できるが、送らない。

### GitHub に使うアカウント

「GitHub に使うアカウント」の選択を変えると、すぐに変わる。remote がなくても選べる。remote があって「なし」にしたときは、同期の状況に「同期エラー: アカウントが設定されていません」と出る。アカウントを選び直すと、次の同期で元に戻る。アカウントの登録・編集と削除は 07 で定める。アカウントを削除したときは、それを使っていた Store の選択が「なし」になる(07)。

「あなた」の決まり方は、この選択にも関わる(01)。選択を変えると「あなた」が変わるときは、変える前に確認ダイアログを出す。本文は「{Store 名} での あなた が @{旧ログイン名} から {新ログイン名} に変わります。」で、ボタンは「変更」(警告色)と「キャンセル」。キャンセルすると選択は変わらない。「あなた」が変わらないときは出さない。アカウントを削除して「あなた」が変わるときの確認は 07 で定める。選択を変えたあとに、「あなた」がメンバーに見つからなくなったときは、次にその Store へ書き込むときに、自動的にメンバーに追加する(トースト「{ログイン名} をメンバーに追加しました」)。

閲覧のみの Store でアカウントを選び替えたときは、remote を変えたときと同じ問い合わせを、新しいアカウントで行う。書き込めるなら印を外し、トースト「{Store 名} は書き込めるようになりました」を出す。それ以外のときは印を残す(選択自体は変わる)。書き込める Store は見直さない。

### このマシンから削除

「このマシンから削除…」を押すと、確認ダイアログ「このマシンから削除」を出す。本文は次のとおり。

- 共通: 「{Store 名} をこのマシンから削除します。」
- remote があるとき: 「remote のリポジトリはそのまま残り、あとで追加し直すことができます。」
- remote がないとき: 「remote がないため、中のタスクはすべて失われます。」(強調する)
- 未送信の変更があるとき(行を改めて): 「未送信の変更が N 件あります。」(強調する)
- 最後に(行を改めて): 「元に戻せません。」

本文の下に、チェックボックス「このマシンのコピーを残す」を置く(初期はオフ)。オンにすると、本文を次のとおりに変える。「{Store 名} を一覧から外します。このマシンのコピーは {パス} に残ります。」を最初に置き、remote があるときは「remote のリポジトリはそのまま残り、あとで追加し直すことができます。」を続ける。未送信の変更があるときは、行を改めて「未送信の変更が N 件あります。」(強調する。remote があるときは「取り込み直したあと、同期で送ります。」を添える)を続ける。「remote がないため、中のタスクはすべて失われます。」と「元に戻せません。」は出さない。続けて「あとで「フォルダから探す」で取り込み直せます。」を出す。ボタンは「外す」(警告色にしない)と「キャンセル」にする。トーストは「{名前} を一覧から外しました。コピーは {パス} に残っています」とする。

ボタンは「削除」(警告色)と「キャンセル」。実行すると、チェックがオフなら、このマシンにある Store のコピーを消す。オンなら、コピーは消さず、一覧から外すだけにする。どちらも、そのあとの扱い(通知、画面、保存したビュー、「あなた」)は同じである。そのあと、その Store のワークスペース・プロジェクト・アイテムは、このマシンでは見えなくなり、受信箱にあったその Store の通知も消える。保存したビューはこのマシンに置いたものなので消えず、その Store のアイテムが出なくなるだけである。remote から追加し直すと、中身が戻る(通知は戻らない)。開いていた画面がその Store のものなら、マイタスクへ移る。トーストは「{名前} をこのマシンから削除しました」。

その Store を同期しているあいだは、「{Store 名} を同期しています。終わってから実行してください」と断る。

この操作は Store の中身を変えないので、削除済み(論理削除)には入らず、保存もアクティビティも残さない。「あなた」はその Store のメンバーに残り、担当も変わらない(01)。アカウントは変わらない。最後の Store も削除できる。Store が 0 件になったら、初回起動の案内に戻る。

## メンバー

メンバーは「設定 > アカウントとメンバー」の「メンバー」に、Store ごとの枠で並べる。1 つの Store の中で共有する一覧で、担当者・オーナー・メンションの候補になる(01)。枠の見出しに Store の名前(閲覧のみの Store には「閲覧のみ」の印)と、「GitHub から取り込み」のボタンを置く。手でメンバーを追加する操作はない。メンバーに載るのは、Store に参加した本人(01)、「GitHub から取り込み」で取り込んだコラボレーター(07)、別の Store から移したワークスペース・プロジェクト・アイテムの担当者など(02・03)である。メンバーを削除する操作もない。Store をこのマシンから削除してもメンバーには残り、アクセスは GitHub の権限で止める(01)。Store がないときは、「メンバー」の欄ごと出さない。非表示の Store の枠も出す。

| 行の内容 | |
|---|---|
| 並び | 追加した順 |
| 表示 | アバター、表示名、「@ログイン名」、「担当 N 件」(削除済みを除く) |
| 「あなた」 | その Store の「あなた」(01)のメンバーに「あなた」の印を付ける |
| ボタン | 編集(「あなた」の行だけ) |

「GitHub から取り込み」は、GitHub のコラボレーターをメンバーに加えるボタンである。取り込みの中身と、使える条件は 07 で定める。使えないときは無効にする。

メンバーは、ログイン名(大文字と小文字を区別しない)で 1 人である。同期で同じログイン名の行が 2 つになったときは、あとから同期した方(06 の「1 つしかないものが 2 つになったとき」と同じ決め方)の行を外して 1 行にする。担当・オーナー・コメントの書き手はログイン名で結びつくので、外しても参照は切れない。表示名は残した行のものになる。この統合は「同期の修復」として保存し、アクティビティに実行者「同期」で「メンバー {ログイン名} の重複を統合」と残す。通知は作らない。同期で直しきれなかった重複は、診断で見つけて直す(後述)。

閲覧のみの Store では、「GitHub から取り込み」と編集を無効にして「閲覧のみの Store です」と添える(01)。

### 編集

「あなた」の行の編集でダイアログ「メンバーを編集」を開く。ほかの人の行には編集を出さない。表示名やログイン名は本人のもので、ほかの人が書き換えるものではないためである。項目は次のとおり。

| 項目 | 内容 |
|---|---|
| 表示名 | 必須。前後の空白は取り除く。50 文字以内。同じ表示名の人がいてもよい(メンバーはログイン名で識別する) |
| ログイン名(@ で呼ぶ名前) | 入力欄を無効にし、「あなたの対応が外れるため変更できません」と添える |

表示名が空のときは、ダイアログを閉じずに「表示名を入力してください」と赤字で示し、何も変えない。50 文字を超えるときも同じで、「表示名は 50 文字以内で入力してください」と示す。

トーストは「{表示名} を変更しました」。1 回の保存になり、アクティビティに「メンバー {表示名} を変更」と残る。

## 削除済み

削除したプロジェクト・アイテム・ワークスペース・スプリント・リリースは、すぐには消えず、この画面に入る(論理削除)。削除の操作そのものは、アイテムは 02、ワークスペースは 03、スプリント・リリースは 05 で定める。ここでは、一覧、復元、完全に削除を定める。

### 一覧

画面は Store ごとの枠に分ける。枠の見出しには、Store の名前(閲覧のみの Store には「閲覧のみ」の印)と、保持日数の選択と「保持日数を過ぎたものを完全に削除…」のボタンを置く。注意書きは次のとおり。

> 削除したものは、保持日数のあいだ、この画面から元の場所に復元できます。保持日数を過ぎると自動で完全に削除します。完全に削除すると元に戻せません。完全に削除しても git の履歴は書き換えないため、削除の前の履歴には内容が残ります。

枠の中は、プロジェクト、アイテム、ワークスペース、スプリント、リリースの順に、種類ごとに削除の新しいものから並べる。階層のインデントはしない。1 行の内容は次のとおり。

- 種類のアイコン、ID(プロジェクト・ワークスペース・スプリント・リリースにはない)、タイトル(ワークスペース・スプリント・リリースは名前)
- ワークスペース名(ワークスペースの行にはない)、削除してからの時間、「あと N 日で完全に削除」(保持日数を過ぎてまだ残っている行は、「あと 0 日」ではなく「保持日数を過ぎています」)
- その行に含まれるもの(アイテムなら子孫、プロジェクトならそのアイテム、ワークスペースならその中身)があるとき、小さい字で「同じ操作で削除した下のもの: {N} 件」(「復元」で一緒に戻る件数。別の操作で削除したものは数えない)
- ボタン: 「復元」、「完全に削除」

アイテムは、子孫も 1 行ずつ並べる。ワークスペースの削除と一緒に消えたプロジェクト・アイテム・スプリント・リリースは、並べない。ワークスペースの行だけを出す。ワークスペースを別の Store へ移したときは、その中の削除済みのものも一緒に移るので、移動元のこの画面には残らない(03)。削除したものがないときは「削除したものはありません」と表示する。閲覧のみの Store では、「復元」「完全に削除」「保持日数」を無効にして「閲覧のみの Store です」と添える。

検索の `is:deleted`(04)から行を押して開いたときは、その Store の枠の中で、そのアイテムの行を選んだ状態にして、見える位置までスクロールする。

### 保持日数

保持日数は Store の設定で、その Store を使う全員で共有する(01)。「7 日」「30 日」「90 日」から選び、既定は 30 日とする。変更は 1 回の保存になり、トーストは出さない。アクティビティに「削除済みの保持日数を {N} 日に変更」と残る。選択の下に「短くすると、過ぎたものは次の自動の完全削除のときに完全に削除されます。同期する Store は同期のあと、同期しない Store はアプリを開いたときと日付が変わったときです」と添える。

今より短い値に変えるときだけ、確認ダイアログを出す。長くするときは出さない。タイトルは「保持日数を変更」、本文は「保持日数を {旧} 日から {新} 日に短くします。{新} 日より前に削除した {M} 件は、次の自動の完全削除で完全に削除されます。元に戻せません。この Store を使う全員に反映されます。」とする。M は、「保持日数を過ぎたものを完全に削除…」と同じ数え方(その下にあるものを含む)の件数である。M が 0 のときは、2 文目を「いま削除済みのものは、この変更では消えません。これから削除するものは {新} 日で完全に削除されます。」にする。ボタンは「変更」(警告色)と「キャンセル」で、キャンセルすると選択は元の値のままになる。短くできる人は限らない(設定は書き込める人なら誰でも変えられる)。

### 復元の単位

復元は、同じ削除操作で消えたものをまとめて戻す。「復元」を押した行に含まれるもの(アイテムなら子孫、プロジェクトならそのアイテム、ワークスペースならその中身)のうち、同じ削除操作で消えたものが、その行と一緒に戻る。

| 押した行 | 戻るもの |
|---|---|
| アイテム | そのアイテムと、同じ削除操作で消えた子孫 |
| プロジェクト | そのプロジェクトと、同じ削除操作で消えたアイテム。プロジェクト別のルールと専用ルールは削除のあいだも残っているので、戻ると働く |
| スプリント、リリース | そのスプリント(リリース)と、同じ削除操作でそこから外れたアイテム。そのあとに別のスプリント(リリース)に入れたアイテムは戻さない |
| ワークスペース | そのワークスペースと、同じ削除操作で消えたプロジェクト・アイテム・スプリント・リリース・設定 |

あとから別の操作で削除したものは、同じ行に含まれていても戻らない。その行が戻ったあとも、一覧に残る。

戻るものは、削除する前の値で、元の場所に戻る。ID は変わらない。アイテムとプロジェクトには、履歴に「復元」が残る(操作した人と時刻を添える)。復元したあとに、ワークスペースのプロパティの値やステータスを変えていたときは、値がなくなったものが「診断と修復」で検出される。

アイテムを戻すときに、そのアイテムが入っていたスプリント・リリースが使えない状態なら、アイテムごとに次のようにして戻す。アイテム・プロジェクト・ワークスペースのどの復元で戻るアイテムも同じである。

- スプリントが完了済みで、アイテムの分類が未着手か進行中のとき: スプリントを「バックログ」にして戻す。完了・中止のアイテムは、完了済みのスプリントに残す(05 の、スプリントを完了するときの扱いと同じ)。
- スプリントが削除済み、または存在しないとき: 「バックログ」にして戻す。
- リリースが削除済み、または存在しないとき: 「なし」にして戻す。アーカイブ済みのリリースは、そのまま残す(02)。

アイテムの履歴には、「復元」に続けて「スプリントを変更」(リリースなら「リリースを変更」)を 1 件足す。通知は出さない。ワークスペースを復元するときは、スプリント・リリースも同じ削除操作で戻るので、同じ削除操作で消えたものは壊れない。

親が削除済みの行は、「復元」を無効にし、次の文言を添える。

| 行 | 条件 | 添える文言 |
|---|---|---|
| アイテム | 親のアイテムが削除済み、またはプロジェクトが削除済み | 親も削除されています。先に親を復元してください |
| プロジェクト、アイテム、スプリント、リリース | ワークスペースが削除済み | ワークスペースも削除されています。先にワークスペースを復元してください |

名前が重なるときも「復元」を無効にする。プロジェクト・スプリント・リリースの名前はワークスペースの中で、ワークスペースの名前と接頭辞は Store の中で重複できないためである(02・03・05)。

| 行 | 条件 | 添える文言 |
|---|---|---|
| プロジェクト | 同じワークスペースに、同じ名前のプロジェクトがある | 同じ名前のプロジェクトがあります。先にそのプロジェクトの名前を変更してください |
| スプリント | 同じワークスペースに、同じ名前のスプリントがある | 同じ名前のスプリントがあります。先にそのスプリントの名前を変えてください |
| リリース | 同じワークスペースに、同じ名前のリリースがある | 同じ名前のリリースがあります。先にそのリリースの名前を変えてください |
| ワークスペース | 同じ Store に、同じ名前のワークスペースがある | 同じ名前のワークスペースがあります。先にそのワークスペースの名前を変更してください |
| ワークスペース | 同じ Store に、同じ接頭辞のワークスペースがある | 同じ接頭辞のワークスペースがあります。先にそのワークスペースの接頭辞を変更してください |

トーストは、アイテムが「{ID} を復元しました」、プロジェクトが「プロジェクトを復元しました」、ワークスペースが「ワークスペースを復元しました」、スプリントが「スプリントを復元しました」、リリースが「リリースを復元しました」。アイテムの行の復元で、スプリント・リリースを上のように戻したときは、トーストの後ろに、スプリントが完了済みなら「スプリント「{名前}」は完了しているため、バックログに入れました」、スプリントが削除済みなら「スプリント「{名前}」は削除されているため、バックログに入れました」、リリースが削除済みなら「リリース「{名前}」は削除されているため、リリースなしにしました」を続ける。「同じ操作で削除した下のもの」があるときは、「{ID} ほか {N} 件を復元しました」「プロジェクトほか {N} 件を復元しました」のように、「ほか {N} 件」を添える(ワークスペース・スプリント・リリースも同じ書き方)。1 回の保存になり、アクティビティに「{ID} を復元」「プロジェクト「{タイトル}」を復元」「ワークスペース「{名前}」を復元」「スプリント「{名前}」を復元」「リリース「{名前}」を復元」と残る。

### 完全に削除

完全に削除は、削除済みのものを Store から取り除く。取り除くのは Store の現在の中身だけで、git の履歴は書き換えない。そのため、削除の前の履歴には内容が残り、ほかのマシンが持っている履歴にも残る。プロジェクトを完全に削除するときは、そのプロジェクトのプロジェクト別のルールと専用ルールも、同じ保存で取り除く。

手動の完全に削除には、行ごとのものと、保持日数を過ぎたものをまとめて消すものがある。

| 操作 | 対象 | 確認ダイアログ |
|---|---|---|
| 行の「完全に削除」 | その行と、その行に含まれるものすべて(別の操作で削除したものを含む)。関連する受信箱の通知も消える | 「完全に削除」。本文は「{ID} {タイトル} を完全に削除します。元に戻せません。」で、含まれるものがあるときだけ、「元に戻せません。」の前に「この下にある削除済みの {N} 件({種類名の一覧})も一緒に完全に削除されます。」を入れる(例: 「ワークスペース WEB を完全に削除します。この下にある削除済みの 23 件(プロジェクト 2・アイテム 20・スプリント 1)も一緒に完全に削除されます。元に戻せません。」。アイテムの行は「(Story 2・Step 1)」のように種類で並べる)。プロジェクトの行に専用ルールがあるときは、「元に戻せません。」の前に「専用のルール {M} 件も削除します。」を入れる。プロジェクト・ワークスペース・スプリント・リリースは、ID のかわりに「プロジェクト」「ワークスペース」「スプリント」「リリース」と書き、タイトルのかわりに名前を書く。ボタンは「完全に削除」(警告色)と「キャンセル」 |
| 「保持日数を過ぎたものを完全に削除…」 | その Store で、削除してから保持日数を過ぎた行 | 「保持日数を過ぎたものを完全に削除」。本文は「{N} 日より前に削除した {M} 件(その下にあるものを含む)を完全に削除します。元に戻せません。」。M は、行そのもの 1 件と、その下にあるものすべての合計である(プロジェクト 1 行と、その下の 50 アイテムなら 51 件)。ボタンは同じ |

どちらの本文にも、続けて「git の履歴は書き換えないため、過去の履歴には内容が残ります。」を添える。過ぎたものがないときは、確認を出さず、トーストで「{N} 日より前に削除したものはありません」と表示する。

実行すると、1 回の保存になる。トーストは、行の「完全に削除」では「完全に削除しました」、「保持日数を過ぎたものを完全に削除…」では出さない。アクティビティには「{ID} を完全に削除」(下にあるものがあるときは「{ID} ほか {N} 件を完全に削除」)「削除済み {M} 件を完全に削除」と残る。確認を開いた時点の件数と実行時の状態が違うときは、実行時の状態で数え直し、アクティビティには実際に消えた件数を残す。別のマシンでの復元・変更と重なったときは、完全に削除を優先する(06)。

完全に削除(手動・自動の両方)で消えるものを相手にした関連は、種類を問わず、相手が削除済みでも、同じ保存で外す。完全に削除するスプリント・リリースを指すアイテムの参照も、同じ保存で外す(アイテムの履歴に「スプリントを変更」「リリースを変更」を残す)。アクティビティと通知は足さない。完全に削除したものを同期で受け取ったマシンも、そのものの受信箱の通知を消す。別の Store へ移したときに移動元に残る転送記録には、完全に削除は触れない(移動元は別の Store で、1 回の保存では書き換えられないため)。

### 保持日数を過ぎたものの自動の完全削除

削除してから保持日数を過ぎたものは、自動で完全に削除する。確認は出さない。

- 削除を行うのは、その Store に書き込めるマシンである。同期する Store(remote があり、GitHub に使うアカウントがある)は、同期に成功した直後(手動の「今すぐ同期」の成功後も含む)に行う。同期しない Store(remote がない、または GitHub に使うアカウントが「なし」)は、アプリを開いたとき、日付が変わったとき、保持日数を短くしたあとに行う。閲覧のみの Store、同期エラーの Store、サイドバーで非表示の Store では、自動では行わない。再表示したら、同期しない Store はすぐ、同期する Store は次の同期のあとに行う。「保持日数を過ぎたものを完全に削除…」のボタンは、どの Store でもいつでも使える。
- 行の完全に削除と同じく、行が保持日数を過ぎたら、その行に含まれるものすべて(含まれるものの削除が新しくても)を一緒に完全に削除する。
- 複数のマシンが同じものを消しても、結果は同じになる。
- 1 つの Store につき 1 回の保存にまとめる。アクティビティに「保持日数を過ぎた削除済み M 件を完全に削除」と、変更した人なしで残る。M は、手動の「保持日数を過ぎたものを完全に削除…」と同じ数え方(その下にあるものを含む)である。
- 手動の完全に削除と同じく、受信箱の通知も消え、消えたものを相手にした関連も外す。プロジェクトを完全に削除するときは、そのプロジェクト別のルールと専用ルールも外す。

## 診断と修復

診断は、Store のデータが 01 と 02〜03 の決まりに合っているかを調べ、合わないものを直す。自動では動かない。「診断を実行」を押したときだけ、このマシンにあるすべての Store(非表示の Store を含む)を調べる。

見出し「診断と修復」の右に「診断を実行」を置く。注意書きは「親のないアイテム、種類の決まりに合わない親子、存在しない値や相手への参照、日付の逆転、番号の重なり、名前・接頭辞・キーの重複、メンバーの重複、親が別のワークスペース・プロジェクトにあるアイテム、Issue の二重リンクを探します。」とする。

### 検出する項目

調べるのは、削除済みでないアイテムと、ワークスペースの設定と、Store のメンバーである。番号の重なりだけは、削除済みも調べる。

次の行は、アイテムを指す。親がない、種類に合わない親子、親の循環、ステータスがない、存在しない値、存在しない人、存在しないスプリント・リリース、宙づりの関連、親が別のワークスペース・プロジェクトにある、日付の逆転と番号の重なりのうちアイテムのもの、Issue の二重リンク。検索の `is:invalid`(04)は、この行に当たるアイテムを探す。次の行は、アイテムを指さない。初期ステータスの分類・接頭辞の重複・プロパティのキーの重複はワークスペースの設定、メンバーの重複はメンバー、名前の重複はワークスペースの設定・プロジェクト・スプリント・リリースを指す。

| 検出 | 条件 | 修復内容 |
|---|---|---|
| 親がない | Epic 以外で、親がない、または親が削除済み | プロジェクトの最初の Epic の下へ移す(最初は、そのプロジェクトのツリーの並び順(04)で先頭の Epic。削除済みを除く)。Step は Task にして移す。プロジェクトに Epic がなければ、「修復で作った Epic」を作ってその下へ移す。プロジェクトは、アイテムが覚えているプロジェクト(親が消えても分かる)で、親が削除済みなら、その親のプロジェクトとする。プロジェクトがまったく分からないとき(プロジェクトが完全に削除されている)は、推測せず、直さない。行は「{ID} の親も、プロジェクトも分かりません」と出し、修復のボタンは無効にして「プロジェクトが分からないため直せません」を添える。「すべて修復」はその分を数えず、直せなかった件数として添える。利用者は、詳細パネルのメニューの「移動…」で親を選び直せる(02) |
| 種類に合わない親子 | 親がいて、01 の表で子の種類を置けない。Epic が親を持っているときも含む(親が存在しない場合を含む) | 作業項目と Step は、親がないときと同じ修復。Epic はプロジェクトの直下へ移す |

| ステータスがない | ステータスが、ワークスペースのステータスにない | ワークスペースの初期ステータスにする |

| 存在しない値 | 優先度・関連システム・選択型・複数選択型の値が、ワークスペースの値の一覧にない | その値を外す。優先度は初期優先度にする。そのほかの単一の値は「なし」にする |

| 存在しないスプリント・リリース | スプリントまたはリリースが、ワークスペースにない(削除済みは含めない。復元すれば参照も戻る。同期でも同じ直し方で直すので、ここで検出するのは、同期で直しきれずに残ったものだけである) | その参照を外す |

### 結果の表示と修復

診断を実行すると、見つかったものを 1 件ずつ並べる。1 行の内容は、「要修復」の印、Store の名前(非表示の Store には「非表示」の印、閲覧のみの Store には名前のあとに「(閲覧のみ)」)と検出の内容(例: 「HH-12 の親がありません」)、修復のボタンである。ボタンの文言は上の表の修復内容に合わせる(例: 「プロジェクトの最初の Epic の下へ」「その値を削除」「開始日と終了日を入れ替える」「新しい番号を振る」「名前を変える」「リンクを外す」「行を統合する」)。見つからなければ「問題はありません」と表示する。一覧の下に「すべて修復」を置く。直せる件数が 0 のときは、「すべて修復」を無効にし(確認ダイアログも出さない)、閲覧のみの Store の分があれば「閲覧のみの Store です」を添える。

| 操作 | 動作 |
|---|---|
| 行のボタン | 確認ダイアログを出し、「修復」を押すとその 1 件を直す。1 回の保存になり、トーストは「修復しました」 |
| すべて修復 | 確認ダイアログを出し、「修復」を押すと、見つかったすべてを直す。直したことで新しく見つかったものも、なくなるまで繰り返す。上限はない。Store ごとに 1 回の保存にまとめ、トーストは実際に直した件数で「N 件を修復しました」 |

確認ダイアログは、どちらもタイトルを「修復」とし、ボタンは「修復」(警告色)と「キャンセル」とする。行のボタンの本文は「{検出の内容}」と「{ボタンの文言}」を並べる(例: 「HH-12 の親がありません」「プロジェクトの最初の Epic の下へ」)。「すべて修復」の本文は「{N} 件を修復します。」に続けて、種類ごとの件数を並べる(例: 「親がない 3 件、日付の逆転 1 件」)。N は、いま見つかっていて直せる件数である。非表示の Store を含むときは、続けて「(非表示の Store の {N} 件を含む)」を添える。閲覧のみの Store の分があるときは、行を改めて「閲覧のみの Store の {K} 件は直せません。」を添える。キャンセルすると何も直さない。

直したあとは、診断をやり直して一覧を更新する。閲覧のみの Store で見つかったものは、ボタンを無効にして「閲覧のみの Store です」と添える。「すべて修復」は、その分を直さずに、直せなかった件数を添えて表示する。トーストは「{N} 件を修復しました。{K} 件は閲覧のみの Store のためそのままです」とする。診断をやり直したあとも、閲覧のみの分の行は残る。

修復は、あなたが行った変更として記録する。アクティビティに「診断で修復: {検出の内容}」(「すべて修復」は「診断で N 件を修復」)と残り、変えたアイテムの履歴にも「診断で修復」が残る。また、番号の重なり以外は、直したアイテムごとに、あなた宛ての受信箱に通知「診断で修復しました: {検出の内容}」を出す(メンバーの重複は、アイテムではないので、通知を出さない)。非表示の Store の通知は、再表示するまで受信箱に出ない。番号の重なりの通知は、上の表のとおり「同期の修復」の 1 件だけで、「診断で修復しました」は重ねて出さない。

結果に、表示中の Store のアイテムの検出が 1 件以上あるときは、一覧の下に「検索で開く」を置く。押すと、検索の画面をテーブルで開き、絞り込みを `is:invalid` に置き換える。レイアウトの設定と列は変えない(04)。検索は診断を実行しなくても、いまの状態で判定するので、結果は診断の結果と、非表示の Store の分だけちがうことがある。

## 初回起動

Store が 1 つもないときは、サイドバー以外の画面に、次の案内を出す。初めて起動したときのほか、最後の Store をこのマシンから削除したときにも出る。

見出しは「Hedgehug へようこそ」。説明は「タスクは git リポジトリ(Store)に保存します。すべての操作はオフラインで完結し、remote があればバックグラウンドで同期します。」とする。続けて 3 つの手順を並べる。

| 手順 | 内容 |
|---|---|
| 1. GitHub と連携する(任意) | 「PR・Issue との連携や、チームの Store の同期に使います。このマシンだけで使う場合は不要で、あとからでも登録できます。」と書き、「アカウントを登録」のボタンを置く(登録の操作は 07)。登録済みのアカウントがあれば、ボタンのかわりに「@ログイン名 を登録しました」を並べ、この手順を済みの見た目にする |
| 2. Store を用意する | 「新しく作成するか、GitHub 上のチームの Store を検索するか、このマシンにある Store のコピーを探します。remote なしで作成すると、このマシンの中だけで使えます。」と書く。「新しい Store を作成」(「Store を追加」のダイアログを開く。このダイアログでは、ログイン名を確認・変更でき、最初のワークスペースの名前と接頭辞を入力する)、「GitHub から検索」(07。「マウント」の前にログイン名を入力する)、「フォルダから探す」(行にログイン名の入力欄を出す)を置く。アカウントが 1 つもなければ「GitHub から検索」は無効にして、「GitHub のアカウントを登録すると使えます」と添える。「フォルダから探す」は、GitHub に問い合わせないので、アカウントがなくても無効にしない |
| 3. 使い始める | 「Store を作成すると、ワークスペースとプロジェクトを作成できます。」と書く。ボタンはない |

Store を 1 つ追加すると、案内は消え、通常の画面になる。

## サーバーに接続できない画面とトークンのない画面

hedgehug の画面は、端末で `hh ui` を実行すると開く URL からだけ使える。アプリの中の操作(Ctrl+クリック、Shift+クリック、中クリック、パレットの Ctrl+Enter)で開いた新しいブラウザのタブは、開いた元のタブと同じ画面として使える。次の 2 つの場合は、ロゴと次の案内を出す。「トークンのない URL」は、画面全体を置き換える。「サーバーに接続できない」は、開いていた画面の上に重ねて出し、下の画面と入力は消さない。通常の画面には戻るボタンを置かない。

| 画面 | 出る条件 | 見出しと文言 | ボタン |
|---|---|---|---|
| サーバーに接続できない | 画面を開いたあとで、`hh ui` が止まるなどして、サーバーにつながらなくなった | 見出し「Hedgehug のサーバーに接続できません」。文言「端末で `hh ui` が動いているか確認してください。接続できると、自動でこの画面を再読み込みします。」 | 「再接続」。押すとすぐに接続を試みる。自動でも 5 秒ごとに、つながるまで回数の上限なしで試みる。つながったら重ねた画面を閉じ、書きかけ(保存していない入力が空でないコメント・説明の入力欄)がなければ元の画面を再読み込みする。あるときは、投稿・保存・キャンセルのあとで再読み込みする。「再接続」を押してつながったときも同じ。ブラウザのタブを閉じたときの書きかけは失われる(保存しない) |
| トークンのない URL | `hh ui` が開いた URL でない(URL にトークンが付いていない、または一致しない。`hh ui` を再起動したあとの、古い URL を含む。サーバーにつながって再読み込みした古い URL は、トークンが一致しないので、この画面に変わる。ブラウザの右クリックメニューの「新しいタブで開く」や、アドレスの貼り付けで開いたブラウザのタブは、トークンが付かないので、この画面になる) | 見出し「Hedgehug の画面を開けません」。文言「この画面は `hh ui` が開いた URL からのみ利用できます。端末で `hh ui` を実行してください。」 | なし |

どちらの画面でも、Store には何も書かない。操作の途中で接続が切れたときは、保存が済んでいない操作は行われなかったものとして扱う(01 の「書き込みの単位」の、1 回の操作の途中で 1 つでも失敗したら元のままにする規則)。インターネットにつながらない場合(オフライン)の表示は 06 で定める。

## 保存の整理

この文書の操作が、Store に保存されるかを一覧にする(01 の決まりの適用)。

| 操作 | Store への保存 |

| Store の名前の変更 | しない |
| Store をこのマシンから削除 | しない |
| メンバーの編集 | する |
| 保持日数の変更 | する |
| 削除済みの復元 | する |
| 完全に削除(手動・自動) | する |
| 診断の修復 | する |
| remote の履歴にそろえる | 未送信の保存があるときだけ、のせ直しの 1 回(実行者あなた)。ないときはしない |

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| 一般の「画面の状態」と「サンプルデータに戻す」 | 設定に置く | 作らない | 01 のとおり、モックにだけある機能のため |
| 「元に戻す」(Ctrl+Z、保存のあとのトーストのボタン、コマンドパレット) | ある | 作らない。元に戻す・やり直しの仕組みはない | ユーザーの指示(2026-11-12)。管理が複雑になる。誤操作で押したとき、何を戻したか分からない |
| 初回起動の「サンプルデータで試す」 | ボタンがある | 作らない | 実際のアプリにサンプルデータはないため |
| 診断の「壊れたデータを作成」 | ボタンがある | 作らない | 01 のとおり、モック専用のため |
| サーバーに接続できない・トークンのない画面 | 設定から切り替えて見る。「(モック)元の画面に戻る」がある | 実際の状態でだけ出す。戻るボタンは置かない。再接続は押したときと 5 秒ごと | 設定から切り替える機能は作らないため |
| トークンのない URL | トークンがない場合 | 一致しない場合も同じ画面 | 正しくないトークンも、使えない URL として同じに扱うのが単純なため |
| 最後の Store の削除 | 「最後の Store は削除できません」と断る | 削除でき、初回起動の案内に戻る | 初回起動の案内がある以上、Store 0 件を認めるのが一貫するため |
| Store 追加のアカウント | 登録順の先頭に自動で決まり、選べない | ダイアログで選べる。既定は先頭。remote がなくても選べる | GitHub に使うアカウントを、追加のときに選べるようにするため。リポジトリごとのアカウントのルールをなくし、GitHub との通信をすべて Store のアカウントで行うため(ユーザーの指示、2026-11-12) |
