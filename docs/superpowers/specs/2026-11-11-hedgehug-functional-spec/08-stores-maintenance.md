# hedgehug 機能仕様 08: Store と保守

この文書は、設定画面の「一般」「Store」「削除済み」「診断と修復」と、「アカウントとメンバー」のうちメンバー、そして初回起動の案内と、サーバーに接続できないときの画面を定める。Store を用意する、メンバーを管理する、消したものを戻す・完全に消す、壊れたデータを直す、という Store の面倒を見る操作がここにまとまっている。用語と共通の決まり(書き込みの単位、元に戻す、閲覧のみの Store、「あなた」)は 01 を参照する。

## 設定画面の構成

設定は、サイドバー上部の歯車から開く。見出しは「設定」、補足は「このマシンの設定と、Store の管理」で、次の 5 つのタブを持つ。

| タブ | 内容 | 定める文書 |
|---|---|---|
| 一般 | 自動同期の設定、キーボードの一覧 | 08(同期の動作は 06) |
| アカウントとメンバー | GitHub アカウント、リポジトリごとのアカウントのルール、メンバー | アカウントとルールは 07、メンバーは 08 |
| Store | Store の一覧と管理 | 08(GitHub からの検索は 07) |
| 削除済み | 論理削除されたものの一覧、復元、完全に削除 | 08 |
| 診断と修復 | 壊れたデータの検出と修復 | 08 |

## 一般

最初に「ログイン名」を置く。このマシンで操作する人の名前で、Store の同期に使う GitHub アカウントがないときに、「あなた」を決めるのに使う(01)。入力欄 1 つで、確定するとすぐに変わる。使える文字はメンバーのログイン名と同じ(英数字・ハイフン・アンダースコア)で、合わなければ「英数字・ハイフン・アンダースコアのログイン名を入力してください」と表示して、元の値に戻す。初期値は、登録した GitHub アカウントのログイン名、なければ git の user.name(英数字・ハイフン・アンダースコアだけのとき)、なければ OS のユーザー名とする。この設定も Store に保存しない。

次に「同期のタイミング」を置く。このマシンだけの設定として次の 2 つを置く。注意書きは「このマシンだけの設定です。」とする。

| 項目 | 内容 | 既定 |
|---|---|---|
| 裏で自動的に同期する | チェックボックス。オフにすると、間隔の選択を無効にする | オン |
| 間隔 | 「1 分ごと」「5 分ごと」「15 分ごと」「30 分ごと」「60 分ごと」から選ぶ | 5 分ごと |

変更はすぐに有効になる。Store には書かないので、保存にもアクティビティにも残らず、元に戻す対象にもならない(01)。自動同期がいつ動き、いつ待つかは 06 で定める。

remote を持つ Store が 1 つでも表示中なら、「すべて同期」のボタンを出す。押したときの動作と結果の表示は 06 に従う。

その下に「キーボード」の一覧を置く。内容は 01 の表のうち、Ctrl+K(コマンドパレット)、C(新規作成)、/(絞り込みに移る)、Ctrl+Z(元に戻す)、Esc(閉じる)の 5 つを、そのままの順で並べる。

## Store

### 一覧

画面の上部に「Store は 1 つの git リポジトリです。共有する相手ごとに分けます。」と書き、右に「GitHub から検索」(07)と「Store を追加」を置く。Store がないときは、一覧を空にして、この 2 つのボタンだけを出す。

Store ごとに 1 つの枠を作り、追加した順に並べる。枠の中身は次のとおり。

| 場所 | 内容 |
|---|---|
| 見出し | Store の名前(色つき)、「N ワークスペース」。非表示なら「非表示」、閲覧のみなら「閲覧のみ」の印 |
| ボタン | 「色」「非表示」(非表示のときは「表示」)「このマシンから削除…」 |
| 入力 | 「remote」の入力欄(空のとき「なし(このマシンだけ)」と薄く表示)、「アカウント」の選択(「なし」と、登録済みのアカウントを「表示名 (@ログイン名)」で並べる) |
| 同期の状況 | remote があれば「未送信 N 件 · 最終同期 …」。最終同期がなければ「なし」。同期できない状態なら「同期できません(アカウントを設定してください)」を添える。remote がなければ「remote がないため同期しません」。remote があれば「今すぐ同期」のボタンも出す |
| ワークスペース | 配下のワークスペースを 1 行ずつ。名前を押すとそのワークスペースの設定を開く。接頭辞(なければ「接頭辞なし」)、「N プロジェクト · M アイテム」を添える |

色・非表示・remote・アカウント・このマシンから削除は、このマシンだけの設定なので、閲覧のみの Store でも操作できる。閲覧のみになるかどうかは、GitHub の権限から決まる(07)。

### 追加

「Store を追加」でダイアログ「Store を追加」を開く。remote を入れるかどうかで、新しく作るか、すでにあるものを clone するかが分かれる。

| 項目 | 内容 |
|---|---|
| 名前 | 必須。入力例は「team-b」 |
| remote(任意) | 入力例は「git@github.com:org/tasks.git」。入れると clone する。空にすると、このマシンに新しい Store を作る |
| アカウント | remote を入れたときだけ選べる。「なし」と登録済みのアカウントから選ぶ。既定は、登録順の先頭のアカウント。アカウントがなければ「なし」 |
| ログイン名 | Store が 1 つもないとき(初回起動)だけ出す。一般のログイン名の設定と同じもので、確認と変更ができる |
| 色 | 7 色(teal・orange・purple・sky・pink・olive・brown)から選ぶ。既定は、ほかの Store が使っていない最初の色。すべて使われていれば teal |

ダイアログの下に「remote を入れると clone し、空にすると新しい Store を作ります。」と添える。

「追加」を押すと、次の順に確かめる。1 つでも合わなければ、ダイアログを閉じずに、その理由を赤字で示す。何も作らない。

| 条件 | 表示 |
|---|---|
| 名前が `^[A-Za-z0-9][A-Za-z0-9_-]*$` に合わない | 名前は英数字、ハイフン、アンダースコアにしてください(先頭は英数字) |
| 同じ名前の Store がある(大文字と小文字を区別しない) | 同じ名前の Store があります |
| remote が、すでに追加した Store の remote と同じ(後述の比べ方) | この remote はすでに Store「{その Store の名前}」として追加されています |
| clone できない(URL が違う、アカウントに権限がない、つながらない) | {remote} を clone できません。remote の URL とアカウントを確認してください |
| clone したリポジトリが hedgehug の Store ではない | {remote} は hedgehug の Store ではないため追加できません |

clone している間は、「追加」を押せないようにして「clone しています…」と表示する。

remote の同じ・違うは、ホスト名、owner、リポジトリ名を取り出して比べる。大文字と小文字は区別せず、末尾の「.git」は無視する。SSH の形式(`git@github.com:org/tasks.git`)と HTTPS の形式(`https://github.com/org/tasks`)は、同じ remote として扱う。remote を変えるとき(後述)にも同じ比べ方を使う。

hedgehug の Store でないリポジトリとは、中身が空ではなく、hedgehug が保存したデータを持たないリポジトリである。空のリポジトリは、Store でないとは扱わない。

条件に合えば Store を一覧の末尾に追加し、使っているアカウントと色を設定する。追加した直後の扱いは次のとおり。

- 新しく作った Store と、空のリポジトリを clone した Store には、ワークスペース「メイン」(接頭辞なし)を 1 つ作る。clone した Store にすでにワークスペースがあれば、「メイン」は作らない。閲覧のみの Store は書き込めないので、空でも作らない。
- 「メイン」を作るのは Store への最初の書き込みなので、「あなた」がまだメンバーに見つからないときは、ダイアログなしで自動的にメンバーに追加してから作る(01)。追加するメンバーの表示名は git の user.name(なければログイン名)、ログイン名は「あなた」のログイン名とする。トースト「{ログイン名} をメンバーに追加しました」を出す。閲覧のみの Store では追加しない。
- 「メイン」を作ったときのトーストは「{名前} を追加しました。ワークスペース「メイン」を作りました」。作らなかったときは「{名前} を追加しました」。

初回起動の案内から追加するときも、設定の「Store」から追加するときも、このダイアログを使う。GitHub からの検索で見つけた Store を追加するときは、07 の手順に従い、上の表のうち remote に関わる検査(同じ remote、clone、Store かどうか)を同じ文言で行う。

Store の名前は、追加したあとは変更できない。

### 色

「色」を押すと、7 色の名前を並べたメニューが開き、いまの色にチェックが付く。選ぶとすぐに変わる。色は Store の名前の印とサイドバーの点に使う。

### 非表示と再表示

「非表示」を押すと、その Store はないものとして扱う。サイドバー、マイタスク、検索、受信箱、アクティビティ、保存したビューの一覧には出ず、作成ダイアログと移動先の候補にも出さない。自動同期と「すべて同期」の対象からも外す。データは消えず、設定の Store の一覧と、「今すぐ同期」は使える。

サイドバーの Store 名の右にあるメニューからも、非表示にできる。このメニューの項目は次の 4 つである。

| 項目 | 動作 |
|---|---|
| 今すぐ同期 | その Store を同期する(06)。remote がなければ無効にして「remote なし」と添える |
| ワークスペースを追加 | 03 のダイアログを開く |
| Store の設定 | 設定の「Store」タブを開く |
| サイドバーで非表示 | その Store を非表示にする |

非表示にしたとき、開いていた画面がその Store のワークスペース・プロジェクト・保存したビューなら、マイタスクへ移る。トーストは「{名前} を非表示にしました。設定の「Store」から再表示できます」。

「表示」を押すと、元の表示に戻る。非表示の Store にワークスペースを追加したときも、自動で表示に戻る。

### remote の変更

remote の入力欄を書き換えて確定すると、すぐに変わる。空にすると remote をなくし、その Store はこのマシンの中だけで使う。未送信の変更は、そのまま残る。

- 入れた remote が別の Store の remote と同じなら、追加のときと同じ理由で断り、入力欄を元の値に戻す。
- 入れたときのトーストは「remote を設定しました」、空にしたときは「remote を削除しました」。
- remote を入れたのに、同期に使うアカウントが「なし」のときは、同期の状況に「同期できません(アカウントを設定してください)」と出す。
- 入れた remote につながらない、または中身が合わないときは、変更はそのまま受け入れ、最初の同期で「同期できません」と表示する(06)。

### 同期に使うアカウント

「アカウント」の選択を変えると、すぐに変わる。remote があって「なし」にしたときは、同期の状況に「同期できません(アカウントを設定してください)」と出る。アカウントを選び直すと、次の同期で元に戻る。アカウントの登録と削除は 07 で定める。アカウントを削除したときは、それを使っていた Store の選択が「なし」になる(07)。

「あなた」の決まり方は、この選択にも関わる(01)。選択を変えたあとに、「あなた」がメンバーに見つからなくなったときは、次にその Store へ書き込むときに、自動的にメンバーに追加する(トースト「{ログイン名} をメンバーに追加しました」)。

### このマシンから削除

「このマシンから削除…」を押すと、確認ダイアログ「このマシンから削除」を出す。本文は次のとおり。

- 共通: 「{Store 名} をこのマシンから削除します。」
- remote があるとき: 「remote のリポジトリはそのまま残り、あとで追加し直すことができます。」
- remote がないとき: 「remote がないため、中のタスクはすべて失われます。」(強調する)
- 未送信の変更があるとき(行を改めて): 「未送信の変更が N 件あります。」(強調する)
- 最後に(行を改めて): 「元に戻せません。」

ボタンは「削除」(警告色)と「キャンセル」。実行すると、このマシンにある Store のコピーを消す。そのあと、その Store のワークスペース・プロジェクト・アイテム・保存したビューは、このマシンでは見えなくなり、受信箱にあったその Store の通知も消える。remote から追加し直すと、保存したビューも含めて戻る(通知は戻らない)。開いていた画面がその Store のものなら、マイタスクへ移る。トーストは「{名前} をこのマシンから削除しました」。

この操作は Store の中身を変えないので、削除済み(論理削除)には入らず、保存もアクティビティも残さず、元に戻せない。アカウントとルールは変わらない。最後の Store も削除できる。Store が 0 件になったら、初回起動の案内に戻る。

## メンバー

メンバーは「設定 > アカウントとメンバー」の「メンバー」に、Store ごとの枠で並べる。1 つの Store の中で共有する一覧で、担当者・オーナー・メンションの候補になる(01)。枠の見出しに Store の名前と、「追加」と「GitHub から取り込み」のボタンを置く。Store がないときは、「メンバー」の欄ごと出さない。非表示の Store の枠も出す。

| 行の内容 | |
|---|---|
| 並び | 追加した順 |
| 表示 | アバター、表示名、「@ログイン名」、「担当 N 件」(削除済みを除く) |
| 「あなた」 | その Store の「あなた」(01)のメンバーに「あなた」の印を付ける |
| ボタン | 編集、削除(ごみ箱の絵) |

「GitHub から取り込み」は、GitHub のコラボレーターをメンバーに加えるボタンである。取り込みの中身と、使える条件は 07 で定める。使えないときは無効にする。

閲覧のみの Store では、「追加」「GitHub から取り込み」、編集、削除をすべて無効にして「閲覧のみの Store です」と添える(01)。

### 追加と編集

「追加」でダイアログ「メンバーを追加」、編集でダイアログ「メンバーを編集」を開く。項目は次のとおり。

| 項目 | 内容 |
|---|---|
| 表示名 | 必須 |
| ログイン名(@ で呼ぶ名前) | 必須。先頭の「@」は取り除いて保存する。使える文字は英数字・ハイフン・アンダースコア |

次のとき、ダイアログを閉じずに理由を赤字で示し、何も変えない。

| 条件 | 表示 |
|---|---|
| 表示名が空、またはログイン名が使える文字でない | 表示名と、英数字・ハイフン・アンダースコアのログイン名を入力してください |
| 同じ Store に、同じログイン名のメンバーがいる(大文字と小文字を区別しない。編集では自分自身を除く) | このログイン名はもういます |

追加のトーストは「{表示名} を追加しました」、編集のトーストは「{表示名} を変更しました」。どちらも 1 回の保存になり、アクティビティに「メンバー {表示名} を追加」「メンバー {表示名} を変更」と残り、元に戻せる。

編集では、ログイン名を変えても、担当・オーナー・ウォッチの対応づけは変わらない。過去のコメントや説明に書かれた「@旧ログイン名」は書き換えない。

「あなた」の行では、表示名だけを変えられる。ログイン名は入力欄を無効にし、「あなたの対応が外れるため変更できません」と添える。

### 削除

削除ボタンを押すと、確認ダイアログ「メンバーを削除」を出す。本文は「{表示名} を削除します。」に続けて、次のうち当てはまるものを並べる。

- 担当している項目があるとき: 「担当している N 件は未割り当てになります。」
- 担当者を変更する自動化が、そのメンバーを指しているとき: 「担当者に指定している自動化 M 件は無効になります。」

ボタンは「削除」(警告色)と「キャンセル」。実行すると、その Store で次のように変わる。

| 変わるもの | 内容 |
|---|---|
| 担当者 | 削除済みを含むすべてのアイテムで、そのメンバーを担当者から外し、未割り当てにする。ユーザー型のプロパティに入っていた値も外す |
| ウォッチ | すべてのアイテムのウォッチから外す |
| プロジェクトのオーナー | そのメンバーがオーナーのプロジェクトは、オーナーなしにする |
| 自動化 | 担当者の変更先にそのメンバーを指すルールを無効にする(03)。ルール自体は残る |
| 残るもの | コメント、作業時間、履歴、作成者、保存したビュー(条件に書かれたログイン名は、該当する人がいなくなるので何にも一致しなくなる)、受信箱の通知 |

トーストは「メンバーを削除しました」。1 回の保存になり、アクティビティに「メンバー {表示名} を削除」と残り、元に戻せる。元に戻すと、担当・ウォッチ・オーナーの対応と、無効にした自動化も元に戻る。

「あなた」のメンバーは削除できない。削除ボタンを無効にし、「自分は削除できません」と添える。

## 削除済み

削除したプロジェクト・アイテム・ワークスペースは、すぐには消えず、この画面に入る(論理削除)。削除の操作そのものは、アイテムは 02、ワークスペースは 03 で定める。ここでは、一覧、復元、完全に削除を定める。

### 一覧

画面は Store ごとの枠に分ける。枠の見出しには、Store の名前と、保持日数の選択と「保持日数を過ぎたものを完全に削除…」のボタンを置く。注意書きは次のとおり。

> 削除したものは、保持日数のあいだ、この画面から元の場所に復元できます。保持日数を過ぎると自動で完全に削除します。完全に削除すると元に戻せません。完全に削除しても git の履歴は書き換えないため、削除の前の履歴には内容が残ります。

枠の中は、プロジェクト、アイテム、ワークスペースの順に、種類ごとに削除の新しいものから並べる。1 行の内容は次のとおり。

- 種類のアイコン、ID(プロジェクトとワークスペースにはない)、タイトル(ワークスペースは名前)
- ワークスペース名(ワークスペースの行にはない)、削除してからの時間、「あと N 日で完全に削除」
- ボタン: 「復元」、「完全に削除」

アイテムは、子孫も 1 行ずつ並べる。ワークスペースの削除と一緒に消えたプロジェクトとアイテムは、並べない。ワークスペースの行だけを出す。削除したものがないときは「削除したものはありません」と表示する。閲覧のみの Store では、「復元」「完全に削除」「保持日数」を無効にして「閲覧のみの Store です」と添える。

### 保持日数

保持日数は Store の設定で、その Store を使う全員で共有する(01)。「7 日」「30 日」「90 日」から選び、既定は 30 日とする。変更は 1 回の保存になり、トーストは出さない。アクティビティに「削除済みの保持日数を {N} 日に変更」と残り、元に戻せる。選択の下に「短くすると、次の同期のあとに、過ぎたものが完全に削除されます」と添える。

### 復元の単位

復元は、同じ削除操作で消えたものをまとめて戻す。「復元」を押した行と、その行の下にあって同じ削除操作で消えたものが戻る。

| 押した行 | 戻るもの |
|---|---|
| アイテム | そのアイテムと、同じ削除操作で消えた子孫 |
| プロジェクト | そのプロジェクトと、同じ削除操作で消えたアイテム |
| ワークスペース | そのワークスペースと、同じ削除操作で消えたプロジェクト・アイテム・スプリント・リリース・設定 |

あとから別の操作で削除したものは、同じ行の下にあっても戻らない。その行が戻ったあとも、一覧に残る。

戻るものは、削除する前の値で、元の場所に戻る。ID は変わらない。アイテムには、履歴に「復元」が残る。復元したあとに、ワークスペースのプロパティの値やステータスを変えていたときは、値がなくなったものが「診断と修復」で検出される。

親が削除済みの行は、「復元」を無効にし、次の文言を添える。

| 行 | 条件 | 添える文言 |
|---|---|---|
| アイテム | 親のアイテムが削除済み、またはプロジェクトが削除済み | 親も削除されています。先に親を復元してください |
| プロジェクト、アイテム | ワークスペースが削除済み | ワークスペースも削除されています。先にワークスペースを復元してください |

名前が重なるときも「復元」を無効にする。プロジェクトの名前はワークスペースの中で、ワークスペースの名前と接頭辞は Store の中で重複できないためである(02・03)。

| 行 | 条件 | 添える文言 |
|---|---|---|
| プロジェクト | 同じワークスペースに、同じ名前のプロジェクトがある | 同じ名前のプロジェクトがあります。先にそのプロジェクトの名前を変更してください |
| ワークスペース | 同じ Store に、同じ名前のワークスペースがある | 同じ名前のワークスペースがあります。先にそのワークスペースの名前を変更してください |
| ワークスペース | 同じ Store に、同じ接頭辞のワークスペースがある | 同じ接頭辞のワークスペースがあります。先にそのワークスペースの接頭辞を変更してください |

トーストは、アイテムが「{ID} を復元しました」、プロジェクトが「プロジェクトを復元しました」、ワークスペースが「ワークスペースを復元しました」。1 回の保存になり、アクティビティに「{ID} を復元」「プロジェクト「{タイトル}」を復元」「ワークスペース「{名前}」を復元」と残り、元に戻せる。元に戻すと、再び削除済みになる。

### 完全に削除

完全に削除は、削除済みのものを Store から取り除く。取り除くのは Store の現在の中身だけで、git の履歴は書き換えない。そのため、削除の前の履歴には内容が残り、ほかのマシンが持っている履歴にも残る。

手動の完全に削除には、行ごとのものと、保持日数を過ぎたものをまとめて消すものがある。

| 操作 | 対象 | 確認ダイアログ |
|---|---|---|
| 行の「完全に削除」 | その行と、その下にあるものすべて(別の操作で削除したものを含む)。関連する受信箱の通知も消える | 「完全に削除」。本文は「{ID} {タイトル} を完全に削除します。元に戻せません。」。プロジェクトとワークスペースは、ID のかわりに「プロジェクト」「ワークスペース」と書き、タイトルのかわりに名前を書く。ボタンは「完全に削除」(警告色)と「キャンセル」 |
| 「保持日数を過ぎたものを完全に削除…」 | その Store で、削除してから保持日数を過ぎた行 | 「保持日数を過ぎたものを完全に削除」。本文は「{N} 日より前に削除した M 件を完全に削除します。元に戻せません。」。ボタンは同じ |

どちらの本文にも、続けて「git の履歴は書き換えないため、過去の履歴には内容が残ります。」を添える。過ぎたものがないときは、確認を出さず、トーストで「{N} 日より前に削除したものはありません」と表示する。

実行すると、1 回の保存になる。トーストは、行の「完全に削除」では「完全に削除しました」、「保持日数を過ぎたものを完全に削除…」では出さない。アクティビティには「{ID} を完全に削除」「削除済み {M} 件を完全に削除」と残る。元に戻せない(01)。

### 保持日数を過ぎたものの自動の完全削除

削除してから保持日数を過ぎたものは、自動で完全に削除する。確認は出さない。

- 削除を行うのは、その Store に書き込めるマシンである。同期の直後に行う。remote のない Store は、アプリを開いたときに行う。閲覧のみの Store では行わない。同期が失敗したときも行わない。
- 複数のマシンが同じものを消しても、結果は同じになる。
- 1 つの Store につき 1 回の保存にまとめる。アクティビティに「保持日数を過ぎた削除済み M 件を完全に削除」と、変更した人なしで残る。元に戻せない。
- 手動の完全に削除と同じく、受信箱の通知も消える。

## 診断と修復

診断は、Store のデータが 01 と 02〜03 の決まりに合っているかを調べ、合わないものを直す。自動では動かない。「診断を実行」を押したときだけ、このマシンにあるすべての Store(非表示の Store を含む)を調べる。

見出し「診断と修復」の右に「診断を実行」を置く。注意書きは「親のないアイテム、種類の決まりに合わない親子、存在しない値や相手への参照、日付の逆転、番号の重なりを探します。」とする。

### 検出する項目

調べるのは、削除済みでないアイテムである。番号の重なりだけは、削除済みも調べる。

| 検出 | 条件 | 修復内容 |
|---|---|---|
| 親がない | Epic 以外で、親がない、または親が削除済み | プロジェクトの最初の Epic の下へ移す。Step は Task にして移す。プロジェクトに Epic がなければ、「修復で作った Epic」を作ってその下へ移す |
| 種類に合わない親子 | 親がいて、01 の表で子の種類を置けない。Epic が親を持っているときも含む(親が存在しない場合を含む) | 作業項目と Step は、親がないときと同じ修復。Epic はプロジェクトの直下へ移す |
| 親の循環 | 親をたどると自分に戻る | 循環の中で番号が最も大きいアイテムを、親がないときと同じ修復で動かす |
| ステータスがない | ステータスが、ワークスペースのステータスにない | ワークスペースの初期ステータスにする |
| 存在しない値 | 優先度・関連システム・選択型・複数選択型の値が、ワークスペースの値の一覧にない | その値を外す。単一の値は「なし」にする |
| 存在しない人 | 担当者・ユーザー型のプロパティが、Store のメンバーにいない | その人を外す。担当者は未割り当てにする |
| 存在しないスプリント・リリース | スプリントまたはリリースが、ワークスペースにない | その参照を外す |
| 宙づりの関連 | ブロックの相手が、Store に存在しない(削除済みは宙づりに含めない。復元すれば関連も戻る) | その関連を外す |
| 日付の逆転 | 終了日が開始日より前 | 開始日と終了日を入れ替える |
| 番号の重なり | 同じワークスペースで、番号が重なっている。同期で重なった分は、同期の時点であとから同期した方に新しい番号が振られる(06)。ここで検出するのは、同期で直しきれずに残った重なりだけで、その場合は作成が最も古いものが番号を持ち続ける | ほかのものに新しい番号を振る。コメントなどに書かれた古い ID は、文字のまま残る |

### 結果の表示と修復

診断を実行すると、見つかったものを 1 件ずつ並べる。1 行の内容は、「要修復」の印、Store の名前と検出の内容(例: 「HH-12 の親がありません」)、修復のボタンである。ボタンの文言は上の表の修復内容に合わせる(例: 「プロジェクトの最初の Epic の下へ」「その値を削除」「開始日と終了日を入れ替える」「新しい番号を振る」)。見つからなければ「問題はありません」と表示する。一覧の下に「すべて修復」を置く。

| 操作 | 動作 |
|---|---|
| 行のボタン | その 1 件を直す。1 回の保存になり、トーストは「修復しました」 |
| すべて修復 | 見つかったすべてを直す。直したことで新しく見つかったものも、なくなるまで繰り返す。上限はない。Store ごとに 1 回の保存にまとめ、トーストは実際に直した件数で「N 件を修復しました」 |

直したあとは、診断をやり直して一覧を更新する。閲覧のみの Store で見つかったものは、ボタンを無効にして「閲覧のみの Store です」と添える。「すべて修復」は、その分を直さずに、直せなかった件数を添えて表示する。

修復は、あなたが行った変更として記録する。アクティビティに「診断で修復: {検出の内容}」(「すべて修復」は「診断で N 件を修復」)と残り、変えたアイテムの履歴にも「診断で修復」が残る。また、直したアイテムごとに、あなた宛ての受信箱に通知「診断で修復しました: {検出の内容}」を出す。修復は元に戻せる。「すべて修復」で複数の Store を直したときは、01 の複数の Store にまたがった操作と同じく、1 回の「元に戻す」でまとめて戻す。

## 初回起動

Store が 1 つもないときは、サイドバー以外の画面に、次の案内を出す。初めて起動したときのほか、最後の Store をこのマシンから削除したときにも出る。

見出しは「Hedgehug へようこそ」。説明は「タスクは git リポジトリ(Store)に保存します。すべての操作はオフラインで完結し、remote があればバックグラウンドで同期します。」とする。続けて 3 つの手順を並べる。

| 手順 | 内容 |
|---|---|
| 1. GitHub と連携する(任意) | 「PR・Issue との連携や、チームの Store の同期に使います。このマシンだけで使う場合は不要で、あとからでも登録できます。」と書き、「アカウントを登録」のボタンを置く(登録の操作は 07)。登録済みのアカウントがあれば、ボタンのかわりに「@ログイン名 を登録しました」を並べ、この手順を済みの見た目にする |
| 2. Store を用意する | 「新しく作成するか、GitHub 上のチームの Store を検索します。remote なしで作成すると、このマシンの中だけで使えます。」と書く。「新しい Store を作成」(「Store を追加」のダイアログを開く。このダイアログでは、ログイン名を確認・変更できる)と、「GitHub から検索」(07)を置く。アカウントが 1 つもなければ「GitHub から検索」は無効にして、「GitHub のアカウントを登録すると使えます」と添える |
| 3. 使い始める | 「Store を作成すると、ワークスペースとプロジェクトを作成できます。」と書く。ボタンはない |

Store を 1 つ追加すると、案内は消え、通常の画面になる。

## サーバーに接続できない画面とトークンのない画面

hedgehug の画面は、端末で `hh ui` を実行すると開く URL からだけ使える。次の 2 つの場合は、画面全体を、ロゴと次の案内に置き換える。通常の画面には戻るボタンを置かない。

| 画面 | 出る条件 | 見出しと文言 | ボタン |
|---|---|---|---|
| サーバーに接続できない | 画面を開いたあとで、`hh ui` が止まるなどして、サーバーにつながらなくなった | 見出し「Hedgehug のサーバーに接続できません」。文言「端末で `hh ui` が動いているか確認してください。接続できると、自動でこの画面を再読み込みします。」 | 「再接続」。押すとすぐに接続を試みる。自動でも 5 秒ごとに試み、つながったら元の画面を再読み込みする |
| トークンのない URL | `hh ui` が開いた URL でない(URL にトークンが付いていない、または一致しない) | 見出し「Hedgehug の画面を開けません」。文言「この画面は `hh ui` が開いた URL からのみ利用できます。端末で `hh ui` を実行してください。」 | なし |

どちらの画面でも、Store には何も書かない。操作の途中で接続が切れたときは、保存が済んでいない操作は行われなかったものとして扱う(01 の「1 回の操作の途中で失敗したら元のまま」)。インターネットにつながらない場合(オフライン)の表示は 06 で定める。

## 保存と元に戻すの整理

この文書の操作が、Store に保存されるか、元に戻せるかを一覧にする(01 の決まりの適用)。

| 操作 | Store への保存 | 元に戻す |
|---|---|---|
| 自動同期の設定 | しない | 対象外 |
| Store の追加(「メイン」を作る場合の保存は除く) | しない | 対象外 |
| 「メイン」の作成 | する | できる |
| Store の色・非表示・remote・アカウントの変更 | しない | 対象外 |
| Store をこのマシンから削除 | しない | できない(確認で示す) |
| メンバーの追加・編集・削除 | する | できる |
| 保持日数の変更 | する | できる |
| 削除済みの復元 | する | できる |
| 完全に削除(手動・自動) | する | できない(確認で示す) |
| 診断の修復 | する | できる |

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| 一般の「画面の状態」と「サンプルデータに戻す」 | 設定に置く | 作らない | 01 のとおり、モックにだけある機能のため |
| 初回起動の「サンプルデータで試す」 | ボタンがある | 作らない | 実際のアプリにサンプルデータはないため |
| 診断の「壊れたデータを作成」 | ボタンがある | 作らない | 01 のとおり、モック専用のため |
| サーバーに接続できない・トークンのない画面 | 設定から切り替えて見る。「(モック)元の画面に戻る」がある | 実際の状態でだけ出す。戻るボタンは置かない。再接続は押したときと 5 秒ごと | 設定から切り替える機能は作らないため |
| トークンのない URL | トークンがない場合 | 一致しない場合も同じ画面 | 正しくないトークンも、使えない URL として同じに扱うのが単純なため |
| 最後の Store の削除 | 「最後の Store は削除できません」と断る | 削除でき、初回起動の案内に戻る | 初回起動の案内がある以上、Store 0 件を認めるのが一貫するため |
| Store 追加のアカウント | 登録順の先頭に自動で決まり、選べない | ダイアログで選べる。既定は先頭 | 同期に使うアカウントを、追加のときに選べるようにするため |
| Store 名の規則の文言 | 「名前は英数字とハイフンにしてください」(実際はアンダースコアも通る) | 英数字、ハイフン、アンダースコアと書く | 文言と実際の規則を合わせるため |
| Store 名の重複 | 大文字と小文字を区別する | 区別しない | 保存先のフォルダ名が、環境によって区別されないため |
| 「メイン」の作成 | clone したリポジトリにも必ず作る | 新しく作った Store と、空のリポジトリを clone した Store にだけ作る。閲覧のみの Store では作らない | すでにワークスペースを持つ Store に、余計なワークスペースを足さないため(台帳 B21) |
| Store の追加の失敗 | 検査がない | clone の失敗、Store でないリポジトリ、同じ remote を断る。remote は SSH と HTTPS を同じものとして比べる | 台帳 B21 |
| remote の変更 | 検査がない | 別の Store と同じ remote は断る | 同じリポジトリを 2 つの Store にしないため |
| 非表示の Store の扱い | 表示・検索・作成の候補・同期から外す | さらに受信箱とアクティビティにも出さない | 非表示にした Store の項目が、一部の画面にだけ残るのを防ぐため |
| 「あなた」の追加 | 決まっていない(モックでは操作する人を切り替える) | ダイアログなしで自動的に追加し、トーストで知らせる。表示名は git の user.name、なければログイン名 | 追加の手間をなくし、本物のメールアドレスを Store に入れないため |
| ログイン名の設定 | なし | 一般に「ログイン名」を置く。初期値は GitHub アカウント、git の user.name、OS のユーザー名の順 | アカウントがなくても「あなた」を決めるため |
| メンバーの項目 | 表示名、ログイン名 | 同じ。メールアドレスは持たない。編集を追加 | メンバーはログイン名だけで識別し、本物のメールアドレスを Store に入れないため |
| ログイン名の重複 | 完全一致で比べる | 大文字と小文字を区別せずに比べる | 01 のログイン名の比べ方に合わせるため |
| メンバーの追加・削除の保存 | 追加は保存を通らず、削除は先頭の Store に記録する | Store の中の 1 回の保存として、その Store に記録する。元に戻せる | 01 の「Store を変える操作はすべて保存」に合わせるため |
| メンバーの削除の影響 | 担当者・ウォッチ・オーナーを外す。自動化と保存したビューは変えない | ユーザー型のプロパティの値も外す。担当者を指す自動化は無効にする。保存したビューは変えない | 存在しない人への参照を残さないため。自動化の扱いは台帳 B18 に合わせた |
| 「あなた」の編集 | なし | 表示名だけ変えられる | ログイン名を変えると、「あなた」の対応が外れるため |
| 削除済みの一覧 | 全 Store をまとめて 1 つに並べる。プロジェクトとアイテムだけ | Store ごとの枠。ワークスペースも並べる | 保持日数が Store ごとの設定になり、ワークスペースの削除も論理削除になったため(台帳 F3、D1) |
| 保持日数 | 「N 日より前」を画面に保存する(マシンごと)。手動で消すときの基準だけ | Store の設定として共有し、過ぎたものは自動で完全に削除する。既定 30 日 | 台帳 F3 |
| 完全に削除の文言 | 「git の履歴から削除します」 | 「完全に削除します」。履歴は書き換えず、過去の履歴には内容が残ると添える | 台帳 F3 |
| 完全に削除の単位 | アイテムだけ個別に消せる | プロジェクト・ワークスペースも個別に消せる | 手動の完全に削除を種類によらずそろえるため(台帳 B25) |
| 完全に削除の記録 | 先頭の Store に記録する | 消した Store に 1 回記録する。元に戻せない | 台帳 A2 |
| 復元の単位 | 削除した時刻の一致で決める | 同じ削除操作で消えたもの | 台帳 B26 |
| 親が削除済みのときの復元 | アイテムだけ断る | プロジェクト・アイテムは、ワークスペースが削除済みのときも断る | ワークスペースの論理削除に合わせるため(台帳 D1) |
| 「あと N 日で完全に削除」 | なし | 削除済みの行に出す | 保持日数を過ぎる時期が分かるようにするため |
| 診断の検出項目 | 親がない、種類に合わない親子、ステータス、存在しない値、日付の逆転、番号の重なり | 存在しない人、存在しないスプリント・リリース、宙づりの関連、親の循環、Epic が持つ存在しない親を加える | 台帳 B15 |
