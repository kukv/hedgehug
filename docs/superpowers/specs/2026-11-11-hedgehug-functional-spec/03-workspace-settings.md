# hedgehug 機能仕様 03: ワークスペースの設定

ワークスペースは、プロパティ・ステータス・ワークフロー・テンプレート・自動化といった「アイテムの決まり」を、ワークスペースごとに持つ。その一部をプロジェクトごとに変える「プロジェクト別のルール」も、ワークスペースの設定の一部として持つ(「プロジェクト別のルール」の節)。この文書は、ワークスペースの作成と、設定の画面で変えられるものの振る舞いを定める。用語・Store・書き込み・閲覧のみの Store は 01 を参照。

## 範囲と画面の構成

ワークスペースの設定は、ワークスペースの画面の「設定」タブにある。サブタブは次の 8 つで、この順に並べる。

| サブタブ | 内容 |
|---|---|
| 一般 | 名前、接頭辞、別の Store へ移動、削除 |
| プロパティ | 組み込み 8 種と追加プロパティ |
| ステータス | ステータスの色・名前・分類・初期ステータス |
| 優先度 | 優先度の値・初期優先度 |
| 関連システム | 関連システムの値 |
| ワークフロー | 遷移の制約 |
| テンプレート | テンプレートと、種類ごとの既定 |
| 自動化 | ルールと最近の実行 |

サイドバーのワークスペースのメニューには、「プロジェクトを作成」「設定を開く」「上へ移動」「下へ移動」「削除…」を出す(並べ替えは 04 を参照)。「設定を開く」はこの設定タブ、「削除…」は一般の削除と同じ確認ダイアログを開く。

サブタブは増やさない。「ステータス」「ワークフロー」「テンプレート」「自動化」のサブタブの上には、そのサブタブの区画に設定を持つプロジェクトがあるときだけ、「プロジェクト別のルールがあるプロジェクト: {ID} {タイトル}・…({N} 件)」を 1 行出す。名前を押すと、そのプロジェクトの設定タブの該当の区画を開く。削除済みのプロジェクトは出さず、件数にも数えない。プロジェクト別のルールの編集は、プロジェクトの設定タブで行う(02)。

スプリントとリリースは 05、アイテムの操作は 02、保存したビューとクエリは 04、通知は 06、削除済みと診断は 08 を参照。

設定の変更は、どれも 01 の書き込みの単位に従う。1 回の変更が 1 回の保存になり、アクティビティに残る。同期で複数のマシンの変更が重なったときは、設定も項目ごとの後勝ちで合わせる。編集と削除が重なったら、編集を残して削除を取り消す。負けた人には「上書き」の通知を出す(06 を参照)。閲覧のみの Store のワークスペースでは、設定の Store に書く入力欄とボタンをすべて無効にし、「閲覧のみの Store です」と添える。サブタブの 8 つは押せる。「選択肢 N」「使う種類」「テンプレートの編集」は開けるが、中の入力欄・チェック・追加・並べ替え・保存のボタンは無効で、「閉じる」だけ使える。設定を変えられる人に役割の区別はなく、Store に書き込める人なら誰でも変えられる。

各操作の保存に残る文と、保存後に出るトーストを次にまとめる。トーストにボタンは付かない。「なし」の操作は、トーストを出さない。

| 操作 | アクティビティの文 | トースト |
|---|---|---|
| ワークスペースの作成 | ワークスペース「X」を作成 | なし |
| 名前の変更 | ワークスペースの名前を「X」に変更 | なし |
| 接頭辞の変更 | 接頭辞を A から B に変更 | 接頭辞を変えました |
| 別の Store へ移動 | ワークスペース「X」を B へ移動 | B へ移動しました |
| ワークスペースの削除 | ワークスペース「X」を削除 | 「X」を削除しました |
| プロパティの追加 | プロパティ「X」を追加 | プロパティを追加しました |
| プロパティの改名 | プロパティ「A」を「B」に改名 | なし |
| 使う種類の変更 | プロパティ「X」を使う種類を変更 | なし |
| プロパティの並べ替え | プロパティの順番を変更 | なし |
| 非表示・表示 | プロパティ「X」を非表示(表示)に設定 | なし |
| プロパティの削除 | プロパティ「X」を削除 | プロパティを削除しました |
| 値の追加 | {一覧}に「X」を追加 | なし |

| 種類ごとの既定 | {種類} の既定のテンプレートを変更 | なし |
| ルールの作成・編集・削除 | 自動化「X」を作成(編集、削除) | ルールを作成しました(削除は「ルールを削除しました」) |
| ルールの有効・無効 | 自動化「X」を有効(無効)にする | なし |
| プロジェクトの使うステータスの変更 | プロジェクト「X」の使うステータスを変更 | なし |

| プロジェクトのルールをワークスペースの設定に戻す | プロジェクト「X」の{区画名}をワークスペースの設定に戻す | ワークスペースの設定に戻しました |

{一覧}は、「ステータス」「優先度」「関連システム」のいずれか、または追加プロパティの選択肢(例: 「顧客」の選択肢)である。

名前の重複は、ワークスペース(Store 内)、プロジェクト・スプリント・リリース・プロパティ・テンプレート・ルール(それぞれワークスペース内)で認めない。比べるときは前後の空白を除き、完全に一致するものを重複とする(大文字と小文字、全角と半角は区別する)。保存する名前も、前後の空白を除いた形にする。値の名前は、同じ一覧の中で大文字と小文字を区別せずに比べる。重複の数に、削除済みのワークスペースとプロジェクトは入れない。

同期で、別々のマシンが同じ名前のものを作って 2 つになったときは、あとから同期した方の名前の末尾に「 (2)」を付ける(すでにあれば (3)、(4)…。ワークスペース、プロジェクト、プロパティ、値、テンプレート、ルール、スプリント、リリース)。「同期の修復」として保存する(06 を参照)。

## ワークスペースの作成

サイドバーの Store のメニュー「ワークスペースを追加」と、コマンドパレットの「ワークスペースを追加」から作る。ダイアログの項目は次のとおり。

- **Store**: 書き込める Store で、非表示でないものから選ぶ。閲覧のみの Store と非表示の Store は候補に出さない。初期値は、メニューを開いた Store。パレットからのときは、既定の Store(08。候補にあるとき)、なければ表示中の Store のうち候補になるものの先頭。
- **名前**: 必須。
- **接頭辞**: 必須。入力と同時に大文字にする。説明に「Epic・Story・Task・Bug・Step の ID が WEB-1 のようになります。」と出す。

次の条件に合わないときは、ダイアログの中にエラーを出して作らない。

| 条件 | 文言 |
|---|---|
| 名前が空 | 名前を入力してください |
| 同じ Store に同じ名前がある | この Store には同じ名前のワークスペースがあります |
| 接頭辞が空 | 接頭辞を入力してください |
| 接頭辞が英大文字で始まる 10 文字以内の英大文字と数字でない | 接頭辞は英大文字で始まる 10 文字以内の英大文字と数字にしてください |
| 同じ Store に同じ接頭辞がある | この Store には同じ接頭辞のワークスペースがあります |

作ると、そのワークスペースの概要を開く。Store が 1 つもないときは「先に Store を追加してください」、書き込める Store がないときは「ワークスペースを追加できる Store がありません」と表示する。書き込める Store が非表示のものだけのときは、「ワークスペースを追加できる Store がありません(非表示の Store は、設定の「Store」で表示に戻してください)」と表示する。

新しく作る Store と、空のリポジトリを clone する Store を追加するときは、Store の追加ダイアログ(08)でワークスペースの名前と接頭辞を入力させ、その値でワークスペースを 1 つ作る。名前と接頭辞はどちらも必須で、検査はこの作成と同じである(上の表の文言をそのまま使う。その Store にはワークスペースがまだないので、「同じ Store に同じ名前・同じ接頭辞がある」には当たらない)。hedgehug のデータがあるリポジトリと閲覧のみの Store では、入力欄を出さず、作らない。

作ったワークスペースの初期値は次のとおり。プロジェクトもアイテムもない。

- プロパティ: 組み込みの 8 種(次章)。追加プロパティなし。
- ステータス: Todo(未着手・グレー)、InProgress(進行中・青)、Done(完了・緑)、Pending(未着手・黄)、Cancel(中止・グレー)。初期ステータスは Todo。
- 優先度: Highest(赤)、High(橙)、Medium(黄)、Low(青)、Lowest(グレー)。初期優先度は Medium。
- 関連システム: Web(青)、API(青緑)、iOS(グレー)、Android(緑)、DB(紫)、CI(黄)。
- ワークフローの制約、テンプレート、自動化、スプリント、リリース: なし。

消すときは削除する(削除の項を参照)。

## 一般

### 名前

入力欄で Enter を押すか、フォーカスが外れたときに保存する。空にすると「名前は空にできません」、同じ Store の別のワークスペースと同名なら「この Store には同じ名前のワークスペースがあります」と表示し、入力を元の名前に戻す。同じ名前に変えたときは何もしない。

### 接頭辞

入力と同時に大文字にする。入力欄の横の「変更」か Enter で確定する。画面に、今の ID の例を、削除済みでないアイテムの番号の小さい方から 3 件分出す(確認の N と同じ範囲)。アイテムがないときは、例の欄に「アイテムはまだありません」と出す。説明は「Epic・Story・Task・Bug・Step の ID の頭に付きます。変更すると、すべての ID が新しい接頭辞で表示されます(番号はそのままです)。」とする。作成のときと同じ規則(空にできないことを含む)で検査し、同じ文言で、トーストのエラーとして断る(ダイアログの中ではない)。

確認ダイアログ「接頭辞を変更」を出す。文言は「N 件の ID が HH-1 → WEB-1 のように変わります。古い ID で書かれたコメントやリンクは、そのままの文字で残ります。旧い接頭辞でも検索できます。」で、ボタンは「変更」。N は、このワークスペースの削除済みでないアイテムの数である。N が 0 のときも、確認ダイアログを出す。本文は「接頭辞を {旧} から {新} に変更します。ID が変わるアイテムはありません。旧い接頭辞でも検索できます。」とする。

変わるのは ID の接頭辞の表示だけで、番号は変わらない。コメントの本文、リンク、アクティビティや通知の文に書かれた古い ID は書き換えない。リンクにもしない。PR の自動リンク(07)も、古い ID は読まない。旧い接頭辞でも探せる(次の段落)。

変更前の接頭辞は、ワークスペースごとに記録として持つ(Store で共有する。何度変えても全部残る)。手での変更と、同期の修復(WEB → WEB2)のどちらでも記録する。自由な語の検索、`project:`・`parent:`・`epic:`、コマンドパレットに、旧い接頭辞で「HH-12」「HH-P1」と入れると、そのワークスペースの 12 番(P1)が見つかる。旧 ID で見つかったものには「旧 ID」と添える。旧い接頭辞をあとから別のワークスペースが使っているときは、現在の ID が一致するものと、旧 ID で一致するものの両方を出し、旧 ID の方に「旧 ID」と添える。画面のアドレスに旧い接頭辞を書いたときも、そのワークスペースを開く(01「画面のアドレス」)。同じ Store の中で、旧い接頭辞をあとから別のワークスペースが使っているときは、いまの接頭辞のワークスペースを開く(別の Store のものとの順は 01「画面のアドレス」)。ワークスペースを完全に削除したときは、その記録も消える。別の Store へ移すときは、記録も一緒に移る。

同期で、同じ接頭辞のワークスペースが 2 つになったときは、あとから同期した方の接頭辞の末尾に数字を付ける(WEB → WEB2。10 文字を超えるときは末尾を削って数字を付ける)。アイテムの ID は WEB-1 から WEB2-1 に変わり、番号は変わらない。古い ID の扱いと旧 ID の記録は、上の接頭辞の変更と同じである。「同期の修復」として保存する(06 を参照)。

### 別の Store へ移動

「ワークスペースをまるごと、別の git リポジトリへ移動します。移動先には、この Store の履歴は引き継がれません。」と説明する。移動先は、自分以外の書き込める Store で、非表示でないものから選ぶ。候補がないときは「移せる Store がありません」と出す。書き込める Store が非表示のものだけのときは、「移せる Store がありません(非表示の Store は、設定の「Store」で表示に戻してください)」と出す。

移動できない条件は次のとおり。エラーはトーストで、先頭に移動先の Store 名を付ける(例: 「sample: この Store には同じ接頭辞のワークスペースがあります」)。

- 移動先に同じ接頭辞のワークスペースがある: 「この Store には同じ接頭辞のワークスペースがあります」
- 移動先に同じ名前のワークスペースがある: 「この Store には同じ名前のワークスペースがあります」

確認ダイアログ「別の Store へ移動」を出し、ボタンは「移動」とする。本文は次の内容を示す。

- 「「X」を A から B へ移動します。」
- 移動する、プロジェクトとアイテムの件数(「プロジェクト {P} 件・アイテム {I} 件を移動します。」)。削除済みのものがあるときは、「削除済みの {M} 件も一緒に移ります。」を続ける
- ワークスペースの外にあるアイテムとの関連が、種類を問わず解除されること(ワークスペースの中のアイテム同士の関連は残る)
- 移動先にいない担当者などが、移動先のメンバーに追加されること(その人数。人数は、下の「移すものに現れるすべての人」(削除済みを含む)で数える。例: 「鈴木さん・高橋さんの 2 人が、移動先のメンバーに追加されます」)
- 移動先に remote がなく、移動元に remote があるとき: 「移動先に remote がないため、ほかの人の Store からは見えなくなります。」

確認のため、削除と同じく、ワークスペースの名前を入力させる。入力が名前と一致しないあいだは移動できず、ボタン「移動」を押すと「名前が一致しません」と表示する。

移動すると、次のようになる。

- ワークスペースの設定、プロジェクト、アイテム、コメント、作業時間、スプリント、リリースが、そのまま移動先へ移る。ID、番号、接頭辞は変わらない。アイテムごとの履歴(プロパティの変更、コメント)も一緒に移る。移らないのは、Store の変更の記録(アクティビティ)である。ワークスペースの中の削除済みのプロジェクト・アイテム・スプリント・リリースも一緒に移り、削除済みのまま、元の削除日時で保持日数を数える。移動元の「削除済み」には、移ったものは残らない。
- 移動先のメンバーに載せる人は、移すものに現れるすべての人である。設定(テンプレートの本体・子・Step の担当者、自動化ルールの担当者の値、ユーザー型のプロパティの値)、プロジェクトのオーナー、アイテムの担当者・ユーザー型のプロパティの人・ウォッチ中の人・作成者、コメントと作業時間の書き手、履歴の操作者を含み、削除済みのものに現れる人も含む。テンプレートの Step の担当者の「親と同じ」と「未割り当て」は、人ではないので照合しない。これらの人を、ログイン名(大文字と小文字を区別しない)で移動先のメンバーと照合する。移動先にいない人は、表示名・ログイン名を移動元のメンバーと同じにして、移動先のメンバーに追加する(メールアドレスは持たない。01)。加えた人ごとに、アクティビティに「メンバー {ログイン名} を追加」と残る。別の人がほぼ同時に移動先へ同じ人を加えたときは、1 行に統合される(06 を参照)。
- ワークスペースの外のアイテムとの関連は、削除済みのものを含め、種類を問わず解除する。
- 移動元には、移した日時を含む転送の記録を残す。移動元の Store にはワークスペースが表示されなくなり、旧い画面のアドレスを開くと、開いたタブのまま移動先のワークスペースを開き、見出しの下(タブの上)に「このワークスペースは {日時} に {Store 名} へ移動しました」を 1 行出す(そのあとさらに別の Store へ移したときは「このワークスペースは {日時} に {B の Store 名} へ移動し、その後 {いまの Store 名} へ移動しました」)。タブを変えるか別の画面を開くと消え、普通に開いたときと、自分で移した直後の新しいアドレスでは出さない。リンクは出さない(もう移動先を開いているため)。例: `/s/work/w/WEB/overview` を開くと、Store「team」のワークスペースの概要が開き、見出しの下に 1 行が出る。「スプリント」のタブを押すと、この 1 行は消える。ID は変わらないので、旧い ID で検索すれば、移動先のアイテムが見つかる。転送の記録は消さず、移すたびに 1 件ずつ残す(移したものの内部 ID・旧 ID・移した日時・移動先の Store 名と新 ID)。旧い画面のアドレスは、旧い ID(ワークスペースは旧い接頭辞)で転送の記録をたどり、記録の内部 ID で、表示中のすべての Store から探して、いまある場所を開く(移動先からさらに別の Store へ移したときも、いまの場所に辿り着く)。見つからないときは、画面は開かず、トーストで、削除済み・完全に削除・移動先の Store が非表示かこのマシンにない、のどれかを言い分けて案内する(文言は 02 の転送の記録に従う)。ワークスペースの文は、02 の文の {旧 ID} を「このワークスペース」に、{新 ID} を {Store 名} に替えたものである(例: 「このワークスペースは {日時} に team へ移動しましたが、削除されています。設定の「削除済み」から復元できます」)。ワークスペースの完全な削除は、転送の記録に触れない。
- 保存は、移動元と移動先で 1 回ずつ(01 を参照)。アクティビティは、移動元に「ワークスペース「X」を B へ移動」、移動先にワークスペースの追加として残る。
- 移動先に remote があるときは、次の順で行う。(1)移動先を同期して受け取る。(2)移動先に保存する。(3)移動先を送信する。(4)成功したら、移動元に保存する(転送の記録)。どれかが失敗したら、何も変えずに元のままにする。失敗はエラーのトーストで「{移動先の Store 名} に送信できないため移動できません: {理由}」と出す。理由は 06 の短い理由(認証に失敗しました、remote に接続できません、remote への書き込みが許可されていません など)で、オフラインのときは「オフラインのため {移動先の Store 名} へ移動できません」とする。移動元の送信は通常の同期で行い、遅れても移動先にはすでに届いているので、その間は他の人に両方の Store で見える。移動元の送信は同期の「未送信」に出る。
- 移動と、移動元での他の人の変更が重なったときは、移動を優先し、他の人の変更は反映されない(06 を参照)。

ワークスペースの転送の記録は、ワークスペースの中のアイテム・プロジェクトの旧い画面のアドレスにも使う。移動元の Store で `/s/work/i/WEB-1` や `/s/work/p/WEB-P1` を開くと、ワークスペースの記録をたどって、移動先のワークスペースの同じ番号のアイテム・プロジェクトを開く(ID が変わらないため、見出しの下の 1 行は出さない)。その番号のものが移動先で削除済みなら、ほかの Store の同じ ID は開かず、削除済みの文(02 の「見つからないとき」)をトーストで出す。次の 3 つの決まりがある。

- 種類ごとの転送の記録(アイテム・プロジェクトの移動)で開けない理由(完全に削除など)が分かるときは、ワークスペースの記録より先にその理由をトーストで出す。
- 移動先の Store が非表示のときは、移す前に接頭辞を変えていても、旧い接頭辞ではたどれない(旧い接頭辞は、表示中の Store の中でだけ照合する)。
- ワークスペースの旧い接頭辞でたどるとき、アドレスの接頭辞は、記録の旧い接頭辞か、見つけたワークスペースのいまの接頭辞・旧い接頭辞のどれかと一致すれば当たりとする。

文言は次のとおりとする(失敗のトーストと戻しの文は、プロジェクトの移動と同じ形)。

- 区画のセレクトの名前は「移動先の Store」、ボタンは「移動…」(閲覧のみの Store では、セレクトとボタンを無効にして「閲覧のみの Store です」と添える)。確認ダイアログのボタンは「移動」「キャンセル」で、名前の入力欄の名前は「確認のため、ワークスペースの名前を入力してください」(削除と同じ)。
- 確認ダイアログの本文の関連の点は「ワークスペースの外にあるアイテムとの関連は、種類を問わず解除されます。ワークスペースの中のアイテム同士の関連は残ります。」、人の点は「{表示名}さん・…の {N} 人が、移動先のメンバーに追加されます」(0 人なら出さない)。
- 失敗のトーストは「{移動先の Store 名} に送信できないため移動できません: {理由}」「オフラインのため {移動先の Store 名} へ移動できません」「移動できませんでした」。移動先に保存したあと移動元に保存できず、取り消しもできなかったときは「ワークスペース「X」を {移動先の Store 名} へ移しましたが、移動元から取り除けず、取り消しもできませんでした。どちらかを削除してください」を出す。
- アクティビティは、移動先に「ワークスペース「X」を {移動元の Store 名} から移動」、取り消したときは「ワークスペース「X」の移動を取り消し」と残す。

### 削除

「ワークスペースを削除…」(危険操作の見た目)から、確認ダイアログ「ワークスペースを削除」を出す。本文は「「X」と、その中の N 件のプロジェクト・M 件のアイテム、スプリント・リリース・設定を削除します。設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」。N はその Store の保持日数である。確認のため、ワークスペースの名前を入力させる。入力が名前と一致しないあいだは削除できず、ボタン「削除」を押すと「名前が一致しません」と表示する。

削除は論理削除である。ワークスペース、その中のプロジェクト、アイテム、スプリント、リリース、設定は、まとめて「削除済み」に入り、保持日数を過ぎると自動で完全に削除される(08 を参照)。削除したあとの扱いは次のとおり。

- 画面は、開いていたものがなくなればマイタスクに移り、開いている詳細パネルは閉じる。
- サイドバー、検索、コマンドパレットには出ない。
- 保存したビューは残す。そのワークスペースだけを対象にしていたビューも消さず、結果は空になる。
- 通知は残る。通知が指すアイテムは「削除されたアイテム」と表示する(06 を参照)。
- アクティビティは消えない。
- 削除済みから復元すると、ワークスペースは、設定・中身・ID のままに戻る(復元の規則は 08 を参照)。
- 削除したワークスペースの中身を、同期の前に別のマシンで変更・追加していたときは、その子も一緒に削除済みに入れる(06 を参照)。

## プロパティ

アイテムの項目(ステータス、担当者など)をプロパティと呼ぶ。タイトルと説明はプロパティではなく、設定を変えられない。スプリントとリリースもプロパティではない(05 を参照)。

### 一覧

プロパティの表は、名前・キー・型・使う種類・操作の順に出す。

- 名前: インラインで編集する。空にすると「名前は空にできません」、ほかのプロパティ(組み込みと非表示のものを含む)と同名なら「同じ名前のプロパティがあります」と、エラーのトーストで表示し、入力を元の名前に戻す。比べ方は上の名前の重複の規則に従う。元の名前に変えたときは何もしない。
- キー: コードの書体で出す。組み込みのものには「組み込み」と添える。
- 型: 組み込みは型の名前、追加は 8 型のどれか。単一選択と複数選択には「選択肢 N」のボタンを添え、選択肢の編集を開く。
- 使う種類: 種類のアイコンを並べる。すべての種類で使うときは「すべて」。押すと、種類のチェックメニューを開く。
- 操作: 上へ・下への矢印。組み込み(ステータス以外)は「非表示」(非表示のときは「表示」)、追加プロパティはごみ箱のボタン。ステータスにはどちらもない。

非表示のプロパティの行は薄く出す。説明は「組み込みのプロパティは名前の変更や、種類ごとの表示・非表示を設定できます。追加したプロパティは、型・選択肢・キーを決められます。キーは絞り込みに使います(例: customer:サンプル)。」とする。

### 組み込みの 8 種

| キー | 名前の初期値 | 型 |
|---|---|---|
| status | ステータス | ステータス |
| assignee | 担当者 | ユーザー |
| priority | 優先度 | 優先度 |
| start | 開始日 | 日付 |
| end | 終了日 | 日付 |
| points | ポイント | 数値 |
| estimate | 見積もり時間 | 時間 |
| systems | 関連システム | 関連システム |

型「時間」は、組み込みの見積もり時間だけが持つ。追加プロパティの型には含めない。

組み込みのプロパティは、削除できない。名前、使う種類、並び順、表示と非表示を変えられる。ただしステータスは、名前と並び順だけを変えられる(使う種類は全種類で固定、非表示にもできない)。

### 追加プロパティ

「プロパティを追加」から作る。ダイアログの項目は、名前、キー、型、使う種類(1 つも選ばないとすべて)である。型は次の 8 つから選ぶ。

| 型 | 値 |
|---|---|
| テキスト | 文字列 |
| 数値 | 数 |
| 日付 | 日付 |
| 単一選択 | 選択肢から 1 つ |
| 複数選択 | 選択肢から複数 |
| ユーザー | Store のメンバーから 1 人 |
| チェック | オンとオフ |
| URL | URL |

キーの入力欄には「英小文字・数字・_。絞り込みで使います」と添える。次の条件に合わないときは、ダイアログの中にエラーを出して作らない。

| 条件 | 文言 |
|---|---|
| 名前が空 | 名前を入力してください |
| 同じ名前のプロパティがある | 同じ名前のプロパティがあります |
| キーが、英小文字で始まる英小文字・数字・_ でない | キーは英小文字で始まる英小文字・数字・_ にしてください |
| キーが、このワークスペースにすでにある、または予約語 | このキーは使用できません(もうあるか、予約されています) |

予約語は、検索の条件のキー(04 を参照)である。`status`、`kind`、`system`、`assignee`、`priority`、`sprint`、`release`、`project`、`parent`、`epic`、`workspace`、`store`、`is`、`has`、`watching`、`sort`、`points`、`estimate`、`start`、`end`、`category`、`group`、`mentions`、`created`、`updated`、`blocks`、`blocked_by`、`causes`、`caused_by`、`duplicates`、`duplicated_by`、`relates_to`、`clones`、`cloned_by` の 34 個。組み込みのキー(`systems` を含む)も、すでにあるキーとして使えない。

型とキーは、作ったあとに変えられない。名前と使う種類は変えられる。同じキーを別のワークスペースで別の型として作ることはできる(検索とテーブルでは、最初に見つかった型で扱う。04 を参照)。

同期で、同じキーのプロパティが 2 つになったときは、あとから同期した方のキーの末尾に数字を付ける(customer → customer2)。「同期の修復」として保存する(06 を参照)。

作った型が単一選択か複数選択のときは、続けて選択肢の編集を開く。選択肢は 0 個でもよい。

### 使う種類

プロパティを使う種類(Epic・Story・Task・Bug・Step)をメニューから選ぶ。チェックのたびに保存し、メニューは開いたままにする。

- 1 つもチェックしない変更は「少なくとも 1 つの種類で使ってください」と断る。
- 全種類をチェックした状態は「すべて」と同じである。
- 使わない種類のアイテムでは、そのプロパティを詳細パネルにも作成ダイアログにも出さず、テーブルのセルは「—」にして編集できない。
- 使う種類から外しても、アイテムの値は消えない。使う種類に戻すと、値が現れる。

### 非表示

組み込みのプロパティ(ステータス以外)を、詳細パネルと作成ダイアログから隠す。テーブルの列メニュー、検索のキー、カンバンのレーン、一括変更では、非表示でも使える。アイテムの値は消えず、表示に戻すと現れる。担当者を非表示にしても、マイタスクと通知は担当者の値を使い続ける。

非表示は、確認なしで行う。

### 並べ替え

上へ・下への矢印で、隣のプロパティと入れ替える。ステータスも動かせる。この順が、詳細パネルのプロパティ欄と、作成ダイアログのクイック項目の並びになる。

### 削除

追加プロパティだけを削除できる。確認ダイアログ「プロパティを削除」(危険操作の見た目)を出し、本文は「「X」を削除します。」に、値の入っているアイテムがあれば「値の入っている N 件から値が消えます。」を続ける。ボタンは「削除」。N は削除済みでないアイテムの数である。この操作で、次のものが同時に変わる。

- すべてのアイテム(削除済みを含む)から、そのプロパティの値が消える。アイテムの履歴には残らない。
- テンプレートに設定していた、そのプロパティの値が消える。
- 保存したビューは残る。そのキーを検索の条件に使っていて、削除によってどのワークスペースにもそのキーがなくなるビューがあるときは、確認ダイアログに「このキーを使う保存したビューの検索条件は、キーがなくなるためエラーになります。」と添える。ビューを開くと、検索の欄に「「customer」というキーはありません」と表示され、結果は空になる。条件を直すまで、そのままである。テーブルの列の設定は、次にそのビューを保存するときに、なくなったキーの列を取り除く。

## 値の編集

ステータス・優先度・関連システムと、追加プロパティの選択肢(単一選択・複数選択)は、同じ形の編集画面で扱う。ステータス・優先度・関連システムは、それぞれのサブタブで編集する。選択肢は、プロパティの表の「選択肢 N」から開く「「X」の選択肢」ダイアログで編集する。値はワークスペースごとに持つ。画面の説明は、優先度・関連システム・選択肢では「名前・色・順番を変更できます。このワークスペースだけの値です。」、ステータスでは分類の説明(後述)に続けて「このワークスペースだけの値です。」とする。

各行は、色のボタン、名前、(ステータスのみ)分類、(ステータスと優先度)初期ステータス・初期優先度の印、使っているアイテムの件数(削除済みを除く)、上へ・下へ、削除の順に並ぶ。末尾に、新しい値の名前の入力欄と「追加」ボタンがある。

### 色

色のボタンから、次の 18 色をメニューで選ぶ。

グレー、青灰、茶、赤、ローズ、桃、赤紫、紫、藍、青、空色、水色、青緑、緑、オリーブ、山吹、黄、橙

値を追加したときの色は、一覧の順に 18 色を繰り返して割り当てる(現在の値の数を 18 で割った余りの色)。

### 名前

空にすると「名前は空にできません」、同じ一覧の別の値と(大文字と小文字を区別せずに)同名なら「同じ名前の値があります」と表示し、元の名前に戻す。追加するときも、重複は同じ文言で断る。

名前を変えても、アイテムの値は変わらない(アイテムは値そのものを指していて、名前の文字ではないため)。検索の条件は値の名前の文字で書くので、変えたあとの旧い名前の条件は何にも一致しなくなる。保存したビューの検索条件は書き換えない。カンバンの WIP 上限は、保存したビューのものも、このマシンのワークスペースとプロジェクトの画面のものも、列の名前で持つので、ステータスの改名に次のように従う。

- 旧い名前のステータスが、このマシンに追加してあるすべての Store(非表示を含む)のワークスペースに残っていないときは、旧い名前の上限を新しい名前に付け替える。ただし、新しい名前にすでに上限があるときは、新しい名前の上限を残し、旧い名前の上限は捨てる(例: 「InProgress」の上限 3 を「Doing」に改名するとき、「Doing」に上限 5 があれば 5 が残る。「Doing」の列は、ワークスペースをまたいで上限 5 になる)。
- 残っているときは、付け替えない(別の Store のワークスペースに「InProgress」が残るなら、上限 3 は「InProgress」の列に残る)。
- 付け替えはこのマシンの設定と、このマシンの保存したビューに対して行う。ほかのマシンの設定とビューは、そのマシンが同期でステータスの改名を受け取ったときに、同じ規則で付け替える。

### 分類(ステータスのみ)

ステータスは、未着手・進行中・完了・中止の 4 つの分類のどれかを持つ。追加したステータスの分類は「未着手」である。説明は「分類は、ボードの列・バックログ・バーンダウン・マイタスクで「未着手・進行中・完了・中止」を見分けるのに使います。」とする。分類は、ほかにも次のところで使う。

- 進捗の集計。「完了」を完了として数え、「中止」は分子にも分母にも入れない(05 を参照)。
- 分類ごとの既定のステータス(次節)を通して、Step のチェック、ツリーの Space キー、カンバンの分類の列へのドラッグ、自動化の初期値、移動のステータスの置き換えの初期値(02)に使う。

分類を変えても、アイテムは変わらない。履歴にも残らず、自動化も動かない。集計とボードの列だけが、すぐに変わる。

### 分類ごとの既定のステータス(ステータスのみ)

4 つの分類のそれぞれに、**既定のステータス**を 1 つ指定する。ステータスのタブの一覧の上に、「未着手の既定」「進行中の既定」「完了の既定」「中止の既定」の 4 つのセレクトを置く。選択肢は、その分類のステータスである。選ぶと保存する。作ったワークスペースの初期値は、未着手が Todo、進行中が InProgress、完了が Done、中止が Cancel である。

既定のステータスは、次の場面で使う。

| 場面 | 使う既定 |
|---|---|
| Step のチェックを入れる | 完了の既定 |
| Step のチェックを外す | 未着手の既定 |
| ツリーで Space を押す(行の分類が完了でないとき) | 完了の既定 |
| ツリーで Space を押す(行の分類が完了のとき) | 未着手の既定 |
| カンバンで、いまと違う分類の列へドラッグする(04) | ドロップした列の分類の既定 |
| 自動化のルールを作るときの値の初期値 | 完了の既定 |
| 移動の確認ダイアログの「ステータスの置き換え」の初期値(02) | 移動先で同じ分類の既定 |

どの分類にも、ステータスが 1 つ以上必要である。既定のステータスは、分類を変えることも削除することもできない。しようとすると「「X」は{分類}の既定のステータスです。先に別のステータスを既定にしてください」と表示して断る。分類の最後の 1 つは必ずその分類の既定なので、これで分類が空になることはない。既定のステータスと初期ステータスは、プロジェクト別のルールで「使わない」にした印があっても、どのプロジェクトでも常に使う(「プロジェクト別のルール」の節)。

初期ステータスは、分類を完了・中止に変えることもできない。しようとすると「「{名前}」は初期ステータスです。完了・中止にするには、先に別のステータスを初期ステータスにしてください」と表示して断る。削除、または完了・中止への分類の変更で、初期ステータスと分類の既定のステータスの両方に当たるときは、1 つの文にまとめて、エラーのトーストで出す。「「Todo」は初期ステータスで、未着手の既定のステータスでもあります。先に別のステータスを、初期ステータスと未着手の既定にしてください」(分類名は、そのステータスの分類)。作ったばかりのワークスペースで「Todo」のごみ箱を押すと、この文が出る。当たるのが 1 つだけのときは、それぞれの文のままである。

### 初期ステータス(ステータスのみ)

新しく作るアイテムの最初のステータスを、**初期ステータス**として 1 つ指定する。各行の「初期ステータスにする」で変え、現在の初期ステータスの行には「初期」の印を付ける。並べ替えでは変わらない。初期ステータスは、次の場面で使う。

- アイテムの作成(作成ダイアログの初期値)、Step の追加
- アイテムの複製(複製はステータスを初期ステータスに戻す)
- 診断の修復のときの置き換え先

初期ステータスに選べるのは、分類が「未着手」か「進行中」のステータスだけである。完了・中止のステータスの行では「初期ステータスにする」を無効にし、「完了・中止のステータスは初期ステータスにできません」と添える。

初期ステータスは、削除できない。削除しようとすると「初期ステータスは削除できません。先に別のステータスを初期ステータスにしてください」と表示する(分類の既定のステータスでもあるときは、前節の 1 つの文にまとめる)。

同期の前に、ほかのマシンで初期ステータスや分類ごとの既定のステータスにした値が、このマシンで同時に削除されていたときは、同期のときにその値の削除を取り消して残す(06 の「同時に編集したとき」と同じく、変更を残す)。同時の削除で、ある分類のステータスが 0 個になるときも、あとから同期した方の削除を取り消す。「同期の修復」として保存する(06 を参照)。

同期で、一方が X を完了または中止の分類にし、他方が X を初期ステータスにして、X が完了または中止の初期ステータスになったときは、初期ステータスを、未着手の既定のステータスに戻す(分類の変更は残す)。「同期の修復」として保存し、実行者は「同期」とする。アクティビティの文は「初期ステータスを「{未着手の既定}」に戻し」とする。通知は、X を初期ステータスにした人のマシンに作り、本文は「「{X}」は {変更した人} が{完了 または 中止}の分類にしたため、初期ステータスを「{未着手の既定}」に戻しました」とする(06 を参照)。初期優先度には分類がないので、この規則はない。

### 初期優先度(優先度のみ)

新しく作るアイテムの最初の優先度を、**初期優先度**として 1 つ指定する。優先度には「なし」がなく、どのアイテムも必ず優先度を持つ。各行の「初期優先度にする」で変え、現在の初期優先度の行には「初期」の印を付ける。並べ替えでは変わらない。初期優先度は、初期ステータスと同じ場面(アイテムの作成、Step の追加、診断の修復の置き換え先)に加えて、ほかのワークスペースへの移動で値が合わなかったときの置き換え先にも使う。複製では、複製元の優先度をそのまま写す。

初期優先度は、削除できない。削除しようとすると「初期優先度は削除できません。先に別の優先度を初期優先度にしてください」と表示する。初期優先度にした値を、別のマシンが同時に削除していたときは、初期ステータスと同じく、同期のときにその値の削除を取り消して残す(06 を参照)。

### 並べ替え

上へ・下への矢印で、隣の値と入れ替える。この順が、メニュー、ワークフローの表、カンバンの列(列の基準がステータスのとき)の並びになる。初期ステータスと初期優先度は変わらない。

### 削除

ステータスと優先度は、初期ステータス・初期優先度を削除できないので、必ず 1 つ以上残る。関連システム・選択肢は、0 個になってもよい。

確認ダイアログ「「X」を削除」(ボタンは「削除」、危険操作の見た目)を出す。本文は、使っているアイテム(削除済みを含まない件数)の有無と値の種類で変わる。

| 場合 | 本文 |
|---|---|
| 使っているアイテムがない | 使っているアイテムはありません。 |
| 単一の値(ステータス、優先度、単一選択の選択肢)を使っている | N 件がこの値を使っています。代わりの値を選んでください。(「代わりの値」のセレクト) |
| 複数の値(関連システム、複数選択の選択肢)を使っている | N 件がこの値を使っています。それらからこの値が削除されます。 |

代わりの値の選択肢は、削除する値以外の値である。ステータスでは「なし」を選べず、初期値は初期ステータス(削除する値が初期ステータスのときは、削除できない)。優先度でも「なし」を選べず、初期値は初期優先度(削除する値が初期優先度のときは、削除できない)。単一選択では「なし」を選べ、初期値は「なし」にする。ステータスのダイアログには「ワークフローの制約と自動化(プロジェクト別のルールを含む)からも削除されます。」と添える。ステータスでは、使っているアイテムがあるとき、本文に「N 件を「{代わりのステータス}」に置き換えます。」を続ける(代わりを選び直すと文も変わる)。

削除すると、次のものが同時に変わる。

- 単一の値: 使っているすべてのアイテム(削除済みを含む)を、代わりの値(または「なし」)に置き換える。アイテムの履歴に、あなたの変更として「旧い値 → 新しい値」を残す。この置き換えは、ワークフローの遷移の制約を検査せず、自動化も動かさない。
- 複数の値: 使っているすべてのアイテムから、その値だけを外す。履歴には残らない。
- テンプレートに設定していた値: 単一の値は代わりの値(または「なし」)に、複数の値は外す。
- ステータスのとき、さらに次の変更をする。
  - ワークフロー: そのステータスの行と、ほかの行の許可先から外す。許可先がすべてなくなった行は、「どこへでも」に戻る。
  - プロジェクト別のルール: 使わないステータスの一覧と、プロジェクトの遷移の制約(上のワークフローと同じ規則)から外す。専用ルールは、次の自動化と同じ規則で書き換え、同じ通知を作る。書き換え先が、そのプロジェクトで使わないステータスでも、そのまま書き換えて残す。
  - 自動化: きっかけまたはすること(ステータスを変更)がそのステータスだったルールは、代わりのステータスに書き換える。書き換えた結果、きっかけとすることが同じステータスになったルールは、無効にする。ルールが変わったとき(無効にしたときも、書き換えただけのときも)は、その Store に書き込める全員のマシンが、受け取った変更から、受信箱の「自動化」へ通知を 1 件ずつ作る(差出人は「hedgehug」)。削除した人のマシンは自分の操作で作り、ほかの人のマシンは受け取った削除の保存から作る。同じ削除を何台が受け取っても、1 台につき 1 件である。閲覧のみの Store、Store を追加したときに取得した過去の変更、非表示の Store では作らない(06 を参照)。文は、無効にしたときは「自動化「X」は、ステータスの削除で、きっかけと同じステータスへの変更になったため、無効にしました」、書き換えただけのときは「自動化「X」は、ステータス「Review」の削除で、{きっかけ または すること}のステータスを「Todo」に書き換えました」とする。
  - カンバンの WIP 上限: 列のなくなった上限は表示されず、保存したビューは次の保存で取り除く。

保存したビューの検索条件は書き換えない。削除した値の名前を使った条件は、何にも一致しなくなる(エラーにはならない)。

## ワークフロー

ステータスの変え方に、遷移の制約を置ける。ステータスごとに必須の項目を決める仕組みは持たない。

### 遷移の制約

行を「今のステータス(From)」、列を「次のステータス(To)」にした表で、チェックした To にだけ、その From から変更できる。説明は「行に表示されているステータスから、チェックしたステータスにだけ遷移できるよう制御することができます。」とする。

- From の行に 1 つもチェックがなければ、制限なし。行の右に「どこへでも」と出す。1 つ以上あれば「制限あり」と出す。
- 自分自身へのセルはなく、「—」を出す。
- チェックのたびに保存する。

制約に反するステータスの変更は断る。文言は「ワークフローの制約: A から B には変更できません(X・Y のみ)」で、X・Y は許可している To である。アイテムのプロジェクトに遷移の制約があるときは、ワークスペースの制約とプロジェクトの制約の両方が許す To だけを X・Y とし、使わないステータスは除く。両方が許す To がないときは「ワークフローの制約: A から B には変更できません(変更できる先がありません)」とする。断るときの見せ方は、操作によって違う。

- ステータスのメニュー: 選べない項目を無効にし、その項目に上の文言を理由として添える。
- ドラッグ、セルの編集、Step のチェック、ツリーの Space キーなど、選べない見た目にしていない操作: 上の文言をエラーとして表示し、何も変えない。
- 一括変更: そのアイテムを変えずに残し、件数と理由を表示する(04 を参照)。
- 自動化: 実行を止める(自動化の章を参照)。

次の変更には、遷移の制約を適用しない。アイテムの作成(Step の追加、テンプレートでの作成、複製を含む。プロジェクトが使うステータスなら、任意の初期ステータスで作れる)、アイテムの移動(同じワークスペース、別のワークスペース、別の Store、プロジェクトの別のワークスペースへの移動)、種類の変更、同期で受け取った変更、同期の修復、値の削除による置き換え、診断の修復、受信箱の「制約を無視して…」と「自分の値に戻す」。

## テンプレート

テンプレートは、アイテムを作るときのひな形である。1 つのアイテムの欄を埋めるだけでなく、その下に作る子と Step の構成も持てる。たとえば Epic「リリース作業」のテンプレートを選ぶと、Epic と、その下の Story「QA」「リリースノート作成」「本番反映」と、それぞれの Step が、1 回で作られる。

### 持てるもの

テンプレートは、1 つの**もとになるアイテム**と、その下の**構成**からなる。

| 部分 | 内容 |
|---|---|
| 名前 | 必須。同じ名前を認めない |
| 種類 | もとになるアイテムの種類。Epic・Story・Task・Bug・Step のどれか。初期値は Task |
| タイトルの書き出し | 作成ダイアログのタイトルの初期値 |
| 説明 | 複数行 |
| 値 | 優先度(「指定しない」と優先度の値。「指定しない」なら初期優先度)、担当者(「未割り当て」と Store のメンバー)、関連システム、その種類で使う追加プロパティ |
| 子 | 種類が Epic のときだけ持てる。子の Story・Task・Bug の並び。各子は、種類・タイトル・説明・値・Step を持つ |
| Step | 種類が Story・Task・Bug のときは、もとになるアイテムの Step。Epic のときは、各子の Step。各 Step は、タイトルと担当者を持つ |

- Step の担当者は「親と同じ」(初期値)、「未割り当て」、Store のメンバーの 3 つから選ぶ。「親と同じ」なら、作ったときに、すぐ上のアイテムの担当者を入れる。「未割り当て」なら、すぐ上のアイテムの担当者によらず、担当者はなしにする(通知は出ない)。
- 値の欄は、そのプロパティが非表示のとき、またはその種類で使わないときは出さない。開始日・終了日・ポイント・見積もり時間・ステータス・スプリント・リリースは、テンプレートに持たない。作ったときのステータスは初期ステータスになる。
- 子と Step の件数に上限は設けない。

### 一覧と編集

一覧は、種類のアイコン、名前、構成の件数(「子 3 件・Step 8 件」。ないものは出さない)、編集、削除の順に出す。ないときは「テンプレートはありません」。作る入口は、一覧の「テンプレートを作成」と、詳細パネルのメニューの「テンプレートとして保存…」(後述)の 2 つである。

編集のダイアログは、上に名前・種類・タイトルの書き出し・説明・値を置き、その下に構成を置く。

- **Story・Task・Bug のとき**: 「Step」の一覧。1 行に、タイトルの入力欄、担当者のセレクト、「上へ」「下へ」、削除の「×」を出す。末尾の「Step を追加」で行を足す。
- **Epic のとき**: 「子」の一覧。1 行に、種類のセレクト(Story・Task・Bug)、タイトルの入力欄、「編集」、「上へ」「下へ」、削除の「×」を出す。末尾の「子を追加」で行を足す。「編集」を押すと、その子の説明・値・Step を入れるダイアログを開く。Step の一覧は、上の Story・Task・Bug のときと同じ形である。
- **Step のとき**: 構成は持たない。

タイトルが空の子と Step の行は、保存するときに捨てる。

保存の条件は、名前が空なら「名前を入力してください」、同じ名前のテンプレートがあれば「同じ名前のテンプレートがあります」と、ダイアログの中に表示して保存しない。種類を変えて保存すると、新しい種類で使わないプロパティの値と、新しい種類で持てない構成(Epic 以外にしたときの子、Epic や Step にしたときのもとになるアイテムの Step)は保存しない。捨てる構成があるときは、保存の前に「子 N 件・Step M 件は、この種類では保存されません」と確認する。編集して保存しても、ほかの項目の値は消えない。

削除は、確認ダイアログ「テンプレートを削除」(危険操作の見た目)を出す。本文は「「X」を削除します。作ったアイテムには影響しません。」で、ボタンは「削除」。削除すると、種類ごとの既定からも、プロジェクトの使うテンプレートと種類ごとの既定からも外れる。プロジェクト別のルールが変わるプロジェクトがあるときだけ、確認ダイアログに「{N} 件のプロジェクト別のルールからも削除されます。」を添える。使うテンプレートが 0 件になるプロジェクトがあれば、「{ID} は、すべてのテンプレートを使えるようになります。」を続ける。

テンプレートは、作るときに中身を写すだけである。作ったアイテムはテンプレートと結びつかず、あとでテンプレートを変えても消しても、作ったアイテムは変わらない。

### アイテムからテンプレートを作る

詳細パネルのメニューの「テンプレートとして保存…」で、いまあるアイテムをもとにテンプレートを作る。Epic・Story・Task・Bug・Step のどれでも使える。ダイアログの項目は次のとおり。

| 項目 | 内容 |
|---|---|
| 名前 | 初期値はアイテムのタイトル。条件は「テンプレートを作成」と同じ |
| タイトルの書き出し | 初期値はアイテムのタイトル |
| 子と Step を含める | チェックボックス。初期値はオン。子も Step もないアイテムでは出さない |

「保存」を押すと、そのアイテムのワークスペースに、次の中身でテンプレートを作る。

- 種類・説明・値(優先度・担当者・関連システム・追加プロパティ)は、アイテムのものを写す。
- 「子と Step を含める」がオンなら、削除されていない子と Step を、並び順のまま写す。子は種類・タイトル・説明・値を写す。Step はタイトルと担当者を写し、担当者がすぐ上のアイテムと同じ(両方なしも含む)なら「親と同じ」、Step が担当者なしで親が担当者ありなら「未割り当て」、そのほかは Step の担当者のメンバーにする(例: 親が田中さんで Step「確認」がなし → 「未割り当て」。親も Step も田中さん → 「親と同じ」)。
- 写さないもの: ステータス、開始日・終了日、ポイント、見積もり時間、スプリント、リリース、コメント、作業時間、関連、GitHub のリンク、履歴。

作ると、アクティビティに「テンプレート「X」を作成」と残り、トースト「テンプレートを作成しました」を出す。保存したテンプレートは、設定のテンプレートタブで直せる。閲覧のみの Store のアイテムでは、この項目を無効にする。

### 適用するときの規則

テンプレートを適用する場面は、作成ダイアログでテンプレートを選んだとき、と、種類の既定が自動で当たるときである(作成ダイアログは 02 を参照)。適用では、作成ダイアログに次のとおりに入れる。

- タイトル: 入力済みならそのまま残し、空のときだけテンプレートのタイトルの書き出しを入れる。テンプレートを切り替えたときも同じ。
- 説明: 自動で当たるとき(ダイアログを開いたとき、種類を切り替えたとき、ワークスペースを変えたとき)は、説明が空のときだけテンプレートの説明を入れ、入力済みなら残す。利用者がテンプレートのセレクトで選んだとき(別のテンプレートに切り替えたときを含む)は、テンプレートの説明で置き換える。いま当てはめているテンプレートの説明と一字一句同じなら、テンプレート由来とみなして、空と同じに扱う(例: Task の既定テンプレートの説明「## 手順」が入っているときに Bug に切り替えると、Bug の既定テンプレートの説明「## 概要」に置き換わる。「## 手順」に 1 文字でも足していれば、残る)。種類やワークスペースを切り替えて、またはセレクトで「なし」を選んで、テンプレートを「なし」に戻すときは、説明がテンプレート由来なら空に戻し、利用者が入力したものは残す。「続けて作成」で説明を空にしたあとは、テンプレートの説明を入れ直さない。
- 優先度・担当者・関連システム・追加プロパティ: テンプレートに値のある項目だけを置き換える。値のない項目は、入力済みのまま残す。表示中でなくなったプロパティや、その種類で使わないプロパティは適用しない。
- 構成: 作成ダイアログの「一緒に作るもの」に、子と Step を読み取り専用で出す(02)。

作成ボタンを押すと、もとになるアイテムと、構成の子と Step を、1 回の保存でまとめて作る。

- 子は、もとになるアイテムの下に、テンプレートの並び順で作る。ステータスは初期ステータス、優先度はテンプレートの値か初期優先度、担当者・関連システム・追加プロパティはテンプレートの値にする。
- Step は、すぐ上のアイテムの下に作る。ステータスは初期ステータス、優先度は初期優先度、担当者はテンプレートで選んだメンバーにする。「親と同じ」なら、すぐ上のアイテムの担当者に、「未割り当て」なら、担当者なしにする。
- 作ったものは、どれも連番の番号を取る。番号は深さ優先で、作成ダイアログの「一緒に作るもの」のツリーの並びの順に振る。もとになるアイテムが先で、続いて子を並び順に、子ごとに、その子の Step を並び順に振る(例: Epic HH-13、子 1 HH-14、子 1 の Step HH-15・HH-16、子 2 HH-17)。スプリントは、作成ダイアログで選んだものを、もとになるアイテムにだけ入れる。

### 種類ごとの既定

5 つの種類のそれぞれに、既定のテンプレートを「なし」またはテンプレートから選ぶ。候補は、その種類のテンプレートだけである。作成ダイアログでその種類を選んだとき、最初に適用する。選ぶと保存する。テンプレートの種類を変えて既定の種類と合わなくなったとき、またはテンプレートを削除したときは、既定から外す。プロジェクトの種類ごとの既定と使うテンプレートにも、同じ規則を使う。

## 自動化

アイテムの出来事をきっかけに、ほかの項目を自動で変えるルールを置ける。説明は「GitHub の出来事やステータスの変化で、アイテムを自動で変えます。自動化が変えたものは受信箱の「自動化」に出ます。」とする。

### ルールの一覧

「ルールを作成」から作る。一覧の各行は、有効・無効のスイッチ、名前、説明(「{きっかけ} → {すること}」。例: 「ステータスが Done になったとき → 担当者を 未割り当て に」。条件がオンのルールは、きっかけを「リンクした PR がすべてマージされたとき」と書く)、編集、削除の順に出す。「リンクした PR がすべてマージされたとき」は一覧の説明だけに使う表示で、きっかけではない(きっかけは全部で 6 つである)。専用ルールには、名前のあとに持ち主のプロジェクトの ID を「HH-P1」のように印で添える(プロジェクトが削除済みなら「HH-P1(削除済み)」)。専用ルールは、プロジェクトの設定タブの「自動化」から作る(「プロジェクト別のルール」の節)。「ルールを作成」で作るのは、ワークスペース全体のルールだけである。作ったルールは、ワークスペース全体のルールも専用ルールも、一覧の末尾に入る。ないときは「ルールはありません」。スイッチの操作は、確認なしで保存する(ON にするときの検査は、ルールの作成の項を参照)。削除は、確認ダイアログ「ルールを削除」(ボタンは「削除」)で「「X」を削除します。」と確認する。

### きっかけとすること

きっかけは次の 6 つから選ぶ。

| きっかけ | 動く場面 |
|---|---|
| PR がリンクされて Open のとき | アイテムに PR をリンクして、その状態が Open のとき。リンク済みの PR が、Open でない状態から Open に変わったことを検知したとき(07 を参照) |
| レビューが依頼されたとき | アイテムに PR をリンクして、PR が Open か Draft で、レビューの状態が「レビュー待ち」のとき。リンク済みの PR(Open か Draft)のレビューの状態が、「なし」から「レビュー待ち」に変わったことを検知したとき(07 を参照) |
| リンクした PR がマージされたとき | PR をリンクした時点で、すでにマージ済みだったとき。リンク済みの PR がマージされたことを検知したとき(07 を参照) |
| リンクした Issue が閉じたとき | アイテムに Issue をリンクして、その状態が Closed のとき。リンク済みの Issue が、Open から Closed に変わったことを検知したとき(07 を参照) |
| ステータスが次になったとき | アイテムのステータスが、選んだステータスに変わったとき |
| Step がすべて完了したとき | Step のステータスが変わり、親のすべての Step が「完了」または「中止」の分類になったとき。親に対して動く。1 回の操作が終わった時点で、操作の前は全 Step が完了・中止ではなく、操作のあとは全 Step が完了・中止になった親ごとに、1 回だけ動く(同じ親の Step 3 件を一括変更で完了にしても 1 回。Step を削除・移動しても動かない) |

すること(アクション)は次の 2 つから選ぶ。

| すること | 値 |
|---|---|
| ステータスを変更 | このワークスペースのステータス |
| 担当者を変更 | Store のメンバー、または「未割り当てにする」。担当者を使う種類のアイテムだけ変える |

作成ダイアログの項目は、名前、きっかけ、(きっかけが「ステータスが次になったとき」なら)ステータス、(きっかけが「リンクした PR がマージされたとき」なら)条件、すること、値である。条件は、チェックボックス「リンク中の PR がすべてマージ済みのときだけ」で、初期値はオフである。チェックすると、そのアイテムの PR のリンク(マージされずに閉じたものを除く)が 1 件以上あり、そのすべてがマージ済みのときだけ、ルールが動く。きっかけを他のものに変えると、条件の選択は保存しない。初期値は、きっかけが「リンクした PR がマージされたとき」、すること「ステータスを変更」、値が完了の既定のステータスである。すること を切り替えると、値を初期化する(ステータスなら一覧の先頭、担当者なら「未割り当てにする」)。保存の条件は次のとおり。

| 条件 | 文言 |
|---|---|
| 名前が空 | 名前を入力してください |
| 同じ名前のルールがある | 同じ名前のルールがあります |
| きっかけが「ステータスが次になったとき」で、すること が「ステータスを変更」で、両方が同じステータス | きっかけと同じステータスには変更できません |

作ったルールは、有効で始まる。

スイッチを ON にするときも、上の表の最後の条件と同じ検査をする。きっかけと同じステータスなら、ON にせず(OFF のまま)、エラーのトーストで「きっかけと同じステータスには変更できません。ルールを編集してください」と表示し、保存もアクティビティも残さない。編集のダイアログの保存は上の表のとおりで、保存のときに断る。直して保存すれば、有効のまま保存できる。検査は、スイッチと保存の 2 つの入口だけに置く。同期でこの状態のルールが届いても、直さずにそのままにする。このルールは、動いても何も変えない(実行の規則を参照)ので害がなく、スイッチを OFF にするか、編集すれば直せる。

### 実行の規則

- 動くのは、このマシンで利用者が値を変える操作と、このマシンが GitHub から PR・Issue の状態と PR のレビューの状態を取り直して保存した変更と、PR を自動でリンクして保存した変更(07)に対してだけである。利用者の操作は、詳細パネル・一覧・テーブルのセルのステータスと担当者の変更、ツリーの Space キー、コマンドパレットの「ステータスを変更…」、カンバンのドラッグ、Step のチェック、「一括変更…」である。一括変更は、アイテムごとに、そのアイテムの変更でルールを判定する(10 件を Done にすれば、ルールは 10 回動き、変えたアイテムごとに通知を 1 件出す)。
- 動かないのは、次のとおり。受信箱の「制約を無視して…」と「自分の値に戻す」、「種類を変更…」、「別のワークスペースへ移動…」と同じワークスペースの別のプロジェクトへの移動、プロジェクトの別のワークスペースへの移動での値の引き直しとステータスの置き換え、複製・作成・テンプレートでの作成・Step の追加(アイテムの作成でも、ステータスのきっかけは動かない)、診断の修復、同期の修復、同期で受け取った変更、値の削除による置き換え。閲覧のみの Store は操作できず、非表示の Store は GitHub の自動の取り直しもしないので、動かない。
- 削除済みのアイテムには動かない。復元しても、さかのぼって動かさない。
- 有効なルールのうち、きっかけに合うものを、一覧の上から順に実行する。専用ルールは、判定するアイテムのプロジェクトが持ち主のときだけ対象にする。アイテムのプロジェクトが「動かさない」と決めたルールは、対象にしない。「Step がすべて完了したとき」は親に対して動くので、親のプロジェクトで判定する。1 つのルールがステータスを変えたら、次のルールは、変えたあとのステータスから遷移の制約を検査する。止められたルールは、その実行を止めて通知し、次のルールへ進む。
- 自動化が行ったステータスの変更は、ほかのルールのきっかけにならない(連鎖しない)。受信箱の「制約を無視して…」で適用した変更も、自動化が行った変更として、きっかけにならない。
- 対象にする種類を絞る設定はない。Epic も Step も対象になる。ただし「担当者を変更」は、担当者を使わない種類のアイテムには何もしない(下を参照)。
- 変更は、操作と同じ保存の中に入る。履歴とアクティビティには、操作した人ではなく「自動化」の変更として残る(06 を参照)。アクティビティの文は「「ルール名」で …」とする。
- 変更したときは、あなた宛てに、受信箱の「自動化」へ通知を出す。
- すること「ステータスを変更」は、すでにそのステータスのアイテムには何もしない。「担当者を変更」は、すでにその値(同じメンバー、または未割り当て)のアイテムと、担当者を使わない種類のアイテムには何もしない。どちらも、保存・通知・アクティビティを出さず、ルールが動いたことにならないので「最近の実行」にも出ない。担当者を非表示にしただけなら、値は使い続けるので、通常どおり変える。例: 田中さんが担当の HH-5 に「担当者を 田中 に」のルールが動いても、何も起きない。Epic「リリース作業」(Epic が担当者を使わない種類のとき)を Done にしても、担当者は変わらず、通知も出ない。Story「QA」(担当者を使う種類のとき)の Step がすべて完了すれば、QA の担当者は田中さんになる。

### 制約で止まったとき

すること「ステータスを変更」は、遷移の制約を検査する。反するときは、実行を止め、アイテムを変えない。文言は、ワークフローの章と同じ「ワークフローの制約: A から B には変更できません(X・Y のみ)」である。アイテムのプロジェクトが使わないステータスへ変えるときも、実行を止める。文言は「このプロジェクトでは「{ステータス}」を使いません」とする。止まった実行は何も変えないので、保存にもアクティビティにも残らない。あなた宛てに、受信箱の「自動化」へ、止まった理由つきの通知を出す。

通知には、次の 2 つのボタンがある(通知の表示は 06 を参照)。

- 「制約を無視して {ステータス名} にする」: 制約の検査をせずに、そのステータスにする。1 回の保存で、アクティビティの文は「「ルール名」の変更を制約を無視して適用」。トーストは「適用しました」。
- 「変更しない」: 何も変えない。保存は行わない。

どちらかを選ぶと、通知を既読にし、選んだ結果(「適用しました」「このままにしました」)を表示する。

### 最近の実行

一覧の下に「最近の実行」を出す。このワークスペースで、自動化が変えたアクティビティを、新しい順に最大 8 件、相対時刻とともに出す(専用ルールの実行を含む)。ないときは「まだ動いていません」。止まった実行は出ない。

## プロジェクト別のルール

プロジェクトごとに、そのプロジェクトのアイテムにだけ効くルールを置ける。使うステータス、遷移の制約、テンプレート、自動化の 4 つである。ワークスペースの設定に「足して絞る」ものだけで、ワークスペースの設定を緩めることはできない。ステータスや種類の定義そのものは、ワークスペースの設定のままである。プロジェクト自身の項目(タイトル・説明・オーナー・開始日・終了日・ステータス)には関わらない(02)。置けるのはプロジェクトだけで、Epic などのアイテムには置けない。必須の項目は持たない(「ワークフロー」)。

プロジェクト別のルールは、ワークスペースの設定の一部として Store で共有し、プロジェクトの内部の ID で結びつく。編集は、プロジェクトの画面の「設定」タブの 4 つの区画で行う(02)。見出しの直下に「このプロジェクトだけのルールです。ステータスや種類の定義は {ワークスペース名} のままです。」と出す。変更のたびに保存する。閲覧のみの Store では、入力欄とボタンをすべて無効にし、「閲覧のみの Store です」と添える。変える人に役割の区別はなく、Store に書き込める人なら誰でも変えられる。

ルールは、アイテムの属するプロジェクトで引く。アイテムを別のプロジェクトへ移したときは、移動先のプロジェクトのルールが、次の判定から効く。

### 使うステータス

区画の見出しは「使うステータス」で、補足は「チェックを外したステータスは、このプロジェクトのステータスのメニュー・作成ダイアログ・カンバンの列に出ません。外しても、そのステータスのアイテムは変わりません。」とする。件数「{使う数} / {全数}」を添える。ワークスペースのステータスを定義順に並べ、1 行に、チェックボックス、色、名前、分類を出す。チェックを外してあるステータスをこのプロジェクトのアイテムが使っているときは、行に「{N} 件が使用中」(削除済みを除く)を添える。保存するのは、外したものの一覧である。ワークスペースにあとから足したステータスは、初めから使う。

初期ステータスと、分類ごとの既定のステータスは、外せない。その行はチェックを付けたまま無効にし、「初期ステータスのため外せません」「{分類}の既定のため外せません」(両方に当たるときは「初期ステータスで、{分類}の既定でもあるため外せません」)と添える。外してから、ワークスペースの設定でそのステータスが初期ステータスや既定になったとき、または同期でそうなったときは、外した印は残すが、使うものとして扱う。初期・既定でなくなれば、外した印が再び働く。修復の保存も、断る文言も持たない。

このプロジェクトだけのルール(専用ルール。「プロジェクトの自動化」を参照)が、そのステータスをきっかけまたはすることに使っているときは、外せない。「「{ステータス}」はこのプロジェクトだけのルール「{ルール名}」が使っているため、使わないことにできません。先にルールを変えてください」をトーストで出し、チェックは変わらない。ワークスペース全体のルールが使っているステータスは、ほかのプロジェクトでは使うので、外すことを断らない。

使わないステータスは、ステータスを選ぶ操作で、次のように扱う。

- ステータスのメニュー、コマンドパレットの「ステータスを変更…」、作成ダイアログのステータスのセレクトには出さない(02)。いまのステータスが使わないステータスのときは、そのステータスだけを、チェックつきで 1 項目残し、「このプロジェクトでは使わない」と添える。選び直しても値は変わらない。
- カンバンのドラッグで、使わないステータスの列へドロップしたときは、何も変えずに「このプロジェクトでは「{ステータス}」を使いません」と表示する。検索・ビューのカンバンでも、カードのプロジェクトが使わないステータスの列へのドロップは、同じ文言で断る(04)。
- 一括変更では、選んだアイテムのどのプロジェクトでも使わないステータスは、一覧から除く。そのプロジェクトで使わないステータスにはできないアイテムは、変えずに残し、理由を控える(04)。
- 自動化の「ステータスを変更」は、実行を止める(「自動化」の章)。
- プロジェクトのカンバンでは、使わないステータスの列を出さない。そのステータスのアイテムがあるときだけ、元の位置に出し、見出しに「使わない」の印を付ける(04)。
- 同期・同期の修復・値の削除による置き換え・診断の修復・受信箱の「制約を無視して…」と「自分の値に戻す」では、断らず、使わないステータスにもなる。そのアイテムはそのまま残る。アイテムの移動は、断らないが、移動先のプロジェクトが使わないステータスを、確認ダイアログの「ステータスの置き換え」で選び直させるので、使わないステータスにならない(02)。複製・Step の追加・テンプレートでの作成は、初期ステータスで作るので、使わないステータスにならない。
- 検索、保存したビュー、テーブルの列とグループ、ガント、レポートには影響しない。

### プロジェクトの遷移の制約

区画の見出しは「ワークフローの制約」で、補足は「ワークスペースの制約に追加することだけできます(緩めることはできません)」とする。表は「遷移の制約」と同じ形で、使うステータスだけを並べる。ワークスペースの制約が許さないセルは、チェックなしで無効にし、「ワークスペースの制約で変更できません」と添える。From の行に 1 つもチェックがなければ「ワークスペースと同じ」と出し、1 つ以上あれば「制限あり」と出す。両方が許す To がない行には、「変更できる先がありません」と添える。チェックのたびに保存する。

変更の可否は、ワークスペースの制約とプロジェクトの制約の両方が許すときだけ「可」とする。制約を適用する操作、断り方、適用しない変更は、「遷移の制約」と同じである。使わないステータスを From または To とするチェックは、使わないあいだ数えない。行のチェックが使わないステータスだけのときは、その行を「ワークスペースと同じ」として扱う。ワークスペースの制約を変えて、両方が許す To がなくなっても、保存を断らず、警告も出さない。

### プロジェクトのテンプレート

区画は、上に「使うテンプレート」、下に「種類ごとの既定」を置く。上は、ワークスペースのテンプレートを種類のアイコンと名前で並べ、チェックボックスで選ぶ。1 つも選んでいないときは、すべて使える(「すべて使えます」と出す)。下は、5 つの種類のそれぞれに、「ワークスペースと同じ({名前}または「なし」)」「なし」と、使うテンプレートのうち種類が合うものから選ぶ。選ぶと保存する。

使えるテンプレートは、種類が合い、使うテンプレートに入るものである。作成ダイアログのテンプレートの選択肢は、使えるものと「なし」である(02)。種類ごとの既定は、プロジェクトの既定があればそれ、なければワークスペースの既定とし、使えるテンプレートに入らないときは「なし」とする。警告は出さない。

テンプレートの削除と種類の変更は、「テンプレート」の規則に従い、プロジェクトの使うテンプレートと種類ごとの既定からも外れる。使うテンプレートが削除などで 0 件になったときは、限定を解除した状態(すべて使える)にする。テンプレートの改名は、ルールに影響しない。

### プロジェクトの自動化

区画は、そのプロジェクトで判定されるルールを、一覧の順に並べる。1 行は、スイッチ、ルールの要約(「{きっかけ} → {すること}」)、名前、出どころ(「ワークスペース」または「このプロジェクトだけ」)である。

- ワークスペースのルール: スイッチは「このプロジェクトで動く」(ON)と「動かさない」(OFF)を切り替える。切り替えは確認なしで保存する。ワークスペースでそのルールが無効のときは、スイッチを無効にして「ワークスペースで無効」と添える。OFF にしたルールは、このプロジェクトの下のアイテムの判定で対象にしない。
- 専用ルール: 「このプロジェクトだけのルールを追加」から作る。作る入口は、この区画だけである。ダイアログの項目、保存の条件、初期値は、「ルールを作成」と同じで、ステータスの選択肢だけ使うステータスにする。スイッチはルール自身の有効・無効で、行に「編集」「削除」を出す。専用ルールは、ワークスペースの「自動化」サブタブの一覧にも並び、そこからも編集と削除ができる。名前の重複は、ワークスペースの中で認めない。

ステータスの削除でルールを書き換える規則と、その通知は、専用ルールにも同じ文で使う(「値の編集」の削除)。ルール名にプロジェクトは添えない。

### ワークスペースの設定に戻す

各区画の「ワークスペースの設定に戻す…」は、確認ダイアログ「ワークスペースの設定に戻す」(ボタンは「戻す」)を出す。本文は「このプロジェクトの{区画名}のルールをすべて削除し、{ワークスペース名} の設定に戻します。」とし、自動化の区画では「このプロジェクトだけのルール {N} 件も削除します。」を続ける。戻すと、使うステータスでは、外してあったチェックがすべて付き、自動化では、動かさない指定がすべて解除される。その区画にこのプロジェクトのルールがないときは、ボタンを無効にする。戻したあとに、元に戻す操作はない(01)。

### 移動・削除・復元

- アイテムの移動(同じワークスペースの別のプロジェクト、別のワークスペース、別の Store)は、ルールの検査をしない。ステータスは、「ステータスの置き換え」で選ばせる(02)。
- プロジェクトを別のワークスペースへ移すときは、ルールも一緒に移る。移動先の同じ名前のステータス・テンプレートに合わせ、合うものがないものは移らない。利用者に引き継ぐかどうかは聞かず、移動元の分は、移動の保存の中で削除する。
  - 使わないステータス: 名前が一致するものだけが移る。
  - 遷移の制約: チェックごとに、From と To の両方が移動先に名前で一致するものだけが移る。
  - 使うテンプレートと種類ごとの既定: 名前と種類が一致するものだけが移る。使うテンプレートが 0 件になったときは、限定を解除した状態にする。種類ごとの既定が合わないときは、「ワークスペースと同じ」にする。
  - ルールを動かさない指定: 移動先のルールとは別物なので、引き継がない。
  - 専用ルール: すべて移る。きっかけとすることのステータスが移動先になければ、「ステータスの置き換え」で選んだステータスに書き換える。ルールは、削除も無効化もしない。
  - 移らないものは、確認ダイアログに先に「移らないもの」として一覧で出す(02)。移動先に、移す専用ルールと同じ名前のルールがあるときは、移動を断る(02)。
- ワークスペースを別の Store へ移す、削除する、復元するときは、プロジェクト別のルールは設定として一緒に動く。
- プロジェクトを削除しても、ルールと専用ルールは削除しない。復元で再び働く。削除済みのプロジェクトの設定タブは開けないので、ルールは編集できない。専用ルールには、一覧で「(削除済み)」の印を付ける。プロジェクトを完全に削除するときは、そのルールと専用ルールも、同じ保存の中で取り除く(08)。

## 変更が及ぶ範囲

設定の変更が、すでにあるデータに及ぼす影響を、操作ごとにまとめる。

| 操作 | アイテム | 設定 | 保存したビュー・WIP 上限 |
|---|---|---|---|
| 接頭辞の変更 | 番号はそのまま、ID の表示だけが変わる(旧い接頭辞でも探せる) | — | 影響なし |
| 別の Store へ移動 | ID はそのまま、外部との関連は種類を問わず解除 | そのまま移る | 影響なし(ビューはこのマシンに置き、すべての Store を対象にするため) |
| ワークスペースの削除 | 論理削除(復元できる) | 論理削除 | ビューは残る |
| プロパティの改名 | 影響なし | — | 影響なし(キーは変わらない) |
| 使う種類の変更・非表示 | 値は残る | — | 影響なし |
| 追加プロパティの削除 | 値が消える(履歴なし) | テンプレートから外れる | キーを使う条件はエラー、列は次の保存で除去 |
| 単一の値の削除 | 代わりの値に置き換え(履歴あり、制約と自動化は動かさない) | テンプレートも置き換え | 条件は書き換えない、列のない WIP は次の保存で除去 |
| 複数の値の削除 | その値を外す(履歴なし) | テンプレートから外れる | 条件は書き換えない |
| ステータスの削除 | 代わりのステータスに置き換え | ワークフロー、自動化、テンプレート、プロジェクト別のルールが追従 | WIP は上記のとおり |
| 値の改名 | 影響なし(値そのものを指している) | — | 条件は書き換えない、WIP はステータスのみ付け替え |
| ステータスの分類の変更 | 影響なし | — | 集計とボードの列が変わる |
| 遷移の制約の変更 | 既存のアイテムは変えない | — | 影響なし |
| プロジェクト別のルールの変更 | 既存のアイテムは変えない(使わないステータスのアイテムはそのまま残る) | — | 影響なし |
