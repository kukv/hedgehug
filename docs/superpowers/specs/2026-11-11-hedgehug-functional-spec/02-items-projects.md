# hedgehug 機能仕様 02: アイテムとプロジェクト

この文書は、アイテムとプロジェクトを作り、直し、動かし、消す操作と、アイテムの詳細パネル、コマンドパレットの振る舞いを定める。用語、階層、書き込み、閲覧のみの Store は 01 に従い、ここでは繰り返さない。

## この文書の範囲

扱うもの: アイテムの種類と親子、プロパティの入力、作成・複製・移動・種類の変更・削除、詳細パネル、ステータスの変更、プロジェクト、コマンドパレット。

他の文書に委ねるもの:

| 内容 | 文書 |
|---|---|
| ステータス・プロパティ・値・ワークフロー・テンプレート・自動化の設定(プロジェクト別のルールを含む) | 03 |
| 検索のクエリ、ツリー・カンバン・テーブル・ガントでの操作(ドラッグを含む)、一括変更 | 04 |
| スプリントとリリースの操作と集計 | 05 |
| 通知を作る規則、受信箱、アクティビティ、番号の重なりの修復 | 06 |
| PR・Issue のリンクの追加と状態の取得 | 07 |
| 削除済みの一覧と復元、完全に削除、メンバーの管理、診断 | 08 |

## アイテムの種類と親子

アイテムの種類は Epic・Story・Task・Bug・Step の 5 つである。置ける親は 01 の表のとおり。種類ごとに持てる項目は次のように異なる。

| 種類 | 子 | スプリント | リリース |
|---|---|---|---|
| Epic | Story・Task・Bug | 入れられない | 設定できる |
| Story・Task・Bug | Step | 入れられる | 設定できる |
| Step | なし | 入れられない | 設定できない |

親子の決まりに合わない場所へは、作成・移動・種類の変更のどの経路でも置けない。移動の経路では、断るときに次の文言を表示する。

| 操作 | 文言 |
|---|---|
| アイテムを、置けない種類のアイテムの下へ動かす | 「{種類} は {種類} の下に置けません」 |
| Epic 以外を、プロジェクトの直下へ動かす | 「プロジェクトの直下には Epic だけを置けます」 |
| アイテムを、別のワークスペースのアイテムの下へドラッグで動かす | 「別のワークスペースには移せません。移動はメニューの「移動…」から」 |
| アイテムを自分自身の下へ動かす | 何も起きない |

兄弟の並び順は、ツリーと詳細パネルで共通である(04)。位置を決めない移動(メニューの「移動…」)と作成では、親の子の末尾に入る。ツリーのドラッグでは、落とした位置に入る(04)。

## プロパティの入力と保存

### プロパティの種類

アイテムのプロパティは、組み込みと追加に分かれる。組み込みはステータス・担当者・優先度・開始日・終了日・ポイント・見積もり時間・関連システムの 8 つ、追加は利用者がワークスペースの設定(03)で足したものである。追加プロパティの型は、テキスト・数値・日付・単一選択・複数選択・ユーザー・チェック・URL の 8 つ。アイテムに表示されるのは、ワークスペースで非表示にされておらず、そのアイテムの種類で使うと設定されたプロパティだけである。

組み込みと追加のほかに、スプリント(Story・Task・Bug のみ)とリリース(Step 以外)の 2 項目を、同じ並びに出す。値の選び方は 05 に従い、次の 2 点だけをここで定める。

- スプリントの選択肢は「バックログ」(スプリントに入れない)と、完了していないスプリントである。実行中のものには「(実行中)」と添える。いま入っているスプリントが完了済みなら、それも選択肢に残す。完了済みのスプリントへ新しく入れることはできない。
- リリースの選択肢は「なし」と、アーカイブされていないリリースである。いま入っているリリースがアーカイブ済みなら、それも選択肢に残す。

プロパティを非表示にしたり、使う種類を変えたりしても、入っていた値は消えない。画面から隠れるだけで、表示し直せば戻る。

### 入力の方法と保存

1 つのプロパティを変えるごとに、1 回の保存になる。変更しても値が前と同じなら、何も保存しない。アクティビティには「{ID} の{プロパティ名}を {値} に変更」と残り、履歴には「{プロパティ名}を 旧 → 新」と残る。

| 型 | 入力の方法 | 未設定の状態 |
|---|---|---|
| ステータス | ボタンからメニューを開いて選ぶ。メニューの扱いは「ステータスの変更」に書く | なし(必ず値がある) |
| 優先度 | ボタンからメニューを開いて選ぶ。「なし」は置かない。選択肢が 7 件以上のとき、メニューに検索欄を出す | なし(必ず値がある。作成時はワークスペースの初期優先度。03) |
| 単一選択 | ボタンからメニューを開いて選ぶ。先頭に「なし」を置く。選択肢が 7 件以上のとき、メニューに検索欄を出す | 「なし」 |
| 担当者・ユーザー | セレクトで選ぶ。先頭に「未割り当て」を置き、メンバー全員を並べる。あなたには「(あなた)」を添える | 「未割り当て」 |
| 日付 | 日付の入力欄 | 空 |
| 数値・ポイント・見積もり時間 | 数値の入力欄。小数も入れられる。見積もり時間は 0.25 時間刻みで増減できる | 空 |
| チェック | チェックボックス | オフ |
| 関連システム・複数選択 | ボタンからメニューを開き、項目ごとに入り切りする。選ぶたびに保存し、メニューは開いたままにする | 何も選ばない |
| テキスト・URL | 文字の入力欄。前後の空白は取り除く | 空 |

保存するときに次の検査をし、合わなければ何も変えずに理由を表示する。

| 対象 | 条件 | 文言 |
|---|---|---|
| 開始日と終了日 | 両方があり、終了日が開始日より前 | 「終了日は開始日以降にしてください」 |
| ポイント | 0 未満の数 | 「ポイントは 0 以上の数で入力してください」 |
| 見積もり時間 | 0 未満の数、または数でない値 | 「見積もり時間は 0 以上の数で入力してください」 |
| 見積もり時間 | 小数第 3 位以下がある(0.123) | 「見積もり時間は小数第 2 位までで入力してください」 |

時間の値(見積もり時間)は、履歴・アクティビティ・通知・一括変更の確認では「N 時間」の形で出す。小数第 2 位までで表示し、末尾の 0 は省く。

日付は片方だけを入れてもよい。値を空にすることは常にできる。

プロパティの値がワークスペースの一覧にないとき(削除された値のまま残っているとき)は、詳細パネルのボタン、テーブルのセル、カンバンのカード、作成と一括変更のダイアログの現在値に、薄い字で「(削除された値)」と出す(01)。クリックすると選択肢が開き、選び直せる。メニューには「(削除された値)」の項目を足さない。

担当者を、あなた以外のメンバーに設定したときは、そのメンバーに通知が出る。ウォッチ中の人への通知は「ウォッチ」に書く。

## ステータスの変更

ステータスは、詳細パネルのほか、一覧やカンバンなどの画面にあるステータスのボタンからも変えられる。ボタンを押すとメニューが開く。

- メニューには、そのアイテムのプロジェクトが使うステータスを並べる(使わないステータスは出さない。03 の「プロジェクト別のルール」)。各項目に分類(未着手・進行中・完了・中止)を添え、いまのステータスにはチェックを付ける。いまのステータスがプロジェクトで使わないものなら、チェックつきで 1 項目だけ残し、「このプロジェクトでは使わない」と添える。
- ワークフローの遷移の制約(03)で、いまのステータスから移れない項目は無効にし、ヒントに理由を出す。理由の文言は「ワークフローの制約: {いま} から {移行先} には変更できません({移れる先}のみ)」である。{移れる先} は、ワークスペースの制約とプロジェクトの制約(03)が両方許す先である。両方が許す先がないときは「(変更できる先がありません)」とする。いまのステータスがワークスペースの一覧にないとき(削除された値のまま残っているとき)は、遷移の制約を検査しない。

ドラッグや Step のチェックなど、メニューを通らない経路で遷移の制約に反したときは、何も変えずに同じ文言を表示する。カンバンのドラッグ、テーブルのセル、一括変更も同じである(04)。自動化がそのステータスに変えようとしたときは、変更せず、ワークフローの制約で止まったときと同じ「自動化」の通知を出す(03・06)。

プロジェクトが使わないステータスには、ステータスを選ぶどの操作でもできない。メニュー・コマンドパレット・作成ダイアログでは選択肢に出さない。カンバンのドラッグ・一括変更・自動化では、何も変えずに「このプロジェクトでは「{ステータス}」を使いません」と断る(03、04)。移動・同期・値の削除による置き換え・診断の修復では断らない。移動は、移すアイテムのステータスを「ステータスの置き換え」で選ばせる(「同じワークスペースの中での移動」「別のワークスペースと別の Store への移動」)。

ステータスごとに必須の項目を決める仕組みは持たない。どのステータスにするときも、ほかの項目の入力は求めない。

## アイテムの作成

### 開き方と初期値

作成ダイアログは、次のどの操作でも開く。

- C キー(入力中とダイアログを開いているときは使えない)。ツリーの行にフォーカスがあるときは、その行の兄弟として開く(04 の「ツリーのキー操作」)
- コマンドパレットの「新規作成」
- 各画面の「作成」「追加」のボタン
- Epic の詳細パネルの「Story」「Task」「Bug」のボタン
- アイテムのメニューの「{種類} を追加」
- プロジェクトのメニューと画面の「Epic を追加」

ボタンから開くとき、およびツリーの行にフォーカスがあるときの C キーは、そのボタンのある場所・フォーカスのある行に合わせて、ワークスペース・プロジェクト・種類・親を初めから入れる(ツリーの行の C キーは、ワークスペース・プロジェクト・親・種類をその行と同じにする。プロジェクトの行では、親をそのプロジェクト、種類を Epic にする)。初期値は次の順に決まる。

| 項目 | 決め方 |
|---|---|
| ワークスペース | 開いた場所が指定したもの、いま開いているワークスペース、いま開いているプロジェクトのワークスペース、書き込める Store の先頭のワークスペース、の順。いま開いているものが閲覧のみの Store のものなら採らず、次の候補へ進む |
| プロジェクト | 開いた場所が指定したもの、いま開いているプロジェクト、そのワークスペースの先頭のプロジェクト、の順 |
| 種類 | 開いた場所が指定したもの。なければ Task |
| ステータス | ワークスペースの初期ステータス(03)。作ったときの初期値は Todo |
| 優先度 | ワークスペースの初期優先度(03)。作ったときの初期値は Medium |
| 親 | 開いた場所が指定したもの。なければ、親にできるものの先頭 |
| スプリント | どの入口から開いても「バックログ」。入れたいスプリントは、ダイアログのスプリントのセレクトで選ぶ |

書き込める Store のワークスペースがないときは、ダイアログを開かず、Store が 1 つもなければ「先にワークスペースを作ってください」、閲覧のみの Store だけなら「アイテムを作成できる Store がありません(閲覧のみの Store だけです)」と表示する。選んだワークスペースにプロジェクトがないときは、「{ワークスペース名} にはプロジェクトがありません。先にプロジェクトを作ってください」と表示し、プロジェクトの作成ダイアログに切り替える。

種類ごとの既定のテンプレート(03。選んだプロジェクトに既定があればそれ、なければワークスペースの既定)があれば、ダイアログを開いた時点、種類を切り替えた時点、ワークスペースを変えた時点で、そのテンプレートを当てはめる。この 3 つで自動で当てはめるときは、説明が空のときだけ、テンプレートの説明を入れる。入力済みの説明は残す。ただし、説明がいま当てはめているテンプレートの説明と一字一句同じなら、テンプレート由来とみなして空と同じに扱い、新しいテンプレートの説明に置き換える。テンプレートを「なし」に戻すときも、説明がテンプレート由来なら空に戻す。利用者が入力したものは残す。

### ダイアログの項目

| 項目 | 内容 |
|---|---|
| 種類 | Epic・Story・Task・Bug・Step から 1 つ選ぶ |
| ワークスペース | 「Store名 / ワークスペース名 (接頭辞)」の形で並べる。閲覧のみの Store と、非表示の Store のワークスペースは出さない |
| プロジェクト | 選んだワークスペースのプロジェクト |
| 親 | Epic 以外で出す。Step は同じプロジェクトの Story・Task・Bug、それ以外は同じプロジェクトの Epic から選ぶ。候補がないときは、セレクトの代わりに赤字で「このプロジェクトには Story・Task・Bug がありません。先に作ってください」(Step の場合)、または「このプロジェクトには Epic がありません。先に作ってください」と出す |
| テンプレート | その種類で、選んだプロジェクトが使えるテンプレート(03)があるときだけ出す。「なし」を含む |
| タイトル | 1 行の入力欄。プレースホルダは「{種類} のタイトル」。Enter で作成する |
| プロパティ | その種類で使う、表示中のすべてのプロパティ。組み込みのプロパティ(ステータス・担当者・優先度・開始日・終了日・ポイント・見積もり時間・関連システム)と追加プロパティを、すべてここで入力できる。ステータスは初期ステータスを初期値にしたセレクトで、選んだプロジェクトが使うすべてのステータスを選べる。優先度は初期優先度を初期値にする |
| スプリント | Story・Task・Bug のみ。完了していないスプリントから選ぶ |
| 説明 | 4 行の入力欄。Markdown とメンションを使える |
| 一緒に作るもの | テンプレートが子や Step を持つときだけ、読み取り専用のツリーで出す。1 行に、種類のアイコン、タイトル、担当者を出す。担当者は、「親と同じ」ならすぐ上のアイテムの担当者を、「未割り当て」なら「未割り当て」と出す。見出しに「一緒に作るもの: 子 N 件・Step M 件」と添える |
| ID の予告 | 「ID は HH-13 になります。」 |
| 続けて作成 | 左下のチェックボックス |

ID の予告は目安である。実際の番号は保存するときに決まり、他の人と同時に番号を取ったときは、同期のあとで振り直される(06)。

プロパティの入力欄の扱いは「プロパティの入力と保存」と同じで、複数選択と関連システムも作成時に選べる。担当者の選択肢は、選んだワークスペースの Store のメンバーである。

### ダイアログの中での連動

- **種類を切り替えたとき**: 親を、新しい種類の候補から選び直す。テンプレートと「一緒に作るもの」は空に戻し、新しい種類の既定のテンプレートがあれば当てはめる。入力済みのタイトルは残す。説明は、利用者が入力したものなら残し、テンプレート由来なら上の規則で扱う。その種類で使えない欄は画面から隠し、その値は作るアイテムに保存しない。Epic または Step に切り替えると、「スプリント」の欄を隠し、選んだスプリントは「バックログ」に戻す。Story・Task・Bug に切り替え直したとき、スプリントは「バックログ」のまま出る。その種類で使わないプロパティ(03)の欄も隠し、入力済みの値は保存しない。ダイアログを開いているあいだだけ値を覚えておき、使える種類に切り替え直すと、入力した値が戻る。「作成」を押した時点で、表示している欄の値だけを保存する。
- **ワークスペースを変えたとき**: プロジェクトを先頭にし、親を選び直す。担当者・開始日・終了日・ポイント・見積もり時間は残す。ただし担当者は、移動先の Store が違うなら、ログイン名が一致するメンバーだけを残す。優先度・関連システム・追加プロパティ・ステータス・スプリントは初期値に戻す。テンプレートと「一緒に作るもの」はいったんなしに戻し、新しいワークスペースの、いまの種類の既定のテンプレートがあれば当てはめる。説明は種類を切り替えたときと同じに扱い、テンプレートに値のあるプロパティだけを入れる。テンプレートに担当者があれば、残した担当者を置き換える。
- **プロジェクトを変えたとき**: 親を選び直す。選んでいるステータスが新しいプロジェクトで使わないものなら、初期ステータスに戻す。選んでいるテンプレートが新しいプロジェクトで使えないものなら、「なし」に戻し(説明がテンプレート由来なら空に戻し)、新しいプロジェクトの、いまの種類の既定のテンプレートがあれば当てはめる。使えるなら、そのまま残す。
- **テンプレートを変えたとき**: 入力済みのタイトルは残し、空のときだけテンプレートのタイトルを入れる。説明はテンプレートのもので置き換える。テンプレートが持つプロパティの値(優先度・担当者・関連システム・追加プロパティ)は、入力済みの値を上書きする。「一緒に作るもの」は、新しいテンプレートのものに入れ替える。「なし」に切り替えたときは、「一緒に作るもの」を空にし、説明がテンプレート由来なら空に戻す。ほかの入力は残す。

### 入力の検査

作成時にはワークフローの遷移の制約を適用しないので、そのプロジェクトで使うどのステータスでも選べる。

タイトルは、保存するすべての経路で、詳細パネルのタイトルと同じ整え方にする(連続する空白と改行を 1 つの空白にまとめ、前後の空白を取り除く)。経路は、この作成ダイアログ、テンプレートから一緒に作る子と Step、複製(整えたあとに「 のコピー」を付ける)である。空かどうかも整えたあとで判定し、空白だけなら「タイトルを入力してください」と出す。

| 条件 | 文言 |
|---|---|
| タイトルが空 | 「タイトルを入力してください」 |
| プロジェクトが選ばれていない | 「プロジェクトを選んでください」 |
| 親が選ばれていない(Step) | 「親になる Story・Task・Bug を選んでください」 |
| 親が選ばれていない(Step 以外) | 「親になる Epic を選んでください」 |
| 開始日と終了日があり、終了日が開始日より前 | 「終了日は開始日以降にしてください」 |
| ポイントが 0 未満 | 「ポイントは 0 以上の数で入力してください」 |
| 見積もり時間が 0 未満、または数でない | 「見積もり時間は 0 以上の数で入力してください」 |
| 見積もり時間に小数第 3 位以下がある | 「見積もり時間は小数第 2 位までで入力してください」 |

検査は上の順に行い、最初に合わなかった 1 つだけをダイアログの中に赤字で出す。合わなかったときは、何も作らず、ダイアログを開いたままにして、入力はそのまま残す。合ったときの作成は 1 回の保存で、ダイアログの扱いは「続けて作成」で決まる(次節)。

### 作成したあと

- **作ったもの**: アイテムを 1 つ作る。ID は、ワークスペースの連番の次の番号になる。ウォッチ中の人は作成者だけである。並びは親の子の末尾である。履歴に「作成」が残る。
- **一緒に作るもの**: テンプレートが子や Step を持つときは、それらも同じ 1 回の保存で作る。作り方は 03 の「適用するときの規則」に従う。番号は、もとになるアイテムが先、続いて子を並び順に、子ごとにその子の Step を並び順に、深さ優先で振る(Epic が HH-13 なら、子 1 が HH-14、子 1 の Step が HH-15・HH-16、子 2 が HH-17)。ID の予告とトーストの「ほか N 件」は、もとになるアイテムの番号のままである。
- **通知**: 担当者があなた以外のメンバーなら、そのメンバーに通知が出る。一緒に作った子と Step も同じで、それぞれの担当者があなた以外のメンバーなら、そのメンバーに通知が出る。説明にメンションがあれば、メンションされたメンバーに通知が出る。
- **アクティビティ**: 「{種類}「{タイトル}」を作成」と残る。一緒に作ったものがあるときは「{種類}「{タイトル}」ほか N 件を作成」とする。
- **表示**: 「{ID} を作成しました」とトーストを出す。一緒に作ったものがあるときは「{ID} ほか N 件を作成しました」とする。作ったものを消すときは、削除する。
- **ダイアログ**: 「続けて作成」がオフなら、ダイアログを閉じ、作ったアイテムの詳細パネルを開く。オンなら、ダイアログを開いたまま、タイトル・説明・エラー表示だけを空にする。ほかの入力、テンプレート、「一緒に作るもの」、プロジェクト、親はそのまま残す。
- **閉じる**: Esc で閉じる。入力した内容の確認はしない。

## 複製

アイテムのメニューの「複製」で、同じ親の下にアイテムをもう 1 つ作る。

| 項目 | 複製での扱い |
|---|---|
| タイトル | 末尾に「 のコピー」を付ける |
| 種類・親・説明・プロパティ | 複製元と同じ |
| スプリント | 複製元と同じ。ただし完了済みのスプリントなら、入れずに「バックログ」にする |
| リリース | 複製元と同じ。ただしアーカイブ済みなら「なし」にする |
| ステータス | ワークスペースの初期ステータス。ワークフローの遷移の制約は検査しない |
| ID | 新しく採番する |
| ウォッチ中の人 | あなただけ |
| 関連 | 複製元の関連は写さない。代わりに、新しいアイテムから複製元へ「clones」の関連を 1 つ付ける(複製元からは「cloned by」と見える) |
| コメント・GitHub リンク(解除の記録を含む)・作業時間・履歴 | 複製しない |
| 子(Epic の Story・Task・Bug、Story・Task・Bug の Step) | 複製しない。構造ごと写したいときは、メニューの「テンプレートとして保存…」で子・Step ごとテンプレートにし、作成ダイアログで使う(03) |

複製が終わると、詳細パネルは新しいアイテムに切り替わる。アクティビティには「{ID} を複製」と残る。担当者があなた以外のメンバーなら、そのメンバーに通知が出る。説明にメンションがあれば、メンションされたメンバーに通知が出る(複製先の説明は新しい本文なので、作成と同じく別の行になる)。トーストは出さない。

## 同じワークスペースの中での移動

アイテムのメニューの「移動…」で、親を変える。

- **Epic**: 同じワークスペースの、ほかのプロジェクトをメニューに並べる。選ぶと、その Epic は選んだプロジェクトの直下に移り、下の Story・Task・Bug・Step もすべて同じプロジェクトに移る。ほかのプロジェクトがないときは、この項目を無効にする。
- **Story・Task・Bug・Step**: 新しい親の候補をメニューに並べる。Step の候補は Story・Task・Bug、それ以外の候補は Epic である。候補には、ワークスペース全体のものを出し、プロジェクトをまたいでよい。自分と自分の子孫、いまの親は出さない。検索欄を付け、各候補にプロジェクト名を添える。選ぶと、そのアイテムと下のものがすべて、新しい親のプロジェクトに移る。

移動の前後で、プロパティ・スプリント・リリース・関連は変わらない。ただし、プロジェクトが変わるときは、ステータスを下の「ステータスの置き換え」で選ぶことがある。ワークフローの制約と、移動先のプロジェクトのルール(使うステータス・遷移の制約。03)の検査はしない。履歴に「親を変更」と残る。アクティビティには、親が変わるときは「{ID} を {ID} の下に移動」、プロジェクトが変わるときは「{ID} を {プロジェクト名} に移動」と残る。トーストは「{ID} の下に移動しました」「{プロジェクト名} に移動しました」である。通知は出ない。

プロジェクトが変わる移動で、移すアイテム(下のものと削除済みのものを含む)のステータスに、移動先のプロジェクトが使わないものがあるときは、選んだあとに確認ダイアログを出す。タイトルは「移動」、本文は「{ID} {タイトル} と、その下の N 件を {プロジェクト名} へ移動します。」(下のものがないときは「{ID} {タイトル} を移動します。」)、ボタンは「移動」と「キャンセル」である。見出し「ステータスの置き換え」の下に、使わないステータスごとに 1 行を出す。1 行は、「{ステータス名}({M} 件)」と、移動先のプロジェクトが使うステータスのセレクトである。初めの値は、元のステータスと同じ分類の、移動先の既定のステータス(03)である。置き換えるものがなければ、ダイアログは出さず、そのまま移す。同じプロジェクトの中で親だけが変わる移動は、ステータスを変えない。

ドラッグでの移動は、画面ごとの操作として 04 に定める。そこでも、親子の決まりと上の断り方は同じである。

## 別のワークスペースと別の Store への移動

アイテムのメニューの「別のワークスペースへ移動…」で、Epic と Story・Task・Bug を、別のワークスペースへ移せる。移す先は、同じ Store の別のワークスペースでも、別の Store のワークスペースでもよい。Step は単独では移せず、親と一緒に移る。

### 移す先の選び方

移す先の候補は、自分以外のワークスペースのうち、書き込める Store にあり、サイドバーで非表示にされておらず、プロジェクトが 1 つ以上あるものである。候補がないときは、ダイアログを開かず「移せるワークスペースがありません(プロジェクトのある、書き込めるワークスペースが要ります)」と表示する。

ダイアログの項目は、移動先のワークスペース、プロジェクト、親の Epic である。Epic を移すときは、親の Epic を選ばない。選んだプロジェクトに Epic がないときは「このプロジェクトには Epic がありません」と出し、ボタンを押せなくする。ダイアログの冒頭には「{ID} {タイトル} と、その下の N 件を移動します。」と出す(下のものがないときは「{ID} {タイトル} を移動します。」)。N は削除済みでないものの数で、下に削除済みのものがあるときは「削除済みの M 件も一緒に移ります。」を続ける。続けて、見出し「移動先で変わること」の下に、次の変更を説明する。

- ID は、移動先のワークスペースの次の番号(「HH-13 からの番号に振り直されます」)から振り直す。
- スプリントとリリースは外す。
- 優先度、関連システムなどは、同じ名前の値に合わせる。合う値がなければ空にする。ステータスは、同じ名前で移動先のプロジェクトが使うものに合わせ、合わないものは、下の「ステータスの置き換え」で選んだステータスにする。
- 別の Store へ移すときは、移さないアイテムとの関連を解除する。移すもの同士の関連は残る。
- 別の Store へ移すときは、移動先のメンバーにいない人を、移動先のメンバーに加える。
- 別の Store へ移すときは、移動先に remote がなく、移動元に remote があるなら、「移動先に remote がないため、ほかの人の Store からは見えなくなります。」を添える。
- 移動元に転送の記録(移した日時を含む)を残し、古い ID からも辿れる。

移すアイテム(下のものと削除済みのものを含む)のステータスに、移動先で使えないもの(移動先のワークスペースにない名前と、移動先のプロジェクトが使わないもの)があるときは、ダイアログに見出し「ステータスの置き換え」を足し、使えないステータスごとに 1 行を出す。1 行は、「{ステータス名}({M} 件)」と、移動先のプロジェクトが使うステータスのセレクトである。初めの値は、元のステータスと同じ分類の、移動先の既定のステータス(03)である。移動先のワークスペースやプロジェクトを選び直したときは、この欄も作り直す。置き換えるものがなければ、この欄は出さない。置き換えは、ステータスだけである。優先度・単一選択などは、下の「値の引き直し」のとおり、合う値がなければ空にして、トーストで知らせる。

ボタンは「移動」で、このダイアログが確認を兼ねる。

### 移すもの

アイテム自身と、その下のすべてのもの(子と孫。削除済みのものを含む)が、一緒に移る。削除済みのものは、移動先でも削除済みのまま、元の削除日時で保持日数を数える。次のものも一緒に移る。

- 説明、コメント、作業時間、ウォッチ中の人、GitHub リンク、詳細パネルの履歴

移動元の Store のアクティビティは、移動元に残る。

移動先では、各アイテムに新しい番号を振る。移動元の番号は再利用しない。番号は、移すアイテムが先、続いて子・孫を並び順に深さ優先で振る。削除済みの子は、同じ親の下の削除されていない子のあとに振る。

### 値の引き直し

プロパティの値は、移動先のワークスペースの定義に合わせて引き直す。

| 種類 | 引き直し |
|---|---|
| ステータス | 値の名前が完全に一致し、移動先のプロジェクトが使うものは、そのまま残す。そうでないものは、確認ダイアログの「ステータスの置き換え」で選んだステータスにする。ダイアログを出せない経路(同期の修復。06)では、「ステータスの置き換え」の初めの値(同じ分類の、移動先の既定のステータス)にする |
| 優先度・関連システム・単一選択・複数選択 | 値の名前が完全に一致するものに置き換える。一致がなければ空にする。複数の値は、一致したものだけが残る |
| 優先度が空になった場合 | 移動先の初期優先度にする |
| テキスト・数値・日付・チェック・URL(組み込みのポイント・見積もり時間・開始日・終了日を含む) | キーが同じで型も同じなら、そのまま残す。組み込みはどのワークスペースにもあるので、そのまま残る |
| 担当者・ユーザー・ウォッチ中の人 | 同じ Store の中なら、そのまま残す。別の Store へ移すときは、ログイン名(大文字と小文字を区別しない)が一致するメンバーに置き換える。一致がなければ、移動先のメンバーに加えて、その人に置き換える |
| 移動先に同じキーのプロパティがない、またはキーが同じで型が違う | 値を捨てる |

値が入っていたのに、空になった、または捨てた項目は、移動後のトーストに「合う値がなく空になった項目」として並べる。優先度を初期優先度にしたときは、「優先度」も並べる。ステータスの置き換えは、確認ダイアログで選ぶので、トーストには並べない。移動先のワークフローの制約と、移動先のプロジェクトのルール(使うステータス・遷移の制約)は検査しない。

### 関連・転送記録・旧 ID

- **関連**: 同じ Store の中の移動では、すべての種類の関連をそのまま残す。別の Store へ移すときは、移すものの集まり(アイテムなら、そのアイテムと下のすべて)の外にあるアイテムとの関連を、種類を問わず解除する(削除済みの外のアイテムとの関連も)。集まりの中のアイテム同士の関連は残す。関連の相手の側からも消える。
- **転送記録**: 移動元の Store に、旧 ID・移したものの内部 ID・移した日時・移動先の Store 名と新 ID を、移すたびに 1 件ずつ記録する。記録は消さず、完全に削除でも消えない(08)。移動先のアイテムの履歴にも、「{旧 ID} から移動」と、移動元の Store・ワークスペース・プロジェクトを残す。旧 ID は、記録の内部 ID で解決する。表示中のすべての Store から内部 ID を探し、いまある場所を開く。別のワークスペースへ何度移しても、すべての旧 ID が、最後の新しいアイテムに辿り着く。B から C へ移したときは B に別の記録ができるだけで、A の記録はそのまま C へ辿り着く。B から A へ移し戻したときは、A の古い記録は戻ったあとの新しい ID に辿り着く(番号は再利用しないので、ID は重ならない)。同じものを 2 人が別々の場所へ移して記録が 2 件できても、内部 ID の現在地で解決するので、残った方に辿り着く。
- **旧 ID から辿れる場所**: ID を入力して探す箇所(コマンドパレット、検索の自由テキストとクエリの `parent:`・`project:`・関連のキー。04)、アクティビティと受信箱に残る旧 ID のリンク、旧い画面のアドレス(アイテムの入口。Store 名とアイテムの ID で、旧 ID でもよい。01「画面のアドレス」)は、新しいアイテムを開く。コメントや説明に書かれた旧 ID の文字は、そのまま残る。
- **見つからないとき**: 画面は開かず、次の文をトーストで出す。削除済みなら「{旧 ID} は {日時} に {新 ID} へ移動しましたが、削除されています。設定の「削除済み」から復元できます」(リンクなし)。完全に削除されていたら「{旧 ID} は {日時} に {新 ID} へ移動しましたが、完全に削除されました」。移動先の Store が非表示、またはこのマシンにないときは「{旧 ID} は {日時} に {Store 名} へ移動しました。この Store はいま表示できません」。いまの場所が記録の移動先と違う(B から C へ移した)ときは「{旧 ID} は {日時} に {B の新 ID} へ移動し、いまは {C の新 ID} にあります」。閲覧のみの Store の中でも、表示だけは解決できる。
- **移した日時の表示**: 旧 ID のリンクから新しいアイテムを開いたときは、「{旧 ID} は {日時} に {新 ID} へ移動しました」と表示する。コマンドパレットで旧 ID から見つかった候補には「旧 ID・{日付} に移動」と添える。接頭辞を変える前の ID(旧い接頭辞)で見つかったものにも、同じく「旧 ID」と添える(03)。旧い接頭辞をあとから別のワークスペースが使っているときは、現在の ID が一致するものと旧 ID で一致するものの両方を出し、旧 ID の方に「旧 ID」と添える。移動先のアイテムの履歴の「{旧 ID} から移動」の行にも、移した日時を出す。日付と時刻の書き方は 01 に従う。

### 保存

- 同じ Store の中の移動は、1 回の保存である。
- 別の Store への移動は、Store ごとに 1 回ずつ、合わせて 2 回保存する。移動元の保存はアイテムを取り除いて転送記録を残し、移動先の保存はアイテムを加える。移動先に remote があるときは、(1)移動先を同期して受信する、(2)移動先に保存する、(3)移動先を送信する、(4)成功したら移動元に保存する(転送記録)、の順に行う。移動先に remote がないときは、移動先に保存してから移動元に保存する。どれかが失敗したら、何も変えずに元のままにする。失敗したときは、エラーのトースト「{移動先の Store 名} に送信できないため移動できません: {理由}」を出す。理由は 06 の短い理由(認証に失敗しました、remote に接続できません、remote への書き込みが許可されていません など)で、オフラインのときは「オフラインのため {移動先の Store 名} へ移動できません」とする。移動元の送信は通常の同期で、遅れても移動先にはすでに届いているので、その間は他の人に両方の Store で見える。移動元の送信は、同期の「未送信」に出る。
- 別の Store への移動と、移動元で他の人が同じものに行った変更が重なったときは、移動を優先する。他の人の変更は反映されない(06)。同じ Store の別のワークスペースへの移動には、この規則は使わない(項目ごとの合わせ方に従う。06)。
- 別の Store への移動では、移動先の保存で、移動先のメンバーにいない人を、移動先のメンバーに加える。対象は、移すものに現れるすべての人で、担当者・ユーザー型のプロパティの人・ウォッチ中の人・作成者、コメントと作業時間の書き手、履歴の操作者である。ログイン名は、大文字と小文字を区別せずに比べる。表示名とログイン名は、移動元のメンバーと同じにする(メールアドレスは持たない。01)。加えた人ごとに、アクティビティに「メンバー {ログイン名} を追加」と残る。
- アクティビティには「{旧 ID} を {移動元} から {移動先} へ移動」と残る。
- トーストは「{旧 ID} は {新 ID} になりました」で、空になった項目があれば「。合う値がなく空になった項目: A・B」を続ける。通知は出ない。
- 移すとき、詳細パネルを開いていれば、新しい ID のアイテムに切り替わる。ブラウザの別のタブや別のプログラムなど、ほかの書き手が移したときは、切り替えず、パネルを閉じる(06)。

## 種類の変更

アイテムのメニューの「種類を変更…」で、アイテムの種類を変える。

| 変更前 | 選べる種類 | 親 |
|---|---|---|
| Story・Task・Bug | 自分以外の Story・Task・Bug | 変わらない |
| Step | Story・Task・Bug | 元の親の親(Epic)の下に移る |
| Epic | 変更できない | なし |

Story・Task・Bug から Step へは変えられない。Epic はメニューの項目を無効にする。Story・Task・Bug が Step を持っていても、種類を変えられる。Step は Story・Task・Bug のどの下にも置けるためである。

変える種類を選ぶと、実行の前に確認ダイアログを出す。

| 部分 | 内容 |
|---|---|
| タイトル | 「種類を変更」 |
| 本文 | 「{ID} の種類を {変更前} から {変更後} に変更します。」。Step から変えるときは「{親の親の ID} の下に移ります。」を続ける |
| ボタン | 「変更」と「キャンセル」 |

変更の前後で、プロパティ・スプリント・リリース・関連は変わらない。新しい種類で使わないと設定されたプロパティの値は、画面から隠れるが、消さずに残す。Step から昇格したアイテムは、末尾の位置で親の Epic の下に入る。ステータスは変わらず、ワークフローの制約も検査しない。履歴に「種類を {変更前} から {変更後} に変更」と残る。アクティビティには「{ID} の種類を {種類} に変更」と残る。通知とトーストは出ない。

## 削除

アイテムの削除は論理削除である。消したものは削除済みに入り、保持日数のあいだは復元でき、保持日数を過ぎると完全に削除される(08)。

アイテムのメニューの「削除…」、または Step の一覧の「×」を押すと、確認ダイアログを出す。

| 部分 | 内容 |
|---|---|
| タイトル | 「{種類} を削除」 |
| 本文 | 「{ID} {タイトル} を削除します。」。下のものがあるときは「下にある N 件({種類名の一覧})も一緒に削除されます。」を続ける |
| 補足 | 「設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」(N は、その Store の削除済みの保持日数) |
| ボタン | 「削除」(危険な操作の見た目)と「キャンセル」 |

- アイテムと、その下のすべてのものを、同じ 1 回の削除として消す。復元は、この削除の単位で行う(08)。
- 開いている詳細パネルが、削除したアイテムのものなら閉じる。
- 削除したアイテムの関連は消さず、一覧から隠す。復元すると、関連も戻る。ただし、関連が戻るのは復元できる間だけで、完全に削除すると、そのものを相手にした関連は、種類を問わず、相手が削除済みでも外れる(08)。削除したアイテムにブロックされていたアイテムは、ブロック中でなくなる。
- 削除したアイテムの履歴には何も足さない。アクティビティには「{ID} {タイトル} を削除」と残る。下にあるものがあるときは「{ID} {タイトル} ほか N 件を削除」とする(N は下にあるものの数)。
- トーストは「{ID} を削除しました」である。通知は出ない。
- 一括での削除は 04 に従う。

## 詳細パネル

アイテムの詳細パネルは、画面の右からせり出す。ヘッダーの全画面ボタンで、画面いっぱいにも広げられる。全画面では、左を本文の列、右をプロパティの列に分ける。パネルの幅は、左の縁をドラッグして変えられ、このマシンに保存される(01)。Esc でパネルを閉じ、全画面も解除する。説明またはコメントの入力欄の中身が保存してあるものと違うときは、パネルを閉じる前に確認する(「説明」に書く)。開いているアイテムが削除されたら、パネルを閉じる。同期や、ブラウザの別のタブ・別のプログラムの変更でそうなったときは、確認を出せないので、そのまま閉じる。書きかけがあるあいだは、画面の反映を待つので、書きかけが失われることはない。

閲覧のみの Store のアイテムでは、パネルの上部に 01 の帯を出し、Store に書くものだけを無効にする。無効にするのは、ウォッチのボタン、タイトル・説明・プロパティ、子の追加ボタン、関連の追加と解除、「PR をリンク」「Issue をリンク」とリンクの「×」、作業時間の入力と「×」、コメントの入力・投稿・編集・削除、メニューの「上へ移動」「下へ移動」「移動…」「別のワークスペースへ移動…」「種類を変更…」「複製」「テンプレートとして保存…」「削除…」である。使えるのは、パンくずのリンク、ID をコピーするボタンとメニューの「ID をコピー」、「PR 用の印をコピー」、全画面、閉じる、子の行のタイトル、プロパティ欄末尾の「プロパティを追加・変更」(設定の画面へ移るだけ)、PR・Issue のリンクの外部リンクである。無効にしたものには「閲覧のみの Store です」を添える。ウォッチは、ボタンにポインターを置いたときの案内に出す。

### 上から順の構成

| 部分 | 内容 |
|---|---|
| ヘッダー | パンくず(Store・ワークスペース・プロジェクト・祖先のアイテム。クリックで移る)、ウォッチのボタン、全画面のボタン、メニュー、閉じるボタン |
| 種類の行 | 種類のアイコンと名前、ID、ID をコピーするボタン(押すと「コピーしました: {ID}」と表示する。コピーできなかったときは「コピーできませんでした。{ID} を選択してコピーしてください」と表示する)、ブロック中のとき「ブロック中」 |
| タイトル | 1 行の入力欄 |
| プロパティ | 「プロパティの入力と保存」の項目。追加プロパティには「追加」と添える。末尾に「プロパティを追加・変更」を置き、ワークスペースの設定(03)へ移る |
| 説明 | Markdown で表示する |
| 子 | Epic は「Story・Task・Bug」、Story・Task・Bug は「Step」。Step にはない |
| 関連 | 5 種類の関連(blocks・causes・duplicates・relates to・clones) |
| GitHub | PR と Issue のリンクの一覧 |
| 作業時間 | 記録の一覧と入力 |
| コメント | コメントの一覧と入力 |
| 履歴 | 変更の一覧 |

メニューの項目は、アイテムの一覧から開くメニューと同じで、「詳細を開く」と「{種類} を追加」を除く。メニューの項目には、「上へ移動」「下へ移動」(同じ親の下の兄弟の中で動かす。端では無効。04)、「移動…」「別のワークスペースへ移動…」「種類を変更…」「複製」「テンプレートとして保存…」(03)「ID をコピー」「削除…」がある。使えない項目は、無効にして理由を添える。

ツリー・テーブルの絞り込み中に行のメニューの「上へ移動」「下へ移動」を使うと、いま画面に見えている兄弟の間で動かす。たとえば HH-5 の「上へ移動」は、見えている直前の兄弟 HH-3 のすぐ前に HH-5 を置く(見えていない HH-4 は触らない)。「下へ移動」は、見えている直後の兄弟のすぐ後ろに置く。見えている兄弟の先頭の行は「上へ移動」を、末尾の行は「下へ移動」を無効にする(見えていない兄弟が先にあっても無効)。動くのは動かした 1 件だけで、アクティビティには「{ID} の順位を変更」と残る。削除済みの兄弟は、見えない兄弟として扱う。詳細パネルのメニューは、絞り込みがないので全兄弟の間で動かす。

「ブロック中」は、そのアイテムをブロックしているアイテムのうち、削除されておらず、完了と中止のどちらでもないものが 1 つでもあるときに出す。

### タイトル

- タイトルは、入力欄からフォーカスが外れたときに保存する。Enter でもフォーカスを外して保存する。
- 連続する空白と改行は 1 つの空白にまとめ、前後の空白は取り除く。文字数の上限は設けない。
- 空にしようとしたときは、「タイトルは空にできません」と表示し、元のタイトルに戻す。前と同じなら何も保存しない。
- 保存すると、履歴に「タイトルを「{新}」に変更」と残り、アクティビティに「{ID} のタイトルを変更」と残る。ウォッチ中の人に通知が出る。

### 説明

- 説明は Markdown で表示する。空のときは「説明を追加」を出す。
- 説明の部分をクリックすると、8 行の入力欄に切り替わる。入力欄の下に「Markdown を使用できます。@ログイン名 でメンション」と添え、「保存」と「キャンセル」のボタンを置く。Ctrl+Enter でも保存できる。
- 自動保存はない。「キャンセル」は確認なしで入力を捨てる。保存したとき、前と同じなら何も保存しない。
- 入力欄の中身が保存してある説明と違うときは、入力欄の中での Esc、別のアイテムの詳細パネルを開く操作、パネルを閉じる操作(「×」、Esc)、画面を移る操作で、確認ダイアログを出す。タイトルは「入力を破棄」、本文は「保存していない説明の変更を破棄します。」、ボタンは「破棄」(危険な操作の見た目)と「キャンセル」(押すと入力欄に戻る)である。入力欄の下の「キャンセル」ボタンを押したとき、中身が保存してある説明と同じとき、「保存」を押したときは出さない。日本語入力の変換中の Esc は、変換の取り消しに使うので、この規則の対象にしない。コメントの入力(新しいコメントと編集)も同じで、本文は「保存していないコメントを破棄します。」とする。
- 編集中に同期で他の人の変更を受け取っても、ブラウザの別のタブや別のプログラムの保存が届いても、入力欄の内容は書き換えない(手動の同期でも同じ)。保存するときは、編集を始めたときの説明を共通の祖先として、保存した時点の説明と行ごとに合わせる(06 の説明の合わせ方と同じ)。別の人が同じ行を変えていたら、両方の版を「-----」ではさんで残し、保存した本人にトースト「説明の同じ箇所が同時に編集されたため、両方を残しました」を出して、「上書き」の通知を作る(06)。別の行なら両方が残り、通知はない。
- 書きかけ(保存していない入力が空でない、説明またはコメントの入力欄)があるあいだは、自動の同期と、画面の自動の反映を行わない(06)。
- 保存すると、履歴に「説明を変更」と残り(差分は残さない)、アクティビティに「{ID} の説明を変更」と残る。ウォッチ中の人には通知しない。
- メンションの通知は、次の「メンション」に従う。

### Markdown

説明とコメントで使える書き方は次のとおり。

| 書き方 | 表示 |
|---|---|
| `#` `##` `###` で始まる行 | 見出し(3 段階) |
| `-` `*` または `1.` で始まる行 | 箇条書き。行頭の `[ ]` は未チェック、`[x]` はチェック済みの印で表示する。表示だけで、クリックでは切り替わらない |
| `**文字**` | 太字 |
| `` `文字` `` | 行内のコード |
| 3 つのバッククォートで囲んだ行 | コードブロック |
| `http://` と `https://` で始まる文字列 | リンク。新しいタブで開く |
| `@ログイン名` | メンションの表示 |

それ以外の行は、1 行を 1 つの段落として表示する。

### メンション

- 説明とコメントの中の `@ログイン名` が、その Store のメンバーのログイン名と一致したとき、そのメンバーに通知が出る。ログイン名は、大文字と小文字を区別せずに比べる。`@` の前にどんな文字があっても、一律にメンションとして扱う。
- 通知は、1 つの本文(アイテムの説明、プロジェクトの説明、1 件のコメント)と、メンションされた 1 人の組み合わせにつき 1 行である。同じログイン名が本文に何度あっても 1 行である。あなた自身には出ない。
- 本文を保存するたびに、その本文でメンションされている人の行を、最新の本文と保存した時刻に書き換え、未読に戻す。まだ行のない人には、行を作る。保存した本文からメンションが消えた人の行は、そのまま残す。
- 対象は、アイテムの作成時の説明、説明の保存、コメントの投稿、コメントの編集、プロジェクトの説明の保存、プロジェクトのコメントの投稿である。
- コメントを書くときは、入力欄の下にある、あなた以外のメンバーの `@ログイン名` のボタンを押すと、入力欄の末尾に `@ログイン名 ` が足される。
- 検索の `mentions:`(04)は、通知の行ではなく、いまの説明と削除されていないコメントから探す。

### 子と Step

Epic の「Story・Task・Bug」の見出しには、完了の数と総数を「3/8」の形で添える。Story・Task・Bug の「Step」の見出しにも、同じ形で添える。数えるのは完了の分類のものだけで、中止のものは分母にも分子にも入れない。

- **Epic の子**: 1 行に、種類のアイコン、ID、タイトル(押すとそのアイテムの詳細パネルを開く)、ステータスのボタン、担当者のアバターを出す。下に「Story」「Task」「Bug」のボタンを置き、押すと、その Epic を親にした作成ダイアログを開く。
- **Step の行**: チェックボックス、タイトル、ID、ステータス、担当者、「上へ」、削除の「×」を出す。タイトルを押すと、その Step の詳細パネルを開く。
- **Step の追加**: 入力欄に「Step を追加して Enter」と添える。Enter で、タイトルを持つ Step を末尾に作る。担当者は親と同じ、ステータスは初期ステータス、優先度は初期優先度にする。担当者があなた以外のメンバーなら、そのメンバーに通知が出る。空のまま Enter を押したときは何もしない。追加したあとは入力欄を空にして、フォーカスを戻す。アクティビティには「{ID} に Step「{タイトル}」を追加」と残る。
- **Step のチェック**: チェックボックスがオンになるのは、Step の分類が完了のときだけで、未着手・進行中・中止はすべてオフで表示する。オフの Step(進行中・中止を含む)を押してオンにすると、完了の既定のステータスにする。オンの Step を押してオフにすると、未着手の既定のステータスにする(03)。進行中だった Step を完了にしてから外すと、進行中ではなく未着手に戻る。遷移の制約に反したときは、「ステータスの変更」の文言で断る。
- **Step の「上へ」**: 直前の Step と順位を入れ替える。先頭の Step では何もしない。詳細パネルのボタンに「下へ」はなく、下げるときはアイテムのメニューの「下へ移動」を使う(04)。アクティビティには「{ID} の順位を変更」と残る。
- **Step の削除**: 確認ダイアログは「削除」の節のとおり。

### 関連

関連は、アイテム同士の関係である。種類は次の 5 つで、画面の表記は英語のままにする。向きのある種類は、片方に関連を足すと、相手の側には逆向きの表記で出る。

| 種類 | 自分の側の表記 | 相手の側の表記 | 振る舞い |
|---|---|---|---|
| ブロック | blocks | blocked by | 「ブロック中」の表示、循環の禁止、ガントの警告と矢印(04) |
| 原因 | causes | caused by | 表示だけ |
| 重複 | duplicates | duplicated by | 表示だけ |
| 関係 | relates to | relates to | 表示だけ。向きはなく、両方の側に「relates to」と出る |
| 複製 | clones | cloned by | 表示だけ。「複製」で自動で付く。手でも付けられる |

**一覧**: 表記ごとに見出しを付けて、blocks・blocked by・causes・caused by・duplicates・duplicated by・relates to・clones・cloned by の順に並べる。関連のない表記の見出しは出さない。各行に、相手の ID とタイトル(押すと相手の詳細パネルを開く)、相手のステータス、解除の「×」を出す。関連が 1 つもないときは「関連はありません」と出す。削除済みの相手は一覧に出さないが、関連は残り、相手を復元すると一覧にも戻る。検索のキー(04)は、この表記の空白を `_` にした名前で、一覧に出る表記と 1 対 1 に対応する。

**追加**: 一覧の下に、追加の行を置く。

| 部分 | 内容 |
|---|---|
| 表記のセレクト | 左に置く。blocks・blocked by・causes・caused by・duplicates・duplicated by・relates to・clones・cloned by の 9 つから選ぶ。初期値は blocks |
| 相手の選択欄 | セレクトの右に置く。プレースホルダは「ID またはタイトルで検索」。入力すると候補を出す |
| 「追加」ボタン | 相手を選ぶまで押せない。押すと、このアイテムから見て、選んだ表記の関連を作る。たとえば「blocked by HH-3」を追加すると、HH-3 が このアイテムをブロックする関連になる |

- 相手の候補は、同じ Store の削除されていないアイテムのうち、自分と Step を除いたものである。ワークスペースをまたいでよい。ほかのワークスペースの候補には、ワークスペース名を添える。Step も、Step 以外のアイテムとの関連を持てる。
- 2 つのアイテムのあいだには、種類ごとに関連を 1 つまで持てる。向きが逆でも同じ種類なら 1 つと数える。すでに同じ種類の関連がある候補は、無効にして「すでに {表記} の関連があります」と添える。種類が違えば、同じ相手と複数の関連を持てる。
- ブロックの関連で、足すと循環になる候補は、無効にして「循環になります」と添える。ほかの種類は循環を検査しない。
- 追加すると、アクティビティに「{ID} {表記} {ID}」(例: 「HH-1 blocks HH-3」)と残る。解除は、確認なしで外し、「{ID} と {ID} の {表記} を解除」と残る。どちらも履歴には残らず、通知も出ない。

### GitHub

一覧には、リンクした PR と Issue を 1 行ずつ出す。1 行には、種別と状態の表示、「{owner/name}#{番号} — {タイトル}」(例: 「example-org/web#12 — ログイン画面を直す」)、解除の「×」を出す。状態が Open か Draft の PR の行には、状態のあとにレビューの表示(「レビュー待ち」「承認済み」「修正依頼」)とチェックの表示(「CI 成功」「CI 失敗」「CI 実行中」)を出す(07)。リンクがないときは「リンクはありません」と出す。

リンクの追加は、一覧の下にある「PR をリンク」「Issue をリンク」のボタンで行う。リンクの内容と状態の取得は 07 に従う。PR は、ブランチ名、PR のタイトル・本文・コメントに書かれたアイテムの ID、`hedgehug:` で始まる印から、自動でもリンクされる(07)。「PR 用の印をコピー」のボタンは、`hedgehug:` で始まる 1 行をコピーし、トースト「コピーしました。PR の説明に貼ってください」を出す。コピーできなかったときは「コピーできませんでした。」と出す。閲覧のみの Store でも押せる(Store に書かない)。Issue は、番号を入れてリンクし、タイトルと状態(Open・Closed)を GitHub から読んで表示する。Issue の状態をアイテムの値に写すことはしない(自動化のルールが動いたときだけ、03 のとおり変える)。

解除は確認なしで外し、アクティビティに残る。トーストは「リンクを解除しました」である。解除した PR は、そのアイテムには、以後、自動ではリンクしない(アイテムが解除の記録を持つ。画面には出さない)。同じ PR を「PR をリンク」で足したときは、記録を消して、ふつうのリンクにする。

### 作業時間

見出しに、記録の合計を「N 時間」の形で出す。時間は小数第 2 位までで表示し、末尾の 0 は省く(0.3 時間、1.25 時間、2 時間)。合計は 100 分の 1 時間の単位で足す。各行、削除の確認ダイアログ、レポートの「作業時間」の列(05)も同じ表記である。アイテムに見積もり時間があるときは「 · 見積もり {N} 時間」を、ポイントがあるときは「 · {N} pt」を、この順に続ける(例: 「2 時間 · 見積もり 6 時間 · 3 pt」)。時間は合計と同じ表記(小数第 2 位まで、末尾の 0 を省く)にする。

- 各行に、記録した人のアバター(記録した人がメンバーにいないときは「不明なユーザー」。01)、「N 時間」、メモ、日付、削除の「×」を出す。行に編集はない。入れ間違いは、削除して入れ直す。
- 入力は、時間、メモ(任意)、「記録」のボタンである。時間の欄は 0.25 時間刻みで増減できる。0 より大きければ、0.1 のような値も記録できる。メモ欄で Enter を押しても記録する。
- 0 以下の値、数でない値、空の時間のときは、「時間を入力してください」と表示して記録しない。小数第 3 位以下があるとき(0.123)は、記録せずに「時間は小数第 2 位までで入力してください」と表示する。上限は設けない。
- 日付は、記録した日になる。過去の日付は入れられない。記録は、記録した人の名前で残る。
- 記録の削除は、「×」を押すと確認ダイアログを出す。タイトルは「作業時間を削除」、本文は「{日付} の {N} 時間の記録を削除します。」、ボタンは「削除」(危険な操作の見た目)と「キャンセル」である。記録の日付は今日にしかできず、消すと作り直せないためである。作業時間は、誰の記録でも、書き込める人なら消せる。トーストは「作業時間を削除しました」である。
- アクティビティには「{ID} に N 時間を記録」「{ID} の作業時間を削除」と残る。履歴には残らず、通知も出ない。
- 見積もりは、ポイントと見積もり時間のプロパティであり、作業時間とは別のものである。作業時間を記録しても、見積もり時間は変わらない。

### コメント

- コメントは、古いものから順にすべて並べる。1 件ごとに、投稿者のアバターと名前(投稿者がメンバーにいないときは「不明なユーザー」。01)、相対時間、編集したときは「(編集済み)」、Markdown で表示した本文を出す。
- **投稿**: 入力欄のプレースホルダは「コメントを書く。@ログイン名 でメンション。Ctrl+Enter で送信」。ボタンか Ctrl+Enter で投稿する。空のときは何もしない。
- **編集と削除**: 自分が書いたコメントにだけ、編集と削除のボタンを出す。編集では、入力欄に「キャンセル」と「保存」を出す。空にして保存したときと、前と同じときは、何も保存せずに閉じる。コメントを消したいときは、削除のボタンを使う。
- **削除**: 確認ダイアログを出す。タイトルは「コメントを削除」、本文は「このコメントを削除します。」、ボタンは「削除」である。トーストは「コメントを削除しました」である。
- 投稿・編集・削除は、アクティビティに「{ID} にコメント」「コメントを編集」「コメントを削除」と残る。履歴には残らない。
- 通知は、投稿のときにウォッチ中の人へ出る(本文の先頭 40 文字を添える)。メンションの通知は「メンション」に従う。編集と削除では、ウォッチ中の人には通知しない。

### ウォッチ

ヘッダーのウォッチのボタンで、あなたがそのアイテムのウォッチ中かどうかを入り切りする。ボタンの表示で、いまどちらか分かるようにする。アクティビティには「{ID} のウォッチを開始」「{ID} のウォッチを解除」と残る。トーストは出さない。

- アイテムを作った人は、最初からウォッチ中になる。担当者になった人、メンションされた人は、自動ではウォッチ中にならない。
- ウォッチ中の人に通知が出るのは、プロパティの変更、タイトルの変更、コメントの投稿のときである。説明の変更、リンク、関連、作業時間、削除、移動、種類の変更では出ない。変更したのがあなた自身のときは、あなたには出ない。
- 受け取った通知は、受信箱の「ウォッチ」に出る(06)。クエリのキー `watching` で、ウォッチ中のアイテムを絞り込める(04)。

### 履歴

履歴は、そのアイテムの変更の一覧で、新しいものから並べる。保存する件数に上限はない。画面には 40 件まで出し、それより古いものがあるときは、一覧の末尾に「すべて表示」を置く。1 行に、操作した人(自動化のときは「自動化」、GitHub からの取り直しと自動リンクのときは「GitHub」、同期の修復のときは「同期」。メンバーにいない人は「不明なユーザー」。01)、変更の文、時刻を出し、同期で受け取った変更には「同期で受信」と添える。履歴がないときは「履歴はありません」と出す。

| 変更 | 文 |
|---|---|
| 作成 | 「作成」 |
| プロパティの変更 | 「{プロパティ名}を {旧} → {新}」。削除された値は「(削除された値)」と出す |
| タイトルの変更 | 「タイトルを「{新}」に変更」 |
| 説明の変更 | 「説明を変更」 |
| 親・プロジェクトの変更 | 「親を変更」 |
| 種類の変更 | 「種類を {旧} から {新} に変更」 |
| スプリントの変更 | 「スプリントを変更」 |
| リリースの変更 | 「リリースを変更」 |
| 削除からの復元 | 「復元」。戻したアイテムのスプリントやリリースを外して戻したときは、続けて「スプリントを変更」(リリースなら「リリースを変更」)(08) |
| 別のワークスペースへの移動 | 「{旧 ID} から移動」と、移動元の Store・ワークスペース・プロジェクト |

履歴に残らないのは、コメント、関連、GitHub リンクの追加と解除、作業時間、ウォッチ、削除である。これらはアクティビティにだけ残る。例外として、GitHub から取り直したリンクの状態・タイトル・レビューの状態の変更と、GitHub が PR を自動でリンクしたことは、操作した人のいない自動の変更として、履歴にもアクティビティにも残る(07)。

検索の「作成日」「更新日」(04)は、この一覧の「作成」の行の時刻と、操作した人が人または自動化の行のうちいちばん新しい行の時刻である。操作した人が「GitHub」または「同期」の行は、更新日に使わない。

## プロジェクト

プロジェクトは、ワークスペースの下で Epic をまとめる。持つ項目は固定で、タイトル・説明・オーナー・開始日・終了日・ステータスである。ステータスは Todo・InProgress・Done・Pending・Cancel の 5 つで、利用者は変えられない。プロジェクトに詳細パネルはなく、概要の画面で扱う。プロジェクトのステータスと、下のアイテムのステータスは、互いに影響しない。ステータスを変えても、下のアイテムも進捗も変わらず、警告も確認も出ない。下が全部完了してもステータスは自動では変わらず、完了・中止のプロジェクトにもアイテムを作れる。下のアイテムのルール(使うステータス・遷移の制約・テンプレート・自動化)の一部は、設定のタブで、このプロジェクトだけ変えられる(03 の「プロジェクト別のルール」)。プロジェクト自身のステータスには関わらない。

### 作成

サイドバーのワークスペースのメニューの「プロジェクトを作成」、ワークスペースの画面の「プロジェクト」のボタンから、作成ダイアログを開く。作ると、そのワークスペースのプロジェクトの連番の次の番号を、プロジェクトの ID として振る(01)。番号は再利用しない。2 台で同時に作って番号が重なったときは、アイテムと同じ規則で振り直す(06)。別のワークスペースへ移すと、移動先の連番で振り直し、移動元に転送記録を残して旧 ID からも辿れるようにする。

| 項目 | 内容 |
|---|---|
| ワークスペース | 「Store名 / ワークスペース名」の形で並べる。閲覧のみの Store と、非表示の Store のワークスペースは出さない |
| タイトル | 1 行の入力欄。Enter で作成する |
| オーナー | 「なし」とメンバー。初めの値はあなた |
| ステータス | 5 つから選ぶ。初めの値は Todo |
| 開始日・終了日 | 日付の入力欄 |

| 条件 | 文言 |
|---|---|
| タイトルが空 | 「タイトルを入力してください」 |
| 開始日と終了日があり、終了日が開始日より前 | 「終了日は開始日以降にしてください」 |
| 同じワークスペースに同じ名前のプロジェクトがある | 「このワークスペースには同じ名前のプロジェクトがあります」 |

名前の比べ方は、ワークスペースの名前と同じである(03)。前後の空白を除き、完全に一致するものだけを重複とする(大文字と小文字、全角と半角は区別する)。保存する名前も、前後の空白を除いた形にする。重複の数に、削除済みのプロジェクトは入れない。

作成すると、そのプロジェクトの概要の画面を開く。トーストは出さない。履歴に「作成」が残り、アクティビティには「プロジェクト「{タイトル}」を作成」と残る。オーナーがあなた以外のメンバーなら、そのメンバーに通知が出る。並びは、ワークスペースの中の末尾である。

### 画面の見出しと構成

プロジェクトの画面の見出しには、パンくずに Store のバッジとワークスペース名のリンク(押すとワークスペースの概要を開く)、その下にプロジェクトのアイコン、プロジェクトの ID(`HH-P1`)とタイトル、右にステータスのピルと「Epic」のボタン(押すと、そのプロジェクトを親にした Epic の作成ダイアログを開く)を出す。見出しの下のタブは、概要・ツリー・カンバン・テーブル・ガント・設定である。ツリー・カンバン・テーブル・ガントは、そのプロジェクトのアイテムを対象にする(04)。

設定のタブは、「名前」「使うステータス」「ワークフローの制約」「テンプレート」「自動化」「別のワークスペースへ移動」「削除」の 7 つの区画に分かれる。「使うステータス」から「自動化」までは、このプロジェクトだけのルールで、03 の「プロジェクト別のルール」で定める。見出しの下に「このプロジェクトだけのルールです。ステータスや種類の定義は {ワークスペース名} のままです。」を出す。

| 区画 | 内容 |
|---|---|
| 名前 | タイトルの入力欄。概要でのタイトルの変更と同じ検査をする |
| 使うステータス | 使うステータスのチェック(03) |
| ワークフローの制約 | プロジェクトだけの遷移の制約の表(03) |
| テンプレート | 使うテンプレートと、種類ごとの既定(03) |
| 自動化 | ルールを動かさない指定と、このプロジェクトだけのルール(03) |
| 別のワークスペースへ移動 | 説明文、移動先のセレクト(「Store名 / ワークスペース名」)、「移動」のボタン。移動先の候補がないときは、セレクトの代わりに「移せるワークスペースがありません」と出す |
| 削除 | 危険な操作の区画。「プロジェクトと、その下の N 件のアイテムを削除します。設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」と説明し、「プロジェクトを削除」のボタンを置く |

### 概要の編集

概要では、次の項目を直接編集できる。1 項目を変えるごとに、1 回の保存になる。変えても値が前と同じなら、何も保存しない。

| 項目 | 入力と検査 |
|---|---|
| タイトル | 入力欄から外れたときに保存する。前後の空白は除く。空のときは「タイトルは空にできません」と表示して元に戻す。同じワークスペースの別のプロジェクトと同じ名前(比べ方は作成と同じ)は、「このワークスペースには同じ名前のプロジェクトがあります」と表示して断る |
| 説明 | アイテムの説明と同じ編集(Markdown、メンション、入力中の確認、同期との合わせ方)。メンションの通知は、アイテムと同じ規則で出す |
| ステータス | 5 つから選ぶ |
| オーナー | 「なし」とメンバーから選ぶ |
| 開始日・終了日 | 終了日が開始日より前なら、「終了日は開始日以降にしてください」と表示して断る。日付を空にすることは常にできる。開始日と終了日が同じ日は認める |

保存すると、履歴に「{項目名}を {値} に変更」と残る(説明は「説明を変更」)。アクティビティには「{タイトル} の{項目名}を {値} に変更」と残る(説明は「{タイトル} の説明を変更」)。値は、ステータスならステータス名、オーナーなら人の名前、日付が空のときは「なし」である。オーナーをあなた以外のメンバーにしたとき、そのメンバーに「プロジェクト「{タイトル}」のオーナーになりました」の通知が出る。ガントでプロジェクトの期間を動かしたときも、同じ履歴とアクティビティが残る(04)。

概要にはさらに次を出す。

- **Epic の一覧**: 各 Epic の ID、タイトル(押すと詳細パネルを開く)、期限、進捗、ステータス、担当者を出す。ステータスのボタンからは、ステータスのメニューを開ける。進捗は、その Epic の下の Story・Task・Bug のうち、棒と「N%」で出す。棒の上にポインターを置くと「{完了} / {対象}」が出る(04 の進捗の表示と同じ)。中止のものは分母にも分子にも入れず、Step は数えない。Epic がないときは「Epic はまだありません。Epic の下に Story・Task・Bug を作れます。」と出す。
- **リポジトリ**: 「リポジトリと PR」の区画の上段で、プロジェクトに結びつけた GitHub のリポジトリを一覧にし、見出しの横に「リポジトリを追加」のボタンを置く。ないときは「リポジトリはまだありません」と出す。使い道は、PR・Issue のリンク先の候補と、PR を自動でリンクするために探すリポジトリである(07)。前回の読み取りが失敗していたときは、そのリポジトリの行の下に「PR を探せませんでした: {理由}」を出す(理由は 07 の「GitHub との通信に失敗したとき」の表示。このマシンだけの表示で、Store には保存しない)。
- **PR と Issue**: プロジェクトの下のアイテムのリンクをすべて並べる。1 行に、「PR」または「Issue」の別と状態のチップ、「{owner/name}#{番号} — {タイトル}」、そのアイテムの ID のリンクを出す。並びはアイテムの ID の番号順で、同じアイテムの中はリンクした順である。状態が Open か Draft の PR の行には、状態のチップのあとにレビューとチェックの表示を出す(07)。PR の状態は Open・Merged・Closed・Draft、Issue の状態は Open・Closed である。ないときは「リンクはありません」と出す。
- **コメント**: アイテムのコメントと同じ。通知は、メンションにだけ出る。ウォッチ中の人はいない。
- **履歴**: プロジェクトの変更の一覧。アイテムの履歴と同じく 40 件まで出し、「すべて表示」を置く。1 行に、操作した人と時刻を添える。文は、作成(「作成」)、項目の変更(「{項目名}を {値} に変更」、説明は「説明を変更」)、移動(「{移動元のワークスペース名} から移動」)、復元(「復元」)である。削除は残さない。
- **注記**: 「プロジェクトのプロパティは固定です。ステータスの値も変更できません。」

### リポジトリの追加と削除

| 操作 | 内容 |
|---|---|
| 追加 | 入力欄に `owner/name` の形で入れる。前後の空白は除く。形式は 07 の「リポジトリの形式」に従い、違うときは「リポジトリは owner/name の形式で入力してください」、すでにあるとき(大文字と小文字を区別しない)は「もう追加されています」と表示して断る。アクティビティには「{タイトル} にリポジトリ {owner/name} を追加」と残る。トーストは出さない |
| 削除 | 一覧の「×」を押すと、確認なしで外す。アクティビティには「{タイトル} からリポジトリ {owner/name} を削除」と残る。トーストは「{owner/name} を削除しました」である |

追加も削除も、プロジェクトの履歴には残らず、通知も出ない。閲覧のみの Store では、「リポジトリを追加」と「×」を無効にし、「閲覧のみの Store です」と添える(01)。

### 名前の変更・移動・削除

プロジェクトのメニュー(開く・Epic を追加・上へ移動・下へ移動・名前を変更…・削除…。上へ移動と下へ移動は 04)と、プロジェクトの設定の画面から操作する。「名前を変更…」は、タイトルを入れるダイアログを開き、概要でのタイトルの変更と同じ検査をする。

**移動**: プロジェクトの設定の「別のワークスペースへ移動」で、プロジェクトを別のワークスペースに移せる。移す先は同じ Store でも別の Store でもよい。候補は、自分以外のワークスペースのうち、書き込める Store にあり、非表示でないものである。

- 確認ダイアログの本文は、「「{タイトル}」を {移動元} から {移動先} へ移動します。N 件のアイテムは {移動先の接頭辞} の番号になります。」である。削除済みのアイテムがあるときは、「削除済みの M 件も一緒に移ります。」を続ける。別の Store へ移すときは、「移さないアイテムとの関連を解除します。移すもの同士の関連は残ります。移動先のメンバーにいない人は、移動先のメンバーに加わります。」を続ける。移動先に remote がなく、移動元に remote があるときは、「移動先に remote がないため、ほかの人の Store からは見えなくなります。」も続ける。
- 移動先に同じ名前のプロジェクトがあるときは、「{移動先} には同じ名前のプロジェクトがあります」と表示して断る。
- プロジェクトにプロジェクト別のルール(03)があるときは、確認ダイアログの本文に、続けて「このプロジェクトのルールは、移動先の同じ名前のステータス・テンプレートに合わせて移ります。」を出し、移らないものを見出し「移らないもの」の下に一覧にする(例: 「使わないステータス「Pending」(移動先にありません)」「遷移のチェック「InProgress から Review」(移動先に「Review」がありません)」「使うテンプレート「Bug 報告」(移動先にありません)」「ルールを動かさない指定 2 件(移動先のルールには引き継ぎません)」)。このプロジェクトだけの自動化ルールは、次の「ステータスの置き換え」で書き換えて、すべて移る。移動先に同じ名前のルールがあるときは、「{移動先} には同じ名前のルールがあります: {名前}。先にルールの名前を変えてください」と表示して断る。
- プロジェクトの下のアイテム(削除済みを含む)が使っているステータスと、このプロジェクトだけの自動化ルールが使っているステータスのうち、移動先のワークスペースにないものがあるときは、確認ダイアログに見出し「ステータスの置き換え」を足し、1 行ずつ出す。1 行は、「{ステータス名}({M} 件)」(ルールだけが使うものは件数を出さない)と、移動先のワークスペースのステータスのセレクトである。初めの値は、元のステータスと同じ分類の、移動先の既定のステータス(03)である。アイテムは、選んだステータスになる。このプロジェクトだけのルールのきっかけやすることにそのステータスがあれば、選んだステータスに書き換える(ルールは、削除も無効にもしない)。置き換えるものがなければ、この欄は出さない。置き換えは、ステータスだけである。
- プロジェクトの下のすべてのアイテム(削除済みを含む)が一緒に移る。各アイテムの扱いは、アイテムを別のワークスペースへ移すときと同じである。値の引き直し、新しい番号、スプリントとリリースを外すこと、別の Store へ移すときの関連の解除(移すアイテムの集まりの外との関連を解除し、集まりの中の関連は残す)を含む。親子の関係は変わらない。番号は、Epic を並び順に、それぞれ同じ規則で振る。プロジェクト自身の説明・オーナー・開始日・終了日・ステータス・結びつけたリポジトリ・コメント・履歴・ルール(03。移り方は上の確認ダイアログのとおり)も一緒に移る。別の Store へ移すときは、プロジェクトのオーナーも、アイテムと同じく、ログイン名が一致するメンバーに置き換える。移動先のメンバーにいない人(移すものに現れるすべての人。オーナー、プロジェクトの専用ルールの担当者の値、プロジェクトのコメントの書き手、アイテムの担当者・ユーザー型のプロパティの人・ウォッチ中の人・作成者、コメントと作業時間の書き手、履歴の操作者)は、移動先の保存で、移動先のメンバーに加える。表示名とログイン名は移動元と同じにし、加えた人ごとにアクティビティに「メンバー {ログイン名} を追加」と残る。コメントの書き手がメンバーにいないときは、移動先でも「不明なユーザー」のままである。メンションの通知の行は作り直さない。
- 移動元の Store に転送記録を残し、旧 ID から辿れる(解決の規則はアイテムと同じ。「旧 ID から辿れる場所」)。旧 ID のリンクから開いたときは、プロジェクトの概要の上部に「{旧 ID} は {日時} に {新 ID} へ移動しました」を出す(普通に開いたときは出さない)。見つからないときの文も、アイテムと同じである。プロジェクトの履歴には、「{移動元のワークスペース名} から移動」と残る。
- 別の Store への移動は、Store ごとに 1 回ずつ保存する。保存の順、失敗したときの表示、移動元で他の人の変更と重なったときの扱いは、アイテムと同じである(「保存」)。アクティビティには「プロジェクト「{タイトル}」を {移動元} から {移動先} へ移動」と残る。
- トーストは「{移動先} へ移動しました」である。通知は出ない。

**削除**: プロジェクトの削除は論理削除である。設定の「削除」から、確認ダイアログを出す。

| 部分 | 内容 |
|---|---|
| タイトル | 「プロジェクトを削除」 |
| 本文 | 「「{タイトル}」と、その下の N 件のアイテムを削除します。」 |
| 補足 | 「設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」 |
| ボタン | 「削除」(危険な操作の見た目)と「キャンセル」 |

- プロジェクトと、その下のすべてのアイテムを、同じ 1 回の削除として消す。復元は、この削除の単位で行う(08)。プロジェクトのルールと専用ルールは消さない(下のアイテムが削除済みのあいだは働かない。復元で働く)。
- そのプロジェクトの画面を開いていたら、ワークスペースの概要に移る。
- アクティビティには「プロジェクト「{タイトル}」を削除」と残る。トーストは「プロジェクトを削除しました」である。

## コマンドパレット

Ctrl+K(Cmd+K)で開く。ダイアログを開いているときは使えない(C キー・/ キーと同じ)。パレットを開いているあいだは、別のダイアログを開かない。パレットから選んだ候補がダイアログを開くとき(新規作成、ワークスペースを追加など)は、パレットを閉じてから開く。入力欄は 1 つで、プレースホルダは「ID・タイトル・コマンドを入力」。下端に「↑↓ で選択 ・ Enter で開く ・ Ctrl+Enter で新しいタブ ・ Esc で閉じる」と添える(Mac は「Cmd+Enter」)。1 文字入れるごとに候補を更新し、選択を先頭に戻す。

候補は次のとおり。

| グループ | 内容 | 出る条件 |
|---|---|---|
| コマンド | 新規作成(ヒントは C)、マイタスクを開く、受信箱を開く、アクティビティを開く、検索を開く、設定を開く、すべての Store を同期(ヒントは Shift+Ctrl+S。Mac は Shift+Cmd+S)、ワークスペースを追加 | 入力が空のときは全部。入力があるときは、名前に入力を含むもの(大文字小文字を区別しない) |
| アイテム | ID(小文字で比べる)またはタイトルに、入力を含むもの。ヒントにプロジェクト名を添える。旧 ID(移動前の ID と、接頭辞を変える前の ID)も対象にし、旧 ID で見つかったものには「旧 ID」と添える | 入力があるとき。削除済みのアイテムと、非表示の Store のアイテムは出さない |
| プロジェクト | プロジェクトの ID またはタイトルに、入力を含むもの。ヒントにワークスペース名を添える。旧 ID も対象にし、旧 ID で見つかったものにはヒントを「旧 ID・{日付} に移動」にする | 入力があるとき。削除済みのプロジェクトと、非表示の Store のプロジェクトは出さない |
| ワークスペース | 名前または接頭辞に入力を含むもの。ヒントに Store 名を添える | 入力があるとき。非表示の Store のワークスペースは出さない |
| ビュー | 名前に入力を含むもの | 入力があるとき |

次の群は、条件を満たすときだけ、この順で「コマンド」の次に出す。

| グループ | 内容 | 出る条件 |
|---|---|---|
| このクエリで | 見出しは「このクエリで」。「検索で開く」(ヒントに「{N} 件」)、「ビューとして保存…」、「{N} 件をまとめて変更…」。入力を、04 のクエリとして読めるときだけ出す。読めるのは、キーを 1 つ以上含み、04 のエラー(絞り込み欄の下に赤字で出すもの)にならないとき | 入力があり、クエリとして読めるとき |
| 選んでいるアイテム | 見出しは「{ID} に対して」(同じ ID のアイテムが別の Store にもあるときは、頭に Store の点を添える)。「ステータスを変更…」「{種類} を追加」「詳細を開く」「別のワークスペースへ移動…」。選んでいるアイテムは、パレットを開いた時点で、詳細パネルを開いているアイテム、なければツリーでフォーカスのある行のアイテム、なければテーブル・バックログで選択がちょうど 1 件のアイテム。「{種類} を追加」の種類は、そのアイテムの下に置ける最初の種類(Epic なら Story、Story・Task・Bug なら Step)で、Step には出さない。「別のワークスペースへ移動…」は、Epic・Story・Task・Bug だけに出す | 選んでいるアイテムがあるとき。入力が空のときは全部。入力があるときは、名前に入力を含むもの。閲覧のみの Store のアイテムでは「詳細を開く」だけ。詳細パネルがすでに開いているアイテムでは「詳細を開く」を出さない |
| 作成 | プロジェクトを作成、スプリントを作成、リリースを作成。スプリントとリリースは、ワークスペースの画面かプロジェクトの画面を開いているときだけ出す | 入力があるとき。名前に入力を含むもの。書き込める Store のワークスペースがないときの扱いは、「新規作成」と同じ(「アイテムの作成」) |
| 設定 | 設定: アカウントとメンバー、設定: Store、設定: 削除済み、設定: 診断と修復、設定: ワークスペース({名前})、設定: プロジェクト({名前})。最後の 2 つは、ワークスペース・プロジェクトの画面を開いているときだけ出す | 入力があるとき。名前に入力を含むもの |
| 最近開いたもの | 最近開いたアイテム。新しい順に最大 8 件。ヒントにプロジェクト名を添える。記録するのは、詳細パネルを開いたとき(行・パレット・リンクのどれからでも)。削除済みのアイテムと、非表示の Store のアイテムは出さない(復元・再表示したら、また出る)。完全に削除されたもの、Store をこのマシンから削除して見えなくなったものは、覚えている一覧から外す。旧 ID でなく、いまの ID で出す。このマシンに覚え、ブラウザの別のタブで開いたものも、パレットを開くたびに最新を読む(01) | 入力が空のとき |

アイテムの候補は、入力にキーがあってクエリとして読めるときも、入力した文字列全体を ID・タイトルに含むものを探す(「このクエリで」の群とは別に動く)。

候補は、グループごとに見出しを付け、グループごとに上限を決める。コマンドは一致したものすべて(最大 8)、プロジェクト・ワークスペース・ビューはそれぞれ最大 5 件である。アイテムは、全体の 40 件から、コマンド・プロジェクト・ワークスペース・ビューが使った件数を引いた残り(最低 17 件)である。「このクエリで」(3 件)、「選んでいるアイテム」(最大 4 件)、「作成」(最大 3 件)、「設定」(最大 6 件)、「最近開いたもの」(最大 8 件)は、上限が小さく固定なので、40 件に数えない。グループの順は、コマンド、このクエリで、選んでいるアイテム、作成、設定、最近開いたもの、アイテム、プロジェクト、ワークスペース、ビューである。グループの中の並びは、アイテムは ID(旧 ID を含む)が入力と一致するものを先、タイトルだけに一致するものを後とし、それぞれの中は、Store の並び、ワークスペースの並び、番号の昇順とする。プロジェクトは ID に一致するものを先、名前だけに一致するものを後とし、それぞれの中はサイドバーの並びとする。ワークスペース・ビューはサイドバーの並びである。上限で切ったグループは、そのグループの末尾に、押せない 1 行「ほか N 件あります。入力を続けて絞り込んでください」を出す(40 件には数えない)。

| 操作 | 動作 |
|---|---|
| ↑ ↓ | 選択を動かす。端で止まる |
| Enter または クリック | 選んだ候補を実行する |
| Ctrl+Enter(Cmd+Enter) | 選んだ候補が行き先のあるもの(アイテム・プロジェクト・ワークスペース・ビュー・最近開いたもの・画面を開くコマンド)なら、ブラウザの新しいタブで開いて、パレットを閉じる。それ以外の候補は、Enter と同じ |
| Esc または 背景のクリック | 閉じる |

候補を実行したときの動作は次のとおり。

| 候補 | 動作 |
|---|---|
| アイテム | 詳細パネルを開く |
| プロジェクト・ワークスペース | それぞれの概要を開く |
| ビュー | そのビューを開く |
| 新規作成 | 作成ダイアログを開く |
| すべての Store を同期 | 06 の「すべて同期」を実行する。remote のある表示中の Store が 1 つもないときは、何も同期せず、トースト「同期する Store がありません(remote のある、表示中の Store が要ります)」を出す。保存にもアクティビティにも残らない |
| ワークスペースを追加 | ワークスペースの追加ダイアログを開く。Store が 1 つもないときは「先に Store を追加してください」と表示する |
| ステータスを変更… | パレットの中で、そのアイテムのプロジェクトが使うステータスの一覧に切り替える。各項目に分類を添え、いまのステータスにチェックを付ける(いまのステータスがプロジェクトで使わないものなら、チェックつきで 1 項目だけ残し、「このプロジェクトでは使わない」と添える)。遷移の制約で移れない項目は無効にし、理由をヒントで出す(「ステータスの変更」のメニューと同じ)。選ぶと変更して、パレットを閉じる。Esc はパレットごと閉じる。メニューで変えたときと同じく、自動化のきっかけになる(03) |
| {種類} を追加 | パレットを閉じてから、そのアイテムを親にした作成ダイアログを開く |
| 詳細を開く | 詳細パネルを開く |
| 別のワークスペースへ移動… | パレットを閉じてから、「別のワークスペースへ移動…」のダイアログを開く |
| 検索で開く | パレットを閉じて、検索の画面をテーブルで開き、絞り込みだけを入力したクエリに置き換える。レイアウトの設定と列は変えない |
| ビューとして保存… | パレットを閉じて、検索の画面をテーブルで開き、絞り込みを入力したクエリにしてから、「ビューとして保存」のダイアログ(04)を開く |
| {N} 件をまとめて変更… | パレットを閉じて、検索の画面をテーブルで開き、絞り込みを入力したクエリにし、すべての行を選んで、「選択したアイテムを一括変更」のダイアログ(04)を開く。一致が 0 件、またはすべて閲覧のみの Store のものなら、無効にして理由(「一致するアイテムがありません」「閲覧のみの Store です」)を添える。クエリに `is:deleted` の語(否定でないもの)があるときも、無効にして「削除済みのアイテムは変更できません」を添える |
| プロジェクトを作成 | パレットを閉じてから、プロジェクトの作成ダイアログを開く。ワークスペースの初めの値は、アイテムの作成ダイアログと同じ順で決める |
| スプリントを作成、リリースを作成 | パレットを閉じてから、開いているワークスペースの「スプリント」「リリース」のタブを開き、作成ダイアログを開く |
| 設定: … | 設定の該当するタブを開く。診断は実行しない。ワークスペース・プロジェクトは、その「設定」タブを開く |
| 最近開いたもの | 詳細パネルを開く(アイテムと同じ) |

一致する候補が 1 つもないときは、「一致するものはありません」と出す。パレットを開く操作は、Store を変えないので、保存にもアクティビティにも残らない。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| ステータスごとの必須項目 | ステータスごとに必須の項目を決め、足りないと必須項目ダイアログで入力させる | 必須項目の仕組みを持たない。必須項目ダイアログもない | ユーザーの指示。ステータスの変更で入力を求めない |
