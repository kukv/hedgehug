# hedgehug 機能仕様 02: アイテムとプロジェクト

この文書は、アイテムとプロジェクトを作り、直し、動かし、消す操作と、アイテムの詳細パネル、コマンドパレットの振る舞いを定める。用語、階層、書き込みと元に戻す、閲覧のみの Store は 01 に従い、ここでは繰り返さない。

| スプリントとリリースの操作と集計 | 05 |
| 通知を作る規則、受信箱、アクティビティ、番号の重なりの修復 | 06 |

## アイテムの種類と親子

アイテムの種類は Epic・Story・Task・Bug・Step の 5 つである。置ける親は 01 の表のとおり。種類ごとに持てる項目は次のように異なる。

| 種類 | 子 | スプリント | リリース |
|---|---|---|---|
| Epic | Story・Task・Bug | 入れられない | 設定できる |
| Story・Task・Bug | Step | 入れられる | 設定できる |
| Step | なし | 入れられない | 設定できない |

親子の決まりに合わない場所へは、作成・移動・種類の変更のどの経路でも置けない。移動の経路では、断るときに次の文言を表示する。

| 操作 | 文言 |
|---|---|
| アイテムを、置けない種類のアイテムの下へ動かす | 「{種類} は {種類} の下に置けません」 |
| Epic 以外を、プロジェクトの直下へ動かす | 「プロジェクトの直下には Epic だけを置けます」 |
| アイテムを、別のワークスペースのアイテムの下へドラッグで動かす | 「別のワークスペースには移せません。移動はメニューの「移動…」から」 |
| アイテムを自分自身の下へ動かす | 何も起きない |

兄弟の並び順は、ツリーと詳細パネルで共通である(04)。新しく作ったアイテムと、移動してきたアイテムは、親の子の末尾に入る。

## プロパティの入力と保存

### プロパティの種類

アイテムのプロパティは、組み込みと追加に分かれる。組み込みはステータス・担当者・優先度・開始日・終了日・ポイント・関連システムの 7 つ、追加は利用者がワークスペースの設定(03)で足したものである。追加プロパティの型は、テキスト・数値・日付・単一選択・複数選択・ユーザー・チェック・URL の 8 つ。アイテムに表示されるのは、ワークスペースで非表示にされておらず、そのアイテムの種類で使うと設定されたプロパティだけである。

組み込みと追加のほかに、スプリント(Story・Task・Bug のみ)とリリース(Step 以外)の 2 項目を、同じ並びに出す。値の選び方は 05 に従い、次の 2 点だけをここで定める。

- スプリントの選択肢は「バックログ」(スプリントに入れない)と、完了していないスプリントである。実行中のものには「(実行中)」と添える。いま入っているスプリントが完了済みなら、それも選択肢に残す。完了済みのスプリントへ新しく入れることはできない。
- リリースの選択肢は「なし」と、アーカイブされていないリリースである。いま入っているリリースがアーカイブ済みなら、それも選択肢に残す。

プロパティを非表示にしたり、使う種類を変えたりしても、入っていた値は消えない。画面から隠れるだけで、表示し直せば戻る。

### 入力の方法と保存

1 つのプロパティを変えるごとに、1 回の保存になる。変更しても値が前と同じなら、何も保存しない。アクティビティには「{ID} の{プロパティ名}を {値} に変更」と残り、履歴には「{プロパティ名}を 旧 → 新」と残る。

| 型 | 入力の方法 | 未設定の状態 |
|---|---|---|
| ステータス | ボタンからメニューを開いて選ぶ。メニューの扱いは「ステータスの変更」に書く | なし(必ず値がある) |
| 優先度・単一選択 | ボタンからメニューを開いて選ぶ。先頭に「なし」を置く。選択肢が 7 件以上のとき、メニューに検索欄を出す | 「なし」 |
| 担当者・ユーザー | セレクトで選ぶ。先頭に「未割り当て」を置き、メンバー全員を並べる。あなたには「(あなた)」を添える | 「未割り当て」 |
| 日付 | 日付の入力欄 | 空 |
| 数値・ポイント | 数値の入力欄。小数も入れられる | 空 |
| チェック | チェックボックス | オフ |
| 関連システム・複数選択 | ボタンからメニューを開き、項目ごとに入り切りする。選ぶたびに保存し、メニューは開いたままにする | 何も選ばない |
| テキスト・URL | 文字の入力欄。前後の空白は取り除く | 空 |

保存するときに次の検査をし、合わなければ何も変えずに理由を表示する。

| 対象 | 条件 | 文言 |
|---|---|---|
| 開始日と終了日 | 両方があり、終了日が開始日より前 | 「終了日は開始日以降にしてください」 |
| ポイント | 0 未満の数 | 「ポイントは 0 以上の数で入力してください」 |

日付は片方だけを入れてもよい。値を空にすることは常にできる。

担当者を、あなた以外のメンバーに設定したときは、そのメンバーに通知が出る。ウォッチ中の人への通知は「ウォッチ」に書く。

## ステータスの変更

ステータスは、詳細パネルのほか、一覧やカンバンなどの画面にあるステータスのボタンからも変えられる。ボタンを押すとメニューが開く。

- メニューには、そのワークスペースのすべてのステータスを並べる。各項目に分類(未着手・進行中・完了・中止)を添え、いまのステータスにはチェックを付ける。
- ワークフローの遷移の制約(03)で、いまのステータスから移れない項目は無効にし、ヒントに理由を出す。理由の文言は「ワークフローの制約: {いま} から {移行先} には変更できません({移れる先}のみ)」である。
- 移行先に必須の項目があり、そのアイテムに空のものがあるときは、項目を無効にしない。選ぶと、次の必須項目ダイアログが開く。

ドラッグや Step のチェックなど、メニューを通らない経路で遷移の制約に反したときは、何も変えずに同じ文言を表示する。

### 必須項目ダイアログ

移行先のステータスに必須の項目があり、そのアイテムに空のものがあるとき、ステータスを変える前に次のダイアログを出す。遷移の制約に反するときは出さず、上の文言で断る。

| 部分 | 内容 |
|---|---|
| タイトル | 「{移行先} にするには」 |
| 本文 | 「{ID} {タイトル} を {移行先} にするには、次の項目が必要です。」 |
| 項目 | 必須の項目をすべて、型に応じた入力欄で並べる。空の項目には「未入力」と添える。複数選択と関連システムはチェックボックスの並びにする |
| 注記 | 「ステータスと入力した項目は、1 回の保存(1 コミット)で変わります。」 |
| ボタン | 「{移行先} にする」。空の項目が残っているあいだは押せない。「キャンセル」と Esc では、何も変えずに閉じる |

- 「{移行先} にする」を押すと、アクティビティに「{ID} を {移行先} にする(必要な項目を入力)」と残る。
- ステータスと入力した項目は、1 回の保存で変わる。どれか 1 つでも保存できなければ、すべて元のままにする。
- チェック型の必須項目は、オフを空として扱う。必須のチェックは、オンにして初めて入力済みになる。
- 必須の項目のうち、そのアイテムに表示されないもの(その種類で使わないもの、非表示のもの)は対象にしない。編集できない項目を求めないためである。
- すでに空のまま残っている項目は、変更を妨げない。次にステータスを変えるときに、このダイアログで入力を求める。

## アイテムの作成

### 開き方と初期値

作成ダイアログは、次のどの操作でも開く。

- C キー(入力中とダイアログを開いているときは使えない)
- コマンドパレットの「新規作成」
- 各画面の「作成」「追加」のボタン
- Epic の詳細パネルの「Story」「Task」「Bug」のボタン
- アイテムのメニューの「{種類} を追加」
- プロジェクトのメニューと画面の「Epic を追加」

ボタンから開くときは、そのボタンのある場所に合わせて、ワークスペース・プロジェクト・種類・親・スプリントを初めから入れる。初期値は次の順に決まる。

| 項目 | 決め方 |
|---|---|
| ワークスペース | 開いた場所が指定したもの、いま開いているワークスペース、いま開いているプロジェクトのワークスペース、書き込める Store の先頭のワークスペース、の順 |
| プロジェクト | 開いた場所が指定したもの、いま開いているプロジェクト、そのワークスペースの先頭のプロジェクト、の順 |
| 種類 | 開いた場所が指定したもの。なければ Task |
| ステータス | ワークスペースの初期ステータス(03) |
| 親 | 開いた場所が指定したもの。なければ、親にできるものの先頭 |

書き込める Store のワークスペースがないときは、ダイアログを開かず「先にワークスペースを作ってください」と表示する。選んだワークスペースにプロジェクトがないときは、「{ワークスペース名} にはプロジェクトがありません。先にプロジェクトを作ってください」と表示し、プロジェクトの作成ダイアログに切り替える。

種類ごとの既定のテンプレート(03)があれば、ダイアログを開いた時点と、種類を切り替えた時点で、そのテンプレートを当てはめる。

### ダイアログの項目

| 項目 | 内容 |
|---|---|
| 種類 | Epic・Story・Task・Bug・Step から 1 つ選ぶ |
| ワークスペース | 「Store名 / ワークスペース名 (接頭辞)」の形で並べる。閲覧のみの Store と、非表示の Store のワークスペースは出さない |
| プロジェクト | 選んだワークスペースのプロジェクト |
| 親 | Epic 以外で出す。Step は同じプロジェクトの Story・Task・Bug、それ以外は同じプロジェクトの Epic から選ぶ。候補がないときは、セレクトの代わりに赤字で「このプロジェクトには Story・Task・Bug がありません。先に作ってください」(Step の場合)、または「このプロジェクトには Epic がありません。先に作ってください」と出す |
| テンプレート | その種類に使えるテンプレートがあるときだけ出す。「なし」を含む |
| タイトル | 1 行の入力欄。プレースホルダは「{種類} のタイトル」。Enter で作成する |
| プロパティ | その種類で使う、表示中のすべてのプロパティ。ステータスは初期ステータスを初期値にしたセレクトで、すべてのステータスを選べる |
| スプリント | Story・Task・Bug のみ。完了していないスプリントから選ぶ |
| 説明 | 4 行の入力欄。Markdown とメンションを使える |
| テンプレートの Step | テンプレートが Step を持つときだけ、「✓」を付けた読み取り専用の一覧で出す |
| ID の予告 | 「ID は HH-13 になります。」。接頭辞がないときは「ID は #13 になります(このワークスペースには接頭辞がありません)。」 |
| 続けて作成 | 左下のチェックボックス |

ID の予告は目安である。実際の番号は保存するときに決まり、他の人と同時に番号を取ったときは、同期のあとで振り直される(06)。

プロパティの入力欄の扱いは「プロパティの入力と保存」と同じで、複数選択と関連システムも作成時に選べる。担当者の選択肢は、選んだワークスペースの Store のメンバーである。

### ダイアログの中での連動

- **種類を切り替えたとき**: 親を、新しい種類の候補から選び直す。テンプレートと Step の一覧は空に戻し、新しい種類の既定のテンプレートがあれば当てはめる。入力済みのタイトルと説明は残す。
- **ワークスペースを変えたとき**: プロジェクトを先頭にし、親を選び直す。担当者・開始日・終了日・ポイントは残す。ただし担当者は、移動先の Store が違うなら、ログイン名が一致するメンバーだけを残す。優先度・関連システム・追加プロパティ・ステータス・スプリント・テンプレート・Step は初期値に戻す。
- **プロジェクトを変えたとき**: 親を選び直す。
- **テンプレートを変えたとき**: 入力済みのタイトルは残し、空のときだけテンプレートのタイトルを入れる。説明はテンプレートのもので置き換える。テンプレートが持つプロパティの値(優先度・担当者・関連システム・追加プロパティ)は、入力済みの値を上書きする。テンプレートの Step の一覧は、新しいテンプレートのものに入れ替える。「なし」に切り替えたときは、Step の一覧だけを空にし、ほかの入力は残す。
- **ステータスを変えたとき**: そのステータスで必須の項目に、「必須」と添える(次節)。

### 必須項目の扱い

作成時は、選んだステータスの必須の項目を、ダイアログの中で入力させる。初期ステータスを選んだときも同じである。作成時にはワークフローの遷移の制約を適用しないので、どのステータスでも初期ステータスとして選べる。

| 条件 | 文言 |
|---|---|
| タイトルが空 | 「タイトルを入力してください」 |
| プロジェクトが選ばれていない | 「プロジェクトを選んでください」 |
| 親が選ばれていない(Step) | 「親になる Story・Task・Bug を選んでください」 |
| 親が選ばれていない(Step 以外) | 「親になる Epic を選んでください」 |
| 選んだステータスの必須の項目が空 | 「{ステータス} にするには {項目}・{項目} が必要です」 |
| 開始日と終了日があり、終了日が開始日より前 | 「終了日は開始日以降にしてください」 |
| ポイントが 0 未満 | 「ポイントは 0 以上の数で入力してください」 |

検査は上の順に行い、最初に合わなかった 1 つだけをダイアログの中に赤字で出す。作成は 1 回の保存で、ダイアログは開いたままにする。

### 作成したあと

- **作ったもの**: アイテムを 1 つ作る。ID は、ワークスペースの連番の次の番号になる。ウォッチ中の人は作成者だけである。並びは親の子の末尾である。履歴に「作成」が残る。
- **テンプレートの Step**: テンプレートが Step を持つときは、1 行ごとに Step を作る。各 Step は、それぞれ連番の番号を取り、担当者は親と同じ、ステータスは初期ステータスにする。
- **通知**: 担当者があなた以外のメンバーなら、そのメンバーに通知が出る。説明にメンションがあれば、メンションされたメンバーに通知が出る。
- **アクティビティ**: 「{種類}「{タイトル}」を作成」と残る。
- **表示**: 「{ID} を作成しました」とトーストを出す。このトーストに「元に戻す」は付けない。Ctrl+Z とコマンドパレットの「元に戻す」では戻せる。作成を戻したアイテムは、削除したときと同じ扱いで削除済みに入り、そこから復元できる。
- **ダイアログ**: 「続けて作成」がオフなら、ダイアログを閉じ、作ったアイテムの詳細パネルを開く。オンなら、ダイアログを開いたまま、タイトル・説明・エラー表示だけを空にする。ほかの入力、テンプレート、Step、プロジェクト、親はそのまま残す。
- **閉じる**: Esc で閉じる。入力した内容の確認はしない。

## 複製

アイテムのメニューの「複製」で、同じ親の下にアイテムをもう 1 つ作る。

| 項目 | 複製での扱い |
|---|---|
| タイトル | 末尾に「 のコピー」を付ける |
| 種類・親・説明・プロパティ・リリース | 複製元と同じ |
| スプリント | 複製元と同じ。ただし完了済みのスプリントなら、入れずに「バックログ」にする |
| リリース | 複製元と同じ。ただしアーカイブ済みなら「なし」にする |
| ステータス | ワークスペースの初期ステータス |
| ID | 新しく採番する |
| ウォッチ中の人 | あなただけ |
| コメント・GitHub リンク・関連・作業時間・履歴 | 複製しない |
| 子の Step | 複製しない |

複製では必須項目の検査をしない。複製が終わると、詳細パネルは新しいアイテムに切り替わる。アクティビティには「{ID} を複製」と残る。担当者があなた以外のメンバーなら、そのメンバーに通知が出る。トーストは出さない。

## 同じワークスペースの中での移動

アイテムのメニューの「移動…」で、親を変える。

- **Epic**: 同じワークスペースの、ほかのプロジェクトをメニューに並べる。選ぶと、その Epic は選んだプロジェクトの直下に移り、下の Story・Task・Bug・Step もすべて同じプロジェクトに移る。ほかのプロジェクトがないときは、この項目を無効にする。
- **Story・Task・Bug・Step**: 新しい親の候補をメニューに並べる。Step の候補は Story・Task・Bug、それ以外の候補は Epic である。候補には、ワークスペース全体のものを出し、プロジェクトをまたいでよい。自分と自分の子孫、いまの親は出さない。検索欄を付け、各候補にプロジェクト名を添える。選ぶと、そのアイテムと下のものがすべて、新しい親のプロジェクトに移る。

移動の前後で、プロパティ・スプリント・リリース・関連は変わらない。ワークフローの制約と必須項目の検査はしない。履歴に「親を変更」と残る。アクティビティには、親が変わるときは「{ID} を {ID} の下に移動」、プロジェクトが変わるときは「{ID} を {プロジェクト名} に移動」と残る。トーストは「{ID} の下に移動しました」「{プロジェクト名} に移動しました」で、「元に戻す」を付ける。通知は出ない。

ドラッグでの移動は、画面ごとの操作として 04 に定める。そこでも、親子の決まりと上の断り方は同じである。

## 別のワークスペースと別の Store への移動

アイテムのメニューの「別のワークスペースへ移動…」で、Epic と Story・Task・Bug を、別のワークスペースへ移せる。移す先は、同じ Store の別のワークスペースでも、別の Store のワークスペースでもよい。Step は単独では移せず、親と一緒に移る。

### 移す先の選び方

移す先の候補は、自分以外のワークスペースのうち、書き込める Store にあり、サイドバーで非表示にされておらず、プロジェクトが 1 つ以上あるものである。候補がないときは、ダイアログを開かず「移せるワークスペースがありません(プロジェクトのある、書き込めるワークスペースが要ります)」と表示する。

ダイアログの項目は、移動先のワークスペース、プロジェクト、親の Epic である。Epic を移すときは、親の Epic を選ばない。選んだプロジェクトに Epic がないときは「このプロジェクトには Epic がありません」と出し、ボタンを押せなくする。ダイアログの冒頭には「{ID} {タイトル} と、その下の N 件を移動します。」と出す(下のものがないときは「{ID} {タイトル} を移動します。」)。続けて、見出し「移動先で変わること」の下に、次の変更を説明する。

- ID は、移動先のワークスペースの次の番号(「HH-13 からの番号に振り直されます」。接頭辞がなければ「#13 から」)から振り直す。
- スプリントとリリースは外す。
- ステータス、優先度、関連システムなどは、同じ名前の値に合わせる。合う値がなければ空にする。
- 別の Store へ移すときは、ブロックの関連を解除する。
- 移動元に転送の記録を残し、古い ID からも辿れる。

ボタンは「移動」で、このダイアログが確認を兼ねる。

### 移すもの

アイテム自身と、その下のすべてのもの(子と孫)が、一緒に移る。次のものも一緒に移る。

- 説明、コメント、作業時間、ウォッチ中の人、GitHub リンク、詳細パネルの履歴

移動元の Store のアクティビティは、移動元に残る。

移動先では、各アイテムに新しい番号を振る。移動元の番号は再利用しない。

### 値の引き直し

プロパティの値は、移動先のワークスペースの定義に合わせて引き直す。

| 種類 | 引き直し |
|---|---|
| ステータス・優先度・関連システム・単一選択・複数選択 | 値の名前が完全に一致するものに置き換える。一致がなければ空にする。複数の値は、一致したものだけが残る |
| ステータスが空になった場合 | 移動先の初期ステータスにする |
| テキスト・数値・日付・チェック・URL | キーが同じで型も同じなら、そのまま残す |
| 担当者・ユーザー・ウォッチ中の人 | 同じ Store の中なら、そのまま残す。別の Store へ移すときは、ログイン名が一致するメンバーに置き換える。一致がなければ空にする(ウォッチ中の人は外す) |
| 移動先に同じキーのプロパティがない、またはキーが同じで型が違う | 値を捨てる |

値が入っていたのに、空になった、または捨てた項目は、移動後のトーストに「合う値がなく空になった項目」として並べる。ステータスを初期ステータスにしたときは、「ステータス」も並べる。移動先のワークフローの制約と必須項目は検査しない。

### 関連・転送記録・旧 ID

- **関連**: 同じ Store の中の移動では、ブロックの関連をそのまま残す。別の Store へ移すときは、移すもの同士を含め、移すものすべての関連を解除する。関連の相手の側からも消える。
- **転送記録**: 移動元の Store に、旧 ID と新 ID の対応を記録する。移動先のアイテムの履歴にも、「{旧 ID} から移動」と、移動元の Store・ワークスペース・プロジェクトを残す。別のワークスペースへ何度移しても、すべての旧 ID が、最後の新しいアイテムに辿り着く。
- **旧 ID から辿れる場所**: ID を入力して探す箇所(コマンドパレット、検索の自由テキストとクエリの `parent:`。04)、アクティビティと受信箱に残る旧 ID のリンクは、新しいアイテムを開く。コメントや説明に書かれた旧 ID の文字は、そのまま残る。

### 保存と元に戻す

- 同じ Store の中の移動は、1 回の保存である。
- 別の Store への移動は、Store ごとに 1 回ずつ、合わせて 2 回保存する。移動元の保存はアイテムを取り除いて転送記録を残し、移動先の保存はアイテムを加える。どちらかが失敗したら、両方とも元のままにする。元に戻すときは、2 回の保存を 1 回の操作としてまとめて戻す。
- アクティビティには「{旧 ID} を {移動元} から {移動先} へ移動」と残る。
- トーストは「{旧 ID} は {新 ID} になりました」で、空になった項目があれば「。合う値がなく空になった項目: A・B」を続ける。通知は出ない。
- 移すとき、詳細パネルを開いていれば、新しい ID のアイテムに切り替わる。

## 種類の変更

アイテムのメニューの「種類を変更…」で、アイテムの種類を変える。

| 変更前 | 選べる種類 | 親 |
|---|---|---|
| Story・Task・Bug | 自分以外の Story・Task・Bug | 変わらない |
| Step | Story・Task・Bug | 元の親の親(Epic)の下に移る |
| Epic | 変更できない | なし |

Story・Task・Bug から Step へは変えられない。Epic はメニューの項目を無効にする。Story・Task・Bug が Step を持っていても、種類を変えられる。Step は Story・Task・Bug のどの下にも置けるためである。

変更の前後で、プロパティ・スプリント・リリース・関連は変わらない。新しい種類で使わないと設定されたプロパティの値は、画面から隠れるが、消さずに残す。Step から昇格したアイテムは、末尾の位置で親の Epic の下に入る。ステータスと、ワークフローの制約・必須項目の検査には影響しない。履歴に「種類を {変更前} から {変更後} に変更」と残る。アクティビティには「{ID} の種類を {種類} に変更」と残る。通知とトーストは出ない。

## 削除

アイテムの削除は論理削除である。消したものは削除済みに入り、保持日数のあいだは復元でき、保持日数を過ぎると完全に削除される(08)。

アイテムのメニューの「削除…」、または Step の一覧の「×」を押すと、確認ダイアログを出す。

| 部分 | 内容 |
|---|---|
| タイトル | 「{種類} を削除」 |
| 本文 | 「{ID} {タイトル} を削除します。」。下のものがあるときは「下にある N 件({種類名の一覧})も一緒に削除されます。」を続ける |
| 補足 | 「設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」(N は、その Store の削除済みの保持日数) |
| ボタン | 「削除」(危険な操作の見た目)と「キャンセル」 |

- アイテムと、その下のすべてのものを、同じ 1 回の削除として消す。復元は、この削除の単位で行う(08)。
- 開いている詳細パネルが、削除したアイテムのものなら閉じる。
- 削除したアイテムの関連は消さず、一覧から隠す。復元すると、関連も戻る。削除したアイテムにブロックされていたアイテムは、ブロック中でなくなる。
- 削除したアイテムの履歴には何も足さない。アクティビティには「{ID} {タイトル} を削除」と残る。
- トーストは「{ID} を削除しました」で、「元に戻す」を付ける。通知は出ない。
- 一括での削除は 04 に従う。

## 詳細パネル

アイテムの詳細パネルは、画面の右からせり出す。ヘッダーの全画面ボタンで、画面いっぱいにも広げられる。全画面では、左を本文の列、右をプロパティの列に分ける。パネルの幅は、左の縁をドラッグして変えられ、このマシンに保存される(01)。Esc でパネルを閉じ、全画面も解除する。開いているアイテムが削除されたら、パネルを閉じる。

閲覧のみの Store のアイテムでは、パネルの上部に 01 の帯を出し、入力欄とボタンを無効にする。

### 上から順の構成

| 部分 | 内容 |
|---|---|
| ヘッダー | パンくず(Store・ワークスペース・プロジェクト・祖先のアイテム。クリックで移る)、ウォッチのボタン、全画面のボタン、メニュー、閉じるボタン |
| 種類の行 | 種類のアイコンと名前、ID、ID をコピーするボタン(押すと「コピーしました: {ID}」と表示する。コピーできなかったときは「コピーできませんでした。{ID} を選択してコピーしてください」と表示する)、ブロック中のとき「ブロック中」 |
| タイトル | 1 行の入力欄 |
| プロパティ | 「プロパティの入力と保存」の項目。追加プロパティには「追加」と添える。末尾に「プロパティを追加・変更」を置き、ワークスペースの設定(03)へ移る |
| 説明 | Markdown で表示する |
| 子 | Epic は「Story・Task・Bug」、Story・Task・Bug は「Step」。Step にはない |
| 関連 | ブロックの関連 |
| GitHub | PR と Issue のリンクの一覧 |
| 作業時間 | 記録の一覧と入力 |
| コメント | コメントの一覧と入力 |
| 履歴 | 変更の一覧 |

メニューの項目は、アイテムの一覧から開くメニューと同じで、「詳細を開く」と「{種類} を追加」を除く。メニューの項目には、Epic のみ「Issue から作る」(Epic の詳細パネルのボタンと同じ。07)、「上へ移動」「下へ移動」(同じ親の下の兄弟の中で動かす。端では無効。04)、「移動…」「別のワークスペースへ移動…」「種類を変更…」「複製」「ID をコピー」「削除…」がある。使えない項目は、無効にして理由を添える。

「ブロック中」は、そのアイテムをブロックしているアイテムのうち、削除されておらず、完了と中止のどちらでもないものが 1 つでもあるときに出す。

### タイトル

- タイトルは、入力欄からフォーカスが外れたときに保存する。Enter でもフォーカスを外して保存する。
- 連続する空白と改行は 1 つの空白にまとめ、前後の空白は取り除く。文字数の上限は設けない。
- 空にしようとしたときは、「タイトルは空にできません」と表示し、元のタイトルに戻す。前と同じなら何も保存しない。
- 保存すると、履歴に「タイトルを「{新}」に変更」と残り、アクティビティに「{ID} のタイトルを変更」と残る。ウォッチ中の人に通知が出る。

### 説明

- 説明は Markdown で表示する。空のときは「説明を追加」を出す。
- 説明の部分をクリックすると、8 行の入力欄に切り替わる。入力欄の下に「Markdown を使用できます。@ログイン名 でメンション」と添え、「保存」と「キャンセル」のボタンを置く。Ctrl+Enter でも保存できる。
- 自動保存はない。「キャンセル」は確認なしで入力を捨てる。保存したとき、前と同じなら何も保存しない。
- 保存すると、履歴に「説明を変更」と残り(差分は残さない)、アクティビティに「{ID} の説明を変更」と残る。ウォッチ中の人には通知しない。
- メンションの通知は、次の「メンション」に従う。

### Markdown

説明とコメントで使える書き方は次のとおり。

| 書き方 | 表示 |
|---|---|
| `#` `##` `###` で始まる行 | 見出し(3 段階) |
| `-` `*` または `1.` で始まる行 | 箇条書き。行頭の `[ ]` は未チェック、`[x]` はチェック済みの印で表示する。表示だけで、クリックでは切り替わらない |
| `**文字**` | 太字 |
| `` `文字` `` | 行内のコード |
| 3 つのバッククォートで囲んだ行 | コードブロック |
| `http://` と `https://` で始まる文字列 | リンク。新しいタブで開く |
| `@ログイン名` | メンションの表示 |

それ以外の行は、1 行を 1 つの段落として表示する。

### メンション

- 説明とコメントの中の `@ログイン名` が、その Store のメンバーのログイン名と一致したとき、そのメンバーに通知が出る。ログイン名は、大文字と小文字を区別せずに比べる。
- `@` の直前が英数字のとき(`foo@bar` のようなメールアドレス)は、メンションとして扱わない。
- 通知が出るのは、保存した本文で新しく増えたログイン名だけである。前の本文にすでにあったログイン名には、再び通知しない。同じログイン名が 1 回の保存に何度あっても、通知は 1 通である。あなた自身には出ない。
- 対象は、アイテムの作成時の説明、説明の保存、コメントの投稿、コメントの編集、プロジェクトの説明の保存、プロジェクトのコメントの投稿である。
- コメントを書くときは、入力欄の下にある、あなた以外のメンバーの `@ログイン名` のボタンを押すと、入力欄の末尾に `@ログイン名 ` が足される。

### 子と Step

Epic の「Story・Task・Bug」の見出しには、完了の数と総数を「3/8」の形で添える。Story・Task・Bug の「Step」の見出しにも、同じ形で添える。数えるのは完了の分類のものだけで、中止のものは分母にも分子にも入れない。

- **Epic の子**: 1 行に、種類のアイコン、ID、タイトル(押すとそのアイテムの詳細パネルを開く)、ステータスのボタン、担当者のアバターを出す。下に「Story」「Task」「Bug」のボタンを置き、押すと、その Epic を親にした作成ダイアログを開く。続けて「Issue から作る」のボタンを置き、押すと、07 の Issue 取り込みダイアログを、その Epic のプロジェクトと親の Epic が決まった状態で開く。プロジェクトにリポジトリがないときは、ボタンとメニューの項目を無効にし、「プロジェクトにリポジトリがありません。プロジェクトの概要で追加してください」と添える(07)。
- **Step の行**: チェックボックス、タイトル、ID、ステータス、担当者、「上へ」、削除の「×」を出す。タイトルを押すと、その Step の詳細パネルを開く。
- **Step の追加**: 入力欄に「Step を追加して Enter」と添える。Enter で、タイトルを持つ Step を末尾に作る。担当者は親と同じ、ステータスは初期ステータスにする。空のまま Enter を押したときは何もしない。追加したあとは入力欄を空にして、フォーカスを戻す。アクティビティには「{ID} に Step「{タイトル}」を追加」と残る。
- **Step のチェック**: オンにすると、「完了」の分類の先頭のステータスにする。オフにすると、「未着手」の分類の先頭のステータスにする。「未着手」の分類のステータスがないときは、「「未着手」の分類のステータスがありません。ワークスペースの設定で分類を決めてください」と表示し、チェックを元に戻す。必須の項目が空のときは、必須項目ダイアログを開く。遷移の制約に反したときは、「ステータスの変更」の文言で断る。
- **Step の「上へ」**: 直前の Step と順位を入れ替える。先頭の Step では何もしない。詳細パネルのボタンに「下へ」はなく、下げるときはアイテムのメニューの「下へ移動」を使う(04)。アクティビティには「{ID} の順位を変更」と残る。
- **Step の削除**: 確認ダイアログは「削除」の節のとおり。

### 関連

関連は、アイテム同士のブロックの関係である。一覧には、このアイテムをブロックしているものを「ブロックされている」、このアイテムがブロックしているものを「ブロックしている」として並べる。各行に、相手へのリンク、相手のステータス、解除の「×」を出す。関連がないときは「関連はありません」と出す。削除済みの相手は一覧に出さないが、関連は残り、相手を復元すると一覧にも戻る。

- 追加のボタンは 2 つある。「ブロックするものを追加」は、選んだ相手をこのアイテムがブロックする関連を作る。「ブロックされるものを追加」は、選んだ相手がこのアイテムをブロックする関連を作る。
- ボタンを押すと、検索欄(プレースホルダは「ID またはタイトルで検索」)付きのメニューが開く。候補は、同じ Store の削除されていないアイテムのうち、自分以外で、Step でなく、すでにどちらかの向きの関連があるもののほうを除いたものである。ワークスペースをまたいでよい。ほかのワークスペースの候補には、ワークスペース名を添える。
- 関連を足すと循環になる候補は、無効にして「循環になります」と添える。Step も、Step 以外のアイテムとの関連を持てる。
- 追加すると、アクティビティに「{ID} が {ID} をブロック」と残る。解除は、確認なしで外し、「{ID} と {ID} の関連を解除」と残る。どちらも履歴には残らず、通知も出ない。解除は Ctrl+Z で戻せる。

### GitHub

一覧には、リンクした PR と Issue を 1 行ずつ出す。1 行には、種別と状態の表示、「リポジトリ — タイトル」、解除の「×」を出す。リンクがないときは「リンクはありません」と出す。

リンクの追加は、一覧の下にある「PR をリンク」「Issue をリンク」「Issue を作成」のボタンで行う。リンクの内容、状態の取得、Issue の作成は 07 に従う。

解除は確認なしで外し、アクティビティに残る。トーストは「リンクを解除しました」で、「元に戻す」を付ける。

### 作業時間

見出しに、記録の合計を「N 時間」の形で出す。アイテムにポイントがあるときは、「 · 見積もり N pt」を続ける。

- 各行に、記録した人のアバター、「N 時間」、メモ、日付、削除の「×」を出す。
- 入力は、時間、メモ(任意)、「記録」のボタンである。時間の欄は 0.25 時間刻みで増減できる。0 より大きければ、0.1 のような値も記録できる。メモ欄で Enter を押しても記録する。
- 0 以下の値、数でない値、空の時間のときは、「時間を入力してください」と表示して記録しない。上限は設けない。
- 日付は、記録した日になる。過去の日付は入れられない。記録は、記録した人の名前で残る。
- 記録の削除は、確認なしで消す。作業時間は、誰の記録でも、書き込める人なら消せる。トーストは「作業時間を削除しました」で、「元に戻す」を付ける。
- アクティビティには「{ID} に N 時間を記録」「{ID} の作業時間を削除」と残る。履歴には残らず、通知も出ない。
- 見積もりは、ポイントのプロパティであり、作業時間とは別のものである。

### コメント

- コメントは、古いものから順にすべて並べる。1 件ごとに、投稿者のアバターと名前、相対時間、編集したときは「(編集済み)」、Markdown で表示した本文を出す。
- **投稿**: 入力欄のプレースホルダは「コメントを書く。@ログイン名 でメンション。Ctrl+Enter で送信」。ボタンか Ctrl+Enter で投稿する。空のときは何もしない。
- **編集と削除**: 自分が書いたコメントにだけ、編集と削除のボタンを出す。編集では、入力欄に「キャンセル」と「保存」を出す。空にして保存したときと、前と同じときは、何も保存せずに閉じる。コメントを消したいときは、削除のボタンを使う。
- **削除**: 確認ダイアログを出す。タイトルは「コメントを削除」、本文は「このコメントを削除します。」、ボタンは「削除」である。トーストは「コメントを削除しました」で、「元に戻す」を付ける。
- 投稿・編集・削除は、アクティビティに「{ID} にコメント」「コメントを編集」「コメントを削除」と残る。履歴には残らない。
- 通知は、投稿のときにウォッチ中の人へ出る(本文の先頭 40 文字を添える)。メンションの通知は「メンション」に従う。編集と削除では、ウォッチ中の人には通知しない。

### ウォッチ

ヘッダーのウォッチのボタンで、あなたがそのアイテムのウォッチ中かどうかを入り切りする。ボタンの表示で、いまどちらか分かるようにする。アクティビティには「{ID} のウォッチを開始」「{ID} のウォッチを解除」と残る。トーストは出さず、Ctrl+Z で戻せる。

- アイテムを作った人は、最初からウォッチ中になる。担当者になった人、メンションされた人は、自動ではウォッチ中にならない。
- ウォッチ中の人に通知が出るのは、プロパティの変更、タイトルの変更、コメントの投稿のときである。説明の変更、リンク、関連、作業時間、削除、移動、種類の変更では出ない。変更したのがあなた自身のときは、あなたには出ない。
- 受け取った通知は、受信箱の「ウォッチ」に出る(06)。クエリのキー `watching` で、ウォッチ中のアイテムを絞り込める(04)。

### 履歴

履歴は、そのアイテムの変更の一覧で、新しいものから並べる。保存する件数に上限はない。画面には 40 件まで出し、それより古いものがあるときは、一覧の末尾に「すべて表示」を置く。1 行に、操作した人(自動化のときは「自動化」、GitHub からの取り直しと mirror のときは「GitHub」)、変更の文、時刻を出し、同期で受け取った変更には「同期で受信」と添える。履歴がないときは「履歴はありません」と出す。

| 変更 | 文 |
|---|---|
| 作成 | 「作成」 |
| プロパティの変更 | 「{プロパティ名}を {旧} → {新}」。削除された値は「(削除された値)」と出す |
| タイトルの変更 | 「タイトルを「{新}」に変更」 |
| 説明の変更 | 「説明を変更」 |
| 親・プロジェクトの変更 | 「親を変更」 |
| 種類の変更 | 「種類を {旧} から {新} に変更」 |
| スプリントの変更 | 「スプリントを変更」 |
| リリースの変更 | 「リリースを変更」 |
| 削除からの復元 | 「復元」 |
| 別のワークスペースへの移動 | 「{旧 ID} から移動」と、移動元の Store・ワークスペース・プロジェクト |

履歴に残らないのは、コメント、関連、GitHub リンクの追加と解除、作業時間、ウォッチ、削除である。これらはアクティビティにだけ残る。例外として、GitHub から取り直したリンクの状態とタイトルの変更、Issue の mirror による変更は、操作した人のいない自動の変更として、履歴にもアクティビティにも残る(07)。

## プロジェクト

プロジェクトは、ワークスペースの下で Epic をまとめる。持つ項目は固定で、タイトル・説明・オーナー・開始日・終了日・ステータスである。ステータスは Todo・InProgress・Done・Pending・Cancel の 5 つで、利用者は変えられない。プロジェクトに詳細パネルはなく、概要の画面で扱う。

### 作成

サイドバーのワークスペースのメニューの「プロジェクトを作成」、ワークスペースの画面の「プロジェクト」のボタンから、作成ダイアログを開く。

| 項目 | 内容 |
|---|---|
| ワークスペース | 「Store名 / ワークスペース名」の形で並べる。閲覧のみの Store と、非表示の Store のワークスペースは出さない |
| タイトル | 1 行の入力欄。Enter で作成する |
| オーナー | 「なし」とメンバー。初めの値はあなた |
| ステータス | 5 つから選ぶ。初めの値は Todo |
| 開始日・終了日 | 日付の入力欄 |

| 条件 | 文言 |
|---|---|
| タイトルが空 | 「タイトルを入力してください」 |
| 開始日と終了日があり、終了日が開始日より前 | 「終了日は開始日以降にしてください」 |
| 同じワークスペースに同じ名前のプロジェクトがある | 「このワークスペースには同じ名前のプロジェクトがあります」 |

作成すると、そのプロジェクトの概要の画面を開く。トーストは出さない。履歴に「作成」が残り、アクティビティには「プロジェクト「{タイトル}」を作成」と残る。オーナーがあなた以外のメンバーなら、そのメンバーに通知が出る。並びは、ワークスペースの中の末尾である。

### 画面の見出しと構成

プロジェクトの画面の見出しには、パンくずに Store のバッジとワークスペース名のリンク(押すとワークスペースの概要を開く)、その下にプロジェクトのアイコンとタイトル、右にステータスのピルと「Epic」のボタン(押すと、そのプロジェクトを親にした Epic の作成ダイアログを開く)を出す。見出しの下のタブは、概要・ツリー・カンバン・テーブル・ガント・設定である。ツリー・カンバン・テーブル・ガントは、そのプロジェクトのアイテムを対象にする(04)。

設定のタブは、「名前」「別のワークスペースへ移動」「削除」の 3 つの区画に分かれる。

| 区画 | 内容 |
|---|---|
| 名前 | タイトルの入力欄。概要でのタイトルの変更と同じ検査をする |
| 別のワークスペースへ移動 | 説明文、移動先のセレクト(「Store名 / ワークスペース名」)、「移動」のボタン。移動先の候補がないときは、セレクトの代わりに「移せるワークスペースがありません」と出す |
| 削除 | 危険な操作の区画。「プロジェクトと、その下の N 件のアイテムを削除します。設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」と説明し、「プロジェクトを削除」のボタンを置く |

### 概要の編集

概要では、次の項目を直接編集できる。1 項目を変えるごとに、1 回の保存になる。変えても値が前と同じなら、何も保存しない。

| 項目 | 入力と検査 |
|---|---|
| タイトル | 入力欄から外れたときに保存する。空のときは「タイトルは空にできません」と表示して元に戻す。同じワークスペースの別のプロジェクトと同じ名前は、「このワークスペースには同じ名前のプロジェクトがあります」と表示して断る |
| 説明 | アイテムの説明と同じ編集(Markdown、メンション)。メンションの通知は、アイテムと同じ規則で出す |
| ステータス | 5 つから選ぶ |
| オーナー | 「なし」とメンバーから選ぶ |
| 開始日・終了日 | 終了日が開始日より前なら、「終了日は開始日以降にしてください」と表示して断る。日付を空にすることは常にできる。開始日と終了日が同じ日は認める |

保存すると、履歴に「{項目名}を {値} に変更」と残る(説明は「説明を変更」)。アクティビティには「{タイトル} の{項目名}を {値} に変更」と残る(説明は「{タイトル} の説明を変更」)。値は、ステータスならステータス名、オーナーなら人の名前、日付が空のときは「なし」である。オーナーをあなた以外のメンバーにしたとき、そのメンバーに「プロジェクト「{タイトル}」のオーナーになりました」の通知が出る。ガントでプロジェクトの期間を動かしたときも、同じ履歴とアクティビティが残る(04)。

概要にはさらに次を出す。

- **Epic の一覧**: 各 Epic の ID、タイトル(押すと詳細パネルを開く)、期限、進捗、ステータス、担当者を出す。ステータスのボタンからは、ステータスのメニューを開ける。進捗は、その Epic の下の Story・Task・Bug のうち、棒と「N%」で出す。棒の上にポインターを置くと「{完了} / {対象}」が出る(04 の進捗の表示と同じ)。中止のものは分母にも分子にも入れず、Step は数えない。Epic がないときは「Epic はまだありません。Epic の下に Story・Task・Bug を作れます。」と出す。
- **リポジトリ**: 「リポジトリと PR」の区画の上段で、プロジェクトに結びつけた GitHub のリポジトリを一覧にし、見出しの横に「リポジトリを追加」のボタンを置く。ないときは「リポジトリはまだありません」と出す。使い道は、PR・Issue のリンク先の候補、Issue の取り込みの候補、Issue の作成先の 3 つである。
- **PR と Issue**: プロジェクトの下のアイテムのリンクをすべて並べる。1 行に、「PR」または「Issue」の別と番号、状態、タイトル、そのアイテムへのリンクを出す。PR の状態は Open・Merged・Closed・Draft、Issue の状態は Open・Closed である。ないときは「リンク中の PR はありません」と出す。
- **コメント**: アイテムのコメントと同じ。通知は、メンションにだけ出る。ウォッチ中の人はいない。
- **履歴**: プロジェクトの変更の一覧。アイテムの履歴と同じく 40 件まで出し、「すべて表示」を置く。
- **注記**: 「プロジェクトのプロパティは固定です。ステータスの値も変更できません。」

### リポジトリの追加と削除

| 操作 | 内容 |
|---|---|
| 追加 | 入力欄に `owner/name` の形で入れる。形が違うときは「owner/name の形式で入力してください」、すでにあるときは「もう追加されています」と表示して断る。アクティビティには「{タイトル} にリポジトリ {owner/name} を追加」と残る。トーストは出さない |
| 削除 | 一覧の「×」を押すと、確認なしで外す。トーストは「{owner/name} を削除しました」で、「元に戻す」を付ける |

### 名前の変更・移動・削除

プロジェクトのメニュー(開く・Epic を追加・上へ移動・下へ移動・名前を変更…・削除…。上へ移動と下へ移動は 04)と、プロジェクトの設定の画面から操作する。「名前を変更…」は、タイトルを入れるダイアログを開き、概要でのタイトルの変更と同じ検査をする。

**移動**: プロジェクトの設定の「別のワークスペースへ移動」で、プロジェクトを別のワークスペースに移せる。移す先は同じ Store でも別の Store でもよい。候補は、自分以外のワークスペースのうち、書き込める Store にあり、非表示でないものである。

- 確認ダイアログの本文は、「「{タイトル}」を {移動元} から {移動先} へ移動します。N 件のアイテムは {接頭辞 または #} の番号になります。」である。削除済みのアイテムがあるときは、「削除済みの M 件も一緒に移ります。」を続ける。
- 移動先に同じ名前のプロジェクトがあるときは、「{移動先} には同じ名前のプロジェクトがあります」と表示して断る。
- プロジェクトの下のすべてのアイテム(削除済みを含む)が一緒に移る。各アイテムの扱いは、アイテムを別のワークスペースへ移すときと同じである。値の引き直し、新しい番号、スプリントとリリースを外すこと、別の Store へ移すときの関連の解除を含む。親子の関係は変わらない。
- 移動元の Store に転送記録を残し、旧 ID から辿れる。プロジェクトの履歴には、「{移動元のワークスペース名} から移動」と残る。
- 別の Store への移動は、Store ごとに 1 回ずつ保存し、元に戻すときは 2 回をまとめて戻す。アクティビティには「プロジェクト「{タイトル}」を {移動元} から {移動先} へ移動」と残る。
- トーストは「{移動先} へ移動しました」で、「元に戻す」を付ける。通知は出ない。

**削除**: プロジェクトの削除は論理削除である。設定の「削除」から、確認ダイアログを出す。

| 部分 | 内容 |
|---|---|
| タイトル | 「プロジェクトを削除」 |
| 本文 | 「「{タイトル}」と、その下の N 件のアイテムを削除します。」 |
| 補足 | 「設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」 |
| ボタン | 「削除」(危険な操作の見た目)と「キャンセル」 |

- プロジェクトと、その下のすべてのアイテムを、同じ 1 回の削除として消す。復元は、この削除の単位で行う(08)。
- そのプロジェクトの画面を開いていたら、ワークスペースの概要に移る。
- アクティビティには「プロジェクト「{タイトル}」を削除」と残る。トーストは「プロジェクトを削除しました」で、「元に戻す」を付ける。

## コマンドパレット

Ctrl+K(Cmd+K)で開く。ダイアログを開いていても開く。入力欄は 1 つで、プレースホルダは「ID・タイトル・コマンドを入力」。下端に「↑↓ で選択 ・ Enter で開く ・ Esc で閉じる」と添える。1 文字入れるごとに候補を更新し、選択を先頭に戻す。

候補は次のとおり。

| グループ | 内容 | 出る条件 |
|---|---|---|
| コマンド | 新規作成(ヒントは C)、マイタスクを開く、受信箱を開く、アクティビティを開く、検索を開く、設定を開く、すべての Store を同期、元に戻す(ヒントは Ctrl Z)、ワークスペースを追加 | 入力が空のときは全部。入力があるときは、名前に入力を含むもの(大文字小文字を区別しない) |
| アイテム | ID(小文字で比べる)またはタイトルに、入力を含むもの。ヒントにプロジェクト名を添える。旧 ID も対象にし、旧 ID で見つかったものには「旧 ID」と添える | 入力があるとき。削除済みのアイテムと、非表示の Store のアイテムは出さない |
| プロジェクト | タイトルに入力を含むもの。ヒントにワークスペース名を添える | 入力があるとき。削除済みのプロジェクトと、非表示の Store のプロジェクトは出さない |
| ワークスペース | 名前または接頭辞に入力を含むもの。ヒントに Store 名を添える | 入力があるとき。非表示の Store のワークスペースは出さない |
| ビュー | 名前に入力を含むもの。ヒントに Store 名を添える | 入力があるとき |

候補は、全体で先頭の 40 件に絞り、グループごとに見出しを付ける。

| 操作 | 動作 |
|---|---|
| ↑ ↓ | 選択を動かす。端で止まる |
| Enter または クリック | 選んだ候補を実行する |
| Esc または 背景のクリック | 閉じる |

候補を実行したときの動作は次のとおり。

| 候補 | 動作 |
|---|---|
| アイテム | 詳細パネルを開く |
| プロジェクト・ワークスペース | それぞれの概要を開く |
| ビュー | そのビューを開く |
| 新規作成 | 作成ダイアログを開く |
| すべての Store を同期 | 06 の「すべて同期」を実行する |
| 元に戻す | 01 の「元に戻す」を実行する |
| ワークスペースを追加 | ワークスペースの追加ダイアログを開く。Store が 1 つもないときは「先に Store を追加してください」と表示する |

一致する候補が 1 つもないときは、「一致するものはありません」と出す。パレットを開く操作は、Store を変えないので、保存にもアクティビティにも残らない。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
