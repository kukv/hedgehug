# hedgehug 機能仕様 05: 計画とレポート

ワークスペースの計画は、バックログでアイテムを並べてスプリントに入れ、スプリントを実行して完了し、リリースでまとめて出す流れで進む。この文書は、その画面の振る舞いと、レポートに出る数値の定義を定める。用語、ID、日付、閲覧のみの Store は 01 に従う。

## この文書の範囲

扱うのは、ワークスペースのタブのうち、バックログ・スプリント・リリース・レポートと、概要にある「{スプリント名} の完了ポイント」のカードである。アイテム自体の操作と詳細パネルは 02、ワークスペースの設定(ステータスの分類を含む)は 03、検索・一括変更・テーブルのスプリント列は 04、同期と通知は 06 に定める。スプリントとリリースを操作できる人は 01 に従う。

## 数え方の共通ルール

バックログ、スプリント、リリース、レポートは、次の同じ数え方を使う。

- **作業項目**: Story・Task・Bug。スプリントとレポートの対象は作業項目だけで、Epic と Step は数えない。削除済みのアイテムは数えない。
- **分類**: ステータスが属する未着手・進行中・完了・中止の 4 つ(03)。未完了は未着手と進行中を指す。
- **ポイント**: ポイントが未設定の作業項目は 0 pt として足す。件数には 1 件として数える。
- **中止の除外**: 分類が中止の作業項目は、進捗・バーンダウン・ベロシティ・リリースの集計から、件数、ポイント、分母のすべてで外す。中止を完了とも未完了とも数えない。累積フロー図だけは、中止の層を別に出す。ただし、見積もりと実績(後述)は中止のアイテムも含める。一覧やスプリントのアイテム欄には、中止のアイテムも表示する。
- **日の終わり時点**: レポートで「ある日の状態」と書いたものは、その日の 24 時(このマシンの時刻帯)の時点の状態を指す。作成前のアイテムは、その日にはないものとして扱う。ステータスの分類は、現在のワークスペースの設定で決める。設定にないステータスは未着手として扱う。

## バックログ

バックログの画面は、上にスプリント、下にバックログを並べる。

### 並びと表示

- 上に並べるのは、完了していないスプリント(実行中と計画中)である。実行中を先頭に置き、計画中は開始日の早い順に並べる。期間未定のものは最後にする。同じ日付や期間未定どうしは名前の昇順にする。
- 各スプリントの枠には、名前、状態(「実行中」または「計画中」)、期間(未定なら「期間未定」)、「N 件 · X pt」、ゴールがあれば「ゴール: …」を表示する。N と X は中止を除いて数え、完了したアイテムは含める。枠のアイテムは並び順どおりに表示し、完了と中止のアイテムも含む。
- 枠が空のときは「バックログからここにドラッグ、または行の「スプリント」で選択」と表示する。
- 下の「バックログ」の枠には、同じワークスペースの作業項目のうち、スプリントに入っておらず、分類が未着手か進行中のものを、並び順に表示する。プロジェクトは問わない。見出しの横に「N 件 · X pt · スプリントに入っていない未完了の Story・Task・Bug」と表示し、空なら「バックログは空です」と表示する。
- スプリントに入っていない完了・中止のアイテムは、バックログにも出ない。検索(04)で探す。完了や中止のアイテムをスプリントからバックログへ移すと、そのアイテムはこの画面から消える。
- 利用者の操作でアイテムがバックログの枠から消えるときだけ、トーストで「{ID} は{分類}のため、バックログには表示されません」と知らせる(分類は「完了」「中止」。例: 「HH-31 は完了のため、バックログには表示されません」)。出す場面は、行のステータスのメニュー、バックログから開いた詳細パネルのステータス、完了・中止のアイテムをスプリントの枠からバックログへ移す操作である。一括変更では、結果のトースト(04)に「。{K} 件は完了のため、バックログには表示されません」を続ける(K は完了・中止になってバックログに出ない件数。完了と中止が混じるときは「完了・中止のため」)。同期で受け取った変更と自動化の変更では出さない。スプリントの枠の中では完了・中止のアイテムも表示されるので、トーストは出さない。
- 下の枠の見出しに、「スプリントを作成」と「作成」のボタンを置く。「スプリントを作成」は後述の作成ダイアログを開く。「作成」は作成ダイアログ(02)を、ワークスペースと種類 Story を決めて開く。バックログから作ったアイテムは、バックログの末尾に入る。作成ダイアログのスプリントの初めの値は、どの入口から開いても「バックログ」である。スプリントの枠に「作成」のボタンはない。入れたいスプリントは、ダイアログのセレクトで選ぶ。

### 行

行には、選択のチェック、ドラッグの持ち手、種類、ID、タイトル、優先度、ステータス、ポイント、担当者、スプリントの選択、「上へ」「下へ」を並べる。選択と一括変更は 04 に従う。

- タイトルを押すと詳細パネルを開く(02)。ステータスを押すとステータスのメニューを開く(02)。
- ポイントはその場で入力して保存する。入力できる値は 02 のポイントの規則に従う。
- 「スプリント」の選択肢は、「バックログ」と、完了していないスプリントすべてである。同じ値を選んだときは何もしない。
- 「上へ」「下へ」は、同じ枠の中で隣の行と順番を入れ替える。先頭の行の「上へ」と末尾の行の「下へ」は無効にする。

### 並び順

作業項目の並び順は、ワークスペースの中で 1 本にそろえる。バックログと各スプリントの枠は、その順番から該当するアイテムを取り出して表示したものである。

- 作業項目を作ったとき、順番の末尾に入る。
- 並べ替えで動くのは、動かしたアイテム 1 件だけである。ほかのアイテムどうしの前後は変わらない。
- 行にドロップしたとき、そのアイテムはドロップ先の行のすぐ前に入る。ドロップ先の枠がスプリントなら、アイテムはそのスプリントに入る。バックログの枠なら、スプリントから外れる。
- 枠の空いた部分にドロップしたとき、スプリントの選択を変えたとき、またはスプリントの完了で移るときは、そのアイテムは移動先の枠の末尾に入る。完了で複数の未完了が移るときは、いまの並び順のまま順番を保って末尾に続ける。移動先がバックログのときも、並びの末尾に入る。
- 同じ位置へのドロップは何もしない。
- 順位が同じアイテムは、作成の保存が早い方が先、同じなら内部 ID の辞書順に並べる。全員の画面で同じ並びになる。
- ドラッグはマウスとタッチの両方で動く。ドラッグでできることは、「スプリント」の選択と「上へ」「下へ」でもできる(01)。

### 完了したスプリントへは入れられない

完了したスプリントにアイテムを入れる操作は、バックログの選択・ドラッグ、詳細パネル、テーブルのセルのどの経路でも断る。表示は「完了したスプリントには入れられません」とする。選択肢には、完了したスプリントを出さない。一括変更(04)も、選択肢に完了したスプリントを出さないので、入れられない。ただし、すでにそのスプリントに入っているアイテムの選択肢には、そのスプリントを残す(アイテムを別のスプリントやバックログへ移すことはできる)。Epic と Step はスプリントに入れられない。

### 記録

| 操作 | 記録される説明 |
|---|---|
| 並べ替え | `{ID} の順位を変更` |
| スプリントの変更(ドラッグ・選択) | `{ID} の スプリント を {スプリント名 または バックログ} に変更` |

行にドロップしてスプリントが変わるときは、アクティビティには「{ID} の順位を変更」の 1 行だけが残り、アイテムの履歴にはスプリントの変更が残る。それ以外は、どちらもアクティビティに残る。アイテムの履歴には、スプリントの変更は残り、並べ替えは残らない。

## スプリント

スプリントは、期間を決めて作業項目をまとめる単位である。ワークスペースが持ち、状態は計画中・実行中・完了の 3 つになる。

### 状態と制約

| 状態 | 内容 | できる操作 |
|---|---|---|
| 計画中(planned) | 作ったばかりの状態。期間は未定でもよい | 編集、開始、削除、アイテムの出し入れ |
| 実行中(active) | 開始した状態。開始日と終了日がある | 編集、完了、アイテムの出し入れ。削除はできない |
| 完了(closed) | 完了した状態。開始日と終了日がある | 編集、削除。アイテムを入れることはできない |

- 1 つのワークスペースで、実行中にできるスプリントは 1 つである。実行中があるあいだは、ほかのスプリントを開始できない。
- 終了日が過ぎても、スプリントは自動では完了しない。実行中のまま残る。
- 完了したスプリントを、再び実行中や計画中に戻す操作はない。
- スプリントの期間は重なってよい。名前は同じワークスペースの中で重複できない。
- 実行中と完了のスプリントは、開始日と終了日を空にできない。

### 作成と編集

スプリントを作成するダイアログ(「スプリントを作成」)と、編集するダイアログ(メニューの「編集…」)は、同じ項目を持つ。タイトルは「スプリントを作成」「スプリントを編集」、ボタンは「作成」「保存」である。

| 項目 | 内容 |
|---|---|
| 名前 | 必須 |
| 開始日・終了日 | 計画中のスプリントは、どちらも空にできる(期間未定) |
| ゴール | 任意の 1 行 |

作成時の既定値は次のとおり。

- 開始日: 終了日のあるスプリントのうち、終了日が最も遅いものの終了日の翌日。終了日のあるスプリントがなければ今日。
- 終了日: 開始日の 13 日後(14 日間)。
- 名前: 開始日の基準にしたスプリントの名前が数字で終わるとき、その数字に 1 を足した名前(`Sprint 7` なら `Sprint 8`)。そうでなければ `Sprint {スプリントの数 + 1}`。この名前が既存のスプリントと重なるときは、重ならなくなるまで数字を 1 つずつ進める(`Sprint 7` が基準で `Sprint 8` があれば `Sprint 9`。`Sprint 9` もあれば `Sprint 10`)。重なりの比べ方は下の検査と同じである。

入力の検査は次のとおり。最初に当たったものを表示して、保存しない。名前の比べ方は 03 に従う。保存する名前は、前後の空白を除いた形にする。計画中のスプリントは、未来の開始日を許す。

| 条件 | 表示 |
|---|---|
| 名前が空(前後の空白を除く) | 名前を入力してください |
| 同じ名前のスプリントがある(自分を除く) | 同じ名前のスプリントがあります |
| 実行中・完了のスプリントで、開始日か終了日が空 | 実行中のスプリントには開始日と終了日が必要です |
| 開始日と終了日があり、終了日が開始日より前 | 終了日は開始日以降にしてください |
| 実行中・完了のスプリントで、開始日が今日より後 | 開始日は今日以前にしてください |

編集は、どの状態のスプリントでもできる。完了したスプリントの期間や名前を変えても、確定値(後述)は変わらない。実行中のスプリントの期間を変えると、バーンダウンの日付の範囲が変わる。

### 開始

計画中のスプリントの「開始」を押すと、開始のダイアログを開く。実行中のスプリントがあるときは、ダイアログを開かずに「実行中のスプリントがあります。先に完了してください」と表示する。

- 本文は「{N} 件・{X} pt で始めます。」とし、N と X は中止を除いて数える。0 件でも開始できる(途中でアイテムを足せるため。本文は「0 件・0 pt で始めます。」)。
- 開始日の既定は今日とする。終了日の既定は、スプリントの終了日が今日以降ならその日、なければ今日の 13 日後とする。
- 開始日と終了日は必須である。空のときは「開始日と終了日を入力してください」、終了日が開始日より前のときは「終了日は開始日以降にしてください」と表示する。開始日は過去の日付にできるが、今日より後にはできない(表示は「開始日は今日以前にしてください」)。開始日と終了日が同じ日は認める。
- ボタンは「開始」。成功すると状態が実行中になり、「{名前} を開始しました」と表示する。

バックログの画面でもスプリントの画面でも、計画中のスプリントに「開始」を常に表示し、実行中のスプリントがあるときは無効にして「実行中のスプリントを先に完了してください」と添える。

### 完了

実行中のスプリントの「完了…」を押すと、完了のダイアログを開く。

- 0 件でも完了できる。本文は「完了 {X} 件・未完了 {Y} 件です。」とする。中止のアイテムがあるときは、「中止 {Z} 件はスプリントに残り、集計には含めません。」を続ける。
- 未完了が 1 件以上あるときだけ、「未完了の {Y} 件の移動先」を選ばせる。選択肢は、計画中のスプリント(開始日の早い順、期間未定は最後)と「バックログ」である。既定は、計画中のスプリントがあれば開始日が最も早いもの、なければ「バックログ」とする。
- ボタンは「完了」。1 回の保存で、次のことを行う。
  - スプリントの確定値を記録する。
  - 未完了のアイテムを移動先の枠の末尾へ、順番を保って移す。移動したアイテムには、スプリントの変更が履歴に残る。
  - 完了と中止のアイテムは、スプリントに残す。
  - 削除済みのアイテムには触らない。参照はそのままで、件数・ポイント・移動先の数にも入れない。
  - 状態を完了にする。
  - 「{名前} を完了しました」と表示する。

**確定値**は、完了のときに記録する、そのスプリントの計画と実績である。ポイントと件数のそれぞれについて、次の 2 つを持つ。

| 確定値 | 定義 |
|---|---|
| 計画(committed) | 開始日の終わり時点でスプリントに入っていた作業項目(中止を除く)の合計。開始日が今日より後のとき(同期で届いた場合)は、今日の終わり時点で数える |
| 実績(completed) | 完了の操作の時点で、スプリントに入っていた作業項目のうち、分類が完了のものの合計(中止を除く) |

確定値は、スプリントの途中で足したり外したりしたアイテム、完了後のアイテムの変更、スプリントの編集のどれにも影響されない。ベロシティは確定値を使う。計画がスプリントの開始時点の量になるので、途中で足したアイテムは実績にだけ入り、計画には入らない。

### 削除

メニューの「削除…」から削除する。実行中のスプリントは無効にし、「実行中は削除できません」と添える。計画中と完了のスプリントは削除できる。

- 確認ダイアログは、タイトル「スプリントを削除」、本文「「{名前}」を削除します。」に続けて、アイテムが入っているときは「入っている {N} 件はスプリントから外れます。未完了のものはバックログに戻ります。」と表示する。さらに「設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」を添える(N はその Store の削除済みの保持日数)。ボタンは「削除」で、危険な操作の見た目にする。
- 削除は論理削除である。削除したスプリントは設定の「削除済み」に行として出て、保持日数を過ぎると自動で完全に削除される(08)。
- 削除すると、入っているすべてのアイテム(完了・中止を含む)からスプリントが外れる。削除済みのアイテムは数えず、参照も変えない。アイテムの履歴には、スプリントの変更が 1 件ずつ残る。「スプリントを削除しました」と表示する。
- 完了したスプリントを削除しているあいだは、そのスプリントのベロシティとバーンダウンは見られない。
- 「削除済み」から復元すると、スプリントが戻り、同じ削除操作でスプリントから外れたアイテムも戻る。ただし、そのあとに別のスプリントに入れたアイテムは戻さない。同じワークスペースに同じ名前のスプリントがあるときは「復元」を無効にし、「同じ名前のスプリントがあります。先にそのスプリントの名前を変えてください」と添える。

### 同期で実行中が 2 つになったとき

別の人が同じワークスペースで別のスプリントを開始し、同期で実行中のスプリントが 2 つ届くことがある。このとき、開始日が最も早いスプリントを実行中のままにして、ほかを計画中に戻す。開始日が同じときは、開始の保存時刻が早いほうを残す。それも同じときは、開始した人のログイン名の辞書順が早いほう、さらに同じならコミットの SHA の辞書順が早いほうを残す。実行中が 3 つ以上届いたときも、この順で先頭の 1 つだけを残し、ほかのすべてを計画中に戻す。計画中に戻したスプリントは、開始日と終了日をそのまま持つ。戻したことは、同期の修復の通知で知らせる(06)。どのマシンでも同じ結果になる。

### 同期で同じ項目を変えたとき

スプリント・リリースは、同期で同じ項目を別の値に変えたときも、アイテムと同じく項目ごとの後勝ちで合わせる。編集と削除が重なったときは、編集を残して削除を取り消す。負けた人には「上書き」の通知を作る(06)。

### 同期で名前が重なったとき

同期の結果、同じワークスペースに同じ名前のスプリントが 2 つ届くことがある。このとき、あとから同期した方の名前の末尾に「 (2)」を付ける。すでにあれば (3)、(4)…とする。直した保存は「同期の修復」として、実行者を「同期」として記録する(06)。リリースの名前も同じである。

### 同期で完了したスプリントに未完了のアイテムが入ったとき

完了したスプリントに、同期で未完了のアイテムが入ってくることがある(別の人が、そのスプリントの完了の前に入れていたときなど)。このとき、そのアイテムをバックログへ戻す。確定値は変えない。直した保存は「同期の修復」として記録し、アイテムをスプリントに入れた人に通知する(06)。

### 存在しないスプリントとリリースの参照

アイテムが、存在しないスプリントやリリースを指していることがある(同期で相手が削除したときなど)。その参照は、スプリントなら「バックログ」、リリースなら「なし」として扱う。スプリントなら、未完了のアイテムはバックログに出る。この状態は診断で検出し、修復できる(08)。削除済みのアイテムを「削除済み」から復元するときも、入っているスプリントが完了済みで分類が未着手か進行中なら、スプリントを「バックログ」にして戻す(完了・中止のアイテムは完了済みのスプリントに残す)。入っているスプリントが削除済みか存在しないときも「バックログ」、リリースが削除済みか存在しないときは「なし」にして戻す(アーカイブのリリースはそのまま残す)。詳しい扱いは 08 に従う。

## スプリントの画面

スプリントの画面は、実行中・計画中・完了の順に、状態の見出しの下へカードを並べる。該当するスプリントがない状態の見出しは出さない。スプリントが 1 つもないときは、「スプリントはまだありません」と「期間を決めて Story・Task・Bug をまとめると、バーンダウンとベロシティが見られます。」を、「スプリントを作成」のボタンとともに表示する。右上にも「スプリントを作成」のボタンを置く。

カードの並びは、計画中を開始日の早い順(期間未定は最後)、完了を終了日の新しい順とする。同じ日付は名前の昇順にする。

カードの内容は次のとおり。

| 項目 | 内容 |
|---|---|
| 見出し | 名前。実行中は、状態に応じたピルを添える(下記) |
| 期間 | 「開始日 〜 終了日」。未定なら「期間未定」 |
| ボタン | 計画中は「開始」、実行中は「完了…」。メニュー(後述) |
| ゴール | あれば「ゴール: …」 |
| 進捗 | 完了ポイントの割合を示すバーと、「{完了} / {全体} 件 · {完了} / {全体} pt」。中止を除いて数える。完了したスプリントには、「 · 確定 {実績}/{計画} pt」を続ける。全体が 0 のときは割合を 0% としてバーを空にし、「0 / 0 件 · 0 / 0 pt」と表示する |
| アイテム | 「アイテム {N} 件」の折りたたみ。実行中のカードだけ開いた状態にする。完了と中止のアイテムも含める。並びはワークスペースの並び順(バックログの枠と同じ)で、完了したスプリントも同じ |

実行中のピルは、終了日が今日以降なら「残り {N} 日」、終了日を過ぎていたら「期限を過ぎています」とする。N は、終了日と今日の日数の差に 1 を足した数で、終了日の当日は「残り 1 日」になる。

完了したスプリントでは、未完了のアイテムが完了のときに移動済みなので、バーと件数は完了したアイテムだけを数える。計画との比較は「確定」の値で見る。

アイテムの行には、種類、ID、タイトル(押すと詳細パネル)、ポイント、ステータス、担当者を表示する。この行に並べ替えの操作(ドラッグ・「上へ」「下へ」)は付けない。並べ替えはバックログの画面で行う。アイテムがなければ「ありません」と表示する。

カードのメニューは次の 3 つである。

| 項目 | 内容 |
|---|---|
| 編集… | 編集のダイアログを開く |
| バーンダウンを見る | レポートのタブへ移り、そのスプリントを選んだ状態にする。計画中のスプリントでは無効にし、「計画中のスプリントにはバーンダウンがありません」と添える |
| 削除… | 前節のとおり。実行中は無効 |

ワークスペースの見出しには、実行中のスプリントがあるとき、「実行中: {名前}({開始日}〜{終了日})」と表示する。

## リリース

リリースは、バージョンのような出荷の単位である。ワークスペースが持ち、名前、予定日、説明、状態を持つ。リリースに入れられるのは、Step を除くアイテム(Epic・Story・Task・Bug)である。入れる操作は、詳細パネルやテーブルのセル、一括変更で行う(02・04)。

### 状態

| 状態 | 表示 | ピルの色 |
|---|---|---|
| unreleased | 未リリース | 青 |
| released | リリース済み | 緑 |
| archived | アーカイブ | 灰 |

どの状態からどの状態へも変えられる。変え方は 2 つある。未リリースのリリースの「リリース済みにする」ボタンと、メニューの「{状態}にする」(現在の状態を除く 2 つ)である。

- リリース済みにするとき、予定日が空なら今日を入れる。ほかの変更で予定日は変えない。
- 未完了の Story・Task・Bug(分類が未着手か進行中)が 1 件以上あるまま、リリース済みにするときは、確認する。タイトルは「リリース済みにする」、本文は「{名前} には未完了のアイテムが {N} 件あります。このままリリース済みにしますか?」、ボタンは「リリース済みにする」である。ほかの状態への変更は確認しない。
- 変更したときは、「{名前} を{状態}にしました」と表示する。
- アーカイブのリリースは、アイテムの選択肢に出さない。ただし、すでにそのリリースに入っているアイテムの選択肢には残す。

### 作成と編集

「リリースを作成」のダイアログと、メニューの「編集…」のダイアログは、同じ項目を持つ。ボタンは「作成」「保存」である。編集は、どの状態でもできる。

| 項目 | 内容 |
|---|---|
| 名前 | 必須。入力欄の例は `v2.1.0` |
| 予定日 | 任意 |
| 説明 | 任意の 1 行 |

検査は、名前が空なら「名前を入力してください」、同じ名前のリリースがあれば(自分を除く)「同じ名前のリリースがあります」である。名前の比べ方は 03 に従い、保存する名前は前後の空白を除いた形にする。新しいリリースの状態は未リリースである。作成したときは「{名前} を作成しました」と表示する。

### 並びと表示

- 並びは、状態(未リリース、リリース済み、アーカイブ)、次に予定日の早い順にする。予定日のないものは、同じ状態の中の最後に置く。同じ予定日は名前の昇順にする。
- カードは、名前、状態のピル、予定日(なければ「日付未定」)、説明、進捗、アイテムの欄を持つ。
- 未リリースで予定日が今日より前のとき、予定日の前に「予定日を過ぎています」を添えて強調する。予定日が今日のときは過ぎていないものとする。
- 進捗は件数で数える。対象は、そのリリースに入っている Story・Task・Bug のうち、分類が中止でないものとする。バーと「{完了} / {対象} 件完了」を表示し、未完了が残るときは「 · 残り {対象 − 完了} 件」を続ける。
- 「アイテム {N} 件」の折りたたみには、Epic を含め、そのリリースに入っているすべてのアイテムを、中止も含めて並べる。なければ「ありません。アイテムの「リリース」で選べます」と表示する。
- リリースが 1 つもないときは、「リリースはまだありません」と「バージョンを作って Epic・Story・Task・Bug をまとめると、何が残っているかが見えます。」を表示する。

### 削除

メニューの「削除…」から削除する。どの状態でも削除できる。

- 確認ダイアログは、タイトル「リリースを削除」、本文「「{名前}」を削除します。」に続けて、アイテムが入っているときは「{N} 件のアイテムからリリースが解除されます。」と表示する。N は、そのリリースに入っているすべてのアイテム(削除済みを除く)の数である。さらに「設定の「削除済み」から戻せます。{N} 日を過ぎると完全に削除されます。」を添える(N はその Store の削除済みの保持日数)。ボタンは「削除」で、危険な操作の見た目にする。
- 削除は論理削除である。削除したリリースは設定の「削除済み」に行として出て、保持日数を過ぎると自動で完全に削除される(08)。
- 削除すると、アイテムからリリースが外れる。削除済みのアイテムは触らず、参照も変えない。アイテムの履歴には、リリースの変更が 1 件ずつ残る。「リリースを削除しました」と表示する。
- 「削除済み」から復元すると、リリースが戻り、同じ削除操作でリリースから外れたアイテムも戻る。ただし、そのあとに別のリリースに入れたアイテムは戻さない。同じワークスペースに同じ名前のリリースがあるときは「復元」を無効にし、「同じ名前のリリースがあります。先にそのリリースの名前を変えてください」と添える。

## スプリントとリリースの記録

| 操作 | 記録される説明 |
|---|---|
| スプリントの作成 | `スプリント「{名前}」を作成` |
| スプリントの編集 | `スプリント「{名前}」を編集` |
| スプリントの開始 | `スプリント「{名前}」を開始` |
| スプリントの完了 | `スプリント「{名前}」を完了` |
| スプリントの削除 | `スプリント「{名前}」を削除` |
| リリースの作成 | `リリース「{名前}」を作成` |
| リリースの編集 | `リリース「{名前}」を編集` |
| リリースの状態の変更 | `リリース「{名前}」を{状態}にする` |
| リリースの削除 | `リリース「{名前}」を削除` |
| スプリントの復元 | `スプリント「{名前}」を復元` |
| リリースの復元 | `リリース「{名前}」を復元` |

スプリントの作成・開始・完了・削除と、リリースの作成・状態の変更・削除では、保存のあとにトーストを出す。トーストにボタンはない。編集はトーストを出さない(01)。

## ワークスペース概要の完了ポイント

ワークスペースの概要にある統計カードのうち、スプリントのカードの定義を次に示す。

- 見出しは「{スプリント名} の完了ポイント」とし、スプリント名は実行中のスプリントの名前にする。実行中のスプリントがないときは「実行中のスプリントなし」とする。
- 対象は、実行中のスプリントに入っている作業項目(Story・Task・Bug)である。Epic と Step は数えず、中止は外す。
- 値は、分類が完了の対象のポイントの合計を、対象全体のポイントの合計で割った形で、「{完了} / {全体} pt」と表示する。ポイントが未設定のものは 0 pt とする。全体が 0 のときは「0 / 0 pt」と表示する。
- 実行中のスプリントがないときは、値に「—」、見出しに「実行中のスプリントなし」と表示する。

## レポート

レポートの画面は、上から順に、単位の選択、バーンダウン、ベロシティ、累積フロー図、サイクルタイム / リードタイム、見積もりと実績を並べる。冒頭に「git 履歴から集計しています。」と表示する。

### 単位と選択

- 単位は「ポイント」と「件数」から選ぶ。既定はポイントである。ポイントを選んでいても、ワークスペースの作業項目にポイントが設定されたものが 1 件もないときは、件数で数え、「ポイントのあるアイテムがないため、件数で数えています」と表示する。
- ポイントで数えるときは、各項目をそのポイント(未設定は 0)で、件数で数えるときは 1 で数える。ラベルは「pt」「件」である。
- 単位を切り替えると、バーンダウンとベロシティの数え方が変わる。累積フロー図は常に件数で数え、サイクルタイム / リードタイムと見積もりと実績は単位の影響を受けない。
- バーンダウンのスプリントは、「スプリントを選択」のセレクトで選ぶ。選択肢は、実行中と完了のスプリントを、開始日の新しい順に並べたものである。計画中のスプリントは出さない。
- 単位とスプリントの選択は、このマシンに保存し、ワークスペースごとに持つ。閲覧のみの Store のワークスペースでも変えられる。保存した選択がないとき、または保存したスプリントがなくなったか計画中のときは、スプリントの選択を次の順で決める。
  1. 実行中のスプリント。
  2. 完了したスプリントのうち、終了日が最も遅いもの(同じ日なら開始日が遅いもの)。
  3. どちらもなければ未選択にして、「スプリントを選んでください」と表示する。

### バーンダウン

選んだスプリントの、残りの作業量の推移を表す。

**日の範囲**: スプリントの開始日から終了日までのすべての日(土日を含む)である。

**スプリントの範囲**: ある日の終わり時点で、そのスプリントに入っていた作業項目である。入れた日と外した日は、アイテムの履歴(スプリントの変更)から決める。過去の日の値も、いまのアイテムの状態から求める。削除済みのアイテムと、別のワークスペースへ移したアイテムは、過去の日も数えない(復元すれば、また数える。種類の変更は作業項目どうしなので影響しない)。確定値は完了のときの値のままである。作成のときにスプリントを選んだアイテムは、作成の時点で入ったものとする。スプリントを削除する操作で外れたアイテムも、外れた日に範囲から出る。ただし、スプリントの完了で次のスプリントやバックログへ移したアイテムは、完了した日の終わりまでは、そのスプリントの範囲に数える。完了による持ち越しが、残りとして見えるようにするためである。

**日ごとの値**: 日 d について、次のとおり。

| 値 | 定義 |
|---|---|
| 総量(d) | d の終わり時点の範囲の作業項目のうち、分類が中止でないものの量の合計 |
| 残り(d) | 総量(d)の対象のうち、d の終わり時点の分類が未着手か進行中のものの量の合計 |
| 理想(k) | 開始日を k = 0 として、総量(開始日) − 総量(開始日) × k ÷ (日数 − 1)。日数が 1 日のときは、その日の値が総量(開始日)になる |

総量は、スプリントの途中で足したり外したり中止したりすると、その日から変わる。理想の線は、開始日の総量から終了日に 0 になる直線で、途中の増減では引き直さない。

**表示する日**: 開始日から、終了日、今日、(完了していれば)完了した日のうち最も早い日までである。未来の日の「残り」の線は引かない。理想の線は終了日まで引く。開始日が今日より後(同期で届いた場合)で表示する日が 0 日のあいだは、グラフの代わりに「開始日({日付})から表示します」と表示する。

**画面の内容**:

- 「総量 {値} {単位}」と「残り {値} {単位}」を表示する。値は、表示する最後の日の総量(d)と残り(d)である。
- 状態の表示は、実行中なら、終了日が今日以降のとき「残り {N} 日」(数え方はスプリントの画面と同じ)、過ぎているとき「期限を過ぎています」とする。完了したスプリントは「完了」とする。
- 完了したスプリントで、総量(開始日)が確定の計画と違うときだけ、グラフの下に「確定の計画 {X} {単位}と開始日の総量が違うのは、完了のあとにアイテムを削除・移動したり、ステータスの分類を変えたりして、いまの状態から数え直しているためです」と表示する。
- 折れ線グラフに、「理想」(点線)と「残り」を描く。縦軸は 0 から切りのよい最大値(1・2・5・10 の倍数)までとし、値がすべて 0 のときは最大値を 1 にし、横軸は日付、「残り」の最後の点には値を添える。凡例を付ける。

### ベロシティ

スプリントごとの計画と実績を、棒グラフで並べて示す。

- 対象は、実行中と完了のスプリントで、開始日の早い順に並べる。
- 完了したスプリントの値は、確定値を使う。「計画」は確定値の計画、「完了」は確定値の実績で、単位に合わせてポイントか件数のどちらかを使う。
- 実行中のスプリントの値は、そのときの履歴から求める。「計画」は、確定値の計画と同じ定義(開始日と今日のうち早い方の日の終わり時点の範囲)で、「完了」は、今日の終わり時点の範囲のうち、分類が完了のものの合計である。
- 棒には値を添え、「計画」「完了」の凡例を付ける。縦軸は、バーンダウンと同じく 0 から切りのよい最大値までとし、値がすべて 0 のときは最大値を 1 にする。
- 開始したスプリントがないときは、「開始したスプリントがありません」と表示する。

**平均**: 見出しの横に、「完了した直近 3 スプリントの平均 {値} {単位}」と表示する。完了したスプリントを開始日の遅い順に最大 3 件取り、それぞれの「完了」の値の平均を、小数第 2 位を四捨五入して小数第 1 位まで表示する。実行中のスプリントは含めない。完了したスプリントが 3 件に満たないときは、あるだけで平均を取る。1 件もないときは「—」と表示する。

### 累積フロー図

作業項目の流れを、日ごとの分類別の件数で積み上げて示す。

- 期間は、今日を含む直近 21 日である(今日の 20 日前から今日まで)。見出しの横に「直近 21 日・件数」と表示する。
- 対象は、ワークスペースの作業項目すべてで、スプリントには関係しない。単位は常に件数である。
- 各日の値は、その日の終わり時点に作成済みの作業項目を、その日の終わり時点の分類で分けた件数である。
- 層は、下から完了、進行中、未着手、中止の順に積む。中止の層を出すのは、この図だけである。凡例の名前は分類の名前(完了・進行中・未着手・中止)とする。
- 縦軸は 0 から、各日の合計の最大値に対する切りのよい最大値までとし、合計がすべて 0 のときは最大値を 1 にする。

### サイクルタイムとリードタイム

作業項目が着手から完了まで、作成から完了までにかかった日数を示す。スプリントやポイントとは無関係で、期間も絞らない。

- 対象は、現在の分類が完了の作業項目である(中止は対象にしない)。
- **完了に到達した時刻**は、ステータスの履歴で、分類が完了以外から完了へ変わった最後の時刻である。完了の分類のステータスどうしの移動は、到達に数えない。履歴に、完了へ到達した記録がないもの(作成のときから完了だったものなど)は、リードタイムにもサイクルタイムにも数えない。
- **着手した時刻**は、完了に到達した時刻の前の区間で、最初に進行中の分類に入った時刻である。区間は、完了の分類から最後に出た時刻(出たことがなければ作成の時刻)から、完了に到達した時刻までとする。たとえば、完了したあとに再び開いて進行中にし、もう一度完了したものは、再び開いた時刻を着手の時刻とする。区間の中に進行中の分類に入った記録がないもの(未着手から直接完了にしたものなど)には、着手の時刻がない。
- リードタイムは、完了に到達した時刻から作成の時刻を引いた日数である。マシンの時計のずれで負になったときは、0 日として数える。
- サイクルタイムは、完了に到達した時刻から着手した時刻を引いた日数である。着手の時刻がないものは数えない。負になったときは、0 日として数える。
- 日数は、24 時間を 1 日とした小数で数える。
- 表示は、それぞれの中央値(件数が偶数なら、中央の 2 つの平均)を、小数第 2 位を四捨五入して小数第 1 位まで、「{値} 日」で示す。対象が 0 件なら「—」と表示する。
- ラベルは、「サイクルタイム 中央値(着手→完了・{N} 件)」と「リードタイム 中央値(作成→完了・{N} 件)」とする。N は、その値に使った件数である。サイクルタイムは、着手の時刻がなくて数えなかったものが 1 件以上あるとき、「(着手→完了・{N} 件、着手を経ていない {M} 件を除く)」とする。

### 見積もりと実績

見積もりのポイントと、実際にかかった作業時間を並べる。

- 対象は、ポイントが設定されている(0 を含む)作業項目のうち、作業時間の記録が 1 件以上あるものである。中止のものも、作業時間は実際にかかったものなので含める。
- 表の列は、アイテム(ID とタイトルのリンク)、見積もり(「{pt} pt」)、作業時間(記録の合計。「{時間} 時間」。表記は 02 の作業時間と同じで、小数第 2 位までとし、末尾の 0 を省く)、時間/pt(作業時間 ÷ ポイントを小数第 2 位を四捨五入して小数第 1 位まで。ポイントが 0 なら「—」)である。行は ID の番号順に並べる。
- 対象がなければ、「ポイントと作業時間の両方があるアイテムがありません。アイテムの「作業時間」で記録できます。」と表示する。

| 中止の扱い | 進捗の分母には入り、バーンダウンの残りでは完了と同じ扱い、ベロシティと累積フロー図では層に入らない。画面ごとに違う | 進捗・バーンダウン・ベロシティ・リリースの集計から、件数・ポイント・分母のすべてで外す。累積フロー図だけ中止の層を出す | 中止したアイテムが進捗を下げないようにするため |
| 完了のダイアログの件数 | 「完了」に中止も含めて数える | 「完了 X 件・未完了 Y 件」に中止を含めず、中止があれば別に知らせる | 中止を完了と数えないため |
| 開始の日付の検査 | 空か、終了日が開始日より前なら「開始日と終了日を正しく入力してください」。未来の開始日も通る | 空と逆転で文言を分ける。逆転は「終了日は開始日以降にしてください」。開始日は今日より後にできない | 日付の範囲の文言を統一(01)し、開始前のスプリントを実行中にしないため |
| 実行中・完了の期間 | 編集で期間を空にできる | 実行中と完了のスプリントは、開始日と終了日を空にできない | バーンダウンの日付の範囲が決まらなくなるため |
| 日付の逆転の文言 | 「終了日は開始日より後にしてください」 | 「終了日は開始日以降にしてください」 | 同じ日を認めているため(01) |
| 完了したスプリントへの追加 | 画面の選択肢には出ないが、禁止の規則はない | どの経路でも断る | 確定したスプリントに量が増えないようにするため |
| 実行中が 2 つ届いたとき | 規則がなく、最初の 1 つだけを実行中として扱う | 開始日が最も早いもの(同じなら開始の保存時刻が早いもの)を実行中に残し、ほかを計画中に戻して通知する | 同期の結果をどのマシンでも同じにするため |
| スプリントの削除の履歴 | アイテムの履歴にスプリントの変更を残さない | アイテムの履歴に 1 件ずつ残す | 完了や並べ替えと同じにして、履歴から範囲を求められるようにするため |
| リリースの削除の履歴 | アイテムの履歴に残さない | アイテムの履歴にリリースの変更を 1 件ずつ残す | スプリントと同じにするため |
| 存在しないスプリントとリリース | 規則がなく、画面が壊れる箇所がある | 「なし」として扱い、診断で検出する | 同期で相手が消えても画面を保つため |
| スプリントの削除の文言 | 「入っている N 件はバックログに戻ります。」 | 「入っている N 件はスプリントから外れます。未完了のものはバックログに戻ります。」 | 完了と中止のアイテムはバックログに出ないため |
| 計画(committed) | 完了の時点のスプリントの全作業項目 | 開始日の終わり時点の範囲 | 計画は開始時点の量であるべきため |
| 実績(completed)と確定値 | ポイントだけを記録する。件数モードでは履歴から再計算する | ポイントと件数の両方を完了のときに記録し、ベロシティはそれを使う | ポイントと件数で定義がずれないようにするため |
| バーンダウンのスプリントの範囲 | 一度でも出入りしたアイテムを、期間のすべての日に数える | その日の終わり時点に入っていたものを数える。総量は日ごとに変わる | スコープの増減を反映するため |
| バーンダウンの理想線 | 全日の総量を使って引く | 開始日の総量から終了日の 0 まで引き、途中で引き直さない | 計画に対する遅れが見えるようにするため |
| 完了による持ち越し | 範囲に残る(履歴の出入りのすべてを数えるため) | 完了した日の終わりまで範囲に数え、持ち越しを残りとして見せる。表示は完了した日までとする | 完了で残りが 0 に見えないようにするため |
| バーンダウンの状態表示 | 実行中以外はリリースの状態名を使って、空になる | 実行中は「残り N 日」、完了は「完了」 | 表示が空になるバグのため |
| バーンダウンを見る | 計画中のスプリントでも選べるが、レポートに出ない | 実行中と完了のスプリントだけ。計画中は無効 | 画面とメニューをそろえるため |
| 期限の日数 | 終了日を過ぎると「残り 0 日」 | 終了日の当日は「残り 1 日」、過ぎたら「期限を過ぎています」 | 当日を含めて数え、遅れを明示するため |
| ベロシティの平均 | 実行中も含めた末尾 3 件。見出しは「直近 3 スプリントの平均」。0 件なら 0 | 完了したスプリントだけの直近 3 件。見出しは「完了した直近 3 スプリントの平均」。0 件なら「—」 | 進行中の途中の値で平均が下がらないようにするため |
| サイクルタイム | 最初の進行中から最後の完了まで。順序が逆になり得る | 最後の完了に至る区間の、最初の進行中から。進行中を経ていないものは対象外とし、除いた件数を併記する | 再び開いたものでも、時間が負にならないようにするため |
| 累積フロー図の層 | 完了・進行中・未着手の 3 層。中止はどの層にもない | 中止を最上段の層として加える | 中止だけは図に出すと決めたため |
| 概要の完了ポイント | Epic を含み得る | 作業項目だけ。中止は外す | スプリント画面と対象をそろえるため |
| リリースの進捗 | Epic・Step を含め、中止は分母に入る | Story・Task・Bug のうち中止でないものの件数 | 進捗の集計から中止を外すため。リリースの進捗は件数を使うと決めたため |
| リリースの並び | 予定日のないものが同じ状態の先頭 | 予定日のないものが同じ状態の最後。同じ予定日は名前の昇順 | スプリントの並びとそろえるため |
| リリースの確認の件数 | Epic を含む未完了の数 | Story・Task・Bug の未完了の数 | 進捗と同じ対象にするため |
| レポートの選択 | 画面を離れると初期値に戻る | ワークスペースごとにこのマシンへ保存する。初期は実行中、なければ終了日が最も遅い完了したスプリント | 毎回選び直さなくてよいようにするため |
| 並べ替えの方法 | ドロップのたびに全アイテムの順位を振り直す | 動かした 1 件だけが動く | 無関係なアイテムの変更を避けるため |
| 枠の空きへのドロップ | 順位を変えず、元の順位の位置に出る | 移動先の枠の末尾に入る | 落とした場所に入るように見せるため |
| 「上へ」「下へ」 | バックログの行だけ | スプリントの枠の行にも付ける。端では無効 | ドラッグで並べ替えられる行に、ボタンの経路を用意するため(01) |
| 開始のボタン | バックログは実行中がないときだけ表示、スプリントの画面は実行中があると無効 | どちらも常に表示し、実行中があると無効にして理由を添える | 操作できない見た目にそろえるため(01) |
| 枠のポイントと件数 | 完了を含み、中止も含む | 完了を含み、中止は除く | 中止を集計から外すため |
| スプリントの画面の並び | 作成した順 | 計画中は開始日の早い順(期間未定は最後)、完了は終了日の新しい順 | 見つけやすくするため |
| 新しいスプリントの名前と開始日 | 終了日のあるものがない場合の規則がない(空の日付で比べる) | 終了日のあるスプリントがなければ今日から始め、名前は `Sprint {数 + 1}` | 規則を決めるため |
| 見積もりと実績の行の順 | 並びの指定がない | ID の番号順 | 規則を決めるため |
| 開始ダイアログの件数 | 「N 件・X pt で始めます」に中止も含める | 中止を除いて数える | 中止を集計から外すため |
| レポートのスプリント選択肢の並び | 作成順 | 開始日の新しい順 | 新しいスプリントを選びやすくするため |
| 完了に到達した時刻 | 最後に完了の分類へ移った記録。完了の分類どうしの移動も数える | 完了以外から完了へ変わった最後の時刻。完了の分類どうしの移動は数えない | 完了後のステータス整理でリードタイムが延びないようにするため |
| トーストの「元に戻す」 | スプリントの開始・完了・削除、リリースの状態の変更・削除、作成のトーストに「元に戻す」を添える | 元に戻す仕組みを持たず、トーストにボタンを添えない | ユーザーの指示(2026-11-12)。管理が複雑になり、誤操作で押したとき何を戻したか分からないため |
| スプリント・リリースの削除 | 確認ダイアログに復元の案内がなく、削除は元に戻すで戻す | 論理削除にして設定の「削除済み」から復元できる。保持日数を過ぎると自動で完全に削除する。確認ダイアログに案内を添える | ユーザーの指示(2026-11-12)。元に戻すをなくしたため、削除をアイテムと同じく復元できるようにする |
| 同期で重なった名前 | 規則がない | あとから同期した方の末尾に「 (2)」を付ける(スプリント・リリース) | ユーザーの指示(2026-11-12)。1 つしかあってはいけないものが 2 つになったときの直し方をそろえるため |
| 完了したスプリントに同期で入った未完了のアイテム | 規則がない | バックログへ戻し、確定値は変えない | ユーザーの指示(2026-11-12)。完了したスプリントに量を増やさないため |
| 同じ日付・期間未定の並び | 決まっていない | バックログとスプリント画面で、名前の昇順 | 表示順を安定させるため |
| 同じ順位の並び | 決まっていない | 作成の保存が早い方が先、同じなら内部 ID の辞書順 | ユーザーの指示(2026-11-12)。同期のあとも全員の画面で同じ並びにするため |
| 実行中・完了の開始日の検査 | 編集では未来の開始日も保存できる | 開始日が今日より後は断る(「開始日は今日以前にしてください」)。計画中は許す | ユーザーの指示(2026-11-12)。開始ダイアログと検査をそろえるため |
| 完了で移すアイテムの位置 | 決まっていない | 移動先の枠の末尾に、順番を保って入れる | ユーザーの指示(2026-11-12)。ドロップや選択の変更と同じにするため |
| 0 件のスプリントと 0 の割合・縦軸 | 決まっていない | 0 件でも開始・完了できる。割合は 0%、縦軸の最大値は 1 | ユーザーの指示(2026-11-12)。途中でアイテムを足せるため。画面を壊さないため |
| 完了のあとの削除・移動とバーンダウン | 決まっていない | いまの状態から数え直し、確定の計画と違うときは注記を出す。確定値は変えない | ユーザーの指示(2026-11-12)。ベロシティの確定値を守りつつ、食い違いの理由を示すため |
| 削除済みのアイテムとスプリント・リリース | 決まっていない | 完了・削除では削除済みに触らず数えない。復元のときは、完了済みや存在しない参照を直して戻す | ユーザーの指示(2026-11-12)。削除済みのものでスプリントやリリースの集計が変わらないようにするため |
| スプリントのアイテムの並び | 決まっていない | ワークスペースの並び順。スプリント画面に並べ替えの操作は付けない | ユーザーの指示(2026-11-12)。バックログの枠と同じ順にするため |
| 新しいスプリントの名前の重なり | 重なっても既定にする | 重ならなくなるまで数字を進める | ユーザーの指示(2026-11-12)。作成を押して断られないようにするため |
| バックログから消えるときのトースト | 知らせない | 完了・中止にした操作で枠から消えるとき、トーストで知らせる | ユーザーの指示(2026-11-12)。元に戻すをなくしたので、何が消えたかを残すため |

| 閲覧のみの Store のレポートの選択 | 決まっていない | 単位とスプリントの選択は変えられる | ユーザーの指示(2026-11-12)。Store に書かないマシンの設定のため |
