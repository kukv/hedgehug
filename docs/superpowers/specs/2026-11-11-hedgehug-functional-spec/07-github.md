# hedgehug 機能仕様 07: GitHub 連携

GitHub のアカウントを登録すると、アイテムを PR や Issue と結び付け、GitHub の Issue を取り込み、チームの Store を GitHub から探せるようになる。登録は任意で、登録しなくても、このマシンの中だけで使う分にはタスク管理のすべてが使える。

用語と、Store で共有するものとマシンごとに持つものの分け方は 01 を参照。詳細パネルのリンクの欄の配置は 02、自動化の定義は 03、同期全体と通知は 06、Store の追加とメンバー一覧の操作は 08 が定める。この文書は、GitHub とのやりとりで利用者に見える振る舞いを定める。

## GitHub を使わない場合

アカウントを 1 つも登録しないとき、次の機能は使えない。使えない入口は無効にし、「GitHub のアカウントを登録すると使えます」と添える。

| 使えないもの | 理由 |
|---|---|
| PR・Issue のリンクの追加、Issue の作成 | GitHub に問い合わせるため |
| Issue の取り込み、Issue の同期 | 同上 |
| PR の状態で動く自動化(PR が Open になったとき、PR がマージされたとき) | PR のリンクを作れないため。ルールの登録はできるが動かない |
| GitHub から Store を検索して追加 | アカウントから見えるリポジトリを探すため |
| GitHub のコラボレーターをメンバーに追加 | 同上 |
| GitHub 上の remote を持つ Store の同期 | 同期に使うアカウントがないため(06) |

次のものは、アカウントがなくても使える。

- アイテム・プロジェクト・ワークスペースの管理、検索、レイアウト、計画、レポート
- remote のない Store(このマシンの中だけで動く)
- すでにリンクされた PR・Issue の表示。Store に保存されたタイトルと状態をそのまま出し、更新はしない

## アカウント

アカウントは、GitHub に接続するときの本人確認の手段を、名前を付けて登録したものである。マシンごとに持ち、Store には保存しない(01)。トークンそのものは保存せず、認証方法だけを記録する。登録・削除・再認証は Store を変えないので、アクティビティには残らず、元に戻せない(01)。

### 登録

設定の「アカウントとメンバー」にある「GitHub アカウント」で「追加」を押すと、「アカウントを追加」ダイアログが開く。ホストは `github.com` に固定する。

| 項目 | 内容 |
|---|---|
| 表示名 | 一覧と各種の選択肢に出す名前。例は「work」 |
| GitHub のログイン名 | GitHub のログイン名 |
| 認証方法 | 次の 4 つから選ぶ。既定は「ブラウザでサインイン(デバイスフロー)」 |

認証方法は次の 4 つである。一覧には「github.com · 」に続けて右の文言を表示する。

| 認証方法の選択肢 | 一覧に出す文言 |
|---|---|
| ブラウザでサインイン(デバイスフロー) | デバイスフローのトークン |
| gh CLI のトークン | gh CLI のトークン |
| 環境変数 | 環境変数 GH_TOKEN |
| OS のキーチェーン | OS のキーチェーン |

入力を確かめる順と、断るときの表示は次のとおり。最初に当てはまったものを表示して、何も登録しない。

| 条件 | 表示 |
|---|---|
| 表示名かログイン名が空 | 表示名とログイン名を入力してください |
| 同じ表示名のアカウントがある | 同じ表示名のアカウントがあります |
| 同じログイン名のアカウントがある(大文字と小文字は区別しない) | 同じログイン名のアカウントがあります |

### 認証の確認

「追加」を押すと、GitHub に問い合わせて、その認証方法で本人確認ができるかを確かめる。確かめられたときだけアカウントを登録し、「アカウントを追加しました」と表示する。確かめられなかったときは、何も登録せず、ダイアログに理由を赤字で出す。

| 認証方法 | 確かめられなかったときの表示 |
|---|---|
| gh CLI のトークン | gh CLI のトークンが見つかりません。端末で `gh auth login` を実行してください |
| 環境変数 | 環境変数 GH_TOKEN が設定されていません |
| OS のキーチェーン | OS のキーチェーンにトークンが見つかりません |
| 共通(トークンが GitHub に拒否された) | トークンが GitHub に受け付けられませんでした。認証方法を確かめてください |
| 共通(トークンのログイン名が入力と違う) | このトークンは @{実際のログイン名} のものです。ログイン名を直してください |
| 共通(通信の失敗) | 「GitHub との通信に失敗したとき」の表示 |

### デバイスフロー

認証方法がデバイスフローのときは、確認の代わりに「GitHub にサインイン」ダイアログを開く。

- 「このコードを GitHub で入力してください。」と、`XXXX-XXXX` の形の 8 文字のコード、「コピー」ボタンを表示する。
- 「https://github.com/login/device を開き、コードを入力して許可します。」と案内し、リンクを添える。
- GitHub で許可されると、ダイアログは自動で閉じ、アカウントを登録して「@{ログイン名} としてサインインしました」と表示する。許可したアカウントのログイン名が入力と違うときは、登録せず、上の表の「トークンのログイン名が入力と違う」の表示を出す。
- 待っているあいだは「許可を待っています」と表示する。
- コードの期限が切れたときは、「コードの期限が切れました」と「再試行」ボタンを表示する。再試行すると新しいコードを出す。GitHub で許可が拒否されたときは、「GitHub で許可が拒否されました」と同じ「再試行」を表示する。

ダイアログを閉じる方法は、「キャンセル」ボタン、Esc、ダイアログの外のクリックのどれでも、アカウントを登録せずに終わる。サインインが済んだときだけ登録するので、サインインの途中のアカウントが一覧に残ることはない。

### 状態

一覧の各行には、表示名、`@ログイン名`、「github.com · {認証方法の文言}」、状態、削除ボタンを表示する。状態は次の 3 つのどれかである。

| 状態 | 意味 | 行の表示 |
|---|---|---|
| 利用可能 | GitHub に接続できる | 緑の「利用可能」 |
| 認証エラー | トークンの失効などで、GitHub に本人確認を拒否された | 赤の「認証エラー」と「再認証」ボタン |
| GitHub App 未導入 | 認証はできるが、ある組織に hedgehug の GitHub App が入っておらず、その組織のリポジトリを読めない | 橙の「GitHub App 未導入」と、組織名、「再確認」ボタン |

認証エラーと GitHub App 未導入の両方に当てはまるときは、認証エラーを表示する。

GitHub App 未導入は、そのアカウントで組織のリポジトリを読もうとして拒否されたときに分かる。分かった組織名は、その組織のリポジトリに問い合わせるたびに確かめ直し、読めたら未導入の記録を外す。組織が複数あるときは、組織ごとに記録する。

GitHub App 未導入のアカウントがあると、アカウント一覧の上に、組織ごとに警告の帯を出す。

> {表示名}: {組織名} に GitHub App が入っていないため、PR と Issue を読めません。

帯には「管理者にインストールを依頼」ボタンがある。押すと、次の依頼文をクリップボードにコピーし、「コピーしました」と表示する。コピーできなかったときは、「コピーできませんでした。文を選択してコピーしてください」と表示し、依頼文を画面に出して選べるようにする。

> {組織名} に hedgehug の GitHub App をインストールしてください(@{ログイン名} が使います)

管理者が GitHub App を入れたあとは、「再確認」を押す。GitHub に問い合わせ、読めたら帯と状態の表示を消す。まだ読めないときは、帯を残す。

### 再認証

認証エラーのアカウントの「再認証」を押すと、登録のときと同じ認証の確認をやり直す。デバイスフローのアカウントは、新しいコードのダイアログを開く。成功すると、状態が「利用可能」に戻り、「{表示名}: @{ログイン名} として再認証しました」と表示する。失敗したときは、登録のときと同じ表示を出し、状態は変えない。

### 削除の影響

アカウントの行のごみ箱ボタンを押すと、「アカウントを削除」の確認ダイアログを開く。本文は次の部品を、当てはまるものだけ、この順につなぐ。

- 「{表示名}」を削除します。
- {Store 名}・{Store 名} の同期に使っているため、それらは同期できなくなります。(remote を持つ Store で、このアカウントを同期に使っているものがあるとき)
- このアカウントを使うリポジトリのルールも削除します。(このアカウントを指すルールがあるとき)

「削除」を押すと、次のとおりになる。完了時に「アカウントを削除しました」と表示する。

- 同期に使っていた Store のアカウントは「なし」になる。その Store は、アカウントを選び直すまで同期できない。表示は 06 に従う。
- このアカウントを指すリポジトリのルールを削除する。
- 「あなた」の決まり方(01)は、アカウントのログイン名の代わりに、このマシンの設定「ログイン名」(08)で探す形になる。
- リンク済みの PR・Issue と、Issue の同期の設定は変わらない。ただし、そのリポジトリを読めるアカウントがなくなれば、状態の更新と同期は止まる(「PR と Issue のリンク」を参照)。

## リポジトリごとのアカウントのルール

設定の「アカウントとメンバー」の「GitHub 連携で使うアカウント」で、リポジトリごとに使うアカウントを決める。GitHub に問い合わせるとき(リンクの取得と更新、Issue の作成・取り込み・同期)は、すべてこのルールで選んだアカウントを使う。

> リポジトリごとに、PR・Issue を読むアカウントを決めます。上のルールから順に当てはめ、どれにも当たらないときは、アイテムがある Store のアカウントで読みます。

### ルールの追加

「ルールを追加」を押すと、「ルールを追加」ダイアログが開く。アカウントが 1 つもないときは、ボタンを無効にする。

| 項目 | 内容 |
|---|---|
| リポジトリ(* を使用できます) | `owner/name` の形のパターン。例は `example-org/*` |
| アカウント | 登録済みのアカウントから選ぶ。「{表示名} (@{ログイン名})」の形で並べる |

パターンが `owner/name` の形でないときは、「owner/name の形式で入力してください(* を使用できます)」と表示して追加しない。形に使える文字は、英数字、`_`、`.`、`-`、`*` である。

追加したルールは、一覧の末尾に加わる。一覧には、パターン、「→ {表示名}」、上へ・下へ・削除のボタンを並べる。ルールがなければ「ルールはありません」と表示する。編集はできない。直すときは、削除して追加し直す。削除に確認は出さない。

### パターンの意味

パターンは、owner と name を、`/` で分けてそれぞれ比べる。

- `*` は、0 文字以上の任意の文字に当たる。`/` には当たらない。1 つのパターンに `*` を何個書いてもよい。
- 英大文字と小文字は区別しない。GitHub がリポジトリ名の大小を区別しないのに合わせる。
- 例として、`example-org/*` は example-org の全リポジトリに、`*/design-tasks` はどの owner の design-tasks にも、`*/*` はすべてのリポジトリに当たる。

### 当てはめの順

リポジトリごとに、次の順で使うアカウントを決める。

1. ルールを上から順に見て、最初に当たったルールのアカウントを使う。順序が意味を持つので、狭いパターンを上に置く。
2. どのルールにも当たらないときは、アイテムがある Store のアカウントを使う。Issue の取り込みはワークスペースがある Store のアカウントを使う。
3. Store にアカウントがないときは、読めるアカウントがないものとして扱い、「GitHub との通信に失敗したとき」の「アカウントがない」を表示する。

当たったルールのアカウントが認証エラーのときは、そのルールを飛ばさず、そのアカウントを使い、認証エラーとして扱う。飛ばして別のアカウントで読むと、意図しない権限で読んでしまうためである。

## GitHub との通信に失敗したとき

GitHub に問い合わせる操作が失敗したときは、何も変えずに、操作したダイアログの中に理由を赤字で出す。同期のあいだの失敗は、ダイアログがないので、リンクの行に出す(「PR と Issue のリンク」の「表示と更新」を参照)。問い合わせているあいだは、操作のボタンを無効にして「GitHub に問い合わせています」と表示する。

| 状況 | 表示 |
|---|---|
| 通信できない | GitHub に接続できません。接続を確かめて、もう一度お試しください |
| 使うアカウントが認証エラー | {表示名}(@{ログイン名})の認証エラーのため、GitHub に接続できません。設定の「アカウントとメンバー」で再認証してください |
| リポジトリを読めない(権限がない、または存在しない) | {リポジトリ} を読めません。リポジトリの権限と、使うアカウントを確かめてください |
| 組織に GitHub App が入っていない | {組織名} に GitHub App が入っていないため、{リポジトリ} を読めません |
| 書き込む権限がない | {リポジトリ} に書き込む権限がありません |
| 番号の PR・Issue がない | {リポジトリ}#{番号} が見つかりません |
| 利用上限に達した | GitHub の利用上限に達しました。{時刻} 以降にもう一度お試しください |
| 読めるアカウントがない | {リポジトリ} を読めるアカウントがありません。設定の「アカウントとメンバー」でアカウントを登録するか、ルールを追加してください |

GitHub はリポジトリがないときと、権限がないときに同じ応答を返すので、この 2 つは区別せず、「リポジトリを読めない」の表示を使う。{時刻} は、利用上限が解除される時刻を、このマシンの時刻で「HH:MM」の形にして出す。解除が翌日以降のときは、日付を前に付ける。

## PR と Issue のリンク

アイテムは、PR と Issue をリンクとして持てる。リンクはアイテムごとに Store に保存し、チームで共有する(01)。1 つのリンクは、種別(PR か Issue)、リポジトリ、番号、タイトル、状態からなる。状態は、PR が Open・Draft・Merged・Closed、Issue が Open・Closed である。

### 追加

詳細パネルの GitHub の欄に、「PR をリンク」「Issue をリンク」「Issue を作成」の 3 つのボタンがある(配置は 02)。「PR をリンク」と「Issue をリンク」は、ダイアログの題名と、確かめる種別が違うだけで、項目は同じである。

| 項目 | 内容 |
|---|---|
| リポジトリ | アイテムが属するプロジェクトのリポジトリがあれば、そこから選ぶ。なければ `owner/name` の形で入力する |
| 番号 | PR または Issue の番号 |
| プロジェクトのリポジトリにも追加する | プロジェクトにリポジトリがなく、入力したリポジトリを使うときだけ出すチェック。既定はオン |

モックにあった「タイトル」と「状態」の入力欄は設けない。「リンク」を押すと、GitHub に問い合わせて、実在の確認とタイトル・状態の取得をする。確かめる順と、断るときの表示は次のとおり。

| 条件 | 表示 |
|---|---|
| リポジトリが `owner/name` の形でない | リポジトリは owner/name の形式で入力してください |
| 番号が正の整数でない | 番号を入力してください |
| このアイテムに同じリポジトリと番号のリンクがある(種別は問わない。リポジトリの大文字と小文字は区別しない) | もうリンクしています |
| GitHub への問い合わせの失敗 | 「GitHub との通信に失敗したとき」の表示 |
| 「PR をリンク」で、番号が Issue だった | {リポジトリ}#{番号} は PR ではなく Issue です |
| 「Issue をリンク」で、番号が PR だった | {リポジトリ}#{番号} は Issue ではなく PR です |
| Issue がすでに別のアイテムにリンクされている | {リポジトリ}#{番号} は {ID} にリンクされています |
| Issue をリンクするアイテムが、すでに別の Issue にリンクしている | このアイテムには Issue がリンクされています |

PR は、同じ PR を複数のアイテムにリンクできる。Issue は、Issue の同期で正本が決まらなくなるのを避けるため、1 つのアイテムに 1 つ、1 つの Issue につき 1 つのアイテムに限る。Issue が別のアイテムにリンクされているかは、このマシンにあるすべての Store の、削除済みを含むアイテムを調べる。

確かめられたら、タイトルと状態を保存してリンクを追加する。ダイアログは閉じ、トーストは出さない。「プロジェクトのリポジトリにも追加する」がオンなら、同じ 1 回の保存で、プロジェクトのリポジトリに加える。

### 表示と更新

リンクの行には、種別と状態を示すチップ、「{リポジトリ} — {タイトル}」、解除ボタンを表示する。リンクがなければ「リンクはありません」と表示する。

リンクのタイトルと状態は、次のときに GitHub から取り直す。

- 詳細パネルを開いたとき。開いたアイテムのリンクを取り直す。
- Store を同期した直後。同期のたびに、その Store のアイテムのリンクのうち、状態が Merged のものを除くすべてを取り直す。Merged の PR は、それ以上状態が変わらないので取り直さない。

取り直した値が保存してある値と違うときだけ、新しい値を保存する。この保存は、操作した人のいない自動の変更として、実行者「GitHub」でアクティビティとアイテムの履歴に残る(06)。複数のマシンが同じ値を書いても、結果は同じである。

取り直しに失敗したときは、保存してある値のまま表示し、その行に、失敗の理由を添える。添える文言は、「状態を更新できませんでした: 」に、「GitHub との通信に失敗したとき」の表示を続けたものである。次の取り直しで成功すれば、添えた文言を消す。

閲覧のみの Store のアイテムのリンクは、取り直さず、保存してある値を表示する(01)。

### 解除

リンクの行の解除ボタンを押すと、確認なしでリンクを外し、「リンクを解除しました」と表示する。元に戻せる(01)。外した Issue は、同期の対象から外れ、取り込み済みの扱いも解け、あらためて取り込める。PR のリンクを外しても、すでに動いた自動化は取り消さない。

### PR の状態で動く自動化

PR のリンクの状態が変わると、そのアイテムで次の自動化のきっかけが起きる。ルールの定義と、実行の規則は 03 が定める。

| きっかけ | 起きるとき |
|---|---|
| PR が Open のとき | PR をリンクして、状態が Open のとき。リンク済みの PR が、Open でない状態から Open に変わったとき(Draft から、または Closed から再び開いたとき) |
| PR がマージされたとき | PR をリンクして、状態が Merged のとき。リンク済みの PR が Merged に変わったとき |

Draft、Closed、Issue では何も起きない。きっかけが起きるのは、そのリンクの更新を実際に保存したマシンだけである。同期で受け取ったリンクがすでに Merged なら、きっかけは起こさない。同じ PR を複数のアイテムにリンクしているときは、アイテムごとにきっかけが起きる。

## Issue の作成

詳細パネルの「Issue を作成」で、アイテムの内容から GitHub に Issue を作り、そのアイテムにリンクする。「GitHub に Issue を作成」ダイアログの項目は次のとおり。

| 項目 | 内容 |
|---|---|
| リポジトリ | プロジェクトのリポジトリから選ぶ。プロジェクトにリポジトリがなければ、`owner/name` の形で入力する |
| タイトル | 初期値はアイテムのタイトル |
| 本文 | 初期値はアイテムの説明 |
| プロジェクトのリポジトリにも追加する | プロジェクトにリポジトリがなく、入力したリポジトリを使うときだけ出すチェック。既定はオン |

ダイアログには「作った Issue はこのアイテムにリンクされます。」と添える。

「作成」を押すと、次の順に確かめる。

| 条件 | 表示 |
|---|---|
| リポジトリが `owner/name` の形でない | リポジトリは owner/name の形式で入力してください |
| タイトルが空 | タイトルを入力してください |
| このアイテムに Issue がすでにリンクされている | このアイテムには Issue がリンクされています |
| GitHub への問い合わせの失敗(書き込む権限がない場合を含む) | 「GitHub との通信に失敗したとき」の表示 |

作れたら、GitHub が付けた番号の Issue を、状態 Open でアイテムにリンクし、「{リポジトリ}#{番号} を作成しました」と表示する。リンクの追加と、チェックがあればプロジェクトのリポジトリへの追加は、1 回の保存である。

GitHub に送るのは、タイトルと本文だけである。担当者とマイルストーンは、Issue の同期が push になっていれば、次の同期で送る。ラベルは送らない。

## Issue の取り込み

GitHub の Open の Issue から、Story・Task・Bug を作る。入口は 2 つある。

- ワークスペースの設定の「GitHub Issue」タブの「Issue の取り込み」。作成先のプロジェクトと親の Epic を選べる。
- Epic の詳細パネルの「Issue から作る」(配置は 02)。作成先は、その Epic と、その Epic のプロジェクトに固定する。リポジトリは、そのプロジェクトのリポジトリから選ぶ。1 つならそれに固定し、複数ならダイアログの中で選べて、既定は先頭にする。

どちらも、アカウントが 1 つもないとき(「GitHub のアカウントを登録すると使えます」と添える)、またはワークスペースの Store が閲覧のみのとき(「閲覧のみの Store です」と添える)は、入口を無効にする。Epic の入口は、そのプロジェクトにリポジトリが 0 件のときも無効にし、「プロジェクトにリポジトリがありません。プロジェクトの概要で追加してください」と添える。設定のタブの入口は、リポジトリがないときの案内を前節に定めた。

### ワークスペースの設定のタブ

タブの「Issue の取り込み」には、次の説明を表示する。

> GitHub の開いている Issue から、Story・Task・Bug を作ります。取り込むのは Open の Issue だけで、タイトル・本文・担当者・マイルストーンを写します。ステータスは初期ステータスになり、作ったアイテムは Issue とリンクされます。担当者はログイン名、マイルストーンはリリースと名前で合わせ、合うものがなければ空にします。

その下に、リポジトリのセレクトと「取り込む Issue を選択…」ボタンを置く。セレクトの選択肢は、このワークスペースのプロジェクトのリポジトリを、重複を除いて並べたものである。選んだリポジトリは、画面の状態としてこのマシンに覚え、次に開いたときの初期値にする。Store には保存しない。プロジェクトにリポジトリが 1 つもないときは、セレクトとボタンの代わりに、「取り込めるリポジトリがありません。プロジェクトの概要で「リポジトリを追加」してください」と赤字で表示する。

### 取り込みのダイアログ

題名は「{リポジトリ} の Issue を取り込む」で、{リポジトリ} は選択中のものである。Epic からの入口で、リポジトリが複数あるときは、項目の先頭に「リポジトリ」のセレクトを置く。項目は次のとおり。

| 項目 | 内容 |
|---|---|
| 作成先のプロジェクト | 既定は、選んだリポジトリを持つ最初のプロジェクト。なければワークスペースの最初のプロジェクト。Epic からの入口では固定 |
| 親の Epic | 既定は、作成先のプロジェクトの最初の Epic。プロジェクトを変えたら、その最初の Epic に戻す。Epic がなければ、セレクトの代わりに「Epic がありません」と赤字で表示する。Epic からの入口では固定 |
| 種類 | Story・Task・Bug から 1 つ。既定は Bug。選んだ種類で、選んだ Issue をすべて作る |
| GitHub のラベルで絞り込む | 「すべて」と、リポジトリのラベルの一覧から 1 つ選ぶ |

Issue の一覧は、Open の Issue を、作成日の新しい順に 100 件ずつ表示する。続きは、一覧の末尾の「さらに読み込む」で読み込む。PR は Issue ではないので、一覧に出さない。ラベルを選ぶと、そのラベルが付いた Open の Issue だけを一覧にする。ラベルを変えたときは、選択をすべて外す。ラベルは絞り込みにだけ使い、作るアイテムには写さない。

一覧の各行には、次を表示する。

- チェックボックス。取り込み済みの Issue は、チェックボックスの代わりに、灰色の「取り込み済み」を出し、選べなくする。
- `#番号`、タイトル、ラベル。
- 担当者(「@ログイン名」。担当者がなければ「担当なし」。複数なら先頭の人の後ろに「ほか N 人」を添える)、マイルストーン(「 · 」で続ける)。

一覧に出る Issue がなければ「一致する Issue はありません」と表示する。一覧の取得に失敗したときは、「GitHub との通信に失敗したとき」の表示を、一覧の位置に赤字で出す。

取り込み済みの判定は、そのリポジトリと番号の Issue をリンクに持つアイテムが、このマシンにあるどこかの Store に 1 つでもあるかどうかである。削除済みのアイテムも、別のワークスペースのアイテムも数える。削除済みを数えるのは、復元でリンクが戻るためである。

ボタンは「N 件を取り込む」である。選択が 0 件のとき、または親の Epic がないときは、無効にする。

### 作られるもの

「N 件を取り込む」を押すと、選んだ Issue 1 件につき 1 つのアイテムを、選んだ種類で、親の Epic の下に作る。全件で 1 回の保存である。押したときに、選んだ Issue を 1 件ずつ GitHub で確かめ直す。一覧を出したあとに、他のアイテムにリンクされた、閉じられた、見つからなくなった Issue は、作らずに残りを作る。作ったあとは、ダイアログの中に結果を出す。

- すべて作れたとき: 「N 件を取り込みました」を表示してダイアログを閉じる。
- 作れなかったものがあるとき: ダイアログを開いたまま、「N 件を取り込みました。M 件は取り込めませんでした: #12(閉じられています)、#15(見つかりません)」の形で表示する。理由は、「閉じられています」「{ID} にリンクされています」「見つかりません」のどれかである。作れた Issue は、一覧で「取り込み済み」に変わる。
- GitHub への通信に失敗したとき: 1 件も作らず、「GitHub との通信に失敗したとき」の表示を出す。

作った分は、全件で 1 回の保存である(01)。取り込みは作成なので、元に戻す対象にしない(01)。担当者が入ったアイテムの割り当て通知は、アイテムを作ったときの通常の規則で出る(06)。

| アイテムの項目 | 値 |
|---|---|
| タイトル | Issue のタイトル |
| 説明 | Issue の本文(空なら空) |
| ステータス | ワークスペースの初期ステータス。遷移の制約は検査しない |
| 優先度 | ワークスペースの初期優先度 |
| 担当者 | Issue の担当者を並び順に見て、最初にメンバーのログイン名と一致した人(大文字と小文字は区別しない)。一致する人がなければ空 |
| リリース | Issue のマイルストーンと名前が一致するリリース(大文字と小文字は区別しない。アーカイブしたリリースは対象にしない)。なければ空。リリースは作らない |
| リンク | Issue。状態は Open |

ラベル、PR、コメントは写さない。取り込みは、Issue の同期の設定を見ずに、この表の項目を写す。取り込んだあとの更新は、Issue の同期の設定に従う。

## Issue の同期

リンクした Issue と、そのアイテムの 5 つの項目を、どちらを正本にして揃えるかを、ワークスペースごとに決める。設定は Store で共有する(01)。PR にはこの設定がなく、常に GitHub が正本である。

設定の「GitHub Issue」タブの「Issue の同期」には、次の説明と、5 行の表を置く。

> リンクした Issue のフィールドを、どちらを正本にして同期するかを決めます。push はアイテムの値を GitHub に送り、mirror は GitHub の値をアイテムに写します。PR は常に GitHub が正本です。

表の列は「GitHub のフィールド」「同期」「補足」である。「同期」の選択肢と意味、既定値は次のとおり。

| 選択肢 | 意味 |
|---|---|
| 同期しない | その項目は揃えない |
| push(アイテム → GitHub) | アイテムの値を GitHub の Issue に送る。アイテムが正本 |
| mirror(GitHub → アイテム) | GitHub の Issue の値をアイテムに写す。GitHub が正本 |

| GitHub のフィールド | 既定 | 補足(画面に出す文) |
|---|---|---|
| タイトル | mirror | (なし) |
| 本文 | push | (なし) |
| 状態(Open / Closed) | mirror | mirror のとき、Issue が「完了」で閉じるとアイテムを完了の既定のステータスに、「対応しない」で閉じると中止の既定のステータスにし、再び開くと完了・中止のアイテムを初期ステータスに戻します。push のとき、完了は「完了」、中止は「対応しない」の理由で閉じます |
| 担当者 | 同期しない | Issue に複数の担当者がいるとき、mirror は先頭のメンバー 1 人、push は担当者をアイテムの 1 人だけにします |
| マイルストーン | 同期しない | リリースと名前で合わせます |

設定を変えるのは 1 回の保存で、次の同期から効く。過去にさかのぼって揃え直すことはしない。同期しないから mirror に変えると、次の同期で、GitHub の値がアイテムの値を上書きする。

### いつ揃えるか

Store を同期するたびに(自動でも手動でも)、その Store の同期が済んだあとで、リンクした Issue を持つアイテムを順に GitHub と照らして揃える。方向が項目ごとに決まっているので、どちらが新しいかは見ず、正本の値で相手を直す。値が同じなら何もしない。

- mirror の項目で GitHub の値が違えば、アイテムを更新して保存する。この保存は、操作した人のいない自動の変更として、実行者「GitHub」でアクティビティとアイテムの履歴に残る(06)。
- push の項目でアイテムの値が違えば、GitHub の Issue を更新する。

リンクした直後や Issue を作った直後は、次の同期を待つ。閲覧のみの Store のアイテムは、push も mirror もしない(01)。Issue のリンクを持たないアイテム、同期の設定がすべて「同期しない」のワークスペースは、問い合わせもしない。

揃えるのに失敗した項目は、何も変えず、次の同期でやり直す。失敗の理由は、リンクの行に「同期できませんでした: 」に続けて、「GitHub との通信に失敗したとき」の表示、または次の表の文言を添えて出す。次に成功したら、添えた文言を消す。

### 項目ごとの規則

| 項目 | push(アイテム → GitHub) | mirror(GitHub → アイテム) |
|---|---|---|
| タイトル | アイテムのタイトルを Issue のタイトルにする | Issue のタイトルをアイテムのタイトルにする。空白の整え方は、アイテムのタイトルの入力と同じ(連続した空白と改行を 1 つの空白にし、前後を取る) |
| 本文 | アイテムの説明(Markdown)を Issue の本文にする | Issue の本文をアイテムの説明にする |
| 状態 | アイテムのステータスの分類が完了なら Issue を「完了(completed)」の理由で Closed に、中止なら「対応しない(not planned)」の理由で Closed に、未着手・進行中なら Open にする。閉じた理由だけが違うときは、理由を直す | 下の「状態の mirror」 |
| 担当者 | Issue の担当者を、アイテムの担当者 1 人だけにする。アイテムが未割り当てなら、Issue の担当者を空にする | Issue の担当者を並び順に見て、最初にメンバーのログイン名と一致した人を、アイテムの担当者にする。一致する人がいない、または担当者がいなければ、未割り当てにする |
| マイルストーン | アイテムのリリースと同じ名前(大文字と小文字は区別しない)のマイルストーンを Issue に付ける。リリースが空なら、Issue のマイルストーンを外す | Issue のマイルストーンと名前が一致するリリースを、アイテムのリリースにする。一致する(アーカイブしていない)リリースがなければ、空にする |

状態の mirror は、次のとおりにする。

- Issue が「完了(completed)」の理由で Closed で、アイテムのステータスの分類が完了でないとき、アイテムを、完了の既定のステータス(03)にする。
- Issue が「対応しない(not planned)」の理由で Closed で、アイテムのステータスの分類が中止でないとき、アイテムを、中止の既定のステータス(03)にする。
- Issue が Open で、アイテムのステータスの分類が完了か中止のとき(再オープン)、アイテムを、ワークスペースの初期ステータスに戻す。
- 上のどちらにも当たらないときは、アイテムを変えない。

担当者は、アイテムに 1 人しか持てず、GitHub の Issue は複数持てる。次の失敗を表の文言で出す。

| 失敗 | 文言 |
|---|---|
| push で、Issue の担当者にできない人だった(リポジトリのコラボレーターでない) | @{ログイン名} は {リポジトリ} の担当者にできません |
| push で、同じ名前のマイルストーンがリポジトリにない | マイルストーン「{名前}」が {リポジトリ} にありません。マイルストーンは作りません |
| 対象の Issue が見つからない(削除または移動された) | {リポジトリ}#{番号} が見つかりません |

Issue 同期による状態・担当者・リリースの変更は、ワークフローの遷移の制約を検査せずに適用する。GitHub で起きたことを反映するもので、断れないためである。この変更は、03 の自動化のきっかけにならない。Step にはリリースがないので、Step に Issue がリンクされていても、マイルストーンの同期の対象にしない。

## GitHub のコラボレーターをメンバーに追加

Store のメンバーの一覧(08)から、その Store の remote の GitHub リポジトリのコラボレーターを、まとめてメンバーに追加できる。メンバー一覧での入口の配置は 08 が定める。

使える条件は、Store の remote が GitHub のリポジトリで、Store に同期用のアカウントがあり、Store が閲覧のみでないことである。満たさないときは入口を無効にし、理由(「この Store の remote が GitHub にありません」「この Store に同期用のアカウントがありません」「閲覧のみの Store です」)を添える。

「GitHub のコラボレーターを追加」ダイアログには、コラボレーターの一覧を、1 人 1 行で出す。

- 各行に、チェックボックス、表示名、`@ログイン名` を並べる。すでに同じログイン名(大文字と小文字は区別しない)のメンバーがいる人は、チェックボックスの代わりに灰色の「追加済み」を出し、選べなくする。
- 一覧に出る人がいなければ「追加できるコラボレーターはいません」と表示する。
- ボタンは「N 人を追加」で、選択が 0 人のときは無効にする。

「N 人を追加」を押すと、選んだ人を 1 回の保存でメンバーに加え、「N 人をメンバーに追加しました」と表示する。メンバーの項目には、次を入れる。

| メンバーの項目 | 値 |
|---|---|
| 表示名 | GitHub のプロフィールの名前。なければログイン名 |
| ログイン名 | GitHub のログイン名 |

コラボレーターの一覧は、Store のアカウントで取得する。取得に失敗したときは、「GitHub との通信に失敗したとき」の表示を、一覧の位置に赤字で出す。GitHub は、リポジトリへの書き込み権限がないアカウントにはコラボレーターの一覧を返さない。その場合は、「コラボレーターの一覧を読めません。このリポジトリへの書き込み権限が必要です」と表示する。

## GitHub から Store を検索

GitHub 上の、チームの Store になっているリポジトリを探して、Store として追加する。入口は、設定の「Store」の「GitHub から検索」と、初回起動の案内(08)である。アカウントが 1 つもないときは、入口を無効にし、「GitHub のアカウントを登録すると使えます」と添える。

「GitHub から Store を検索」ダイアログは、開いたときに、次のとおり探す。

- 「利用可能」のアカウントがないときは、一覧の代わりに「GitHub から検索するには、認証済みのアカウントが必要です。設定の「アカウントとメンバー」で登録してください」と赤字で表示する。
- 利用可能なアカウントすべてについて、そのアカウントから見えるリポジトリを GitHub に問い合わせる。そのうち hedgehug の Store であるものを一覧にする。Store かどうかの判定は 08 の規則に従う。探しているあいだは「検索しています」と表示する。
- 説明として「アカウントから見える、hedgehug の Store になっているリポジトリです。」を表示する。
- 見つかったものがなければ「hedgehug の Store になっているリポジトリは見つかりませんでした」と表示する。
- 複数のアカウントから同じリポジトリが見えるときは、1 行にまとめる。

一覧の各行に、次を表示する。

| 表示 | 内容 |
|---|---|
| `owner/name` | リポジトリ |
| 「書き込み可」(緑) | そのアカウントに書き込み権限(push 以上)があるとき |
| 「閲覧のみ」(橙) | 書き込み権限がなく、読み取りだけのとき。この Store は閲覧のみの Store になる(01) |
| 名前の入力欄と「マウント」ボタン | まだ追加していないリポジトリ。名前の初期値は、リポジトリ名から末尾の `-tasks` を除いたもの |
| 「マウントしました」(灰) | すでにこのマシンに追加してあるリポジトリ。ダイアログで追加した行も、ダイアログを開いたまま、この表示に変わる。remote の URL を、SSH と HTTPS の違いを無視して比べて判定する(08) |

「マウント」を押すと、名前を次の順に確かめる。

| 条件 | 表示 |
|---|---|
| 英数字で始まる、英数字・`_`・`-` だけの名前でない | 名前は英数字、ハイフン、アンダースコアにしてください(先頭は英数字) |
| 同じ名前の Store がある(大文字と小文字は区別しない) | 同じ名前の Store があります |

通ったら、そのリポジトリを remote とする Store を追加し、「{名前} をマウントしました」と表示する。Store の中身の扱い(空のリポジトリのときだけ、ワークスペース「メイン」を作る)は 08 が定める。追加してもダイアログは閉じず、フッターは「閉じる」ボタンだけにする。続けて別のリポジトリを追加できる。

その Store の同期に使うアカウントは、そのリポジトリを探し当てたアカウントにする。複数のアカウントから見えるときは、書き込み権限のあるアカウントを優先し、同じなら登録の早いアカウントにする。閲覧のみかどうかは、マウントの時点の権限で決め、あとから権限が変わっても自動では変わらない。権限が変わったときは、Store をこのマシンから外して、もう一度検索して追加する。書き込めると思って編集した Store の push が拒否されたときの表示は 06 が定める。

探している途中で GitHub への通信に失敗したときは、「GitHub との通信に失敗したとき」の表示を、一覧の位置に赤字で出す。一部のアカウントだけ失敗したときは、見つかった分を一覧にして、失敗したアカウントごとに「{表示名}: 」に続けて失敗の表示を並べる。

## アクティビティに残る文

GitHub 連携の保存は、アクティビティと履歴に次の文で残る(06)。{ID} はアイテムの ID である。

| 操作 | 文 |
|---|---|
| PR・Issue のリンクを追加 | {ID} に {リポジトリ}#{番号} をリンク |
| リンクを解除 | {ID} のリンクを解除 |
| Issue の作成 | {リポジトリ}#{番号} を作成してリンク |
| Issue の取り込み | {リポジトリ} の Issue N 件を取り込み |
| Issue の同期の設定の変更 | Issue の同期({項目名})を {値} に変更。{値} は「同期しない」「push」「mirror」 |
| GitHub のコラボレーターをメンバーに追加 | GitHub のコラボレーター {N} 人をメンバーに追加 |

リンクの取り直しと、Issue の同期による自動の変更の文は 06 が定める。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| アカウントの確認 | ログイン名の存在とトークンを確かめない | 4 つの認証方法のすべてで、追加のときに GitHub に問い合わせて確かめ、確かめられなければ登録しない | 使えないアカウントを登録させないため |
| デバイスフローの中断 | キャンセルだけがアカウントを消し、Esc では未認証のまま残る | キャンセル、Esc、外側のクリックのどれでも登録しない。サインインが済んだときだけ登録する | 途中のアカウントを残さないため |
| デバイスフローの操作 | 「許可しました」「期限切れにする」を押す | 許可は GitHub から自動で検出する。拒否と期限切れは再試行できる | モック専用の操作だったため(01) |
| 同じログイン名のアカウント | 検査しない | 追加できない | 同じ表示名を断るのと揃え、同じ人を二重に登録しないため |
| GitHub App 未導入 | 「認証エラー」のアカウントすべてに、固定の組織名の帯を出す | 認証エラーとは別の状態にし、組織名は実際の組織を出す。「再確認」ボタンを加える | 2 つの意味を 1 つの状態に使っていたため |
| アカウントの削除 | ルールが残り、「(削除されたアカウント)」と出る。remote の有無を見ずに使っていた Store を同期エラーにする | そのアカウントを指すルールも削除する。確認には remote を持つ Store だけを挙げる | 宙づりのルールを残さず、同期の要らない Store を巻き込まないため |
| ルールのパターン | `*` の意味が決まっていない | `*` は 0 文字以上で `/` を越えず、大文字と小文字は区別しない。最初に当たったルールを使い、認証エラーのアカウントのルールも飛ばさない | 最も単純で、GitHub の名前の扱いに合うため |
| ルールの使い道 | PR・Issue を「読む」アカウント | 読む操作と書く操作(Issue の作成と同期)のどちらも、同じルールでアカウントを選ぶ | 書き込みのアカウントを別に選ばせないため |
| リンクのダイアログ | タイトルと状態を手で入力する。実在を確かめない | 番号だけを入力し、GitHub から取得する。種別の違いと実在、重複を確かめる | 実物を GitHub から取得するため(01) |
| プロジェクトにリポジトリがないとき | PR のリンクは入力できるが、Issue の作成は断る | PR のリンクも Issue の作成も、リポジトリを入力でき、プロジェクトのリポジトリに加えるかをチェックで選ぶ | 2 つの操作を揃えるため |
| Issue のリンクの数 | 1 つのアイテムに何本でも、同じ Issue を複数のアイテムにもリンクできる | 1 つのアイテムに 1 つ、1 つの Issue につき 1 つのアイテム。PR は制限しない | Issue の同期で、正本のアイテムが決まらなくなるため |
| リンクの更新 | 状態を更新する仕組みがない。「マージされたことにする」で手で変える | 詳細パネルを開いたときと、Store の同期のあとに取り直す。Merged は取り直さない | 実物の状態を保つため |
| PR が Open になったきっかけ | PR をリンクした時点だけ | リンク済みの PR が Open に変わったときも起こす | 状態を更新するようになるため |
| Issue の作成 | 仮の番号を付ける。ラベル・担当者・マイルストーンは送らない | GitHub が付けた番号を使う。送るのはタイトルと本文だけで、担当者とマイルストーンは同期の設定に従う | 実物を作るため。同期の設定と矛盾しないため |
| 取り込みのリポジトリの選択 | 保存の操作を通らず、Store を変えるかが決まっていない | 画面の状態としてこのマシンに覚える。Store には保存しない | Store を変えない操作のため |
| 取り込みの一覧の件数 | ラベルごとに「(N 件)」を付け、「すべて(N 件)」と出す | 件数は付けず、「すべて」と出す。一覧は新しい順に 100 件ずつ読み込む | 件数が多いと、すべてを数えるのに時間がかかるため |
| 取り込みの複数担当者 | 決まっていない | 並び順で最初にメンバーと一致した人 1 人 | アイテムの担当者は 1 人のため |
| 取り込みの入口 | ワークスペースの設定のタブだけ | 設定のタブと、Epic の「Issue から作る」(ユーザーの回答 F4) | Epic の中で取り込めるようにするため |
| Issue の状態の同期 | mirror で、Issue が閉じたときだけ動く | push と mirror の両方を定め、完了・中止は Closed、未着手・進行中は Open とする。再オープンで、完了・中止のアイテムを初期ステータスに戻す | 決まっていなかった push と再オープンを決めるため |
| Issue の同期の補足 | 状態とマイルストーンにだけ補足がある | 担当者に、複数担当者の扱いの補足を加える | 担当者の人数の違いを利用者に見せるため |
| Issue の同期のいつ | 決まっていない | Store の同期のたび。失敗した項目は次の同期でやり直し、理由はリンクの行に出す | 最も単純で、同期の仕組みと揃うため |
| Issue を閉じた理由 | 区別しない | 「完了」で閉じたら完了の既定、「対応しない」で閉じたら中止の既定にする。push でも、完了と中止で閉じる理由を分ける | 対応しないで閉じた Issue を、完了と数えないため(ユーザーの指示) |
| Issue 同期の変更の検査 | 決まっていない | 遷移の制約を検査せず、自動化のきっかけにもならない | GitHub で起きたことを断れず、連鎖を防ぐため |
| GitHub への通信の失敗 | 表示がない | 状況ごとの表示を決める(「GitHub との通信に失敗したとき」) | 失敗を利用者が判断できるようにするため |
| GitHub のコラボレーター | なし | Store のメンバーに、GitHub のコラボレーターをまとめて追加できる(ユーザーの回答 F1。2026-11-12 の再点検でも残すと確認)。ダイアログと文言は新設 | 本人が参加する前でも、担当者の候補に載せられるようにするため |
| Store の検索 | 固定の 3 リポジトリ。マウントするアカウントは「認証済みの最初の」アカウント | アカウントから見えるリポジトリを検索する。マウントするアカウントは探し当てたアカウント(書き込み権限のあるものを優先)。閲覧のみは権限で決める | 実物を検索するため(01) |
| 取り込みの説明文 | 「ステータスは最初のステータスになり」 | 「ステータスは初期ステータスになり」 | 03 で、初期ステータスを一覧の先頭とは別に指定すると定めたため |
| 取り込みの担当者・マイルストーンの照合 | 担当者は全メンバーからログイン名の完全一致。マイルストーンは大文字と小文字を区別し、アーカイブ済みのリリースも対象 | 担当者は大文字と小文字を区別せず、Issue の担当者を並び順に見て最初に一致した人。マイルストーンは大文字と小文字を区別せず、アーカイブ済みのリリースは対象外 | 名前とログイン名の大文字小文字の扱いを他の画面と揃え、選べないリリースに入れないため |
| 取り込みと検索の入口 | アカウントがなくても、閲覧のみの Store でも押せる | アカウントがないとき、閲覧のみの Store のときは無効にして理由を添える。Epic の入口はリポジトリがないときも無効 | 押してから断るより先に分かるようにするため(01) |
| Epic からの取り込みのリポジトリ | なし(入口がない) | そのプロジェクトのリポジトリから選ぶ。1 つなら固定、複数なら選べて既定は先頭 | 入口を新設するため |
| 取り込みの失敗 | 失敗の扱いがない | 実行時に各 Issue を確かめ直し、作れないものを除いて残りを作る。結果はダイアログに出す。通信の失敗は 1 件も作らない | 一覧を出したあとの変化に対応するため |
| 取り込みの通知とアクティビティ | 担当者が入っても通知を出す。文は「{リポジトリ} の Issue N 件を取り込み」 | 通知は 06 の通常の規則。文は「アクティビティに残る文」のとおり | 作成と同じ扱いにするため |
| Issue の同期の補足 | 状態とマイルストーンにだけ。状態は「閉じると完了にする」 | 状態に再オープンを加え、担当者にも補足を付ける | 決めた規則を画面で分かるようにするため |
| Issue の同期の設定の変更の文 | 項目名と値を英語のキーのまま出す | 項目名と値を画面の表記で出す | 画面の語に揃えるため |
| Store の検索のダイアログ | 追加すると行が「マウントしました」に変わり、ダイアログは開いたまま | 同じ。フッターは「閉じる」だけ | モックどおり |
| Store 名の検査文言 | 「名前は英数字とハイフンにしてください」 | 「名前は英数字、ハイフン、アンダースコアにしてください(先頭は英数字)」。重複は大文字と小文字を区別しない | 08 と同じにするため |
| 依頼文のコピー | 結果を表示しない | 成功は「コピーしました」。失敗は「コピーできませんでした。文を選択してコピーしてください」 | 結果が分かるようにするため |
| コラボレーターのメールアドレス | (モックにない) | 取り込まない。メンバーはログイン名で識別し、メールアドレスは持たない | 「あなた」の決め方の変更(01) |
