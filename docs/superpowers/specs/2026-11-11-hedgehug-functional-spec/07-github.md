# hedgehug 機能仕様 07: GitHub 連携

GitHub のアカウントを登録すると、アイテムを PR や Issue と結び付け、チームの Store を GitHub から探せるようになる。登録は任意で、登録しなくても、このマシンの中だけで使う分にはタスク管理のすべてが使える。

用語と、Store で共有するものとマシンごとに持つものの分け方は 01 を参照。詳細パネルのリンクの欄の配置は 02、自動化の定義は 03、同期全体と通知は 06、Store の追加とメンバー一覧の操作は 08 が定める。この文書は、GitHub とのやりとりで利用者に見える振る舞いを定める。

## GitHub を使わない場合

アカウントを 1 つも登録しないとき、次の機能は使えない。使えない入口は無効にし、「GitHub のアカウントを登録すると使えます」と添える。

| 使えないもの | 理由 |
|---|---|
| PR・Issue のリンクの追加 | GitHub に問い合わせるため |
| PR の自動リンク | PR を読めないため |
| PR・Issue の状態で動く自動化(PR がリンクされて Open のとき、レビューが依頼されたとき、リンクした PR がマージされたとき、リンクした Issue が閉じたとき) | PR・Issue のリンクを作れないため。ルールの登録はできるが動かない |
| GitHub から Store を検索して追加 | アカウントから見えるリポジトリを探すため |
| GitHub のコラボレーターをメンバーに追加 | 同上 |
| GitHub 上の remote を持つ Store の同期 | Store に GitHub に使うアカウントがないため(06) |

次のものは、アカウントがなくても使える。

- アイテム・プロジェクト・ワークスペースの管理、検索、レイアウト、計画、レポート
- remote のない Store(このマシンの中だけで動く)
- すでにリンクされた PR・Issue の表示。Store に保存されたタイトルと状態(PR はレビューの状態を含む)をそのまま出し、更新はしない。チェックの結果は、このマシンが読んだ値がなければ出さない

## アカウント

アカウントは、GitHub に接続するときの本人確認の手段を、名前を付けて登録したものである。マシンごとに持ち、Store には保存しない(01)。トークンは Store には保存しない。デバイスフローで登録したアカウントは、アプリを再起動しても使える(サインインし直さない)。登録・編集・削除・再認証は Store を変えないので、アクティビティには残らない(01)。

### 登録

設定の「アカウントとメンバー」にある「GitHub アカウント」で「追加」を押すと、「アカウントを追加」ダイアログが開く。ホストは `github.com` に固定する。

| 項目 | 内容 |
|---|---|
| 表示名 | 一覧と各種の選択肢に出す名前。例は「work」 |
| GitHub のログイン名 | GitHub のログイン名 |
| 認証方法 | 次の 4 つから選ぶ。既定は「ブラウザでサインイン(デバイスフロー)」 |

認証方法は次の 4 つである。一覧には「github.com · 」に続けて右の文言を表示する。

| 認証方法の選択肢 | 一覧に出す文言 |
|---|---|
| ブラウザでサインイン(デバイスフロー) | デバイスフローのトークン |
| gh CLI のトークン | gh CLI のトークン |
| 環境変数 | 環境変数 GH_TOKEN |
| OS のキーチェーン | OS のキーチェーン |

入力を確かめる順と、断るときの表示は次のとおり。最初に当てはまったものを表示して、何も登録しない。

| 条件 | 表示 |
|---|---|
| 表示名かログイン名が空(前後の空白を取り除いてから見る。空白だけなら空として扱う) | 表示名とログイン名を入力してください |
| 同じ表示名のアカウントがある(大文字と小文字は区別しない) | 同じ表示名のアカウントがあります |
| 同じログイン名のアカウントがある(大文字と小文字は区別しない) | 同じログイン名のアカウントがあります |

### 認証の確認

「追加」を押すと、GitHub に問い合わせて、その認証方法で本人確認ができるかを確かめる。確かめられたときだけアカウントを登録し、「アカウントを追加しました」と表示する。確かめられなかったときは、何も登録せず、ダイアログに理由を赤字で出す。

| 認証方法 | 確かめられなかったときの表示 |
|---|---|
| gh CLI のトークン | gh CLI のトークンが見つかりません。端末で `gh auth login` を実行してください |
| gh CLI のトークン(10 秒たっても応答がない) | gh CLI から応答がありません。端末で `gh auth status` を確かめてください |
| 環境変数 | 環境変数 GH_TOKEN が設定されていません |
| OS のキーチェーン | OS のキーチェーンに、サービス hedgehug・アカウント github.com/{ログイン名} のトークンが見つかりません |
| OS のキーチェーン(このマシンに OS のキーチェーンがない。WSL など) | このマシンでは OS のキーチェーンを使えません。gh CLI のトークンか環境変数を使ってください |
| 共通(トークンが GitHub に拒否された) | トークンが GitHub に受け付けられませんでした。認証方法を確かめてください |
| 共通(トークンのログイン名が入力と違う) | このトークンは @{実際のログイン名} のものです。ログイン名を直してください |
| 共通(通信の失敗) | 「GitHub との通信に失敗したとき」の表示 |

### 接続のたびの照合

gh CLI のトークン、環境変数、OS のキーチェーンのアカウントは、GitHub に接続するたびに、端末からトークンを読み直す(端末の値を見るだけで、通信しない)。読み直した値が、このアプリで最後に確かめた値と違うとき、またはアプリを開いてから初めての接続のときだけ、GitHub に 1 回問い合わせて、ログイン名を登録と照合する。ログイン名が同じなら、そのまま接続する。違うときは、接続せず、アカウントの状態を「認証エラー」にして、行の「認証エラー」の下に、登録のときと同じ文言「このトークンは @{実際のログイン名} のものです。ログイン名を直してください」を赤字で出す。同期は 06 の「認証に失敗した」、リンクの取得などは「GitHub との通信に失敗したとき」の「使うアカウントが認証エラー」になる。デバイスフローのアカウントは、トークンが hedgehug の保存分で変わらないので、この照合はしない。

認証方法が OS のキーチェーンのときは、サービス `hedgehug`・アカウント `github.com/{ログイン名}` の項目からトークンを読む。デバイスフローで得たトークンも、同じ場所に保存する。キーチェーンにトークンを入れる入口は、画面には持たない(CLI の仕様で決める)。

### デバイスフロー

認証方法がデバイスフローのときは、確認の代わりに「GitHub にサインイン」ダイアログを開く。

- デバイスフローに使う client ID(GitHub App か OAuth App のもの。どちらかは確かめない)は、このマシンの `config.yaml` の `hosts` に、ホスト `github.com` の `client_id` として書く。hedgehug は client ID を組み込まない。書かれていないときは、「GitHub にサインイン」を開かず、「アカウントを追加」ダイアログに「デバイスフローを使うには、config.yaml の hosts に github.com の client_id を設定してください。gh CLI のトークン・環境変数・OS のキーチェーンは、設定なしで使えます」を赤字で出す。
- GitHub が期限付きのトークンを返したとき(GitHub App で、トークンの期限を切っていないとき)は、期限が近づいたら、一緒に受け取った更新用のトークンで取り直す。利用者には見せない。取り直しに失敗したとき(更新用のトークンの期限切れ・取り消し)は、GitHub に拒否されたときと同じく「認証エラー」にする。
- 許可されたトークンを OS のキーチェーンに保存できないときは、登録せず、「GitHub にサインイン」を閉じて「アカウントを追加」に戻り、「このマシンでは OS のキーチェーンを使えません。gh CLI のトークンか環境変数を使ってください」を赤字で出す。

- 「このコードを GitHub で入力してください。」と、`XXXX-XXXX` の形の 8 文字のコード、「コピー」ボタンを表示する。
- 「https://github.com/login/device を開き、コードを入力して許可します。」と案内し、リンクを添える。
- コードの取得に失敗したときは、「GitHub にサインイン」を開かず、「アカウントを追加」ダイアログに理由を赤字で出す。理由は「GitHub との通信に失敗したとき」の表示である。
- GitHub で許可されると、ダイアログは自動で閉じ、アカウントを登録して「@{ログイン名} としてサインインしました」と表示する。許可したアカウントのログイン名が入力と違うときは、登録せず、「GitHub にサインイン」を閉じて「アカウントを追加」に戻り、ログイン名の欄に、上の表の「トークンのログイン名が入力と違う」の表示を赤字で出す。
- 待っているあいだは「許可を待っています」と表示する。待っているあいだに通信が切れたときは、つながるまで待ち続ける。
- コードの期限は GitHub が返す時間に従う。期限が切れたときは、すぐに、「コードの期限が切れました」と「再試行」ボタンを表示する。再試行すると新しいコードを出す。GitHub で許可が拒否されたときは、「GitHub で許可が拒否されました」と同じ「再試行」を表示する。

ダイアログを閉じる方法は、「キャンセル」ボタン、Esc、ダイアログの外のクリックのどれでも、アカウントを登録せずに終わる。サインインが済んだときだけ登録するので、サインインの途中のアカウントが一覧に残ることはない。

### 状態

一覧の各行には、表示名、`@ログイン名`、「github.com · {認証方法の文言}」、状態、削除ボタンを表示する。状態は次の 3 つのどれかである。

| 状態 | 意味 | 行の表示 |
|---|---|---|
| 利用可能 | GitHub に接続できる | 緑の「利用可能」 |
| 認証エラー | トークンの失効などで、GitHub に本人確認を拒否された。またはトークンのログイン名が登録と違う(「接続のたびの照合」) | 赤の「認証エラー」と「再認証」ボタン |
| GitHub App 未導入 | 認証はできるが、ある組織に、デバイスフローに使った GitHub App が入っていない(OAuth App なら、組織がその App のアクセスを許していない)ため、その組織のリポジトリを読めない | 橙の「GitHub App 未導入」と、組織名、「再確認」ボタン |

認証エラーと GitHub App 未導入の両方に当てはまるときは、認証エラーを表示する。認証エラーのあいだは、状態の表示は認証エラーだけにして、GitHub App 未導入の帯は出さない(未導入の記録は消さずに残す)。認証エラーが直ったとき、記録があれば、橙の「GitHub App 未導入」と帯が出る。この記録は、次に問い合わせて読めれば消える(下のとおり)。

認証エラーになるのは、そのアカウントを使う次のどれかで GitHub がトークンを拒否(401)したときである。Store の同期(06 の「認証に失敗した」と同じ事象)、リンクの追加と取り直し、PR の自動リンクの探索、コラボレーターの取得、Store の検索、組織の「再確認」、「接続のたびの照合」でのログイン名の不一致。権限不足や利用上限(403)では状態を変えない。

認証エラーから「利用可能」に戻るのは、次のどちらかである。
- 行の「再認証」を押す。
- 自動の確かめ直し。認証エラーのアカウントは、「GitHub を読む間隔」ごとに 1 回、トークンを読み直して本人を確かめる。確かめられ、ログイン名が登録と同じなら、「利用可能」に戻す(トーストは出さない)。デバイスフローはトークンが変わらないので自動では戻らず、「再認証」だけで戻る。設定「一般」の「裏で自動的に同期する」がオフのあいだは、自動の確かめ直しもしない。

GitHub App 未導入は、そのアカウントで組織のリポジトリを読もうとして拒否されたときに分かる。分かった組織名は、その組織のリポジトリに問い合わせるたびに確かめ直し、読めたら未導入の記録を外す。組織が複数あるときは、組織ごとに記録する。

GitHub App 未導入のアカウントがあると、アカウント一覧の上に、組織ごとに警告の帯を出す。

> {表示名}: {組織名} に GitHub App が入っていないため、PR と Issue を読めません。

帯には「管理者にインストールを依頼」ボタンがある。押すと、次の依頼文をクリップボードにコピーし、「コピーしました」と表示する。コピーできなかったときは、「コピーできませんでした。文を選択してコピーしてください」と表示し、依頼文を画面に出して選べるようにする。

> {組織名} に GitHub App をインストールしてください(@{ログイン名} が使います)

管理者が GitHub App を入れたあとは、「再確認」を押す。「再確認」は、そのアカウントの未導入の組織すべてに問い合わせ、組織ごとに更新する。読めた組織の帯と、行の組織名だけを消す。読めない組織の帯と行の組織名は残し、その帯の中に赤字で「まだ読めません」を出す。すべての組織が読めたら、状態は「利用可能」に戻る。読めた組織があったときは、トースト「{表示名}: {組織名} を読めるようになりました」を出す(複数なら組織名を「・」でつなぐ)。

「再確認」と「再認証」の失敗の理由は、トーストにせず、その行の中(状態の下)に赤字で出す。対象は、gh CLI・環境変数・OS のキーチェーンの「再認証」の失敗(「認証の確認」の表の文言)と、「再確認」「再認証」の通信の失敗(「GitHub との通信に失敗したとき」の表示)である。赤字は、次にその行を操作するまで、または別のタブへ移るまで残し、成功したら消す。デバイスフローの「再認証」の失敗は、開いたダイアログの中に出す(「デバイスフロー」のとおり)。問い合わせているあいだは、その行の「再確認」「再認証」を無効にして、「GitHub に問い合わせています」を行に出す。

### 再認証

認証エラーのアカウントの「再認証」を押すと、登録のときと同じ認証の確認をやり直す。デバイスフローのアカウントは、新しいコードのダイアログを開く。成功すると、状態が「利用可能」に戻り、「{表示名}: @{ログイン名} として再認証しました」と表示する。GitHub App 未導入の記録があれば、そのあと橙の「GitHub App 未導入」と帯が出る(「状態」を参照)。失敗したときは、登録のときと同じ表示を出し、状態は変えない。失敗の表示場所は「状態」のとおり。

### 編集

一覧の各行に、ごみ箱ボタンの左に「編集」ボタンを置く。押すと「アカウントを編集」ダイアログを開く。項目は「アカウントを追加」と同じ 3 つ(表示名・GitHub のログイン名・認証方法)で、いまの値が入っている。ボタンは「保存」と「キャンセル」である。

- 入力の検査は「登録」と同じである。ただし、同じ表示名・同じログイン名の検査は、このアカウント自身を除く。
- 「保存」を押すと、「認証の確認」(デバイスフローなら「デバイスフロー」のサインイン)を、新しい値で行う。確かめられたときだけ保存する。確かめられなければ、何も変えず、ダイアログに理由を赤字で出す。
- 保存すると、同じアカウントのまま値だけを入れ替える。Store に割り当てたアカウントはそのまま残る。完了時に「アカウントを変更しました」と表示する。
- 保存でログイン名が変わり、そのアカウントを割り当てた Store(非表示・閲覧のみを含む)で「あなた」が変わるときは、保存の前に「アカウントを変更」の確認ダイアログを出す。本文は、「削除の影響」の「あなた」が変わる Store の 1 行と同じ文(「{Store 名} での あなた が @{旧ログイン名} から {新ログイン名} に変わります。」)を Store ごとに 1 行並べる。ボタンは「変更」(警告色)と「キャンセル」である。
- 同期などで使われている最中でも保存できる。実行中の処理は古い値で最後まで続け、次の接続から新しい値を使う。
- アカウントは Store に保存しないので、同期で他の人と競合しない。アクティビティには残らない(01)。

### 削除の影響

アカウントの行のごみ箱ボタンを押すと、「アカウントを削除」の確認ダイアログを開く。本文は次の部品を、当てはまるものだけ、この順につなぐ。

- 「{表示名}」を削除します。
- {Store 名}・{Store 名} の同期に使っているため、それらは同期できなくなります。(remote を持つ Store で、このアカウントを割り当てているものがあるとき。非表示の Store と閲覧のみの Store も含む)
- {Store 名} での あなた が @{旧ログイン名} から {新ログイン名} に変わります。(このアカウントの削除で「あなた」が変わる Store があるとき。その Store ごとに 1 行。変わらないときは出さない)

「削除」を押すと、すぐに削除する(行を消し、Store の割り当てを「なし」にする)。完了時に「アカウントを削除しました」と表示する。すでに始まっている同期と取り直しは、取り出し済みのトークンで最後まで続け、結果は通常どおり表示する(同期カードの状態も更新する)。トークンは、その処理が終わった時点で破棄する。そのほかは次のとおりになる。

- このアカウントを割り当てていた Store のアカウントは「なし」になる。その Store は、アカウントを選び直すまで同期できず、GitHub を読めない。次の同期は「アカウントが設定されていないため同期できません」になる(06)。
- 「あなた」の決まり方(01)は、アカウントのログイン名の代わりに、このマシンの設定「ログイン名」(08)で探す形になる。
- リンク済みの PR・Issue は変わらない。ただし、その Store にアカウントがなくなれば、状態の更新、PR の自動リンク、同期は止まる(「PR と Issue のリンク」を参照)。

## GitHub との通信に使うアカウント

GitHub に問い合わせるとき(Store の同期、PR・Issue のリンクの取得と更新、コラボレーターの取り込み)は、すべて、その Store に割り当てたアカウントを使う。リンクはアイテムがある Store のアカウントである。アカウントは、設定の「Store」の「GitHub に使うアカウント」で割り当てる(08)。remote のない Store にも割り当てられる。

Store にアカウントがないときは、読めるアカウントがないものとして扱い、「GitHub との通信に失敗したとき」の「読めるアカウントがない」を表示する。割り当てたアカウントが認証エラーのときは、別のアカウントで読まず、認証エラーとして扱う。

GitHub に問い合わせるたびに、GitHub の応答に付く日時と、このマシンの時計を比べる。ずれが 5 分以上のときの警告は、設定「一般」とサイドバーの同期カードに出す(06、08)。

## GitHub との通信に失敗したとき

GitHub に問い合わせる操作が失敗したときは、何も変えずに、操作したダイアログの中に理由を赤字で出す。同期のあいだの失敗は、ダイアログがないので、リンクの行に出す(「PR と Issue のリンク」の「表示と更新」を参照)。PR の自動リンクのための読み取りの失敗は、リンクの行がないので、プロジェクトの概要のリポジトリの行に出す(02)。問い合わせているあいだは、操作のボタンを無効にして「GitHub に問い合わせています」と表示する。GitHub への 1 回の問い合わせは、30 秒応答がないと中断し、「通信できない」の表示を出す。ボタンは、問い合わせているあいだだけ無効にし、中断で有効に戻す。デバイスフローの待機(「デバイスフロー」)は、この時間切れの対象にしない。

| 状況 | 表示 |
|---|---|
| 通信できない | GitHub に接続できません。接続を確かめて、もう一度お試しください |
| 使うアカウントが認証エラー | {表示名}(@{ログイン名})の認証エラーのため、GitHub に接続できません。設定の「アカウントとメンバー」で再認証してください |
| リポジトリを読めない(権限がない、または存在しない) | {リポジトリ} を読めません。リポジトリの権限と、使うアカウントを確かめてください |
| 組織に GitHub App が入っていない | {組織名} に GitHub App が入っていないため、{リポジトリ} を読めません |
| 書き込む権限がない | {リポジトリ} に書き込む権限がありません |
| 番号の PR・Issue がない | {リポジトリ}#{番号} が見つかりません |
| 利用上限に達した | GitHub の利用上限に達しました。{時刻} 以降にもう一度お試しください |
| 読めるアカウントがない | {リポジトリ} を読めるアカウントがありません。設定の「Store」で GitHub に使うアカウントを選んでください |

GitHub はリポジトリがないときと、権限がないときに同じ応答を返すので、この 2 つは区別せず、「リポジトリを読めない」の表示を使う。{時刻} は、利用上限が解除される時刻を、このマシンの時刻で「HH:MM」の形にして出す。解除が翌日以降のときは、日付を前に半角スペースで足す(日付の形は 01 の書き方に従い、今年なら「11/13 09:00」、それ以外の年なら「2027/01/03 09:00」)。GitHub が秒数だけを返したときは、いまの時刻に秒数を足し、分に切り上げて「HH:MM」にする。時刻も秒数も分からないときは、「GitHub の利用上限に達しました。しばらくしてからもう一度お試しください」と出し、自動の読み取りは 1 分後まで止める。

## PR と Issue のリンク

アイテムは、PR と Issue をリンクとして持てる。リンクはアイテムごとに Store に保存し、チームで共有する(01)。1 つのリンクは、種別(PR か Issue)、リポジトリ、番号、タイトル、状態からなる。状態は、PR が Open・Draft・Merged・Closed、Issue が Open・Closed である。PR のリンクは、さらにレビューの状態(なし・レビュー待ち・承認済み・修正依頼)を持つ。アイテムは、解除した PR の記録(「解除」)も持つ。チェックの結果は Store に保存せず、このマシンが読んだ値だけを表示する。

### PR の自動リンク

PR は、ブランチ名や PR の説明から見つけて、アイテムに自動でリンクする。自動でリンクするのは PR だけで、Issue は手で「Issue をリンク」する(Issue の本文に ID を書いても付かない)。

**探すリポジトリ**

その Store の、削除済みでないプロジェクトに結びつけたリポジトリ(02)と、その Store の削除済みでないアイテムがリンクしているリポジトリを探す。Store の remote のリポジトリは探さない。探すのは、GitHub に使うアカウントがあり、書き込めて、非表示でない Store だけである。探せなかったときの表示は 02 が定める。

**探す時期**

「GitHub を読む間隔」の読み取りと同じ読み取りで、リポジトリごとに探す。前回の読み取りのあとに更新された PR をすべて見る。このマシンが、その Store のそのリポジトリを初めて読むときは、更新が新しい順に 100 件までを見る。プロジェクトにリポジトリを追加したとき(「PR をリンク」の「プロジェクトのリポジトリにも追加する」がオンのときを含む)は、間隔によらずすぐに探す。詳細パネルを開いたときは、開いたアイテムのリンクを取り直すだけで、探さない。

**見る場所と形**

| 見る場所 | 読む形 |
|---|---|
| ブランチ名 | `hh/` か `hedgehug/` のあとに ID が続き、そのあとが `-` か名前の終わり(例: `hh/WEB-1-login`、`hedgehug/WEB-1`)。大文字と小文字は区別しない |
| PR のタイトルと本文 | PR の印、または ID(`WEB-1`) |
| PR のコメント | 同じ。古い方から 100 件まで |

ID は、ワークスペースの接頭辞、`-`、番号の並びである(`WEB-1`)。タイトル・本文・コメントでは、すぐ前かあとに `-` が隣り合うものは、ID として読まない(「PRE-WEB-7」から「WEB-7」は取らない)。旧い ID(接頭辞を変える前、別のワークスペースへ移る前)は読まない。PR の印は、`hedgehug:` か `hh:` に、アイテムの内部の ID を続けたもので、詳細パネルの「PR 用の印をコピー」(02)で取れる。PR の本文に印があるときは、タイトルと本文のほかの ID を読まない。コメントは読む。

**リンクするアイテム**

その Store の、削除済みでないアイテム(Epic・Story・Task・Bug・Step)である。プロジェクトにはリンクしない(プロジェクトの ID「WEB-P1」は読まない)。削除済みのアイテムには付けず、復元してもさかのぼっては付けない。ID が複数の Store にあるときは、その PR のリポジトリを探している Store ごとに、その Store のアイテムにリンクする。1 つの PR が複数のアイテムに当たるときは、すべてにリンクする。Draft・Open・Merged の PR をリンクする。マージされずに閉じた PR(Closed)は、新しくリンクしない。すでにリンクしてある PR が Closed になったときは、リンクを残して状態を「Closed」と出す。すでにそのアイテムに同じリポジトリと番号のリンクがあるとき、解除の記録にあるときは、足さない。

**足すもの**

種別が PR のリンクを、タイトル・状態・レビューの状態とともに足す。1 回の保存で、実行者は「GitHub」である(「アクティビティに残る文」、06)。

**解除と付け直し**

解除すると(「解除」)、その PR は自動ではもうそのアイテムに付かない。付けたいときは、手で「PR をリンク」する。

### 追加

詳細パネルの GitHub の欄に、「PR をリンク」「Issue をリンク」の 2 つのボタンがある(配置は 02)。「PR をリンク」と「Issue をリンク」は、ダイアログの題名と、確かめる種別が違うだけで、項目は同じである。閲覧のみの Store のアイテムでは、「PR をリンク」「Issue をリンク」とリンクの解除ボタンを無効にする(01)。

| 項目 | 内容 |
|---|---|
| リポジトリ | アイテムが属するプロジェクトのリポジトリがあれば、そこから選ぶ。なければ `owner/name` の形で入力する |
| 番号 | PR または Issue の番号 |
| プロジェクトのリポジトリにも追加する | プロジェクトにリポジトリがなく、入力したリポジトリを使うときだけ出すチェック。既定はオン |

`owner/name` の形は、owner が英数字とハイフン、name が英数字・ピリオド・アンダースコア・ハイフンの `^[A-Za-z0-9-]+/[A-Za-z0-9._-]+$` である。前後の空白は取り除いてから見る。`*` や空白、2 つ以上の `/` を含むものは、形が違うものとして断る。リポジトリを入力する他の箇所(02)も、同じ形と同じ文言で検査する。

モックにあった「タイトル」と「状態」の入力欄は設けない。「リンク」を押すと、GitHub に問い合わせて、実在の確認とタイトル・状態の取得をする。確かめる順と、断るときの表示は次のとおり。

| 条件 | 表示 |
|---|---|
| リポジトリが `owner/name` の形でない | リポジトリは owner/name の形式で入力してください |
| 番号が正の整数でない | 番号を入力してください |
| このアイテムに同じリポジトリと番号のリンクがある(種別は問わない。リポジトリの大文字と小文字は区別しない) | もうリンクしています |
| GitHub への問い合わせの失敗 | 「GitHub との通信に失敗したとき」の表示 |
| 「PR をリンク」で、番号が Issue だった | {リポジトリ}#{番号} は PR ではなく Issue です |
| 「Issue をリンク」で、番号が PR だった | {リポジトリ}#{番号} は Issue ではなく PR です |
| Issue がすでに別のアイテムにリンクされている | {リポジトリ}#{番号} は {ID} にリンクされています |
| Issue をリンクするアイテムが、すでに別の Issue にリンクしている | このアイテムには Issue がリンクされています |

PR は、同じ PR を複数のアイテムにリンクできる。Issue は、1 つのアイテムに 1 つ、1 つの Issue につき 1 つのアイテムに限る。Issue が別のアイテムにリンクされているかは、このマシンにあるすべての Store の、削除済みを含むアイテムを調べる。同期で、1 つの Issue が 2 つのアイテムにリンクされた、または 1 つのアイテムに 2 つの Issue がリンクされたときは、あとから同期した方のリンクを外す(06)。解除した PR を手でリンクし直すと、その保存で、アイテムの解除の記録から消える。「もうリンクしています」の検査は、リンクだけを数え、解除の記録は数えない。

確かめられたら、タイトルと状態を保存してリンクを追加する。ダイアログは閉じ、トーストは出さない。「プロジェクトのリポジトリにも追加する」がオンなら、同じ 1 回の保存で、プロジェクトのリポジトリに加える。アクティビティには、リンクの文に「(プロジェクトのリポジトリにも追加)」を添えて 1 行で残る(「アクティビティに残る文」)。プロジェクトの履歴には、リポジトリの追加を残さない(02)。

### 表示と更新

リンクの行には、種別と状態を示すチップ、「{owner/name}#{番号} — {タイトル}」(例: 「example-org/web#12 — ログイン画面を直す」)、解除ボタンを表示する。状態が Open か Draft の PR の行には、チップのあとに、レビューの表示(「レビュー待ち」「承認済み」「修正依頼」。なしは出さない)と、チェックの表示(「CI 成功」「CI 失敗」「CI 実行中」。なしは出さない)を出す。Merged と Closed の PR には出さない。閲覧のみ・アカウントなし・非表示・オフラインの Store では、レビューは保存してある値を出し、チェックはこのマシンが読んだ値があるときだけ出す。リンクがなければ「リンクはありません」と表示する。

リンクのタイトル・状態・レビューの状態・チェックの結果は、次のときに GitHub から取り直す。

- 詳細パネルを開いたとき。開いたアイテムのリンクを取り直す。
- GitHub を読む間隔ごと(下の「GitHub を読む間隔」)。リポジトリごとに、そのリポジトリのリンクのうち、状態が Merged のものを除くすべてを取り直す。Merged の PR は、それ以上状態が変わらないので取り直さない。

非表示の Store のリンクは、GitHub の自動の取り直しをしない(08 の「ないものとして扱う」)。

取り直す値は、タイトル、状態、レビューの状態である。レビューの状態は、GitHub が承認済み・修正依頼と判定していればそれ、なければ各レビュアーの最新の意見に修正依頼があれば修正依頼、承認があれば承認済み、意見がなくレビューの依頼が 1 件以上あればレビュー待ち、それ以外はなしとする。チェックの結果は、Store に保存せず、このマシンだけが読んだ値として持つ。他のマシンには共有しない。

取り直した値が保存してある値と違うときだけ、新しい値を保存する。この保存は、操作した人のいない自動の変更として、実行者「GitHub」でアクティビティとアイテムの履歴に残る(06)。複数のマシンが同じ値を書いても、結果は同じで、アクティビティと履歴には、最も早い保存の 1 行だけが出る(06)。複数のマシンが別の値を書いたときは、06 の規則で保存時刻があとの値が残り、次の取り直しで GitHub の値にそろう。この保存と、PR の自動リンクの保存は、リンクの変更なので、ウォッチ・割り当ての通知を作らない(06)。保存によって自動化が動いたときは、03 のとおり「自動化」の通知が出る。

取り直しに失敗したときは、保存してある値のまま表示し、その行に、失敗の理由を添える。添える文言は、「状態を更新できませんでした: 」に、「GitHub との通信に失敗したとき」の表示を続けたものである。次の取り直しで成功すれば、添えた文言を消す。削除された PR・Issue や、権限が外れた・存在しないリポジトリのように本当に見つからないリンクも、「GitHub を読む間隔」ごとに取り直し続ける。上限や打ち切りは設けない。不要なら、利用者が解除ボタンで外す。

改名・移管されたリポジトリは、GitHub のリダイレクトを追って移動先で読む。見つかれば通常の取り直しとして扱い(エラーは出さない)、保存したリポジトリ名を新しい名前に書き換える。この書き換えは、タイトル・状態の変更と同じ自動の変更(実行者「GitHub」)で、アクティビティには「{ID} のリンクを {旧}#{番号} から {新}#{番号} に更新」と残る。書き換えると、同じアイテムの別のリンク、または別のアイテムの Issue のリンクと同じ内容になるときは、書き換えず、旧名のまま取り直しを続ける(エラーは出さない)。

閲覧のみの Store のアイテムのリンクは、取り直さず、保存してある値を表示する(01)。

### GitHub を読む間隔

GitHub を読むこと(PR・Issue のリンクの取り直しと PR の自動リンクの探索、権限とコラボレーターの読み取り)は、Store の同期とは別の間隔で行う。間隔は、設定「一般」の「同期のタイミング」にある「GitHub を読む間隔」で決める(5・15・30・60 分ごと。既定は 5 分ごと。08)。

- リポジトリごとに数え、前回から更新されたものだけを読む。
- 利用上限の残りが 10% 未満のあいだは、選んだ間隔の 3 倍にし、上限が戻るまで続ける。
- 上限を使い切って断られたら、上限が戻る時刻まで読まない(時刻は「GitHub との通信に失敗したとき」の {時刻} と同じ決め方。分からないときは 1 分後まで)。
- 読み取りに失敗したら、次の間隔まで読み直さない。
- remote のない Store のリンクも、この間隔で読む。
- この間隔は、自動で読むときだけに効く。利用者の操作で読むとき(詳細パネルを開いたとき、リンクを追加したとき、プロジェクトにリポジトリを追加したとき、コラボレーターの取り込み、Store の検索)は、間隔によらずすぐに読む。
- 設定「一般」の「裏で自動的に同期する」をオフにすると、「GitHub を読む間隔」は選べなくなり、GitHub を自動で読むのも止まる。
- 自動で読むときは、06 の「自動で同期する」で自動の同期を待たせる条件と同じ条件のあいだは始めず、解けたら続けて読む。
- 前回に読んだ(試した)ときから間隔が過ぎていれば、アプリを開いた直後と、オンラインに戻ったときにも読む。失敗したあとは、アプリを開いたときも、次の間隔まで読み直さない。
- リンクの取り直しと PR の自動リンクの探索は、書き込める Store で、非表示でないものだけで行う(「表示と更新」、「PR の自動リンク」)。

### 解除

リンクの行の解除ボタンを押すと、確認なしでリンクを外し、「リンクを解除しました」と表示する。誰が付けたリンクでも、Store に書き込める人なら解除できる。操作した人は、アクティビティの「{ID} のリンクを解除」の行に出る。閲覧のみの Store では、解除ボタンを無効にする(01)。保存に失敗したとき(通信の失敗など)は、エラーのトースト「リンクを解除できませんでした」を出す。PR のリンクを解除すると、その PR は、そのアイテムの解除の記録に入り、自動ではもうそのアイテムに付かない。解除の記録は画面に出さない。同じ 1 回の保存で、リンクを外し、記録に足す。手で「PR をリンク」し直すと、記録から消える。解除の記録は、アイテムを複製しても写さず、アイテムを完全に削除すると、リンクと一緒に消える。同期での合わせ方は、リンクも記録も 06 の「値を複数持つ項目」と同じで、自動リンクの解除だけの特別な規則は設けない。PR のリンクを外しても、すでに動いた自動化は取り消さない。

### PR・Issue の状態で動く自動化

リンクの状態、PR のレビューの状態が変わると、そのアイテムで次の自動化のきっかけが起きる。次の 4 つが、03 のきっかけ(全部で 6 つ)のうち PR・Issue のものである。ルールの定義と、実行の規則は 03 が定める。

| きっかけ | 起きるとき |
|---|---|
| PR がリンクされて Open のとき | PR をリンクして、状態が Open のとき。リンク済みの PR が、Open でない状態から Open に変わったとき(Draft から、または Closed から再び開いたとき) |
| レビューが依頼されたとき | PR をリンクして、状態が Open か Draft で、レビューの状態が「レビュー待ち」のとき。リンク済みの PR(状態が Open か Draft)のレビューの状態が、「なし」から「レビュー待ち」に変わったとき |
| リンクした PR がマージされたとき | PR をリンクして、状態が Merged のとき。リンク済みの PR が Merged に変わったとき |
| リンクした Issue が閉じたとき | Issue をリンクして、状態が Closed のとき。リンク済みの Issue が、Open から Closed に変わったとき。閉じた理由は区別しない(「計画なし」で閉じた Issue でも起きる) |

「PR がリンクされて Open のとき」は、Draft と Closed の PR では起きない。「レビューが依頼されたとき」は、Merged と Closed の PR では起きない。「レビュー待ち」から「承認済み」「修正依頼」に変わったあと、再び依頼しても、レビューの状態が「なし」に戻るまでは起きない。「レビュー待ち」が「なし」になってから、また「レビュー待ち」になれば、また起きる。Issue が再び開かれて、また閉じられたときも、また起きる。

きっかけが起きるのは、そのリンクの更新を実際に保存したマシンだけである。同期で受け取ったリンクの状態では、状態が何であっても、きっかけは起こさない。このマシンが、そのリポジトリを初めて読んだときの自動リンクでは、きっかけを起こさない(「PR の自動リンク」)。2 回目以降の自動リンクでは、手でリンクしたときと同じにきっかけが起きる。同じ PR を複数のアイテムにリンクしているときは、アイテムごとにきっかけが起きる。1 回の読み取りで同じきっかけが同じアイテムに複数起きたときは、そのアイテムの、そのきっかけに 1 回だけ起きる。複数のマシンで同じ自動化が動いて同じ変更を保存したときは、アクティビティと履歴に最も早い保存の 1 行だけが出る(06)。

## GitHub のコラボレーターをメンバーに追加

Store のメンバーの一覧(08)から、その Store の remote の GitHub リポジトリのコラボレーターを、まとめてメンバーに追加できる。メンバー一覧での入口の配置は 08 が定める。

使える条件は、Store の remote が GitHub のリポジトリで、Store に GitHub に使うアカウントがあり、Store が閲覧のみでないことである。満たさないときは入口を無効にし、理由(「この Store の remote が GitHub にありません」「この Store に GitHub に使うアカウントがありません」「閲覧のみの Store です」)を添える。

「GitHub のコラボレーターを追加」ダイアログには、コラボレーターの一覧を、1 人 1 行で出す。

- 開くと、コラボレーターを 100 人ずつ最後まで読む(組織のメンバーを含む「すべて」)。読んでいるあいだは「GitHub に問い合わせています」を出し、ボタンを無効にする。途中のページで失敗したら、読めた分は出さず、「GitHub との通信に失敗したとき」の表示を一覧の位置に赤字で出す。
- 種別がユーザー以外(ボット)は出さない。ログイン名の昇順に並べる。何も選ばれていない状態で開く。
- 一覧の上に検索欄を置く。入力した文字をログイン名に含む行だけを残す(大文字と小文字は区別しない)。一覧の見出しに、チェックボックス「表示中のうち選べる人をすべて選択」を置く。検索で隠れた行の選択は残る。
- 各行に、チェックボックスと `@ログイン名` を並べる。すでに同じログイン名(大文字と小文字は区別しない)のメンバーがいる人は、チェックボックスの代わりに灰色の「追加済み」を出し、選べなくする。
- 一覧に出る人がいなければ「追加できるコラボレーターはいません」と表示する。
- ボタンは「N 人を追加」で、選択が 0 人のときは無効にする。

「N 人を追加」を押すと、選んだ人の GitHub のプロフィールの名前を取得する。取得に失敗したら、何も追加せず、ダイアログの中に「GitHub との通信に失敗したとき」の表示を赤字で出す。取得できたら、その時点でメンバーを読み直し、すでにいる人は加えず、残りの人を 1 回の保存でメンバーに加えて、「N 人をメンバーに追加しました」と表示する。保存・トースト・アクティビティの N は、実際に加えた人数である。選んだ人が全員すでにメンバーだったときは、保存せず、エラーのトースト「選んだ人はすでにメンバーです」を出す。メンバーの項目には、次を入れる。

| メンバーの項目 | 値 |
|---|---|
| 表示名 | GitHub のプロフィールの名前(選んだ人の分だけ、追加のときに取る)。なければログイン名 |
| ログイン名 | GitHub のログイン名 |

コラボレーターの一覧は、Store のアカウントで取得する。取得に失敗したときは、「GitHub との通信に失敗したとき」の表示を、一覧の位置に赤字で出す。GitHub は、リポジトリへの書き込み権限がないアカウントにはコラボレーターの一覧を返さない。その場合は、「コラボレーターの一覧を読めません。このリポジトリへの書き込み権限が必要です」と表示する。

## GitHub から Store を検索

GitHub 上の、チームの Store になっているリポジトリを探して、Store として追加する。入口は、設定の「Store」の「GitHub から検索」と、初回起動の案内(08)である。アカウントが 1 つもないときは、入口を無効にし、「GitHub のアカウントを登録すると使えます」と添える。

「GitHub から Store を検索」ダイアログは、開いたときに、次のとおり探す。

- 検索に使うのは、「利用可能」と「GitHub App 未導入」のアカウントである(認証エラーのアカウントは使わない)。未導入の組織のリポジトリは読めないので、一覧にその組織のものは出ないが、個人・ほかの組織のリポジトリは出る。
- 検索に使えるアカウントがないとき(すべて認証エラー)は、一覧の代わりに「GitHub から検索するには、認証済みのアカウントが必要です。設定の「アカウントとメンバー」で再認証してください」と赤字で表示する。「登録してください」は、アカウントが 1 つもないときの入口の無効の説明だけにする。
- 検索に使えるアカウントすべてについて、そのアカウントから見えるリポジトリを GitHub に問い合わせる。それを一覧にする。一覧の段階では、hedgehug の Store かどうかを判定しない。検索は topic を使わない。Store を作るときに付く topic「hedgehug-store」(08)は、GitHub 上で見分けるための印である。探しているあいだは「検索しています」と表示する。
- 説明として「アカウントから見えるリポジトリです。」を表示する。認証エラーで外れたアカウントがあれば、その説明の下に、アカウントごとに 1 行、「{表示名}(@{ログイン名})は認証エラーのため検索していません」を表示する。
- 見つかったものがなければ「リポジトリは見つかりませんでした」と表示する。
- 複数のアカウントから同じリポジトリが見えるときは、1 行にまとめる。

一覧の各行に、次を表示する。

| 表示 | 内容 |
|---|---|
| `owner/name` | リポジトリ |
| 「書き込み可」(緑) | そのアカウントに書き込み権限(push 以上)があるとき |
| 「閲覧のみ」(橙) | 書き込み権限がなく、読み取りだけのとき。この Store は閲覧のみの Store になる(01) |
| 名前の入力欄と「マウント」ボタン | まだ追加していないリポジトリ。名前の初期値は、リポジトリ名から末尾の `-tasks` を除き、規則に合う形に整えたもの(`.` を `-` に置き換え、先頭が英数字でないあいだは先頭の 1 文字を削る。例: `my.repo-tasks` は `my-repo`、`_team-tasks` は `team`。整えた結果が空になるとき(例: `-tasks`)は空欄)。このマシンに Store が 1 つもないときは、「ログイン名」の入力欄も出す。初期値は、このマシンのログイン名が設定済みならそれ、なければそのリポジトリを探し当てたアカウントの GitHub のログイン名(01、08)。欄の下に、「この名前はメンバーとして Store に残り、あとから消せません。」と、「この Store では GitHub のログイン名 @{その行のアカウントのログイン名} があなたになります。ここに入れた名前は、アカウントを使わない Store で使います。」を添える |
| 「マウントしました」(灰) | すでにこのマシンに追加してあるリポジトリ。ダイアログで追加した行も、ダイアログを開いたまま、この表示に変わる。remote の URL を、SSH と HTTPS の違いを無視して比べて判定する(08) |

「マウント」を押すと、名前を次の順に確かめる。

| 条件 | 表示 |
|---|---|
| 英数字で始まる、英数字・`_`・`-` だけの名前でない | 名前は英数字、ハイフン、アンダースコアにしてください(先頭は英数字) |
| 同じ名前の Store がある(大文字と小文字は区別しない) | 同じ名前の Store があります |
| 「ログイン名」の入力欄を出しているとき、それが空、使えない文字を含む、または 39 文字を超える(前後の空白は取り除いてから検査する。中の空白は使えない文字) | 英数字・ハイフン・アンダースコアのログイン名(39 文字以内)を入力してください |

通ったら、そのリポジトリを clone して、Store かどうかを判定する。clone している間は、押した行の「マウント」ボタンを無効にして、行に「clone しています…」と表示する。ほかの行の「マウント」と、ダイアログの「閉じる」(Esc・外側のクリックを含む)も、無効にする。clone に失敗したときは、その行の下に、08 の「Store を追加」と同じ文言(「{remote} を clone できません。remote の URL とアカウントを確認してください」)を赤字で出す。Store でなければ、追加せず、同じ場所に 08 の文言(「{remote} は hedgehug の Store ではないため追加できません」)で断る。この hedgehug より新しい版の形式で保存されていれば、同じ場所に 08 の文言(「{remote} は新しい版の hedgehug で作られています。hedgehug を更新してください」)で断る。名前の検査の赤字も、押した行の下に出す。次にどの行かの「マウント」を押したら、前の赤字は消す。「同じ remote」の検査は、この経路には置かない。追加済みのリポジトリの行は「マウントしました」に変わり、「マウント」ボタンがないので、同じ remote には到達できない。

Store であれば、そのリポジトリを remote とする Store を追加する。remote は `https://github.com/{owner}/{name}.git` の形で登録する。どちらの形で入力しても、通信は Store のアカウントのトークンで行い、SSH の鍵は使わない。色は、08 の「Store を追加」と同じ既定(ほかの Store が使っていない最初の色。すべて使われていれば teal)にする。ダイアログに色の選択は設けない。あとから設定の「Store」の「色」で変えられる。

clone したリポジトリが空(hedgehug のデータが何もない)で、書き込める Store になるときだけ、clone のあと、ダイアログを閉じずに、その行の下に「ワークスペースの名前」「ワークスペースの接頭辞」の欄を出し、「追加」で続ける。検査と断る文言は、08 の「Store を追加」のワークスペースの欄(03「ワークスペースの作成」と同じ)と同じにする。この入力を待つあいだは Store をまだ追加しておらず、ほかの行の「マウント」と「閉じる」は無効のままにする。キャンセルすると、何も追加しない。hedgehug のデータがあるリポジトリと、閲覧のみの Store には、この欄を出さない(中身の扱いは 08 が定める)。

追加したときは、トーストを別々に、この順で出す。(1)ワークスペースを作ったときは「{名前} をマウントしました。ワークスペース「{ワークスペースの名前}」を作りました」、作らなかったときは「{名前} をマウントしました」。(2)「あなた」がメンバーにいなければ、「{ログイン名} をメンバーに追加しました」。閲覧のみの Store では、(2)を出さない。追加してもダイアログは閉じず、フッターは「閉じる」ボタンだけにする。続けて別のリポジトリを追加できる。

その Store に割り当てるアカウント(GitHub に使うアカウント)は、そのリポジトリを探し当てたアカウントにする。複数のアカウントから見えるときは、書き込み権限のあるアカウントを優先し、同じなら登録の早いアカウントにする。閲覧のみかどうかは、マウントの時点の権限で決め、あとから権限が変わっても自動では変わらない。見直すのは、閲覧のみの Store に限って、次の 3 つの操作をしたときだけである(トーストなどの詳細は 08)。書き込める Store は見直さない(push が拒否されたとき 06 で気づく)。(1)remote を空にした: 印を外す。(2)remote を別の github.com のリポジトリに変えた: 新しい remote の権限を、その Store のアカウントで GitHub に問い合わせ、書き込めるなら印を外す。読み取りのみ・読めないときは印を残す。通信に失敗したときは、印を残し、変更自体は受け入れる。(3)「GitHub に使うアカウント」を選び替えた: (2)と同じ問い合わせを、新しいアカウントで行う。印はこのマシンだけの設定なので、同期で他の人と競合しない。非表示の Store でも同じである。「閲覧のみ」に戻す操作は設けず、戻すには、Store をこのマシンから外して、もう一度検索して追加する。書き込めると思って編集した Store の push が拒否されたときの表示は 06 が定める。

探している途中で GitHub への通信に失敗したときは、「GitHub との通信に失敗したとき」の表示を、一覧の位置に赤字で出す。一部のアカウントだけ失敗したときは、見つかった分を一覧にして、失敗したアカウントごとに「{表示名}: 」に続けて失敗の表示を並べる。

## アクティビティに残る文

GitHub 連携の保存は、アクティビティと履歴に次の文で残る(06)。{ID} はアイテムの ID である。

| 操作 | 文 |
|---|---|
| PR・Issue のリンクを追加 | {ID} に {リポジトリ}#{番号} をリンク |
| PR・Issue のリンクを追加(「プロジェクトのリポジトリにも追加する」がオンで、プロジェクトにリポジトリを加えたとき) | {ID} に {リポジトリ}#{番号} をリンク(プロジェクトのリポジトリにも追加) |
| リンクを解除 | {ID} のリンクを解除 |
| リンクのリポジトリ名の書き換え(改名・移管の追従) | {ID} のリンクを {旧}#{番号} から {新}#{番号} に更新 |
| GitHub のコラボレーターをメンバーに追加 | GitHub のコラボレーター {N} 人をメンバーに追加(N は実際に加えた人数) |

リンクの取り直しと、PR の自動リンクによる自動の変更の文は 06 が定める。

## モックからの変更点

| 項目 | モック | この仕様 | 理由 |
|---|---|---|---|
| アカウントの確認 | ログイン名の存在とトークンを確かめない | 4 つの認証方法のすべてで、追加のときに GitHub に問い合わせて確かめ、確かめられなければ登録しない | 使えないアカウントを登録させないため |
| デバイスフローの中断 | キャンセルだけがアカウントを消し、Esc では未認証のまま残る | キャンセル、Esc、外側のクリックのどれでも登録しない。サインインが済んだときだけ登録する | 途中のアカウントを残さないため |
| デバイスフローの操作 | 「許可しました」「期限切れにする」を押す | 許可は GitHub から自動で検出する。拒否と期限切れは再試行できる | モック専用の操作だったため(01) |
| 同じログイン名のアカウント | 検査しない | 追加できない | 同じ表示名を断るのと揃え、同じ人を二重に登録しないため |
| GitHub App 未導入 | 「認証エラー」のアカウントすべてに、固定の組織名の帯を出す | 認証エラーとは別の状態にし、組織名は実際の組織を出す。「再確認」ボタンを加える | 2 つの意味を 1 つの状態に使っていたため |
| アカウントの削除 | remote の有無を見ずに使っていた Store を同期エラーにする | 確認には remote を持つ Store だけを挙げる。「あなた」が変わる Store があるときは、変わる前に確認で知らせる | 同期の要らない Store を巻き込まないため。「あなた」が知らないうちに変わらないようにするため(ユーザーの指示、2026-11-12) |
| リポジトリごとのアカウントのルール | リポジトリごとに、PR・Issue を読むアカウントを決めるルールがある | ルールをなくす。GitHub との通信は、すべてその Store に割り当てたアカウントで行う。remote のない Store にも割り当てられる | ユーザーの指示(2026-11-12)。仕組みを単純にするため。GitHub App が入っていない別の組織の PR は読めないが、ケースが少ないので受け入れる |
| アカウントの保存 | 決まっていない | デバイスフローで登録したアカウントは、アプリを再起動しても使える。トークンは Store には保存しない | ユーザーの指示(2026-11-12)。再起動のたびにサインインし直さないため |
| デバイスフローの失敗 | 失敗の扱いがない | コードを取得できないときは「アカウントを追加」に理由を出す。待機中の通信切断はつながるまで待つ。別の人が許可したときは「アカウントを追加」に戻り、ログイン名の欄に赤字を出す。コードの期限は GitHub が返す時間に従う | ユーザーの指示(2026-11-12)。失敗を利用者が判断できるようにするため |
| リンクのダイアログ | タイトルと状態を手で入力する。実在を確かめない | 番号だけを入力し、GitHub から取得する。種別の違いと実在、重複を確かめる | 実物を GitHub から取得するため(01) |
| プロジェクトにリポジトリがないとき | PR のリンクは入力できる | PR・Issue のリンクで、リポジトリを入力でき、プロジェクトのリポジトリに加えるかをチェックで選ぶ | プロジェクトにリポジトリがなくてもリンクできるようにするため |
| Issue のリンクの数 | 1 つのアイテムに何本でも、同じ Issue を複数のアイテムにもリンクできる | 1 つのアイテムに 1 つ、1 つの Issue につき 1 つのアイテム。PR は制限しない | Issue とアイテムを 1 対 1 にするため |
| Issue の取り込み・同期・作成 | 設定の「GitHub Issue」タブと Epic の「Issue から作る」で Issue を取り込める。リンクした Issue と 5 つの項目を push・mirror で同期できる。詳細パネルで Issue を作成できる | すべてなくす。Issue はリンクして、タイトルと状態(Open・Closed)を GitHub から読んで表示するだけにする。Issue の状態をアイテムの値に写すことはしない(自動化のルールが動いたときだけ、03 のとおり変える) | ユーザーの指示(2026-11-12)。取り込みと同期は、アイテムの値を GitHub と双方向に合わせるため、競合・制約・通知の細かな規則が増え、管理が複雑になるため |
| リンクの更新 | 状態を更新する仕組みがない。「マージされたことにする」で手で変える | 詳細パネルを開いたときと、設定「一般」の「GitHub を読む間隔」ごとに取り直す。Merged は取り直さない | 実物の状態を保つため。Store の同期とは別の間隔にするのは、ユーザーの指示(2026-11-12)。利用上限を使い切らないため |
| PR が Open になったきっかけ | PR をリンクした時点だけ | リンク済みの PR が Open に変わったときも起こす | 状態を更新するようになるため |
| GitHub を読む間隔 | なし | リポジトリごとに数え、前回から更新されたものだけを読む。利用上限の残りが 10% 未満のあいだは間隔を 3 倍にし、使い切ったら戻る時刻まで読まない。失敗したら次の間隔まで読み直さない。remote のない Store も同じ間隔で読む | ユーザーの指示(2026-11-12)。利用上限を使い切らないため |
